## 1. 로그아웃 구현

로그아웃은 두 가지 작업이 필요하다:
1. DRF 서버에 POST 요청 → **DB에 저장된 토큰 삭제**
2. 자신이 가진 `token.value`를 `null`로 초기화

```js
// stores/accounts.js
import { useRouter } from 'vue-router'

export const useAccountStore = defineStore('account', () => {
  const router = useRouter()

  const logOut = function () {
    axios({
      method: 'post',
      url: `${API_URL}/accounts/logout/`
    })
      .then((res) => {
        token.value = null                      // 토큰 초기화
        router.push({ name: 'LoginView' })      // 로그인 페이지로 이동
      })
      .catch((err) => console.log(err))
  }

  return { signUp, logIn, token, isLogin, logOut }
})
```

### App.vue에 로그아웃 버튼 추가

일관성을 위해 링크보다는 form submit 방식으로 구현한다.

```html
<!-- App.vue -->
<form @submit.prevent="logOut">
  <input type="submit" value="Logout">
</form>
```

```js
// App.vue
import { useAccountStore } from '@/stores/accounts'
const accountStore = useAccountStore()
const logOut = function () {
  accountStore.logOut()
}
```

## 2. 자연스러운 흐름을 위한 기타 기능

### 1. 로그인 성공 후 자동으로 메인 페이지로 이동

```js
// stores/accounts.js
const logIn = function (payload) {
  // ...
    .then(res => {
      token.value = res.data.key
      router.push({ name: 'ArticleView' })  // 자동 이동 추가
    })
}
```

### 2. 회원가입 성공 후 자동으로 로그인까지 진행

회원가입 응답에도 `key` 값이 오지만, 교재 방식대로 `logIn` 함수를 직접 호출하여 처리한다.

```js
// stores/accounts.js
const signUp = function (payload) {
  const { username, password1 } = payload
  // ...
    .then(res => {
      const password = password1    // password1 값을 password로 재사용
      logIn({ username, password }) // logIn 함수 호출 → 자동 로그인 + 메인 이동
    })
}
```

## 3. Django Signals

> "특정 이벤트 발생 시 알림을 보내는 시스템"

모델의 데이터 저장·삭제 같은 특정 시점에 추가 로직을 실행하고 싶을 때 사용한다.
예: 새 게시글 작성 시 이메일 알림 발송, 회원가입 시 환영 메일 전송.

### 사용 방법

**Step 1.** `signals.py` 파일 생성

```python
# articles/signals.py
from django.db.models.signals import post_save
from django.dispatch import receiver
from .models import Article

@receiver(post_save, sender=Article)
def article_post_save(sender, instance, created, **kwargs):
    if created:  # 새로 생성된 경우에만 True
        print(f"알림: 새로운 게시글이 작성되었습니다! (제목: {instance.title})")
```

**Step 2.** `apps.py`에 `ready` 메서드 등록 — **이 단계를 빠뜨리면 시그널이 동작하지 않는다!**

```python
# articles/apps.py
class ArticlesConfig(AppConfig):
    default_auto_field = 'django.db.models.BigAutoField'
    name = 'articles'

    def ready(self):
        import articles.signals  # 시그널 파일 import
```

| 시그널 종류 | 시점 |
|---|---|
| `pre_save` | 저장 직전 |
| `post_save` | 저장 직후 |
| `pre_delete` | 삭제 직전 |
| `post_delete` | 삭제 직후 |

## 4. 환경 변수 (Environment Variable)

API 키 같은 민감한 정보를 코드에 직접 작성하면 GitHub 등에 노출될 수 있다.
환경 변수로 관리하면 보안 이슈를 피하고, 개발/프로덕션 환경별로 값을 다르게 설정할 수 있다.

### Vite에서 환경 변수 사용하는 법

**Step 1.** 프로젝트 루트에 `.env.local` 파일 생성

```
VITE_API_URL=http://127.0.0.1:8000
VITE_TMDB_API_KEY=eyJhfiwnfdk202f...
```

**주의사항:**
- 변수명은 반드시 `VITE_` 접두어로 시작해야 한다 (없으면 값이 노출되지 않음)
- 변수명과 값 사이에 공백 없음

**Step 2.** 코드에서 불러오기

```js
const API_URL = import.meta.env.VITE_API_URL
const API_KEY = import.meta.env.VITE_TMDB_API_KEY
```

> `.env.local`은 `.gitignore`에 추가해서 GitHub에 올라가지 않도록 한다.
> 두 스토어(articles, accounts)에서 같은 API_URL을 사용할 때, 환경 변수로 관리하면 한 곳에서만 수정하면 된다.
