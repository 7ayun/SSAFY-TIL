## 🎯 학습 목표
* 알고리즘처럼 명확한 정답을 찾는 과정이 아닌, 수많은 기술을 조합해 최적의 경험을 만드는 **'종합 예술'**로서의 웹 개발 패러다임을 이해합니다.
* 기술 변화가 매우 빠른 웹 특성에 맞춰 **최소 5년 이내의 최신 자료**를 선별하고, 공식 문서(MDN)를 기반으로 'How'보다 **'Why'**를 탐구하는 학습 능력을 배양합니다.
* HTML 태그에 단순한 디자인적 접근이 아닌 **'의미(Semantic)'**를 부여하여 검색 엔진(SEO)과 시각장애인(스크린 리더)이 이해할 수 있는 웹 구조를 설계합니다.
* CSS의 3가지 적용 방식과 선택자별 **명시도(Specificity) 가중치 규칙**을 완벽히 습득하여 복잡한 스타일 충돌을 해결합니다.
* 웹 페이지 레이아웃의 근간인 **박스 모델(Box Model)**과 **`border-box`**의 물리적 계산 원리를 파악하여 정교한 UI를 구현합니다.

## 💡 주요 개념 정리

### 1. 웹 개발의 철학과 학습 전략
* **웹 개발의 본질:** 명확한 논리 구조를 찾는 알고리즘과 달리, 웹은 표준 기술들을 조합해 최적의 사용자 경험을 만들어가는 종합 예술에 가깝습니다.
* **검색 및 학습 원칙:**
    * **MDN 발췌독:** 웹 기술은 방대하므로 공식 문서를 처음부터 끝까지 읽지 말고, 필요한 부분만 특정해서 검색하여 읽는 능력이 중요합니다.
    * **Why 위주의 탐구:** 'How To'보다 'Why'를 검색하여 원리를 파악하는 것이 실력 향상에 훨씬 도움이 되며, AI에게 질문할 때도 원리와 힌트를 묻는 방식을 권장합니다.
    * **5년의 법칙:** 웹 기술은 변화가 매우 빠릅니다. 구글링 시 **작성된 지 5년 이상 된 블로그 글**은 현재 표준과 다를 확률이 매우 높으므로 지양해야 합니다.

### 2. 웹페이지의 3요소 (집 짓기 비유)

* **HTML (철골 프레임):** 웹페이지의 의미와 구조를 정의하는 뼈대 역할을 수행합니다.
* **CSS (인테리어):** 웹페이지의 디자인, 색상, 레이아웃(배치)을 담당하여 시각적 경험을 만듭니다.
* **JavaScript (전기 배선/동작):** 마우스 클릭, 드래그, 상호작용 등 동적인 기능을 구현합니다.

### 3. HTML (HyperText Markup Language)
* **HyperText:** 링크를 통해 문서 간을 비선형적으로 자유롭게 이동할 수 있는 구조로, 사용자가 주도적으로 탐색할 수 있게 합니다.
* **Markup:** 태그(`<>`)를 사용하여 데이터의 구조(대제목, 문단 등)를 잡는 언어입니다. 프로그래밍 언어와 달리 연산, 변수, 반복 기능은 지원하지 않습니다.
* **시맨틱(Semantic) 마크업의 가치:**
    * 단순히 글자를 크게 보이게 하려고 `h1` 태그를 쓰는 것이 아니라, '이 문서의 최상위 제목'이라는 **의미**를 부여하기 위해 사용해야 합니다.
    * **스크린 리더와 SEO:** 시각장애인용 리더기는 `<b>`(단순 굵게)는 무시하지만, `<strong>`(중요함)은 강조해서 읽어주며, 이는 검색 엔진이 페이지를 올바르게 해석하는 결정적 근거가 됩니다.

### 4. HTML 문서 구조 및 요소 특징
* **기본 뼈대 구성:**
    * `<!DOCTYPE html>`: 해당 문서가 HTML5임을 선언합니다.
    * `<html>`: 전체 컨텐츠를 포함하는 가장 큰 태그입니다.
    * `<head>`: 인코딩 설정(`utf-8`), 브라우저 탭 제목(`title`), 메타 데이터 등 설정 정보가 담기며 실제 화면에는 출력되지 않습니다.
    * `<body>`: 웹 화면에 표시되는 모든 실제 내용이 담기는 몸통으로, 한 문서에 하나만 존재해야 합니다.
* **작성 규칙 (Attribute):**
    * 요소 이름과 속성 사이는 반드시 **공백**으로 구분하며, 여러 속성 사용 시에도 콤마 없이 공백으로 나열합니다.
    * 속성값은 **큰따옴표(`""`)** 사용이 스타일 가이드상 권장됩니다.

### 5. CSS 적용 방식 및 명시도(Specificity)
* **적용 방식 비교:**
    | 방식 | 위치 및 방법 | 실무적 특징 및 권장도 |
    | :--- | :--- | :--- |
    | **인라인 (Inline)** | HTML 태그 내 `style` 속성 | 유지보수와 재사용성이 최악이므로 특수한 경우 외 지양합니다. |
    | **내부 (Internal)** | `<head>` 내 `<style>` 태그 | 한 파일 내에서 빠른 확인 시 편리하나 재사용성이 낮습니다. |
    | **외부 (External)** | 별도 `.css` 파일 연결 (`<link>`) | **실무 표준**. 가독성과 유지보수성이 가장 높아 강력 권장됩니다. |

* **명시도(Specificity) 가중치:** 스타일 충돌 시 승리하는 규칙입니다.
    1.  `!important`: 모든 규칙을 무시하고 무조건 승리 (구조를 파괴하므로 권장하지 않음).
    2.  인라인 스타일 (태그 내부 작성).
    3.  아이디 선택자 (`#`) - 문서 내 유일성.
    4.  클래스 선택자 (`.`) - **OOCSS의 핵심, 재사용 스타일**.
    5.  요소 선택자 (태그 이름).
    6.  전체 선택자 (`*`).
    * **캐스케이딩:** 가중치가 완벽히 같다면 코드상 가장 **나중에(아래에)** 작성된 스타일이 최종 적용됩니다.

### 6. CSS 박스 모델 (Box Model) 및 사이징
* **구성 요소:** Margin(바깥 여백), Border(테두리), Padding(안쪽 여백), Content(실제 내용물).
* **`box-sizing: border-box` 의 물리적 원리:**
    * **`content-box`(기본값):** `width: 100px` 설정 시, 좌우 패딩(10px*2)과 테두리(2px*2)가 더해져 실제 박스 너비는 **124px**이 됩니다.
    * **`border-box`(표준):** 테두리를 기준으로 크기를 계산하여 설정한 `width` 내에 패딩과 테두리가 포함되게 하여 너비를 100px로 유지합니다. 현대 개발의 필수 초기화입니다.
* **단위 체계:** 절대 단위(`px`)보다 루트 폰트 사이즈를 기준으로 하는 상대 단위 **`rem`**을 사용하는 것이 다양한 기기 대응(반응형)에 유리합니다.

## 💻 기능 구현 및 코드 실습

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>웹 기초 비급 실습</title>
    
    <link rel="stylesheet" href="style.css">
    
    <style>
        /* 1. 글로벌 리셋: 전체 선택자로 모든 박스의 계산 기준을 테두리로 고정함 */
        * {
            box-sizing: border-box;
            margin: 0;
            padding: 0;
        }

        /* 2. OOCSS 기초: 클래스 선택자 위주로 재사용 가능한 스타일 설계. 실무 활용 99% */
        .text-blue {
            color: blue;
        }
        
        .highlight {
            background-color: yellow;
            font-weight: bold;
        }

        /* 3. 명시도 전쟁: ID는 강력하지만 재사용이 불가능하므로 사용을 지양함 */
        #main-header {
            color: purple; /* 요소 선택자보다 우선순위가 높음 */
        }
    </style>
</head>
<body>
    <h1 id="main-header">나의 첫 웹 페이지 리팩토링</h1>

    <p class="text-blue">
        이것은 문단입니다. <strong class="text-highlight">중요한 키워드</strong>는 
        시맨틱하게 강조하여 검색 엔진과 스크린 리더에 정보를 정확히 전달합니다.
    </p>

    <a href="[https://www.google.com](https://www.google.com)">구글 공식 사이트 이동</a>

    <img src="images/sample.png" alt="샘플 시연용 이미지">

    <ul>
        <li>항목 1: HTML (구조)</li>
        <li>항목 2: CSS (스타일)</li>
        <li>항목 3: JavaScript (동작)</li>
    </ul>

    <div style="width: 200px; padding: 20px; border: 5px solid black; margin: 30px;">
        Box Model Border-Box 실습 영역
    </div>
</body>
</html>
```

## 🚀 복습 및 AI 인사이트
* **헷갈렸던 점 (물리적 원리):**
    * `margin-left: 25px`는 박스를 왼쪽으로 옮기는 명령이 아니라, **왼쪽 영역에 25px의 빈 공간을 확보**하여 실제로는 박스가 **오른쪽으로 이동**하게 된다는 점을 정확히 인지해야 합니다.
    * 클래스를 여러 개 부여할 때(`class="blue green"`) HTML에 적은 순서가 아니라 **CSS 파일에서 아래(나중에) 선언된 스타일**이 우선권을 갖는 캐스케이딩 규칙을 주의 깊게 확인해야 합니다.
    * **상속(Inheritance):** 텍스트 관련 요소(Color, Size 등)는 부모에게 주면 자식에게 흐르지만, **너비(width)나 테두리(border)** 같은 레이아웃 속성은 절대 상속되지 않습니다.
* **AI 활용 팁:**
    * 웹 기술은 5년만 지나도 구식이 됩니다. AI에게 코드를 요청할 때 반드시 **"최신 표준(MDN 기준)에 맞는 방식인가?"**를 검증하고 정보의 시점을 체크하는 습관이 중요합니다.
    * 단순히 정답 코드를 받는 것보다, 특정 UI 구조에 대해 **"가장 시맨틱한 태그 구성은 무엇이며, 그 이유는 무엇인가?"**라고 질문하여 설계 원리를 습득해야 합니다.
    * **인터넷 익스플로러(IE)**와 같은 구형 브라우저 호환성 문제를 AI와 함께 검토하되, 현대 표준인 **Reset(Reboot)** 설정을 통해 공평한 시작점을 잡는 것이 효율적입니다.
