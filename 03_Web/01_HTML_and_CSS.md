## 💡 주요 개념 정리

### 1. 웹 개발 학습의 올바른 방향성
* **알고리즘과의 차이점:** 명확한 정답 하나를 찾는 알고리즘(논리적 접근)과 달리, 웹은 방대한 기술을 조합해 최적의 경험을 만드는 '종합 예술'에 가까움
* **검색 방식의 전환:** 'How To'로 바로 정답을 찾는 것보다 원리를 묻는 'Why' 중심으로 검색 및 AI 프롬프팅 권장 (AI에게 물어볼 때도 힌트와 원리를 요구할 것)
* **정보의 최신화 주의:** 웹 기술은 매우 빠르게 변하므로 최소 5년 이상 된 기술 블로그 글은 현재 표준과 다를 수 있어 참고 지양
* **공식 문서 활용:** 웹 개발자의 바이블인 모질라 재단의 **MDN Web Docs** 적극 활용 (구글링 시 항상 `MDN` 키워드를 붙여서 검색하는 습관 필요)

### 2. 웹 페이지 구성 요소의 비유 (집 짓기)
* **HTML (구조):** 집의 철골 프레임 구조. 웹의 의미와 뼈대 담당
* **CSS (스타일):** 집의 인테리어 및 배치. 웹의 디자인과 레이아웃 제어
* **JavaScript (동작):** 집의 전기 배선 및 상호작용. 클릭 시 드롭다운, 드래그 등 페이지와의 동적 상호작용 담당 (웹 과정 후반부 학습)

### 3. HTML (HyperText Markup Language) 핵심 원리
* **HyperText (비선형성):** 1페이지에서 2페이지로 순서대로 가는 선형 구조가 아님. 링크(`a` 태그)를 통해 사용자가 주도적으로 어디든 즉시 접근 및 이동 가능한 텍스트
* **Markup Language:** 태그를 이용해 데이터의 구조를 잡는 언어 (마크다운의 `#` 헤딩이 HTML의 `h1` 문법을 차용한 것). 연산이나 변수가 없으므로 프로그래밍 언어에는 해당하지 않음
* **태그의 의미론적(Semantic) 중요성:** 단순한 크기 변경이나 디자인이 목적이 아님. 구글 검색 엔진이나 시각장애인용 '스크린 리더'가 문서를 올바르게 해석하기 위해 의미에 맞는 태그 사용 필수
  * `h1` 태그: 문서의 최상위 대제목을 의미하므로 하나의 HTML 문서에 1개만 존재하는 것을 권장
  * `b` 태그 vs `strong` 태그: 시각적으로는 둘 다 굵은 글씨지만, `strong`은 "중요하다"는 의미를 담고 있어 스크린 리더가 강조해서 읽어줌
* **HTML 문서 기본 뼈대:**
  * `<!DOCTYPE html>`: 이 문서가 HTML 문서임을 컴퓨터에 선언하는 최상단 코드
  * `<head>`: 사용자 화면에 보이지 않는 메타 데이터(설정). 브라우저 탭의 제목(`<title>`), 인코딩 설정(`<meta charset="utf-8">`) 등 포함
  * `<body>`: 실제 웹 페이지 화면에 출력되는 모든 몸통 내용. 하나의 HTML 문서당 단 1개만 존재해야 함
* **빈 요소 (닫는 태그가 없는 태그):**
  * `<meta>`, `<img>` 등 내부에 품을 '내용(컨텐츠)'이 없기 때문에 닫는 태그가 불필요함
  * `<img>` 태그의 `alt` 속성: 이미지 경로 오류 시 출력되는 대체 텍스트이자, 스크린 리더가 이미지를 설명할 때 읽어주는 필수 값

### 4. CSS (Cascading Style Sheets) 핵심
* **Cascading (폭포수):** 폭포수처럼 위에서 아래로 단계적으로 스타일이 떨어지며 적용된다는 의미
* **CSS 적용 3가지 방법:**
  1. **인라인 (Inline):** 태그 안에 직접 작성 (`<h1 style="color: blue;">`). HTML 구조를 지저분하게 만들고 유지보수성과 재사용성을 극도로 떨어뜨리므로 강력히 비권장
  2. **내부 (Internal):** `<head>` 내 `<style>` 태그에 작성. 파일 이동 없이 한 화면에서 테스트하기 좋아 수업 중 자주 사용
  3. **외부 (External):** 별도의 `.css` 파일을 만들고 `<link>` 태그로 연결. 실무에서 가장 권장되는 표준 방식
* **선택자 (Selector):**
  * **전체 (`*`):** 문서 내 모든 요소 선택
  * **요소 (`h1`, `p`):** 특정 태그 전체 선택
  * **클래스 (`.name`):** 점(`.`)으로 시작. 재사용성을 위해 만들어두고 여러 태그에 부여. 실무 활용도 99%
  * **아이디 (`#name`):** 샵(`#`)으로 시작. HTML 상에서 기능적으로 막히진 않으나, 의미론적으로 문서 내 단 1개만 유일하게 사용하는 것을 권장
* **명시도 (우선순위 가중치 규칙):** 좁고 구체적으로 선택할수록 힘이 강함
  * `!important` (생태계 파괴자, 계단식 룰 무시. 특수 케이스 외 비권장) **>** 인라인 스타일 **>** 아이디(`id`) **>** 클래스(`class`) **>** 요소 태그 **>** 전체(`*`)
  * 가중치가 완전히 동일하다면, 코드상 마지막에 선언된(가장 아래에 작성된) 스타일이 승리
  * **주의:** HTML 태그 내의 클래스 이름 작성 순서(`class="green orange"`)는 명시도에 아무런 영향을 주지 않음. 오직 CSS 파일 내의 선언 순서가 중요

### 5. CSS 속성 값과 단위 및 상속
* **절대 단위 (`px`):** 직관적이고 디자인 시안과 동일하게 고정되지만, 모바일/태블릿 등 다양한 디바이스 화면 크기에 유연하게 대응하기 힘듦
* **상대 단위 (`em` vs `rem`):** 반응형 웹을 위한 핵심
  * `em`: 바로 위 부모 요소의 폰트 사이즈 기준 (1em = 1배). 단점은 태그가 깊게 중첩될수록 연쇄적으로 크기가 변해 예측이 어려움
  * `rem`: Root(최상위 html 태그, 보통 16px) 기준. 중첩에 구애받지 않고 내 갈 길을 가는 일관된 상대 크기 유지가 가능해 전체 텍스트 구조를 짤 때 주로 사용
  * **팁:** 값이 `0`일 때는 단위 생략 권장 (`0px`, `0rem`, `0%` -> `0`)
* **상속 (Inheritance):**
  * 텍스트 관련 속성(color, font-size, 정렬 등)은 부모에서 자식으로 자동 상속됨 (개발자 도구에서 `inherited from parent` 확인 가능)
  * 박스 관련 속성(width, height, border, margin 등) 및 위치 지정(position)은 상속되지 않음

### 6. CSS 박스 모델 (Box Model) 및 스타일 가이드
* **핵심 정의:** CSS는 원형 이미지를 포함한 웹의 모든 요소를 네모난 상자(Box)로 인식하여 배치함
* **구성 4요소:**
  1. **Margin:** 테두리 바깥의 외부 여백 (주의: `margin-left: 25px`은 '왼쪽으로 이동'이 아니라 '왼쪽 마진 영역에 25px을 줘서 오른쪽으로 밀어내는 것')
  2. **Border:** 요소의 테두리
  3. **Padding:** 테두리와 실제 내용물 사이의 내부 여백
  4. **Content:** 요소의 실제 내용물 (`width`, `height` 값)
* **단축 속성:** 방향 4개 지정 시 상-우-하-좌(시계방향) 순서로 적용됨
* **Box-Sizing의 비밀 (가장 잦은 오류 원인):**
  * 기본값 `content-box`: 설정한 `width` 100px이 Content만의 크기. 만약 Padding 10px, Border 2px이 양쪽에 붙으면 100 + 10*2 + 2*2 = 실제 화면을 차지하는 너비는 124px이 되어 레이아웃이 깨짐
  * 해결책 `border-box`: 설정한 `width` 100px 안에 테두리와 패딩을 모두 포함시켜 직관적인 계산이 가능하도록 강제하는 필수 초기 설정
* **스타일 가이드 및 디버깅 팁:**
  * 태그는 대소문자 구분 없으나 모두 소문자 작성 권장
  * 속성 값은 큰따옴표(`"`) 사용 권장
  * HTML은 콤마(`,`) 대신 공백으로 다중 속성 구분
  * HTML/CSS는 에러 출력이 없으므로 반드시 크롬 개발자 도구(F12 또는 Ctrl+Shift+I)를 켜두고 요소 검사를 통해 디버깅(취소선 확인 등) 진행 필수

## 💻 기능 구현 및 코드 실습

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>Patrick's Web Profile</title>
  <link rel="stylesheet" href="./style.css">
</head>
<body>
  <h1 id="main-title">AI 학습 조력자 패트릭</h1>

  <img src="[https://loremflickr.com/320/240](https://loremflickr.com/320/240)" alt="랜덤 샘플 이미지" class="profile-img">

  <p class="description txt-bold">
    안녕하세요! 저는 <strong>웹 개발</strong>을 배우고 있습니다 <br>
    제 GitHub은 <a href="[https://github.com](https://github.com)">여기</a>를 클릭하세요
  </p>

  <ul class="skill-list">
    <li>HTML5</li>
    <li class="highlight txt-bold">CSS3</li>
    <li>Python</li>
  </ul>
</body>
</html>
```

```css
/* style.css */

/* 박스 사이즈 계산을 테두리 기준으로 직관화 (124px 오류 방지) */
* {
  box-sizing: border-box;
  margin: 0; /* 값이 0일 경우 단위 생략 원칙 */
  padding: 0;
}

#main-title {
  color: darkviolet; /* 텍스트 속성이므로 자식 요소가 있다면 자동 상속됨 */
  margin-top: 2rem; /* 루트 기준 상대 단위 사용 (보통 32px) */
}

/* 실무에서 99% 사용하는 클래스 선택자 */
.description {
  width: 300px; 
  padding: 20px;
  border: 2px solid black; /* 축약 속성: 너비, 스타일, 색상 (순서 무관) */
}

.txt-bold {
  font-weight: bold;
}

/* 자손 결합자 활용 */
.skill-list li {
  color: gray;
  margin-left: 20px; /* 왼쪽 여백을 20px 줘서 상자를 오른쪽으로 밀어냄 */
}

/* 가중치(명시도) 싸움: 아래 코드가 태그 선택자(li)를 이기고 주황색 적용됨 */
.skill-list .highlight {
  color: orange; 
}
```

## 🚀 복습 및 AI 인사이트
* **헷갈렸던 점 1 (선언 순서 vs 가중치):** HTML 태그 안에 `class="green orange"`라고 적었다고 해서 우선순위가 정해지는 것이 아님. 가중치가 같다면 무조건 CSS 파일에서 가장 마지막(아래)에 적힌 속성이 승리함
* **헷갈렸던 점 2 (마진의 방향성):** `margin-top: 50px`은 "위로 50px 이동"이 아니라, "내 윗통수에 50px짜리 외부 여백을 둠"을 의미. 결과적으로 박스는 화면에서 아래로 이동하게 됨
* **AI 활용 팁:** 속성 동작 불량이나 개념 혼동 시 AI에게 "해결 코드만 줘"가 아니라 "MDN Web Docs 표준 가이드를 기반으로 왜 이런 문제가 발생했는지(Why) 설명해 줘"라고 프롬프팅. 레거시 기술 대신 최신 표준 원리 습득 가능
