## 1. 파운데이션 모델의 개념

### 1-1. 정의

**대량의 데이터를 기반으로 사전 학습된 대규모 AI 모델**. 다양한 태스크에 범용적으로 활용할 수 있는 기초 모델의 역할을 한다. 텍스트 생성(ChatGPT, Gemini, Claude), 비디오 생성(Sora), 이미지 생성 등이 모두 파운데이션 모델의 예시이다. 최근에는 텍스트를 넘어 오디오·이미지·비디오를 동시에 입출력할 수 있는 **멀티모달 파운데이션 모델**로 발전하고 있다.

### 1-2. 기존 AI 모델과의 핵심 차이 — 별도 학습의 필요 여부

2020년 이전 AI 모델: 감정 분류를 하려면 감정 분류 데이터를 수천~수십만 개 만들고, 그 데이터로 별도 학습해야 감정 분류**만** 가능한 모델을 만들 수 있었다.

파운데이션 모델: 새로운 태스크를 위해 별도의 데이터 수집·학습 없이, **자세한 설명과 소수의 예시**만으로 새로운 태스크를 해결. 학습에는 수백~수천억 원이 들지만, 한 번 잘 학습해놓으면 어디서든 범용적으로 사용 가능.

### 1-3. 파운데이션 모델의 3가지 핵심 요소

**1) 빅데이터**: 2010년 이후 인터넷 데이터가 기하급수적으로 증가. 딥러닝 모델은 학습 데이터가 늘어날수록 성능이 좋아진다는 것이 관측됨.

**2) 자가지도 학습(Self-Supervised Learning)**: 인터넷 데이터를 지도학습(사람이 레이블링)으로 활용하려면 데이터 생성 속도보다 레이블링 속도가 느려 병목 발생. 해결: 데이터 스스로에서 레이블을 만드는 자가지도 학습.

핵심 방법 — **다음 토큰 예측(Next Token Prediction)**: 인터넷에서 "아까 밥 먹고 왔어"를 추출하면, "아까 밥 먹고"를 입력, "왔어"를 정답으로 자동 분할. 사람이 정답을 알려줄 필요 없이 데이터 자체에서 입력/출력 쌍을 생성. 이를 60~70억 인구가 만든 인터넷 데이터 전체에서 반복하면, 노이즈는 자연스럽게 제거되고 **인류가 어떻게 응답하는지의 근사치**와 **웹상의 지식 체계**를 학습할 수 있다. 자가지도 학습 단독으로는 대충 학습하는 것이지만, 이를 굉장히 많은 데이터에서 반복하는 것이 핵심.

**3) 트랜스포머 모델**: 입력 데이터 중 어떤 부분이 중요한지를 주의 집중(어텐션)하는 메커니즘을 학습하는 모델. 동일하게 생긴 블록을 여러 개 쌓는 구조. 대규모 데이터를 가장 잘 학습하고 이해할 수 있는 인공신경망 구조로 검증됨.

## 2. 텍스트 파운데이션 모델(거대 언어 모델)

### 2-1. 언어 모델에서 거대 언어 모델로

GPT-1, BERT 같은 **이전 세대 언어 모델**도 3가지 요소를 모두 갖추고 있었다. BERT는 테스크마다 별도로 만들던 이전 모델들보다 **단일 모델**로 더 높은 성능을 달성했다. 하지만 여전히 소규모 추가 학습이 필요했고, ChatGPT처럼 학습 없이 바로 쓸 수 있는 수준은 아니었다.

### 2-2. GPT 시리즈 발전사

**GPT-1**: 사전 학습 후 특정 문제를 위한 별도 학습 필요. 기존 언어 모델과 동일한 방식.

**GPT-2**: 더 많은 데이터 + 더 큰 모델(1.5B)로 학습. 놀라운 발견 두 가지: (1) **추가 학습 없이도 텍스트 지시만으로 어느 정도 새로운 태스크 수행 가능**. (2) 모델 규모를 3배/7배/10배로 키워도 **테스트 성능이 계속 좋아지며 과적합이 일어나지 않음** — 모델이 더 커질 여지가 있다는 의미.

**규모의 법칙(Scaling Law)**: 작은 규모 실험의 결과만으로 추세선을 그려 더 큰 규모의 실험 결과를 **예측**할 수 있다. 데이터 규모, 모델 사이즈, 연산량(학습 기간) 모두에서 성립. **테스트 로스**(다음 토큰 예측 정확도)가 규모에 비례해 개선.

이것이 중요한 이유 — 회사 의사결정 근거: "10억 써서 여기까지 달성했는데, 100억 주면 성능을 50% 개선 가능" 같은 추론이 가능해짐. GPT-2(1.5B)에서 GPT-3(175B)로 100배 규모를 키우는 결정은 회사 명운을 거는 일이었는데, 규모의 법칙이 그 근거가 됨.

**GPT-3 (175B 파라미터)**: GPT-2 대비 100배 규모. 텍스트 데이터 4TB(3,000억 단어), 학습비용 약 150억 원 추산. 데이터 구성: 커먼 크롤(인터넷) 60% + 책·위키피디아·검수된 웹 데이터 40%. 깊이(레이어 수)와 넓이(뉴런 수) 모두 크게 증가.

### 2-3. 창발성(Emergent Property)

모델 규모를 계속 키우다 보니 예상하지 못한 성질이 나타나기 시작. 대표적 예시가 **인컨텍스트 러닝**: 1.3B 모델은 예시를 아무리 보여줘도 감을 못 잡고, 13B는 50개 예시에 20%. 그런데 **175B 모델은 예시 1개만으로도 태스크를 풀기 시작**하고, 10개에 60% 정확도. 규모가 작을 때는 없었지만 커지면서 나타나는 성질을 **창발성**이라 한다.

### 2-4. 거대 언어 모델의 정의

10억+ 매개변수를 가지고, 조 단위 데이터에서 학습되어, 창발성이 나타나기 시작하는 언어 모델. 트랜스포머 구조 기반. 창발성이 발현하지 않으면 LLM이라고 할 수 없다.

### 2-5. 폐쇄형 vs 개방형

**폐쇄형**: ChatGPT, Claude, Gemini. 앱/API 형태. 우수한 성능 + 사용 편의성. 단점: API 호출 비용 발생(토큰당 과금), 구독료, 모델 내부 비공개(블랙박스), 사고 과정(리즈닝) 비공개.

특징 비교: ChatGPT(전반적 우수, 최다 유저), Claude(안전지향, 코딩 특히 우수 — Claude Code가 이슈), Gemini(최장 입출력, 뛰어난 멀티모달). 비용 대비 성능이 계속 개선되는 추세.

**개방형**: LLaMA(Meta), Gemma(Google), Qwen(Alibaba), 한국은 엑사원, 솔라, 국가대표 AI 프로젝트(5개 회사 경쟁). 무료 다운로드, 정보 공개, 커스터마이징 가능. 단점: GPU 필요, 폐쇄형 대비 6개월~1년 성능 갭.

오픈소스 전략의 이유: (1) 유저를 끌어들여 대화 데이터를 학습에 재활용(무료 계정은 학습 데이터 활용 동의 단서 조항), (2) 투자 유치를 위한 영향력 증명. 유명세 확보 후 폐쇄형으로 전환하는 경우도 있음(Qwen 사례).

중국 모델(Qwen, DeepSeek) 주도로 개방형이 빠르게 발전. 한국도 국가대표 AI 프로젝트로 경쟁 중.

## 3. 거대 언어 모델의 학습 — 정렬 학습(Alignment Training)

### 3-1. GPT-3의 한계

질문을 이해하지 못하고 질문을 변형하며 반복(답습). "6살 아이에게 달 착륙을 설명해줘"라는 질문에 질문 자체를 약간씩 바꿔서 반복. 안전성 이슈: "정지 표지판을 어떻게 자르냐"는 질문에 실제 방법을 알려줌 — 하면 안 된다는 것을 배운 적이 없기 때문.

### 3-2. 정렬 학습의 목적과 두 단계

목적: 거대 언어 모델의 출력이 **사용자의 의도를 잘 파악**하고 **사용자의 가치를 잘 반영**하도록 하는 것.

**지시학습**: 유저의 질문이 어떤 의도인지 파악하고 적절한 응답을 내뱉도록 학습.
**선호학습**: "이 행동이 유저의 가치에 반하는가"를 판단하여 거부할 수 있도록 학습.

### 3-3. 지시학습 상세

핵심 철학: **모든 서로 다른 자연어 태스크를 하나의 템플릿(지시+입력→자연어 출력)으로 통합**하여 하나의 단일 모델이 모든 태스크를 동시에 학습하도록 한다.

기존 방식: 100개 태스크 → 100개 데이터셋 + 100개 모델. 지시학습: 하나의 모델이 어떤 지시가 오든 유동적으로 대응.

**데이터 생성**: (1) 기존 NLP 데이터를 템플릿으로 변환(템플릿은 사람이 설계, 변환 자체는 자동화), (2) 유저 데이터를 수집하여 사람이 올바른 정답 작성(InstructGPT 방식 — 미완성 모델을 일단 공개하여 유저 질문을 수집, 사람을 고용하여 올바른 응답 작성).

**Flan 논문의 핵심 발견** — 태스크 레벨 분리로 일반화 측정(학습/테스트에서 같은 카테고리의 태스크가 겹치지 않도록):
- 태스크 종류를 늘릴수록 성능 향상 → **다양성과 규모가 중요**
- 80억 파라미터 이하 모델에서는 지시학습이 **역효과** → 지시 일반화도 **창발성**
- 자연어 형태의 템플릿이 가장 효과적("SST2라는 데이터에서 왔다"보다 "사람에게 대화하듯 지시하는 것"이 좋음)

사전학습 vs 사후학습: 사전학습은 레이블 없이 웹 데이터로 자가지도 학습. 사후학습은 레이블 데이터로 행동양식 부여. 지시학습은 사후학습의 일부. 특정 질문에 익숙해지는 것이 아니라 **사람이 대화하는 패턴**에 익숙해지도록 하는 데 의의.

### 3-4. 선호학습 상세 — RLHF

정답이 정해져 있지 않은 태스크에서 복수 정답 중 더 선호되는 응답을 학습. 선호도 레이블: 약 100명 정도의 사람에게 투표시켜 수집. 선택지(A,B,C,D)는 지시학습 모델이 생성하고, 사람이 순서를 매김(예: D>C>A=B).

**ChatGPT의 비밀**: ChatGPT 이전 모델은 학습 방법을 모두 공개했지만, ChatGPT부터는 비공개. 블로그 글의 단서: "InstructGPT와 같은 RLHF 방법을 썼고, 대화 데이터를 추가 혼합했다". 따라서 InstructGPT를 이해하면 ChatGPT의 핵심 원리를 파악 가능.

**InstructGPT의 3단계**:

**스텝 1 — 지시학습**: 실제 유저 입력을 수집하고, 사람을 고용하여 올바른 정답을 작성. GPT-3를 파인튜닝. 전략: 미완성 모델을 빨리 공개 → 유저 질문 수집 → 사람이 올바른 응답 작성.

**스텝 2 — 보상 모델(Reward Model) 학습**: 지시학습 모델이 하나의 질문에 대해 복수 응답(A,B,C,D) 생성. 사람이 D>C>A=B 순서로 선호도를 매김. **보상 모델**: 질문+응답 하나를 받아 "사람이 몇 점을 줬을 것 같은지"를 **스칼라 점수**로 예측하는 별도 모델. D는 100점, A는 -5점 식으로 출력하여 사람의 순서를 재현. 지시학습 모델과는 다른, 오롯이 사람 선호를 흉내내기 위한 모델.

**스텝 3 — 강화학습**: **사람이 전혀 개입하지 않는** 단계. 사람이 한 번도 보지 않은 새로운 입력 → 지시학습 모델이 응답 생성 → 보상 모델이 점수 판정 → 100점이면 "잘했어, 이걸 계속 만들어", -5점이면 "이건 만들면 안 될 것 같아". 보상 모델 관점에서 더 좋은 응답을 더 많이 만들도록 지시학습 모델을 추가 학습하는 것이 강화학습.

결과: 지시 수행 능력 향상, 해로운 응답/거짓말 확률 감소, 모델 크기가 커질수록 지시 능력 지속 향상. **LLaMA-2 Chat도 동일한 3단계 파이프라인** 사용하여 당시 ChatGPT에 비등한 성능 달성.

> **교수님 강조**: 무엇이 옳고 그름인지는 나라마다, 유저마다 다르다. 중국 모델과 미국 모델의 행동양식이 다른 이유가 여기에 있으며, 한국 특화 파운데이션 모델이 필요한 이유이기도 하다.

## 4. 거대 언어 모델의 추론 — 디코딩 알고리즘

### 4-1. 자동 회귀 생성(Auto-Regressive Generation)

거대 언어 모델은 한 번에 문장 전체를 만드는 것이 아니라 **단어(토큰) 하나씩 순차적으로** 생성. 이전 단계의 출력이 다음 단계의 입력으로 사용. "I am a student"는 모델이 **4번**에 걸쳐 만든 것.

종료 조건: (1) **EOS 토큰**(End of Sentence) — 모델이 자체적으로 판단(학습 시 BOS/EOS 토큰을 데이터에 포함), (2) **사전 정의 길이** — 사용자가 설정(예: max_tokens=2048). EOS는 모델 결정, 길이 제한은 사용자 결정.

거대 언어 모델은 **확률 분포만 제공**: "왔어" 50%, "왔는데" 20%... 이 확률 분포에서 어떤 단어를 선택할지는 디코딩 알고리즘이 결정.

실제 코드에서는 `model.generate()` 함수 하나로 모든 생성이 이루어지며, 이 함수의 30개 이상의 인자(argument) 설정에 따라 디코딩 알고리즘이 바뀐다.

```python
# GPT-2 추론 예시 (교수님 수업 코드)
from transformers import GPT2LMHeadModel, GPT2Tokenizer

model = GPT2LMHeadModel.from_pretrained("gpt2")
tokenizer = GPT2Tokenizer.from_pretrained("gpt2")

text = "아까 밥 먹고"
inputs = tokenizer(text, return_tensors="pt")  # 자연어 → 토큰(전처리)
outputs = model.generate(**inputs)              # 자동 회귀 생성 (핵심)
result = tokenizer.decode(outputs[0])           # 토큰 → 자연어(후처리)
```

### 4-2. 그리디 디코딩(Greedy Decoding)

매 스텝에서 확률이 가장 높은 토큰을 선택. 장점: 간단. 단점: 현재 시점만 고려하므로 **국소 최적(local optimum)** 문제. 예: "The nice woman"(0.2) vs "The dog has"(0.36) — 첫 스텝에서 "nice"가 확률 높았지만 장기적으로는 "dog" 경로가 거의 2배 높은 joint probability.

### 4-3. 빔서치(Beam Search)

K개 후보를 동시에 고려. K=2이면 매 스텝에서 모든 후보의 다음 경우를 확인한 뒤 상위 2개만 유지. 장기적으로 더 좋은 응답을 찾을 수 있다. 단점: LLM을 빔 사이즈 K배만큼 호출 → **연산량이 K에 비례하여 증가**. 거대 언어 모델에서 빔서치는 매우 부담스러운 일.

### 4-4. 샘플링(Sampling)

확률 분포에 비례하여 **랜덤하게** 토큰 선택. 같은 질문에도 매번 다른 응답 가능. 연산량은 그리디와 동일. 단점: 확률이 낮은 저품질 토큰 선택 가능.

빔서치와의 차이: 빔서치는 모든 경로를 **다 보고** 결정. 샘플링은 확률에 비례하여 **하나의 경로를 랜덤하게 선택**하여 진행.

### 4-5. 템퍼레처(Temperature)

하이퍼파라미터 T로 확률 분포를 조작. T=1: 원본. T>1: 분포 균등화(다양성↑, 소설가에 적합). T<1: 분포 샤프화(집중↑, 수학자에 적합). T→0: 최고 확률 토큰만 남음. T→∞: 모든 토큰 동일 확률.

일반적으로 0.7 정도를 가장 많이 사용(학습된 것보다 약간 더 샤프하게). 1.2~1.5 이상이면 논리에 맞지 않는 말을 하기 시작. 근본적인 저품질 토큰 문제를 직접 해결하지는 못함.

### 4-6. Top-K 샘플링

확률 상위 K개 토큰만 남기고 나머지 배제(확률 재정규화). 문제: K가 고정이므로, 균등한 분포에서는 K가 커야 하고 피키한 분포에서는 K가 작아야 하는데 자동 조절 불가. 균등한 분포에서 K가 작으면 좋은 토큰도 버려지고, 피키한 분포에서 K가 크면 저품질 토큰이 남는다.

### 4-7. Top-P(Nucleus) 샘플링

K를 고정하지 않고, **누적 확률이 P%에 도달할 때까지의 토큰**만 고려. 확률이 높은 순으로 정렬하여 하나씩 더해가며 P를 초과하는 시점에서 커트. 균등한 분포에서는 K가 크게, 소수 토큰에 집중된 분포에서는 K가 작게 자동 조절. P=0.9~0.95가 일반적. 사람 관점에서도 자연스러운 알고리즘. 다양한 평가지표에서 사람 응답과 가장 유사한 결과.

**실제 GPT의 디코딩**: **템퍼레처 + Top-P 샘플링 조합**. OpenAI Playground에서 temperature, max_tokens, top_p 설정 가능. 기본값: temperature=1(원본), top_p=1(순수 샘플링), max_tokens=2048.

**GPT가 매번 다른 답을 하는 이유**: 랜덤 샘플링 기반이므로 같은 입력에 같은 파라미터로도 다른 응답 생성. 같은 응답을 원하면 temperature=0으로 설정하지만, 실제로는 0.001 등 극소값으로 처리(그리디 디코딩과 샘플링의 추론 방식이 달라 효율성 문제). 따라서 **폐쇄형 모델에서는 완전히 같은 응답을 받을 방법이 없다**. 개방형 모델에서는 그리디 디코딩 설정 가능.

> **교수님 강조**: 지금의 GPT는 "확률 최고 토큰을 내뱉는" 것이 아니라 "랜덤 샘플링을 더 잘하기 위해 Top-P 샘플링과 템퍼레처를 쓰는" 것이다. Playground에서 파라미터를 바꿔보면 재미있다.

## 5. 프롬프트 엔지니어링 — Chain-of-Thought

### 5-1. 프롬프트 엔지니어링

프롬프트 = 지시 + 예시로 구성된 입력. 어떻게 질문하느냐에 따라 모델 성능이 완전히 달라진다. 내가 원하는 것을 명확하게 지시에 넣어야 원하는 출력이 나온다.

### 5-2. Chain-of-Thought(CoT) 프롬프팅

핵심: 예시에 **풀이 과정(레셔널)**을 포함. 질문 → 풀이 과정 → 정답 형식의 예시를 보여주면, 모델도 풀이 과정을 먼저 생성하고 정답을 생성.

GSM8K(미국 초등학교 수학) 성능: 일반 퓨샷 성능에 비해 CoT 프롬프팅으로 **기하급수적 성능 향상**, 파인튜닝 모델 성능을 초과. 모델이 작을 때는 효과 없지만 모델이 커지면서 효과 극대화 — 추론 능력도 **창발성**.

마지막 철자 연결 태스크에서도 2글자 예시로 4글자 문제를 풀 수 있는 **일반화 성능** 관찰.

### 5-3. 제로샷 CoT

"Let's think step by step"이라는 **유인 문장 한 줄**만 추가하면 예시 없이도 CoT 작동. 제로샷에서 30~60% 성능 향상. 모델 내부에 복잡한 사고 능력이 숨어 있었고, 유인 문장으로 끄집어냄.

다른 문구("First", "Let's think about this logically")도 효과가 있지만 "Let's think step by step"이 가장 효과적. 핵심: **바로 정답을 내뱉게 하지 않고 사고 공간을 만들어주는 유인 정책**이 중요.

현재 최신 모델은 CoT가 **내재화**되어 있어 별도 프롬프트 없이도 자동으로 사고 과정을 거침.

## 6. 거대 언어 모델의 평가

### 6-1. 정답이 정해진 경우 — 벤치마크

**MMLU**(57개 전문분야 객관식), **GSM8K**(수학) 등. 예측과 정답을 비교하여 평균 정확도 측정. 주의: 평가 시 몇 샷을 주는지, CoT를 쓰는지에 따라 결과가 달라지므로 **동일 조건**이 아니면 비교 무의미.

### 6-2. 정답이 정해지지 않은 경우

**방법 1 — 사람이 표준 정답 작성 후 유사도 측정**: 단어 수준 오버랩(ROUGE 스코어 등), 벡터 공간 유사도(코사인 유사도 — 비슷한 문장은 1, 다른 문장은 -1이 되도록 별도 모델 학습). 한계: 복잡한 문제에서 표준 정답 작성 어려움.

**방법 2 — 생성 텍스트만으로 품질 측정**: **Perplexity(PPL)** — 확률적 자연스러움 측정. 낮을수록 자연스러움. 독창성·유창성 등 다양한 기준은 수학적 정의 어려움.

**방법 3 — LLM-as-a-Judge**: LLM을 평가자로 활용. 태스크 설명 + 평가 텍스트 + 평가 기준을 프롬프트로 제공 → LLM이 점수+이유 출력. 기존 평가 지표보다 **사람과 가장 유사한 평가**. LLaMA-3 학습 시 데이터 필터링에도 LLM 평가자 활용(1~5점 디테일한 프롬프트).

### 6-3. 상대적 선호 평가 — LM Arena

실제 유저가 익명 모델 A, B의 응답을 비교하여 선호 투표. **ELO 레이팅**으로 순위 산출. 가장 신뢰도 높은 벤치마크. 회사들이 공식 출시 전에 익명 모델(파인애플, 나노바나나 등)로 먼저 테스트 후 커뮤니티 반응 확인.

### 6-4. LLM 평가의 편향 문제

**위치 편향**: 먼저 보여준 응답을 선호. 해결: 순서를 뒤집어 두 번 평가 후 평균.

**길이 편향**: 복사+붙여넣기로 내용 없이 길게 만들어도 높은 점수. 해결: 통계적 보정(알파카 이벨 V2에서 길이 요소 제거 후 1등 모델이 바뀜).

**자기선호 편향**: GPT가 평가하면 GPT 응답을, Claude가 평가하면 Claude 응답을 선호. 익명화해도 각 모델이 좋아하는 표현이 달라 높은 확률로 탐지 가능. **아직 완벽히 해결되지 않은 문제**. LLM 판사가 사회에 도입되면 자기선호 편향이 심각한 문제가 될 수 있음.

## 7. 거대 언어 모델의 응용

### 7-1. 멀티모달 파운데이션 모델

텍스트 파운데이션 모델(LLM)이 **기반**. 이미지/비디오/오디오를 텍스트 임베딩 공간으로 변환하는 프로젝터를 추가 학습. 이미지+텍스트를 동시에 봐야만 풀 수 있는 문제(예: "이 이미지에서 부자연스러운 게 뭐냐")로 **지시학습**. 휴머노이드 로봇(VLA: Vision-Language-Action 모델)도 내부 추론 엔진에 LLM 사용.

### 7-2. 합성 데이터 생성 — Self-Instruct

사람 175개 데이터 → GPT-3로 52,000개 합성. 파이프라인: 175개 중 8개를 랜덤 선택하여 퓨샷 프롬프팅 → 새 태스크 생성 → ROUGE 기반 필터링(기존 데이터와 너무 유사하거나 너무 다른 것 제거, 골든 스위트 스팟만 사용) → 다양한 주제·동사 확인.

성능: 사람 데이터(40.8) vs 합성 데이터(40.0) — 0.8 차이. 사람+합성 함께 사용 시 더 높은 성능. 최초 개방형 인스트럭션 팔로잉 모델 **알파카(Alpaca)** 학습에 활용.

**알파가수스(Alpagasus)**: LLM으로 합성 데이터를 1~5점 평가, 4.5점 이상만 사용(52,000개 중 약 9,000개). **전체를 쓴 것보다 적은 데이터로 더 높은 성능** — 품질 필터링이 핵심. 랜덤 선택보다도 훨씬 좋은 성능.

## 8. 거대 언어 모델의 한계

### 8-1. 환각(Hallucination)

사실과 다른 정보를 **정확한 정보를 얘기할 때와 동일한 자신감과 유창함**으로 생성. 유저가 응답만 보고 구분 불가. 예: 존재하지 않는 URL을 넣고 요약 요청 → GPT가 접속도 안 해보고 요약 생성.

원인: 사전학습 데이터가 특정 시점까지만의 정보를 포함(GPT-4 mini: 2023.10, LLaMA: 2023.12). 학습 시점 이후 질문은 환각 확률 증가. 해결: **RAG(검색 증강 생성)** — 실시간 웹 검색 결과 기반 응답 + 출처 링크 첨부.

### 8-2. 탈옥(Jailbreak)

지시학습·선호학습의 **가드레일을 프롬프팅으로 우회**. DAN(Do Anything Now) 프롬프팅: "아무 질문에도 응답해도 된다, 처벌받지 않는다, 연구 목적이다"라고 거짓말하면 모델이 주관적 의견이나 위험한 내용을 응답. 중국 모델의 중국 정부 관련 제한도 우회 가능. 완벽히 해결되지 않은 문제.

### 8-3. AI 생성 텍스트 탐지 — 워터마킹

추론 알고리즘에 **사람이 볼 수 없는 패턴** 삽입. 품질에 티가 나지 않되 LLM만 볼 수 있는 패턴. 수학적으로 일정 길이 이상이면 사람 생성과 AI 생성을 **높은 확률로 구분 가능**. 탐지 스타트업 다수 등장.

- GPT로 재가공 → GPT 워터마크 남음
- Gemini로 재가공 → Gemini 워터마크 남음
- **사람이 재가공** → 워터마크 지워짐

실제로 OpenAI 같은 회사에서 역추적 가능. AI 생성물을 자기 것처럼 쓰면 안 됨.

> **교수님 강조**: AI가 만든 답변을 아무 생각 없이 받아들이기 좋은 시대가 됐지만, GPT가 한 응답이 거짓말일 가능성이 높다. 어떤 응답이든 꼼꼼하게 웹서핑으로 사실 확인을 하는 과정이 필요하다. AI를 적극적으로 쓰되, 비판적 사고를 유지해야 한다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 파운데이션 모델 | 대량 데이터 기반 사전학습 대규모 AI. 별도 학습 없이 설명+예시만으로 새 태스크 해결 |
| 3가지 요소 | 빅데이터 + 자가지도학습(다음 토큰 예측) + 트랜스포머 모델 |
| GPT 발전 | GPT-1(추가학습 필요) → GPT-2(규모 키우니 태스크 수행 가능, 과적합 없음) → 규모의 법칙 발견 |
| 규모의 법칙 | 데이터·모델·연산량 로그 스케일 증가 시 테스트 성능 선형 증가. 작은 실험으로 큰 실험 결과 예측 |
| GPT-3 (175B) | 4TB, 약 150억원. 커먼크롤 60% + 양질 40%. 깊이+넓이 증가. 창발성 나타남 |
| 창발성 | 1.3B: 효과 없음, 13B: 미미, 175B: 예시 1개로 태스크 수행. 인컨텍스트 러닝, 추론 능력 등 |
| LLM 정의 | 10억+ 파라미터, 조 단위 데이터 학습, 창발성 나타나는 언어 모델 |
| 폐쇄형 vs 개방형 | 폐쇄형: 성능↑+편의성↑, 비용+블랙박스 / 개방형: 무료+커스터마이징, GPU 필요+6개월~1년 갭 |
| 정렬 학습 | 사전학습=지능, 사후학습(지시+선호)=교육. 의도 파악 + 가치 판단 |
| 지시학습 | 모든 태스크를 자연어 템플릿(지시+입력→출력)으로 통일. 다양성·규모 중요. 80억 이하 역효과 |
| 선호학습/RLHF | 3단계: 지시학습 → 보상 모델(사람 선호 흉내, 스칼라 점수) → 강화학습(사람 개입 없이 추가 학습) |
| 자동 회귀 생성 | 토큰 하나씩 순차 생성. 종료: EOS(모델 결정) 또는 사전 정의 길이(사용자 결정) |
| 그리디 디코딩 | 확률 최고 선택. 간단하지만 국소 최적 문제 |
| 빔서치 | K개 후보 동시 고려. 장기 최적 탐색. 연산량 K배 증가 |
| 샘플링 | 확률 비례 랜덤 선택. 다양한 응답. 저품질 가능성 |
| 템퍼레처 | T>1: 다양성↑, T<1: 집중↑. 일반적 0.7 사용. 1.2~1.5 이상 비논리적 |
| Top-K | 상위 K개만 고려. K 고정이라 분포에 따라 부적절 |
| Top-P(Nucleus) | 누적 확률 P%까지 고려. K 자동 조절. GPT 실제 사용 방식 |
| GPT 실제 디코딩 | 템퍼레처 + Top-P 조합. 매번 다른 답 = 랜덤 샘플링. temperature=0이어도 0.001로 처리 |
| CoT | 예시에 풀이 과정 포함 → 추론 성능 급등. 파인튜닝 모델 초과. 모델 작을 때 효과 없음 = 창발성 |
| 제로샷 CoT | "Let's think step by step" 한 줄로 30~60% 향상. 사고 공간 유인 정책 |
| 평가: 정답 있음 | MMLU, GSM8K. 정확도. 디코딩 방식 통일 안 하면 비교 무의미 |
| 평가: 정답 없음 | ROUGE(단어 오버랩), 벡터 유사도(코사인), Perplexity(확률적 자연스러움) |
| LLM-as-Judge | LLM 평가자. 사람과 가장 유사. LLaMA-3 데이터 필터링에도 활용 |
| LM Arena | 실제 유저 선호 투표 + ELO 레이팅. 가장 신뢰도 높은 벤치마크. 익명 모델 선출시 |
| 평가 편향 | 위치(순서 뒤집어 해결), 길이(통계 보정), 자기선호(미해결 — GPT는 GPT를 선호) |
| 멀티모달 응용 | LLM 기반 + 인코더/프로젝터 추가. 지시학습으로 연결. 휴머노이드(VLA)도 LLM 엔진 |
| 합성 데이터 | Self-Instruct: 175개→52,000개(알파카). ROUGE 필터링. 알파가수스: 4.5점 이상만 사용 → 적은 데이터로 더 높은 성능 |
| 환각 | 거짓을 자신감 있게 생성. 학습 시점 한계. 해결: RAG(검색 증강 생성) |
| 탈옥 | DAN 프롬프팅으로 가드레일 우회. 완벽 해결 안 됨 |
| 워터마킹 | 추론 알고리즘에 패턴 삽입. 수학적으로 탐지 가능. 사람이 재가공하면 지워짐. LLM으로 재가공하면 해당 LLM 워터마크 남음 |
