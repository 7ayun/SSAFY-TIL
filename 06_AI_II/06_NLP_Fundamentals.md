## 1. 워드 임베딩(Word Embedding)

### 1-1. 원핫 벡터의 구조

딥러닝은 숫자 정보를 이용해서 입력과 출력의 맵핑 함수를 찾는 메커니즘인데, 언어는 숫자가 아닌 심볼이다. 가장 간단한 변환 방법이 **원핫 인코딩(원핫 벡터)**이다.

코퍼스에서 중복 없는 단어를 모아 **보캐뷸러리(사전)**를 구성한다. 보캐뷸러리 크기 예시: 음성 처리 약 2만 개, Penn Treebank(월스트리트 저널 금융 문헌) 5만 개, 언어모델 약 50만 개, 구글 검색엔진 1,300만 개.

50만 개의 보캐뷸러리를 사용한다고 하면 원핫 벡터는 50만 차원으로 이루어져 있고, 499,999개의 0과 단 하나의 1로 구성된다. 이 1은 크기가 1인 것이 아니라 **인디케이터(지시자)**로서 "사전에서 n번째에 있는 단어"를 표시하는 것이다.

### 1-2. 원핫 벡터의 문제점

검색 엔진에서 "삼성 노트북 배터리 사이즈"라는 쿼리와 "삼성 노트북 배터리 용량"이라는 문서가 있을 때, 사람이 보면 거의 같은 뜻이지만 "사이즈"와 "용량"의 원핫 벡터는 완전히 다르다. "갤럭시 핸드폰"과 "갤럭시 스마트폰"도 마찬가지.

두 벡터의 유사도를 구할 때 **내적(dot product)**을 사용한다. 1×vocabulary 벡터와 vocabulary×1 벡터를 곱하면 1×1 스칼라가 나오며, 이 값이 크면 유사하고 0에 가까우면 관련이 없다. 원핫 벡터는 어떤 두 단어도 내적이 0이다 — 서로 **직교(orthogonal)**한다. 0이 아닌 위치(1이 있는 위치)가 서로 달라서 의미 있는 관련도를 계산할 수 없다.

구체적 문제:
- **차원의 저주(Curse of Dimensionality)**: 50만 차원은 저장·연산에 부담이 크다. 두 벡터의 관계를 살펴볼 때 50만 × 50만의 곱하기가 필요하고, 차원이 커질수록 유의미한 패턴 발견이 어려워진다
- **의미론적 정보 부재**: 스마트폰과 핸드폰, 은행과 금융 등 유사한 관계가 절대 표현되지 않는다

### 1-3. 워드 임베딩의 철학

**"그 단어를 알려면 그 단어 주변(컨텍스트, 맥락)을 봐라."** 이웃 단어(neighborhood)라고도 한다. 은행이라는 단어 앞뒤에 "정부", "위기", "규제", "돈" 같은 맥락이 있으면 금융 은행이라는 의미를 파악할 수 있다. 이 원리를 이용하여 중심 단어와 주변 맥락의 관계를 학습하면 기계에게도 사람이 언어를 이해하는 메커니즘을 도입할 수 있다.

워드 임베딩의 특징 (원핫 벡터와 비교):
- **밀집(Dense)**: 50만 차원이 아닌 50~1,000차원. 차원이 좁혀진 만큼 각 차원이 더 의미 있는 값을 가지려 한다
- **연속(Continuous)**: 0과 1이 아닌 실수값으로 공간상 조밀한 표현
- **분산(Distributed)**: "은행"의 임베딩에 "정부", "위기", "규제", "돈" 등 관련 단어와 유사한 정보가 반영. 독립적 표현이 아니라 관련 단어들과 공유되는 정보를 가짐

### 1-4. Word2Vec — 스킵그램과 CBOW

2013년 구글이 개발한 대표적 워드 임베딩 알고리즘. 토마스 미콜로프, 제프 딘, 일리아 서츠케버 등이 저자에 포함.

**스킵그램(Skip-gram)**: 중심 단어를 입력으로 → 주변 단어를 예측.
- 인코더: 중심 단어의 원핫 벡터를 입력받아 임베딩 벡터로 변환
- 디코더: 임베딩을 입력받아 보캐뷸러리 크기의 확률 분포를 출력
- 정답(Y): 주변 단어의 원핫 벡터 (확률 100%, 나머지 0%)
- 예측(Y-hat): 보캐뷸러리 차원의 실수값 확률 분포
- 크로스 엔트로피 로스로 인코더·디코더를 학습
- 예: "banking"이 중심 단어일 때, 50만 개 단어 각각의 발생 확률을 극대화 — "into", "turning", "crisis", "as" 등 주변에 관측된 단어들의 확률을 높이도록 학습
- 실제로는 주변 단어를 하나씩 따로 예측하여 여러 스텝에 걸쳐 학습 (같은 문장에서 학습량이 많음)

**CBOW(Continuous Bag of Words)**: 주변 단어들을 입력으로 → 중심 단어를 예측.
- 주변 단어들(예: the, quick, fox, runs)의 임베딩을 더하거나 평균내어 합침
- 합친 벡터를 디코더에 넣어 중심 단어(brown) 예측
- 단어 순서 정보는 고려되지 않는 것이 한계

**스킵그램이 더 효과적인 이유**: CBOW는 맥락 정보를 한 번에 넣고 중심 단어를 한 번 예측하는데, "beautiful" 대신 더 자주 등장하는 단어("nice" 등)에 편향된다. 스킵그램은 중심 단어 하나에서 주변 단어를 여러 번 각각 예측하므로 같은 문장에서도 학습 스텝이 많고, 드물게 등장하는 단어에도 학습이 잘 된다. 대신 학습이 더 오래 걸린다.

**학습 완료 후**: 인코더를 원핫 벡터 → 워드 임베딩 변환 모듈로 활용한다.

**한계**: 동음이의어(apple = 사과/회사, banking = 은행/다른 뜻)를 구분하지 못하고 여러 뜻을 하나의 벡터에 함축한다. 한국어 조사는 보통 단어와 분리되어 처리된다("단어"+"는" → 별개 토큰).

> **교수님 강조**: 궁금한 질문을 품고 들어라. 언어를 어떻게 숫자로 표현할까? 맥락을 어떻게 반영할까? 한계점은? 이런 질문을 추적하면서 듣는 것이 좋다.

## 2. RNN(Recurrent Neural Network)

### 2-1. 시퀀스 데이터의 특성

텍스트, 음성(Spoken Language), 비디오(이미지 프레임 연결), 시청 로그 등 시간축에 따라 기록된 모든 데이터가 순차적(시퀀스) 데이터이다. 세상은 시간의 축에 지배를 받으므로, 시간축대로 기록된 모든 것이 순차적 데이터.

핵심 특성:
1. **순서 정보가 중요**: 같은 단어라도 순서에 따라 의미가 달라진다
2. **장기 의존성(Long-term Dependency)**: 1차시에서 한 이야기와 4차시에서 한 이야기가 연결되듯, 멀리 떨어진 정보 간 관계가 중요
3. **가변 길이**: 문장마다 단어 수가 다르다

### 2-2. MLP/CNN의 한계

MNIST 같은 고정 입력(28×28=784차원)에서는 잘 동작하지만, 텍스트는 입력 차원이 가변적이다. 히든 레이어 차원이 고정되어야 학습 파라미터 크기도 고정되는데, 가변 입력에는 이 구조가 맞지 않는다. 번역이나 챗봇처럼 입출력이 모두 가변적인 문제는 완전히 처리 불가.

### 2-3. RNN의 동작 원리

핵심 아이디어: **히든 벡터를 레이어 간이 아닌 시간축(타임스텝)에 따라 업데이트하는 히든 스테이트**로 정의한다. 사람의 메모리처럼 시간이 흐르면서 계속 업데이트된다.

```
h_t = tanh(W_xh · x_t + W_hh · h_{t-1} + b)
```

- **W_xh**: 현재 단어(x_t)에 대한 선형 변환 파라미터
- **W_hh**: 이전 히든 스테이트(h_{t-1})에 대한 선형 변환 파라미터
- 두 파라미터 모두 **타임스텝 T에 관계없이 동일** (아래 첨자에 T가 없음)
- h_0: 랜덤 초기화 (아무 의미 없는 정보)
- tanh: 비선형 활성화 함수

시간축으로 펼치면: x_1과 h_0 → h_1, x_2와 h_1 → h_2, ..., x_T와 h_{T-1} → h_T. 파라미터가 고정이므로 가변 길이 입력을 처리할 수 있다.

**활용 형태**:
- **토큰 레벨 분류(품사 태깅 등)**: 매 타임스텝마다 출력하고 로스 계산
- **시퀀스 레벨 분류(감성 분석 등)**: 마지막 h_T만 사용. W_HY라는 선형 변환으로 히든 벡터(예: 100차원)를 클래스 수(긍정/부정이면 2차원)로 변환하고 소프트맥스/시그모이드로 확률 분포 생성

h_T까지 만드는 영역이 **인코더**, 그 이후 클래스 확률로 변환하는 부분이 **클래시피케이션 레이어(소프트맥스 레이어)**.

### 2-4. RNN의 한계

- **정보 필터링 불가**: 수식을 보면 이전 맥락과 현재 단어를 매우 성실하게 동일한 과정으로 반복하여 축적할 뿐, 관련 없는 정보를 걸러내는 역할이 없다
- **장기 기억 상실**: 히든 벡터 차원이 고정(예: 100)인데 단어가 늘어나면 모든 정보를 효과적으로 담을 수 없고, T타임쯤 왔을 때 초기 정보가 많이 상실된다
- **기울기 소실(Vanishing Gradient)**: 백프로파게이션 시 타임스텝을 거슬러 올라가면서 기울기가 0에 수렴. 초록색처럼 가까운 단어 간 관계는 잘 학습하지만 멀리 떨어진 단어 간 관계는 포착 어려움

## 3. LSTM(Long Short-Term Memory)

### 3-1. 핵심 아이디어: 두 개의 메모리

처음 제안된 것은 오래됐지만 2015~2016년부터 본격 활용. RNN과의 차이는 **셀 스테이트(Cell State)**를 추가한 것이다. LSTM = Long Short-Term Memory — 장기 메모리와 단기 메모리를 둘 다 가진다.

- **히든 스테이트(h_t)**: 단기 메모리 (Short-Term Memory)
- **셀 스테이트(C_t)**: 장기 메모리 (Long-Term Memory)
- 둘 다 같은 차원 (예: 100차원)

셀 스테이트는 공장의 **컨베이어 벨트**처럼 시간축을 따라 흘러가는 정보의 집약체이다. RNN에는 없었던 "중요한 정보를 읽고, 중요하지 않은 정보를 지우고, 저장된 것에서 필요한 것만 뽑아 쓰는" 능력을 세 개의 게이트가 담당한다.

### 3-2. 세 개의 게이트 — 상세

모두 시그모이드 함수를 통해 0~1 사이 값을 출력한다. **스칼라가 아니라 히든 벡터와 같은 차원(100차원)의 벡터**를 출력하며, 셀 스테이트와 **엘리먼트 와이즈 곱셈(Element-wise Multiplication)**으로 의사결정한다.

**임시 히든 스테이트(tilde C_t)**: RNN의 h_t 수식과 유사하게, 이전 히든 스테이트(h_{t-1})와 현재 입력(x_t)을 합쳐 tanh를 통과시킨 벡터. 100차원.

**Forget Gate(f_t)**: h_{t-1}과 x_t의 정보를 합쳐 시그모이드를 통과시킨 100차원 벡터. C_{t-1}의 각 차원에 대해 "기억할 곳은 1에 가깝게, 잊을 곳은 0에 가깝게" 결정. C_{t-1}과 엘리먼트 와이즈 곱셈하면 일부 정보가 삭제된다.

**Input Gate(i_t)**: 마찬가지로 100차원의 0~1 벡터. tilde C_t(현재 읽은 콘텐츠)에서 어떤 정보를 셀 스테이트에 새로 저장할지 결정. tilde C_t와 엘리먼트 와이즈 곱셈.

**셀 스테이트 업데이트**: C_t = f_t ⊙ C_{t-1} + i_t ⊙ tilde C_t. 이전 장기기억에서 불필요한 것을 잊고, 현재 콘텐츠에서 필요한 것을 추가.

**Output Gate(o_t)**: 축적된 C_t에서 현재 타임스텝에 필요한 정보만 히든 벡터(h_t)로 출력할지 결정. h_t = o_t ⊙ tanh(C_t). 장기기억은 매번 다 쓰는 것이 아니라 필요한 것만 꺼내 쓴다 — 1차시 지식은 1차시에, 4차시 지식은 4차시에 아껴뒀다가 출력.

세 게이트의 파라미터는 로스 계산과 그래디언트 디센트를 통해 자동으로 학습된다.

## 4. 언어 모델과 N-gram

### 4-1. 언어 모델의 정의

인간의 언어를 모방하여 모델링한 것. 인간의 언어는 랜덤한 단어 조합이 아니라, 그럴싸하게(conceivable) 발생하는 문장들의 집합에 높은 확률을 가지는 모델이다.

실질적으로는 **맥락이 주어졌을 때 다음 단어의 확률이 높은 것을 예측**하는 모델(Next Word Prediction). 아이폰 키보드 단어 추천(정확도 낮음 — 소형 모델), 웹 검색어 자동완성(정확도 높음 — 서버 모델 + 개인화) 등이 모두 언어 모델.

문장의 확률을 조건부 확률로 분해: P("the cat sat on the mat") = P(the) × P(cat|the) × P(sat|the cat) × ...

### 4-2. N-gram 언어 모델

연속된 N개 단어 묶음. Unigram(1개), Bigram(2개), Trigram(3개), 4-gram(4개). 보통 4-gram에서 멈춘다 — 5-gram 이상은 등장 확률이 희박하여 의미 있는 묶음이 안 됨.

**확률 계산 예시**: "the student opened their ___"에서 다음 단어를 예측할 때, 코퍼스에서 "the student opened their"가 1,000번 등장했고, "the student opened their book"이 400번 등장했다면 P(book|the student opened their) = 400/1000 = 0.4. "exam"이 100번이면 P(exam) = 0.1. 통계상 정답은 book.

**한계**: N을 제한해야 하므로 앞쪽 맥락이 잘린다. 예를 들어 더 앞에 "감독관"이라는 단어가 있었다면 exam이 더 적절하지만, N-gram이 그 맥락을 포함하지 못해 book을 선택한다. 그래도 단어를 계속 생성하면 꽤 그럴싸한 문장이 나오기도 한다.

### 4-3. 통계적 기계 번역(SMT)

수십 년간 N-gram 언어 모델을 활용하여 번역을 수행했다. 베이즈 정리를 적용하면:

```
argmax_Y P(Y|X) = argmax_Y P(X|Y) × P(Y)
```

- **P(X|Y)**: 라이클리후드(우도) — 번역 후보 Y에 맞췄을 때 입력 X가 그럴싸한지. "Hi, How are you?"와 "안녕하세요?"가 관련 있는지
- **P(Y)**: 언어 모델 — 후보 Y가 사람들이 실제로 쓰는 자연스러운 문장인지. "안녕하세요?"와 "잘 지내 안녕" 중 더 그럴싸한 문장

수백 명의 과학자가 시스템을 유지해야 했고, 성능도 좋지 못했다. 2014년 뉴럴 기계 번역(NMT)의 등장으로 SMT 시대가 완전히 종료.

## 5. Seq2Seq (Sequence-to-Sequence)

### 5-1. 인코더-디코더 구조

2014년 일리아 서츠케버 등이 제안. 인코더(RNN/LSTM)가 소스 문장을 벡터화하고, 디코더(RNN/LSTM)가 타겟 문장을 한 단어씩 생성한다.

- **인코더**: 영어 "The black cat drank milk"를 순차적으로 읽어 h_1 → h_2 → ... → h_7까지 히든 스테이트 업데이트. 함수 f(가장 간단하면 마지막 h_7)를 통해 디코더에 전달
- **디코더**: SOS(Start of Sentence) 스페셜 토큰으로 생성 시작. 한 단어씩 "Le" → "chat" → "noir" → ... → EOS(End of Sentence) 생성
- RNN인지 LSTM인지는 성능 차이만 있을 뿐 구조적 차이는 아님

### 5-2. 조건부 언어 모델

디코더는 **조건부 언어 모델(Conditional Language Model)** — 인코더가 제공하는 조건에 따라 생성 내용이 달라진다. 조건만 바꾸면 다양한 태스크에 적용:

- **번역**: 입력 문장과 의미론적으로 같은 타겟 언어 생성
- **요약**: 입력과 의미론적으로 같지만 길이가 짧은 출력 생성
- **챗봇**: 대화 맥락에 상응하는 응답 생성
- **코드 생성**: 자연어 명령에 준하는 코드 생성

### 5-3. 학습: 티처 포싱(Teacher Forcing)

디코더가 매 타임스텝에서 출력한 단어와 정답 레이블을 비교하여 로스를 구하고, 모든 타임스텝의 로스를 합쳐 백프로파게이션으로 인코더·디코더를 동시에 학습한다.

**문제**: 학습 초기에 모델이 잘못된 단어를 생성하면, 그 잘못된 단어가 다음 입력으로 들어가서 에러가 연쇄적으로 전파된다(Error Propagation).

**티처 포싱**: 학습 시 모델의 실제 출력 대신 **정답 문장을 입력으로 강제 제공**한다. SOS → "Le" 정답 제공 → "chat" 예측, SOS+Le → "chat" 정답 제공 → "noir" 예측... 매 타임스텝마다 앞까지는 에러 없는 정답 문장을 넣으므로 학습이 안정적.

학습 때는 티처 포싱을 쓰지만 테스트 때는 정답을 모르므로 모델 자체 출력을 사용 — 학습/테스트 간 괴리 발생. 해결: 10번 중 8번은 티처 포싱, 1~2번은 모델 출력을 넣는 **하이브리드 방식**.

### 5-4. 디코딩: 빔서치(Beam Search)

디코더가 매 타임스텝에서 50만 개 단어의 확률 분포를 출력한다. 무조건 확률이 가장 높은 단어를 선택하는 것을 **그리디 디코딩**이라 한다.

**그리디의 문제**: 프랑스어 번역에서 "Le" 다음 "chat(고양이)"이 정답인데, 미세한 확률 차이로 "chien(개)"이 선택되면 이후 전체가 망가진다. 한 번 발생한 오류를 되돌릴 방법이 없다.

**빔서치**: K개의 후보(가설)를 계속 유지하며 탐색. K=2 예시:
1. 첫 번째 스텝: 50만 개에서 상위 2개 선택 (예: "Le", "Chat")
2. 두 번째 스텝: "Le" 뒤에 50만 개 + "Chat" 뒤에 50만 개 → 총 100만 개에서 상위 2개 선택 (예: "Le chat", "Le sien")
3. 세 번째 스텝: "Le chat" 뒤 50만 개 + "Le sien" 뒤 50만 개 → 상위 2개 선택
4. EOS가 나올 때까지 반복. K개 완성 문장이 모이면 최종 확률 비교

**빔서치라는 이름**: 울트라맨이 레이저 빔을 쏠 때 팔꿈치부터 손가락까지 일정한 너비를 유지하듯, K의 후보가 계속 고정된 너비를 유지한다. K가 너무 크면 안 좋은 후보가 섞여 불상사 발생 가능.

## 6. 어텐션(Attention)

### 6-1. 바틀넥 문제

인코더의 마지막 히든 벡터 하나(예: h_7)에 모든 정보를 담아 디코더에 전달해야 한다. 이것은 700페이지 해리포터를 읽고 **책을 덮은 뒤 기억만으로 번역**하는 것과 같다. 매번 번역할 때마다 관련 부분을 **다시 들춰보고** 싶고, 매번 필요한 정보가 달라진다.

### 6-2. 어텐션의 메커니즘 상세

디코더가 매번 인코더의 모든 타임스텝을 **병렬적으로** 참조할 수 있게 한다. 직렬 정보(h_7)는 이미 전달했고, 추가로 병렬 정보를 어텐션으로 가져온다.

1. 디코더의 히든 벡터(S_1)가 **쿼리** 역할
2. 인코더의 모든 히든 벡터(H_1, ..., H_7)가 **밸류** 역할
3. 쿼리와 각 밸류의 **내적**으로 **어텐션 스코어** 계산
4. 소프트맥스로 **어텐션 확률 분포(α^1_i)** 생성. α^1은 디코더 1번째 타임스텝, i는 인코더 타임스텝
5. 확률 분포대로 밸류의 **가중합** → 어텐션 출력(A_1). 예: 첫 번째 디코딩에서 "The"에 해당하는 정보가 더 많이 담김
6. A_1을 S_1과 **concatenation**하여 보캐뷸러리 차원의 확률 분포 계산 → "Le" 출력

**두 번째 디코딩 스텝**: 쿼리가 S_2로 바뀌고, 같은 인코더 벡터들과 다시 스코어 계산. "Le chat" 이후 "noir(검은)"를 생성해야 하므로 "black"과 "cat"에 높은 어텐션이 걸린다. 매 디코딩 스텝마다 필요한 정보가 달라지는 것이 핵심.

### 6-3. 어텐션의 효과 — 성능 비교 분석

번역 실험에서 4가지 메소드를 비교:
- **RNNsearch-50**: 어텐션 사용, 히든 벡터 50차원 → 문장이 길어져도 성능 유지/상승
- **RNNsearch-30**: 어텐션 사용, 히든 벡터 30차원 → 어텐션이 효과적으로 발생하지 못함 (쿼리·캔디데이트의 질이 차원에 의존)
- **RNNenc-50**: 어텐션 미사용, 히든 50 → 문장 길어지면 성능 급격히 하락 (갭이 확 벌어짐)
- **RNNenc-30**: 어텐션 미사용, 히든 30

흥미로운 발견: RNNsearch-30(어텐션+작은 파라미터)이 RNNenc-50(어텐션 없음+큰 파라미터)보다 성능이 좋다. **모델 사이즈가 더 적음에도 어텐션 메커니즘 하나로 성능 우위**.

**추가 효과**:
- **백프로파게이션**: 그래디언트가 어텐션 경로로도 직접 흘러 기울기 소실 완화
- **설명 가능성(XAI)**: 어텐션 히트맵으로 시각화. 프랑스어-영어는 어순이 비슷하므로 대각선으로 높은 어텐션이 관찰 → 모델이 정상 동작함을 확인

### 6-4. 어텐션 스코어 변형

- **Dot Product**: 쿼리와 밸류를 직접 내적. 차원이 같아야 하는 제약
- **Multiplicative (General)**: 쿼리와 밸류 사이에 학습 가능한 매트릭스를 두어 곱셈. 차원 제약 해소, 학습 여지 증가
- **Additive**: 쿼리와 밸류를 작은 뉴럴넷의 병렬 입력으로 보고 스코어 출력
- **Scaled Dot-Product**: 트랜스포머에서 사용 (6장에서 상세)

> **교수님 강조**: 쿼리와 밸류가 있고 둘 간의 관계를 표현하는 스코어만 나오면 그만이다. 방식은 상상력에 따라 다양하게 만들 수 있다.

## 7. 트랜스포머(Transformer)

### 7-1. RNN 기반의 남은 문제

인코더-디코더 간 어텐션은 해결했지만:
- 인코더 내부 / 디코더 내부에서는 여전히 **순차적 처리**(h_{t-1} 없이 h_t 불가)
- 문장이 길어지면 인코더/디코더 각각 내부에서도 장기 의존성 문제
- 순차적이므로 **병렬화 불가** → 100억 개 이상의 대규모 데이터 학습 시 큰 문제

### 7-2. 셀프 어텐션(Self-Attention)

같은 문장 내에서 단어 간 어텐션. 쿼리와 밸류가 같은 문장에서 나오므로 "셀프"이다.

**"어제 카페에 갔었어 거기 사람 많더라"** 예시:
- "거기"라는 단어의 표현을 배우려면 → "카페"(실체), "갔었어"(동사), "많더라"(상태) 등의 정보가 필요
- 모든 단어가 똑같은 중요도가 아니므로 **어텐션으로 가중치 부여**
- "카페"의 표현을 배울 때는 → "거기"(대명사, co-reference)와 자기 자신이 중요

모든 단어가 **쿼리/키/밸류** 세 가지 역할을 동시에 수행한다.

### 7-3. QKV 분리와 변환

각 단어의 512차원 벡터를 **W_Q, W_K, W_V** (학습 가능한 행렬, 512×64)로 변환하여 64차원의 쿼리/키/밸류 벡터를 생성한다. 인코더-디코더 어텐션에서는 키와 밸류가 구분되지 않았지만(인코더 벡터가 양쪽 역할), 셀프 어텐션에서는 **세 역할을 분리**한다.

- **키 벡터**: 쿼리와 내적하여 스코어 계산에 사용
- **밸류 벡터**: 스코어(확률 분포)대로 가중합에 사용
- 역할 분리가 꼭 필요한 건 아니지만 트랜스포머에서는 세 가지로 구분

**"어제"가 쿼리일 때**: 어제의 쿼리 벡터와 모든 단어의 키 벡터를 내적 → 스코어 → 소프트맥스 → 밸류 벡터의 가중합 → 어제에 대한 업데이트된 표현(O_i). 모든 단어에 대해 **병렬 계산 가능** (서로 디펜던시 없음).

```
Attention(Q, K, V) = softmax(Q·K^T / √d_k) · V
```

### 7-4. 셀프 어텐션의 세 가지 문제와 해결

**문제 1 — 순서 정보 부재 → 포지셔널 인코딩**

가중합이므로 단어 순서가 고려되지 않는다. 순서 정보를 표현하는 벡터를 임베딩에 더한다.

요구사항은 워드 임베딩과 유사: (1) 각 순서마다 고유한(겹치지 않는) 표현, (2) 가까운 순서(1번째, 2번째)는 유사하고 먼 순서(1번째, 100번째)는 먼 관계. 사인/코사인 주기함수로 이를 만족시키는 아름다운 벡터를 생성할 수 있다.

**문제 2 — 비선형성 부족 → 피드포워드 네트워크**

셀프 어텐션은 가중합(선형)이라 여러 번 쌓아도 수학적으로 한 번과 동일하다. MLP에서 비선형 활성화 없이 레이어를 여러 번 쓰나 한 번 쓰나 같은 것과 동일.

**ReLU 활성화가 포함된 피드포워드 네트워크**를 셀프 어텐션과 셀프 어텐션 사이에 삽입. 매 단어마다 같은 뉴럴넷을 적용(RNN처럼 파라미터 공유). 보통 2개의 레이어로 구성.

**문제 3 — 미래 참조 불가 → 마스크드 셀프 어텐션**

디코더에서 미래 단어를 참조하면 안 된다. 학습 시에는 정답을 알고 있지만, 구현적으로 미래 위치의 어텐션 스코어에 **-∞를 할당**한다. 소프트맥스에서 e^(-∞) = 0이 되어 해당 위치의 가중치가 사실상 0이 된다.

### 7-5. 멀티헤드 어텐션(Multi-Head Attention)

한 모듈에서 어텐션을 **여러 번(예: 8번)** 수행. W_Q, W_K, W_V를 8세트 두어 각 헤드가 서로 다른 관점의 어텐션을 학습.

512차원을 8헤드로 나누면 각 헤드는 64차원. 단어가 많은 실제 문장에서 8번의 어텐션이 서로 꽤 다르고 상호보완적인 결과를 낸다. 예: 한 헤드는 동사/상태에 집중, 다른 헤드는 개체(entity)에 집중.

### 7-6. Scaled Dot-Product

쿼리·키 벡터의 차원(d_k)이 커질수록 내적 값이 커져 소프트맥스가 극단적(0.99 등)이 된다. 한 단어에 어텐션이 극단적으로 쏠리는 문제 발생.

해결: **√d_k로 나누어 안정화**. d_k = 64면 √64 = 8로 나눈다. 헤드가 1개면 d_k = 512, 8개면 d_k = 64. 이 분모를 scale factor라고 하며, 이 방식을 Scaled Dot-Product라고 한다.

### 7-7. 레지듀얼 커넥션 & 레이어 노멀라이제이션

**레지듀얼 커넥션(Residual Connection)**: 셀프 어텐션/피드포워드를 거치는 경로 외에 **거치지 않는 스킵 경로**를 둔다. 백프로파게이션 시 레이어를 거치지 않는 경로로 그래디언트가 흘러 기울기 소실 완화. 로스 공간을 더 컨벡스(convex)하게 만든다.

**레이어 노멀라이제이션**: 시험 점수 비유 — 9점을 받았는데 만점이 10점이면 잘한 거고, 만점이 100점이면 못한 거다. 만점이 매번 바뀌면 혼란스럽다. 값의 분포가 레이어마다 왔다갔다하면 모델 학습에 나쁜 신호. 같은 분포 내에 일관적으로 있게 정규화한다.

### 7-8. 트랜스포머의 완전한 구조

"Attention is All You Need" (2017). 제목은 비틀즈의 "All You Need is Love" 패러디. 일저자는 공유 전날 AI 세계에 불러올 파장에 설레서 잠을 못 잤다고 한다.

- **인코더**: (셀프 어텐션 + 레지듀얼&놈 + 피드포워드 + 레지듀얼&놈) 블록을 **6번** 반복
- **디코더**: (마스크드 셀프 어텐션 + 레지듀얼&놈 + **인코더-디코더 어텐션(크로스 어텐션)** + 레지듀얼&놈 + 피드포워드 + 레지듀얼&놈) 블록을 **6번** 반복
- 인코더-디코더 어텐션: 디코더의 쿼리와 **마지막 인코더 블록**의 키·밸류를 캐싱하여 반복 사용
- 마지막에 리니어(W_HY) + 소프트맥스로 보캐뷸러리 확률 분포 → 그리디/빔서치로 텍스트 생성

**성과**: 번역 정확도도 올라가고, 병렬 연산 가능하므로 학습 비용도 더 적게 나왔다.

## 8. 사전학습(Pre-training)

### 8-1. 사전학습의 필요성

트랜스포머의 W_Q, W_K, W_V × 멀티헤드 수 × 블록 수 × 인코더/디코더 = 방대한 파라미터. 번역은 병렬 코퍼스(성경이 인류 최초의 빅데이터)가 풍부했지만, 요약·챗봇 등은 지도학습 데이터가 부족.

해결: 웹의 대용량 텍스트로 **사람의 레이블링 없이** 일반적인 언어 이해를 선행 학습(사전학습, Pre-training). 다음 단어 맞추기나 빈칸 맞추기는 텍스트만 있으면 입력/출력 자동 생성. 100억 개 데이터를 다 레이블링된 것으로 사용 가능.

이후 소량의 지도학습 데이터로 미세조정(파인튜닝/어댑테이션). 사전학습된 모델 자체만으로도 의미 있을 수 있다(파운데이션 모델).

Word2Vec도 사전학습의 일종이지만 임베딩 레이어만 학습. 이제는 **인코더 영역까지** 사전학습하는 것이 핵심 발전.

모델 구조는 세 파트: 임베딩 레이어 + 인코더 + 소프트맥스/분류 레이어. 트랜스포머를 인코더만/디코더만/인코더-디코더로 나눠서 사전학습한다.

### 8-2. BERT — 인코더 모델

트랜스포머의 **인코더만** 사용. 앞뒤 맥락을 모두 볼 수 있어 텍스트 **이해/분류** 태스크에 강점.

**마스크드 언어 모델(Masked Language Model, MLM)**: 입력 단어의 **15%**를 마스킹하고 원래 단어를 예측. 너무 많이 가리면 맥락이 사라져 학습이 안 되고, 너무 적으면 학습이 오래 걸린다.

15% 중에서:
- **80%는 [MASK] 토큰**: 기본적인 빈칸 맞추기
- **10%는 랜덤 단어로 교체**: 웹 텍스트는 노이즈가 심하다(트위터 데이터의 90%는 해석 불가한 수준). 랜덤 단어를 넣어 **백신 효과** — 오타가 있어도 전체 맥락을 이해하는 능력
- **10%는 원래 단어 유지**: MLM은 학습용이고 실제 사용 시에는 마스크된 단어를 맞출 기회가 없다. 실제 환경에 노출시켜 정상 단어에서도 좋은 확률 분포 표현을 배우도록 함

**구조**: 인코더 12블록 쌓음. 입출력 모두 512차원 벡터. 입력 컨텍스트 윈도우 512개 단어(512와 벡터 차원 512가 공교롭게 같은 숫자).

**CLS 토큰과 Next Sentence Prediction(NSP)**: 문장 맨 앞에 [CLS](클래스) 스페셜 토큰을 넣고, 두 문장을 [SEP](세퍼레이트) 토큰으로 구분하여 입력한다. 연속된 두 문장(is-next) 또는 랜덤으로 조합한 두 문장(not-next)에 대해 CLS 토큰의 최종 표현으로 이진 분류. 사람의 레이블링 없이 자동 생성 가능.

CLS 토큰이 **첫 번째 위치**인 이유: RNN은 마지막 히든 벡터가 문장 전체 의미를 담았지만, 트랜스포머는 순차 업데이트가 아니므로 마지막일 필요 없다. 가변 길이 시퀀스에서 **항상 첫 번째가 전체 의미를 종합한다**고 약속하는 것이 더 쉽다.

**어댑테이션(파인튜닝)**:
- **토큰 레벨**: 품사 태깅(36개 품사 분류), 개체명 인식(NER — 각 단어가 엔티티인지 분류)
- **토큰 레벨 — SQuAD 질의응답**: 문서가 주어졌을 때 정답이 문서 내에 존재. 매 토큰에서 (1) 정답 시작 위치 스코어 (2) 정답 끝 위치 스코어 — 두 개의 확률 분포를 출력. 시작이 가장 높은 위치와 끝이 가장 높은 위치의 스팬(span)을 정답으로 추출
- **문장 레벨**: CLS 토큰으로 감성 분류(긍정/부정)
- **문장 쌍 레벨**: NLI(Natural Language Inference — 두 문장의 논리적 관계: 함의/모순/중립, AI 기초과학에 해당), QQP(Quora Question Pairs — 두 질문이 중복인지 판별)

BERT는 이전 모델(BiLSTM+Attention, ELMo, GPT-1)을 모든 벤치마크에서 능가. 다양한 태스크를 한 번에 평가하는 GLUE 벤치마크 시대가 열림. 한계: 텍스트 생성 능력이 부족하여 생성형 AI 시대에는 부적합.

### 8-3. T5 — 인코더-디코더 모델

**Text-to-Text Transfer Transformer** (T가 5번 등장해서 T5).

**핵심 아이디어 — 모든 태스크를 텍스트→텍스트로 통일**: 번역(원래 텍스트→텍스트), 문법 체크("not acceptable"이라는 텍스트 생성), 유사도(3.8이라는 스코어 자체를 텍스트 생성), 요약(텍스트→짧은 텍스트). 디코딩 형태가 달라 멀티태스크 학습이 어려웠는데, 전부 텍스트 생성으로 바꿔서 동시 학습 가능.

**프리픽스(Prefix)**: 서로 다른 태스크를 구별하기 위한 최소 정보. "translate English to German:", "cola:", "stsb:", "summarize:" 등. 없으면 번역인지 요약인지 헷갈린다. 설명적이지 않고 태스크 구분만 하는 태그지만, 나중에 더 발전하여 현재의 **인스트럭션(명령어)**으로 진화했다.

**사전학습: 스팬 코럽션(Span Corruption)**: 일반적인 언어 모델(앞 맥락 → 다음 단어)보다 성능이 좋았던 방법. 문장에서 연속된 단어(span)를 스페셜 토큰으로 대체하고, 디코더가 빠진 부분을 생성. 예: "Thank you _____ me to your party last _____" → 디코더가 "for inviting" / "last" 생성.

더 좋은 이유: 단순 다음 단어 예측에서는 문장이 길어질수록 앞단 문장이 별로 필요 없을 수 있지만, 스팬 코럽션은 **앞뒤 맥락을 모두 파악**해야 빈 곳을 채울 수 있어 인코더·디코더가 더 큰 챌린지를 가지고 더 좋은 학습을 한다. 실험에서도 디노이징(스팬 코럽션) 방식이 일반 LM보다 전반적으로 성능이 좋았다.

### 8-4. GPT — 디코더 모델

트랜스포머의 **디코더만** 사용. 앞 맥락만 참조하는 오토리그레시브(auto-regressive) 모델.

**디코더를 선호하는 이유**: (1) 인코더 6블록 + 디코더 6블록 대신 **디코더 12블록으로 올인**하면 더 깊은 사고 가능, (2) 유니코드/통계 기법으로 통합 보캐뷸러리를 만들어 인코더/디코더 간 보캐뷸러리 차이 문제가 해소됨.

**GPT-1**: 트랜스포머 디코더로 사전학습. 텍스트 **분류** 위주. CLS 대신 **Extract** 토큰(마지막 위치), SEP 대신 **Delimiter**, 맨 앞에 **Start** 토큰 사용. BERT보다 먼저 나왔지만 인코더 기반 BERT가 분류에서 더 우수.

분류 적용 방식: 단일 문장 → 마지막 Extract 벡터로 분류 / NLI → Delimiter로 두 문장 분리 후 분류 / 유사도 → 순서를 바꿔 두 번 인코딩하고 더해서 분류 / 멀티초이스 → 각 후보별 스코어를 뽑아 소프트맥스.

성능: ELMo, BiLSTM+Attention 등을 능가. 사전학습된 언어모델이 텍스트 문제를 잘 푼다는 것을 먼저 밝힘.

**GPT-2**: 파라미터·데이터를 약 10배 증강. 텍스트 **생성 능력** 발현 — "과학자들이 안데스 산맥에서 영어를 잘하는 유니콘을 발견했다"라는 프롬프트에 그럴싸한 장문의 이야기를 생성.

**GPT-3 (175B 파라미터)**: **인컨텍스트 러닝(In-Context Learning)** 능력 발견. 파라미터를 변경하지 않고(트레이닝이 아님) 입력에 포함된 패턴을 매칭하는 능력. 패턴 매칭이므로 러닝이라 부를 수 있지만 트레이닝(파라미터 변경)은 아니다.

- **퓨샷(Few-shot)**: 여러 예제를 입력에 포함. 영어→프랑스어 예제를 주면 번역 패턴 매칭
- **원샷(One-shot)**: 예제 하나만 포함
- **제로샷(Zero-shot)**: 예제 없이 명령만으로 수행. 당시에는 제로샷 능력이 아주 강하지는 않았음

**GPT-3 성능 표 분석 — 세 가지 관점**:
1. **파라미터 크기 → 성능**: 1.3B, 13B, 175B로 10배씩 키울 때 성능이 점프. 특히 100B 이상부터 크게 개선
2. **예제 수 → 성능**: 예제를 많이 줄수록 성능 향상. 175B는 기울기가 더 급격 → 인컨텍스트 러닝 능력이 더 강함
3. **명령 유무 → 성능**: 작은 모델(1.3B, 13B)은 명령을 이해하지 못함 — 명령 있든 없든 성능 차이 없음. "번역해"라고 하면 진짜 번역이 아니라 "번역해 제발" "번역해 이 문장을" 같은 다음 단어를 생성. 175B는 명령 유무에 따른 성능 차이가 크다 = 명령을 이해하는 능력이 생김. 단, 예제를 충분히 주면 명령 여부와 무관하게 성능 수렴

GPT-3의 성능은 파인튜닝된 SOTA에 근접했지만 크게 뛰어넘지는 않았다. 파인튜닝은 수백~수천 개 데이터를 학습한 것이고 GPT-3는 채팅창에서 명령 한 번으로 비슷한 성능을 낸 것이 의의. **파인튜닝 성능을 크게 뛰어넘은 것은 GPT-3.5/InstructGPT/ChatGPT** — 인스트럭션 튜닝, CoT 등 추가 기법으로 비약적 발전.

> **교수님 강조**: GPT-3는 발명이 아니라 **발견**이다. 어떤 은하계의 문명이든 충분히 발전하면 인공 지능의 발현은 약속된 것이다. 우리가 그 존재를 마주한 것이고, 메커니즘을 완전히 이해하지 못했기 때문에 발견이라 부른다. 마치 외계인을 만난 것과 같다. 어떤 프롬프트를 넣어야 원하는 결과를 얻는지 — 외계인과 대화할 수 있는 프로토콜을 찾는 연구가 2020년부터 시작됐다.

### 8-5. Chain-of-Thought (CoT) 프롬프팅

GPT-3가 수학 문제에서 특히 취약했다. 1,750억 개의 파라미터를 태운 것이 심심풀이 챗봇을 위한 것이 아니라 더 높은 목적을 위한 것인데 수학조차 못 풀었다.

**풀이 과정(레셔널, rationale)을 예제에 포함**하면: "로저가 테니스볼 5개가 있고, 3개들이 캔 2개를 더 샀다. 총 몇 개?" → 예제에 "5개 + (3×2)개 = 11개"라는 중간 과정을 넣어줬더니, 새 문제에서도 모델이 풀이 과정을 흉내내며 정답을 생성. 성능: CoT 없이 18% → CoT 적용 57%. 파인튜닝 모델(55%)을 초과.

**제로샷 CoT (도쿄대)**: "Let's think step by step"이라는 한 문장만 추가하면 예제 없이도 CoT가 작동. 퓨샷 CoT보다 성능은 낮지만, 제로샷이 된다는 것의 의미가 크다:
- 예제를 주는 것 = 특정 태스크를 사전에 정한 것
- 제로샷 = **즉흥적으로 아무 문제나** 낼 수 있다
- 이는 로봇에 적용 가능하다는 뜻 — 맥주 가져오기, 숙제 해주기, 강아지 산책 등 매번 예제를 보여줄 수 없는 상황
- 산업적 적용 범위가 엄청나게 확대됨

### 8-6. 현재와 미래 (질의응답)

- **디코더 단독 모델 경쟁**: 어느 정도 마무리. 지금은 AI **에이전트**를 어떻게 발전시킬지가 핵심 화두
- **트랜스포머의 한계**: 표준이 되었지만 잘 해석하지 못하는 데이터도 많다. Mamba 등 새 아키텍처 연구 진행
- **스케일링 법칙**: 파라미터·학습기간을 로그 스케일로 키우면 성능이 선형 증가. 하지만 에너지(전기), GPU, 데이터가 부족. 반도체 개발, 합성 데이터, 학습 효율 향상이 필요
- **프론티어 랩의 핵심**: 강화학습 기술. 그것이 AI 발전의 구세주인지, 한계가 있어 넘어서야 하는지가 논의 중
- **AGI**: 사람의 모든 영역에서 발군 → AI가 잘하는 영역에서 우수하면 AGI라는 기준으로 변화. AI가 잘할 수 있는 영역에서 스스로 성장하는 시대는 이미 빠르게 오고 있다

> **교수님 강조**: 3~5년 안에 엄청난 일이 발생할 것이며, 인류에게 긍정적인 방향이길 바란다. 인공지능 산업은 에너지, 국가 간 주도권, 전쟁과 복잡하게 연결되어 변수가 크다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 원핫 벡터 | 50만 차원, 모든 단어 직교(유사도 0), 차원의 저주, 의미 정보 없음 |
| 워드 임베딩 | "주변을 봐라" 철학. 밀집·연속·분산 표현. Word2Vec(스킵그램이 더 효과적) |
| 스킵그램 vs CBOW | 스킵그램: 주변 단어를 하나씩 여러 번 예측, 드문 단어에 유리. CBOW: 중심 단어 한 번 예측 |
| 한계 | 동음이의어 미구분, 맥락 정보 부족, 순서 고려 안 됨 |
| RNN | 히든 스테이트를 시간축으로 업데이트. 동일 파라미터 공유. 가변 길이 처리 가능 |
| RNN 한계 | 정보 필터링 불가, 장기 기억 상실, 기울기 소실 |
| LSTM | 셀 스테이트(장기) + 히든 스테이트(단기). 3게이트: Forget(삭제), Input(저장), Output(출력) |
| 게이트 작동 | 시그모이드로 0~1 벡터 출력 → 셀 스테이트와 엘리먼트 와이즈 곱셈. 스칼라가 아닌 벡터 의사결정 |
| 언어 모델 | 맥락 → 다음 단어 확률 예측. N-gram(통계, 맥락 제한) → 뉴럴 언어 모델 |
| SMT | 베이즈 분해: P(X\|Y) × P(Y). 라이클리후드 + 언어모델. 수십 년간 사용, 성능·유지 한계 |
| Seq2Seq | 인코더-디코더. 디코더 = 조건부 언어 모델. 조건만 바꾸면 번역/요약/챗봇/코드 생성 |
| 티처 포싱 | 학습 시 정답을 다음 입력으로 강제 제공. 에러 전파 방지. 하이브리드(8:2) 방식 |
| 빔서치 | K개 후보 고정 너비로 유지. 레이저 빔 비유. K가 너무 크면 오히려 불리 |
| 어텐션 | 쿼리(디코더)-밸류(인코더) 내적 → 소프트맥스 → 가중합. 바틀넥·기울기 소실 해소, XAI |
| 어텐션 성능 | 작은 파라미터+어텐션 > 큰 파라미터+어텐션 없음. 긴 문장에서 효과 극대화 |
| 스코어 변형 | Dot Product, Multiplicative(학습 파라미터 추가), Additive(작은 뉴럴넷), Scaled Dot-Product |
| 셀프 어텐션 | 같은 문장 내 QKV 분리. W_Q/W_K/W_V(512→64)로 변환. 병렬 처리 가능 |
| 포지셔널 인코딩 | 순서 벡터를 임베딩에 더함. 사인/코사인 주기함수로 고유성+유사도 관계 |
| 피드포워드 | 셀프 어텐션 사이에 ReLU 포함 뉴럴넷 삽입. 비선형성 부여 |
| 마스크드 어텐션 | 미래 위치에 -∞ → 소프트맥스 후 0. 디코더 전용 |
| 멀티헤드 | 어텐션 8회 병렬. 512/8=64차원. 상호보완적 관점 학습 |
| Scaled Dot-Product | √d_k로 나누어 소프트맥스 안정화. 극단적 어텐션 방지 |
| 레지듀얼+레이어놈 | 스킵 경로로 기울기 소실 완화. 값 분포 정규화로 학습 안정 |
| 트랜스포머 | 인코더 6블록 + 디코더 6블록. 크로스 어텐션은 마지막 인코더에서. 성능+효율 동시 향상 |
| 사전학습 | 대용량 웹 데이터, 레이블 불필요. 임베딩→인코더까지 확장. 파운데이션 모델로 발전 |
| BERT | 인코더. MLM(15%: 80/10/10) + NSP(CLS+SEP). 12블록, 512차원. 이해/분류에 강점 |
| BERT 어댑테이션 | SQuAD(시작/끝 위치), NLI(함의/모순/중립), QQP(중복 판별), POS, NER 등 |
| T5 | 인코더-디코더. 텍스트→텍스트 통일, 멀티태스크, 프리픽스→인스트럭션 조상. 스팬 코럽션 |
| GPT | 디코더 전용. GPT-1(분류, Extract 토큰) → GPT-2(생성 발현) → GPT-3(ICL, 175B) |
| GPT-3 발견 | 100B+ 에서 명령 이해 능력 출현. 파인튜닝 근접 성능을 프롬프트만으로 달성 |
| CoT | 풀이 과정을 예제에 포함 → 18%→57%. 제로샷 CoT("step by step") → 산업 적용 확대 |
| 현재/미래 | 에이전트 시대. 스케일링 한계(에너지/GPU/데이터). 새 아키텍처(Mamba). 3~5년 내 큰 변화 예상 |
