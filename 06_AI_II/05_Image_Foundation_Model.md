## 1. AI 모델과 파운데이션 모델의 개념

### 1-1. AI 모델이란 무엇인가

AI 모델은 본질적으로 **함수(또는 프로그램)**이다. 입력을 넣으면 적절한 출력이 나오는 함수이며, 그 입출력 관계(패턴)를 코딩이 아닌 **데이터로 학습**한다는 점이 기존 프로그램과 다르다. 추가로 AI 모델에는 **학습할 때 보지 못했던 데이터에 대해서도 작동해야 하는 의무**가 있다. 대표적인 AI 모델이 뉴럴 네트워크이다.

### 1-2. 이상적인 AI 모델과 검색 엔진

이상적인 AI 모델은 이 세상에 발생 가능한 모든 데이터를 기억하고 있는 것이다. 이를 가장 간단하게 구현하는 방법은 **검색 엔진(최근접 이웃 탐색, Nearest Neighbor Search)**이다 — 모든 데이터를 DB에 넣고 가장 유사한 과거 패턴을 리턴하면 된다.

하지만 현실적으로 모든 데이터를 저장하기에는 **스토리지 비용이 너무 크고 검색 비용도 크다**. 이를 해결하는 방법이 **압축**이다.

### 1-3. 학습 = 압축

기계학습이란 결국 **데이터의 패턴을 파악하여 압축**하는 것이다. 유사하게 발생하는 패턴을 정리하고, 비슷함과 다름을 자동으로 파악하면서 새로운 데이터에도 일반화할 수 있는 능력이 생긴다. 이 압축된 지식을 담는 그릇이 뉴럴 네트워크이다.

### 1-4. 파운데이션 모델의 정의

데이터를 쉽게 취득하고, 세상의 수많은 데이터를 최대한 기억하게 만들면 이상적인 AI 모델에 가까워진다. 그렇게 만든 것이 **파운데이션 모델**이다.

파운데이션 모델은 엄밀한 기술 용어라기보다 마케팅/비즈니스 용어에 가깝다. 스탠포드 대학 연구소의 보고서에서 처음 새로운 범주로 구분하면서 유명해졌다. **대규모 데이터를 폭넓게 학습한 후 다양한 문제에 빠르게 적용 가능한 범용 대형 AI 모델**을 통칭한다.

- 파운데이션 모델은 프리트레인드 모델인가? → **참** (파운데이션 모델 ⊂ 프리트레인드 모델은 아님)
- 프리트레인드 모델이 파운데이션 모델인가? → **아닐 수 있다** (훨씬 더 많은 데이터로 학습한 것)
- 여러 태스크를 동시에 수행하는 모델인가? → 반드시 그렇지 않다. 타겟 태스크에 적응시키면 쉽게 변형되고 성능이 빠르게 나오는 **적응성이 좋은 모델**이다

> **교수님 강조**: 기존 딥러닝은 아이를 매번 처음부터 키우는 것(From Scratch)이었다면, 파운데이션 모델은 이미 성인의 뇌를 가진 상태에서 새로운 일을 시키는 것과 같다.

### 1-5. 파운데이션 모델의 세 가지 특징

**특징 1 — 대규모성(Large Scale)**: 트랜스포머 모델을 주로 사용한다. 트랜스포머가 선호되는 이유는 **스케일링 법칙(Scaling Law)**을 잘 따르기 때문이다 — 데이터를 넣을수록, 모델을 키울수록 성능이 계속 올라간다. 기존 ResNet 등은 일정 이상에서 성능이 포화되거나, 고전 이론에서는 오히려 모델이 커지면 불리하다는 주장도 있었다. 초기에는 인터넷 텍스트를 비지도학습으로 학습하여 대규모 데이터 수집 비용을 줄였다.

**특징 2 — 적응성(Adaptability)**: 사전학습 후 약간의 파인튜닝만으로 새로운 태스크에 빠르게 적응한다. 사전학습 시 하나의 대표 태스크에 대해 잘 작동하면 되고, 타겟 태스크에 적응시키면 성능이 바로 나오기 시작한다.

**특징 3 — 범용성(Generality)**: 과거에는 1,000개 클래스 구분이 대단했지만, 파운데이션 모델은 만 개 이상의 물체를 구분하고, 자연어 기반으로 클래스에 구애받지 않는 범용 분류가 가능해졌다.

### 1-6. AI 개발 패러다임의 변화

과거에는 매번 랜덤 초기화에서 처음부터 새로 학습했다. 이제는 **잘 학습된 파운데이션 모델을 얼마나 잘 발견하고 활용하느냐**가 핵심이다. 파운데이션 모델 하나를 획득하는 비용은 일반 대학/연구소 수준을 넘어 대기업에서도 버거울 정도이지만, 감사하게도 대기업들이 수백~수천억을 투자해 만든 모델을 오픈소스로 공개하고 있다.

### 1-7. 파운데이션 모델 활용 기법

다운로드받은 파운데이션 모델을 활용하는 방법들:

- **제로샷(Zero-shot)**: 추가 학습 없이 바로 질의. 어떠한 맥락도 없이 던지는 것
- **퓨샷(Few-shot)**: 몇 개의 예제를 보여준 뒤 질의. 인컨텍스트 러닝
- **파인튜닝(Fine-tuning)**: 모델 가중치를 소량의 데이터로 추가 업데이트
- **프롬프트 엔지니어링**: 입력 텍스트를 잘 설계하여 성능 향상
- **프롬프트 튜닝**: 학습 가능한 가상 토큰을 입력에 추가하여 자동으로 최적 프롬프트 탐색

## 2. CLIP 모델

### 2-1. 사람 같은 AI를 향한 여정

사람의 지능은 크게 **Perception(지각 — 오감)** 과 **Cognition(인지 — 사고)** 으로 나뉜다. 2022년 11월 ChatGPT 등장 전까지는 각 분야별로 부분적인 능력만 개별 모델링했다. ChatGPT가 높은 추론 성능을 보여주면서, 사람들은 "Cognition 파트는 언어 모델을 끼워넣으면 되는 거 아니야?"라고 생각하기 시작했다.

하지만 언어 능력만으로는 현실 세계를 다루기에 충분하지 않다. 백문이 불여일견이듯, 같은 것을 보고 감상하고 대화하려면 **시각 능력**이 필수이다. 그래서 언어 모델에 눈을 붙여주기 시작한 것이 **비전 랭귀지 모델(VLM)**이고, 그 눈의 역할을 하는 것이 **CLIP**이다.

### 2-2. CLIP의 구조와 학습

CLIP(Contrastive Language-Image Pre-training)은 **텍스트와 이미지의 유사도를 학습**하는 모델이다. 텍스트 인코더와 이미지 인코더로 구성되며, 각각 특징 벡터를 추출하여 유사한지 아닌지를 판별한다.

**데이터 수집 — Alt Text 활용**: HTML 표준에 alt 속성이 있다. 이미지를 로딩할 수 없는 환경(저대역폭, 장애인 지원)을 위해 이미지를 글로 설명해 둔 것이다. 수십 년간 웹 개발자들이 성실하게 작성해온 이 데이터를 다운로드받아 이미지-텍스트 쌍 **4억 개**를 수집했다. 중복, 저해상도, 짧은 텍스트 등을 필터링하는 정제 과정도 중요하다.

이것이 지도학습인 이유: 사람이 alt text를 작성했으므로 사실상 사람이 레이블링한 것이다.

**모델 구조**: 텍스트 인코더는 트랜스포머 인코더 온리, 이미지 인코더는 초기에 ResNet이었으나 현재는 ViT(Vision Transformer)가 표준. 서브워드 단위 토큰화, 패치 단위 입력.

**대조학습(Contrastive Learning)**:
- 양성 데이터(강아지 텍스트 ↔ 강아지 이미지)는 서로 끌어당기게
- 음성 데이터(서로 다른 것)는 서로 밀게
- 특징 벡터를 정규화(L2 norm = 1)한 뒤 내적 → 코사인 유사도
- 소프트맥스 + 크로스 엔트로피 로스로 학습

```python
# CLIP 학습 슈도코드
I_f = image_encoder(image)    # 이미지 특징 추출
T_f = text_encoder(text)      # 텍스트 특징 추출
I_f = normalize(I_f)          # L2 정규화
T_f = normalize(T_f)          # L2 정규화
logits = I_f @ T_f.T          # 내적 (코사인 유사도)
loss = cross_entropy(logits, labels)  # 양성은 높이고 음성은 낮추기
```

### 2-3. CLIP의 파운데이션 모델 특성

ImageNet으로 학습한 ResNet과 비교했을 때, ImageNet 내에서는 성능 차이가 별로 없었지만, 스케치/만화 같은 새로운 도메인에서 **60%의 성능이 추가학습 없이 유지**되었다. 기존 모델은 이런 도메인에서 실패했다. 제로샷 전이(Zero-shot Transfer)가 발생하기 시작한 것이다.

### 2-4. CLIP 기반 제로샷 분류기 구현

추가 학습 없이 분류기를 만드는 방법:

1. 분류하려는 카테고리를 텍스트로 구성 ("a photo of a airplane", "a photo of a dog" 등)
2. 텍스트 인코더로 특징 벡터를 미리 뽑아 등록 (VectorDB 구축)
3. 질의 이미지가 들어오면 이미지 인코더로 특징 벡터 추출
4. 모든 등록된 텍스트 벡터와 내적(코사인 유사도) 계산
5. 가장 높은 값의 카테고리를 반환

카테고리 외에도 "밝은 이미지 / 어두운 이미지", "고화질 / 저화질", "만화스러운 / 실제 같은" 등 다양한 기준을 설계 가능.

> **교수님 강조**: 이건 필살기다. 학습 없이 분류기를 만들 수 있다. 카테고리가 정말 많을 경우에는 기존 검색 시스템의 효율적인 자료구조/알고리즘을 활용하면 된다.

## 3. SigLIP — CLIP의 개선

### 3-1. 소프트맥스의 문제

소프트맥스는 합이 1인 함수로, 한쪽이 높아지면 다른 쪽이 낮아져야 한다(한정 자원 분배). 이 때문에 음성 데이터를 **무한히 멀리** 밀어내는 데 집착하게 되고, 정작 중요한 양성 데이터를 가깝게 만드는 것에 집중하지 못했다.

### 3-2. 시그모이드로 교체

SigLIP(Sigmoid Loss for Language-Image Pre-training)은 소프트맥스를 **시그모이드**로 교체했다. 시그모이드는 양 끝에서 기울기가 0에 수렴하므로, 충분히 멀어진(또는 충분히 가까워진) 쌍은 더 이상 업데이트하지 않는다. 어설픈 것(경계 근처)에만 집중하고, 명확한 것은 무시한다.

```
Loss = -log(sigmoid(z_ij * s_ij))
# z_ij: 양성이면 +1, 음성이면 -1
# s_ij: i번째 이미지와 j번째 텍스트의 코사인 유사도
```

결과적으로 노이즈에도 더 강건하고 전반적 성능이 향상되었다. **코드는 로스 함수 부분만 교체**, 모델은 동일하다. SigLIP2도 공개되어 최신 VLM에 널리 활용되고 있다.

## 4. 멀티모달 정합과 확장

### 4-1. 멀티모달 정합(Multimodal Alignment)

CLIP/SigLIP은 텍스트와 이미지의 특징 벡터가 **같은 공간**에서 비교 가능하게 만든다. 이를 멀티모달 정합이라 한다.

**ImageBind**(Meta): 이미지, 텍스트, 오디오, 열화상, 3D, 센서 등 여러 모달리티를 하나의 공유 벡터 공간으로 정렬. 소리로 이미지를 검색하거나, 3D로 텍스트를 검색하는 등 크로스모달 검색이 가능해진다.

### 4-2. 멀티모달 정합의 역방향 활용 (심화)

CLIP의 순방향은 입력 → 특징 벡터이다. 이를 **역방향으로 활용**하면 번역(Translation)이 된다:

- 이미지 입력 + 랜덤 텍스트 입력 → 유사도 계산 → 유사도를 높이는 방향으로 **텍스트만 업데이트**(모델은 고정) → 이미지를 잘 설명하는 텍스트가 생성됨 (이미지 캡셔닝)
- 반대로 텍스트를 고정하고 이미지를 업데이트하면 이미지 에디팅
- 중간에 미분 가능한 3D 렌더링 레이어를 넣으면 텍스트만으로 3D 객체 생성 가능 (학습 데이터 불필요)

핵심: 이것은 **학습이 아니라 최적화**이다. 단일 데이터에 대해서만 반복 업데이트한다. 모델은 건드리지 않고 입력만 업데이트한다.

> **교수님 강조**: 이미지 데이터도 필요 없고 학습도 필요 없다. GPU는 필요하지만 메모리가 많이 필요하진 않다. 프로토타입으로 쓸 수 있는 유용한 필살기다.

## 5. 비전 랭귀지 모델(VLM)

### 5-1. VLM의 기본 구조

언어 모델(LLM)에 CLIP의 비전 인코더(텍스트 인코더는 버림)를 접붙이는 구조이다:

1. **비전 인코더(고정)**: CLIP/SigLIP의 이미지 인코더. 이미지를 특징 벡터로 변환
2. **프로젝션 레이어(학습)**: 비전 특징을 LLM이 이해할 수 있는 형태(소프트 프롬프트)로 변환하는 통역사. 선형 레이어 또는 MLP
3. **LLM(고정 또는 미세조정)**: 텍스트 토큰과 변환된 비전 토큰을 함께 받아 응답 생성

비전 인코더와 LLM은 이미 학습된 것을 가져오므로, 실제 학습하는 부분은 프로젝션 레이어뿐이라 비교적 적은 비용으로 구축 가능.

### 5-2. LLaVA (Visual Instruction Tuning)

2023년에 공개된 대표적 VLM이다. **2단계 커리큘럼 학습**:

**1단계 — 사전학습**: 프로젝션 레이어만 학습. 비전 인코더와 LLM은 고정. 이미지/인스트럭션/답변의 3개 데이터 페어 사용.

**2단계 — 파인튜닝**: 프로젝션 레이어 + LLM을 함께 미세조정. LLM은 태어나서 한 번도 시각 데이터를 본 적이 없으므로, 진짜 시각을 뼛속 깊이 이해하게 하려면 이 단계가 필요. 효율적 학습을 위해 정밀도를 낮춘 플로팅 포인트(FP16 등)로 메모리 절감.

**학습 데이터 생성 — 합성 데이터**: COCO 데이터셋(이미지 + 캡션 + 좌표 정보)에서 캡션을 ChatGPT에게 주고 "이 답변이 나올 만한 질문을 만들어줘"라고 역질문을 생성. 대화형, 상세 설명, 복합 추론 유형의 질문을 자동 생성하여 (이미지, 질문, 답변) 트리플릿을 만들었다.

**인스트럭션 파인튜닝의 의미**: 언어 모델이 아무리 똑똑해도, 사용자 명령대로 행동하지 않으면 쓸모없다. 질문에 맞는 답을 하게 만드는 것이 인스트럭션 파인튜닝이며, ChatGPT가 성공한 핵심 기술 중 하나이다.

### 5-3. Qwen-VL (알리바바)

중국 알리바바에서 만들어 무료 공개한 대형 멀티모달 모델. 미국의 대부분의 기관/기업에서 베이스로 사용할 정도로 기술 기반을 점령했다.

주요 특징:
- **다중 이미지 입력**: 두 개 이상의 이미지를 넣어 비교/분석 가능
- **다국어 지원**: 번역, 다국어 텍스트 인식
- **물체 탐지 출력**: 바운딩 박스 좌표까지 출력
- **3단계 커리큘럼**: 사전학습(저해상도, 비전 인코더 학습) → 멀티태스크(고해상도, 전체 학습) → 인스트럭션 파인튜닝

**버전별 발전**:
- QwenVL: 448×448 고정 해상도
- **Qwen2-VL**: 동적 해상도 지원, 위치 인베딩 개선, 장편 비디오 이해, 다국어 OCR
- **Qwen2.5-VL**: 문서 파싱 강화(테이블, 차트, 수학 공식, 악보), 객체 그라운딩, 장시간 비디오 이벤트 추출
- **Qwen2.5-Omni**: 옴니모델(읽고, 쓰고, 보고, 듣고, 말하기). Thinker + Talker 구조. 소스코드/오픈웨이트 전부 공개
- **Qwen3/3.5**: 3D 바운딩박스 좌표 출력, 컴퓨터 유즈/모바일 에이전트 기능, 비주얼 코딩

> **교수님 주의**: VLM에 이미지를 넣을 때 모델이 학습된 해상도를 반드시 확인해야 한다. 고해상도 이미지를 모델의 작은 입력 크기로 축소하면 내용이 안 보여서 성능이 떨어진다. 큰 이미지는 잘라서 여러 번 넣는 것도 좋은 테크닉이다.

### 5-4. InternVL

다이나믹 해상도에 특히 집중한 모델. 다양한 해상도의 이미지를 여러 방식으로 크롭하여 입력. 싱글 이미지, 비디오, 멀티 이미지 입력 지원. 커리큘럼이 더 복잡하여 학습 중간에 언어 모델 크기를 키우기도 한다. 1B~수십B까지 다양한 크기의 모델이 공개되어 있다.

### 5-5. 도메인 특화 VLM

파운데이션 모델을 파인튜닝하여 특화 모델을 만든다:
- **의료**: LLaVA-Med 등. 병리진단, 분류, 의료 영상 분석. 한국 스타트업 루닛이 세계 1~2위
- **제조업**: 불량 탐지. 전세계 시장 비율이 크고 AI 서비스 사업 모델로 유망
- **3D**: 3D LLM, 3차원 공간 내비게이션 에이전트. 지도에 없는 정보(화장실, 쓰레기통 등)를 검색하는 언바운드된 서비스 가능성
- **로봇**: 로봇 언어 액션 모델(RLA). 모터 제어 시그널까지 출력

## 6. 경량 VLM(Small VLM)

### 6-1. 왜 경량화가 필요한가

VLM은 언어 모델보다 비전 컴포넌트가 추가되어 더 크다. GPU 서버가 필수이고 비용이 매우 크다. GPU 좋은 것 한 장이 1,000~1,500만원이고, 파운데이션 모델 학습에는 8장 이상 × 서버 여러 대가 필요(서버 1대 1~4억). GPT-3 학습 전기세만 약 40억원이었다.

### 6-2. 모델 크기 기준

현재 기준으로 **10B 이하**면 작은 편, 2~4B이면 확실히 작다. Small LLM → Small VLM으로 발전 중.

### 6-3. 대표적 Small VLM

**SmallVLM(Hugging Face)**: SigLIP 비전 인코더 + LLaMA 1.7B. 이미지 1장 입력 시 GPU RAM 5GB 수준. 특수한 인터페이스로 이미지 2장까지도 메모리를 작게 유지.

**MoonDream(0.5B)**: 8비트 양자화 시 모델 크기 약 400MB, 실행 메모리도 유사. 스마트폰 탑재 가능. 물체 탐지, 포인팅(XY 좌표), 시선 방향 판단, 문서 읽기 등 지원.

**양자화(Quantization)**: 모델 파라미터의 실수 표현 정밀도(32비트 → 8비트, 4비트)를 낮춰 메모리를 줄이는 기술. 파일 크기, 메모리, 실행 속도가 개선되지만 정확도/출력 품질이 감소한다.

**Gemini Nano**: 구글의 온디바이스용 경량 모델(2~3B). 픽셀/갤럭시 스마트폰에 탑재. 실시간 이미지·비디오 인식, 대화 기능.

### 6-4. 한국어 VLM의 필요성

**토큰화 문제**: 영어 중심 토크나이저에서 한국어는 같은 내용을 표현하는데 토큰이 훨씬 많이 필요하다. "이번 방학 때 뭐해?"가 영어 최적화 토크나이저에서는 13개 토큰, 자소 단위면 더 많다. 서브워드 단위로 최적화하면 8개로 줄일 수 있다. 토큰이 많으면 컨텍스트 윈도우를 많이 차지하고, API 비용도 증가하고, 성능도 떨어진다.

네이버 HyperCLOVA X, 카카오, 업스테이지 SOLAR 등이 한국어 파운데이션 모델을 개발하고 있다.

### 6-5. 모델 서빙과 배포

**LMDeploy**: LLM/VLM의 효율적 압축·배포·서빙 오픈소스 툴킷. REST API로 외부에서 호출 가능. InternVL, Qwen, DeepSeek, Phi 등 다양한 모델 지원. **Gradio**: Hugging Face 연동 웹 인터페이스. 파이썬 몇 줄로 인터랙티브 웹 앱 배포 가능.

## 7. 기타 이미지 파운데이션 모델

### 7-1. SAM (Segment Anything Model)

Meta가 10억 개 마스크 + 1,100만 이미지로 학습하여 공개한 세그멘테이션 파운데이션 모델. 클릭, 박스, 부분 세그먼트, 텍스트 등 다양한 입력으로 세그멘테이션 수행. SAM2부터 비디오 트래킹도 지원.

### 7-2. Set of Mark (SoM) — VLM의 안경

VLM의 시각 능력은 전체적인 내용을 러프하게 이해하는 데는 좋지만, 세밀한 공간 이해(왼쪽/오른쪽 구분 등)에는 약하다. SoM은 세그멘테이션 모델로 물체를 분리한 뒤 번호를 붙여서 VLM에 입력하면 성능이 크게 향상되는 트릭이다. 컴퓨터 유즈 에이전트에서 버튼을 찾는 데도 유용하다.

### 7-3. Grounding DINO & Grounded SAM

텍스트로 물체를 탐지하는 파운데이션 모델. "달리는 소녀"를 입력하면 달리는 소녀만 탐지. Grounding DINO + SAM = Grounded SAM으로 인스턴스 탐지+세그멘테이션을 동시에 수행.

### 7-4. 이미지 생성 모델

- **DALL-E**: OpenAI. ChatGPT에 통합. 클로즈드 소스
- **Midjourney**: 아티스틱 스타일에 강점. 미술 대회 대상 수상 이력. 클로즈드 소스
- **Stable Diffusion**: Stability AI. **오픈소스/오픈웨이트**. Diffusion 기반
- **Flux2**: 오픈소스. 브랜드 가이드라인, 조명, 레이아웃, 로고, 복잡한 텍스트 생성에 강점
- **ControlNet**: Stable Diffusion을 파인튜닝하여 스케치/엣지/포즈/세그멘테이션맵 등 다양한 조건 입력 지원. 커뮤니티에서 활발히 버전 공유

### 7-5. 생성 모델의 3D 응용

이미지 생성 모델이 원근감 등 물리적 지식을 이해하고 있다는 가정하에, 생성 모델을 파인튜닝하여 **깊이맵(Depth) 추정**(Marigold), **2.5D 이미지 조인트 생성**, **노블뷰 생성**(카메라 궤적 입력 → 새로운 시점 이미지 생성) 등에 활용. Depth Anything 3 등 3D 파운데이션 모델도 등장.

### 7-6. Sapiens — 사람 중심 파운데이션 모델

Meta가 2024년 공개. 2D 포즈 추정, 신체 부위 세그멘테이션, 깊이 추정, 법선 벡터 예측. 진정한 의미는 사람의 행동·자세를 **객관적으로 자동 측정**할 수 있는 도구가 되었다는 것. 기존 사회과학의 주관적 설문 방식을 과학적으로 만들어주는 객관화 도구.

### 7-7. 비디오 생성과 월드 모델

**Sora(OpenAI)**: 텍스트 → 비디오 생성. 물리적으로 그럴듯한 영상이 생성되어 3D 복원까지 가능할 정도. 이를 보고 **월드 모델(World Model)** — 물리 세계를 시뮬레이션하는 모델 — 로서의 가능성을 인식. 로봇 분야에서 태스크 플래닝(언어모델) → 시뮬레이션(비디오 생성) → 액션 플래닝(모터 제어) 구도로 활용.

**Veo3(Google)**: 소리 싱크까지 맞는 비디오 생성. 실제와 구분 불가 수준. 딥페이크 경각심 필요.

## 8. 개인화와 파인튜닝

### 8-1. 파인튜닝의 필요성

파운데이션 모델이 범용적이라 해도, 특정 도메인(위성사진, 의료영상, 제조불량 등)에서는 바로 적용이 어려운 경우가 많다. 적은 데이터와 리소스로 도메인에 최적화하는 것이 파인튜닝이다.

> **교수님 강조**: AI 리터러시(활용 능력)는 누구나 갖춰야 하고, 차별화를 위해서는 리터러시 플러스 플러스 — AI를 내 입맛대로 변경하여 사용하는 능력 — 가 필요하다. 그 마지막 퍼즐 조각이 AI 개인화 능력이다.

### 8-2. 파인튜닝의 핵심: 학습률(Learning Rate)

파인튜닝은 기존 학습 코드와 동일하되, 데이터를 적게 사용하고 **학습률을 작게** 설정한다. 이미 좋은 출발점에서 시작했기 때문에, 학습률이 크면 기존에 학습된 지식을 덮어버린다. 보수적으로 시작해야 한다.

그래디언트 디센트에는 두 가지가 필요: (1) **방향**(기울기, 백프로파게이션으로 구함), (2) **크기**(학습률). 학습률이 너무 크면 발산(점프만 반복), 너무 작으면 로컬 미니마에 갇힌다. 적절한 값은 실험을 통해 찾아야 한다.

### 8-3. 프롬프트 디자인 vs 프롬프트 튜닝 vs 파인튜닝

**프롬프트 디자인**: 모델 고정. 사람이 설계한 프롬프트(퓨샷 예제 등)를 입력. 추가학습 없음. 컨텍스트 윈도우 제한으로 예제를 무한정 넣을 수 없다.

**프롬프트 튜닝**: 모델 고정. **학습 가능한 가상 토큰**을 입력 앞에 추가하고, 이 토큰의 임베딩만 백프로파게이션으로 학습. 사람의 디자인 없이 자동으로 최적 프롬프트를 찾는다. 해석은 불가능(그냥 숫자열). 매우 적은 파라미터로 개인화 가능. 모델 지식 손상 없음.

**파인튜닝**: 모델 파라미터 전체(또는 일부)를 업데이트. 융통성과 성능이 가장 높지만 데이터와 리소스가 더 필요하고 기존 지식 손상 위험.

관계: 왼쪽(프롬프트 디자인)으로 갈수록 **효율적이지만 융통성 낮음**, 오른쪽(파인튜닝)으로 갈수록 **성능 좋지만 비용 높음**. 프롬프트 튜닝은 딱 중간.

### 8-4. LoRA (Low-Rank Adaptation)

모델 전체를 파인튜닝하면 비용이 감당 안 되므로, 기존 레이어 옆에 **학습 가능한 작은 파라미터(어댑터)**만 접붙여서 그것만 학습하는 방법이다. 기존 파라미터는 고정하여 지식 손상이 없고, 프롬프트 튜닝보다 더 많은 부분을 건드려 융통성이 좋다. **성능도 높고 효율도 좋은 두 마리 토끼**를 잡는 방법이다.

### 8-5. DreamBooth — 개인화 사례

이미지 생성 모델을 **내 강아지/내 얼굴**에 맞게 개인화하는 방법. 3~5장의 사진만으로 학습 가능한 토큰(프롬프트 튜닝) + 모델 파인튜닝을 결합하여, "V dog in the Acropolis" 같은 프롬프트로 내 강아지 전용 이미지를 생성.

## 9. 합성 데이터 활용

### 9-1. 지식 증류(Knowledge Distillation)

큰 선생님 모델이 입력에 대한 출력(소프트 레이블)을 생성하면, 이를 정답처럼 사용하여 작은 학생 모델을 학습시키는 방법. 합성 데이터의 일종이다. 장점: 입력 데이터만 마련하면 되므로 레이블링 비용이 없고, 선생님과 학생의 **모델 구조가 달라도** 된다(파인튜닝은 동일 구조 필요).

### 9-2. InstructPix2Pix — GPT로 학습 데이터 생성

이미지 편집 모델을 학습하려면 (편집 전 이미지, 명령어, 편집 후 이미지)의 트리플릿이 필요하지만, 이런 데이터는 존재하지 않았다.

해결 과정:
1. 기존 이미지-캡션 데이터에서 캡션을 가져옴
2. GPT를 700개의 사람 작성 예제로 파인튜닝하여 "캡션이 주어지면 편집 명령어와 편집된 캡션을 자동 생성"하도록 학습
3. 편집 전 캡션 + 편집 후 캡션을 Stable Diffusion + Prompt-to-Prompt에 넣어 이미지 쌍을 합성
4. 최종적으로 (원본 이미지, 명령어, 편집된 이미지)의 합성 데이터 트리플릿을 대량 생성
5. 이 합성 데이터로 명령어 기반 이미지 편집 모델 학습

### 9-3. 시뮬레이션 기반 합성 데이터

단순한 이미지 프로세싱이나 시뮬레이션으로 합성 데이터를 만드는 방법. 세그멘테이션 마스크된 물체를 배경에 붙여넣어(Copy & Paste) 비디오를 만들거나, 실제 수집 불가능한 데이터(모션 증폭 비디오, 로봇 학습 데이터 등)를 대체. NVIDIA가 로봇 학습을 위해 비디오 생성 모델로 합성 데이터를 만드는 사례도 있다.

### 9-4. 합성 데이터 유의사항

- 레이블 품질 불일치: VLM/LLM 기반 레이블러가 일관적 기준으로 생성하지 않는 경우
- 레이블 정교화, 클래스 사전 검토, 교차 모델 검증, 휴먼 검수 필요
- 할루시네이션: 실제 존재하지 않는 것을 생성하므로 정교한 프롬프트/후처리/검증/실 데이터 병용 필요
- 합성 데이터로 학습 → 합성 데이터 생성 → 반복하면 성능이 떨어질 수 있음 (태스크에 따라 다름)

## 10. 파운데이션 모델의 미래 방향

언어 모델에 눈(비전)·귀(오디오)를 달아주는 멀티모달 확장이 진행 중이다. 비디오 생성 모델(Sora 등)이 **월드 모델**로서 상상력을 제공하고, 언어 모델에 **도구 사용 능력**(검색 엔진, API, 컴퓨터 유즈)을 부여하여 세상과 인터랙션하는 **에이전트**로 발전하고 있다. 멀티 에이전트 시스템(연구 자동화, 업무 자동화)으로도 확장 중이다.

> **교수님 강조**: 유용한 파운데이션 모델이 정말 많다. 다운로드해서 써보는 것만으로도 재밌다. 본인만의 파운데이션 모델 리스트를 만들어놓고 적재적소에 활용하는 것이 경쟁력이다.

| Qwen-VL | 알리바바 공개. 다중 이미지/다국어/물체 탐지/옴니모델. 산업계 기술 기반 점령 |
| InternVL | 다이나믹 해상도 특화. 다양한 크기 모델 공개 |
| VLM 입력 주의 | 모델 학습 해상도를 확인하고 적절히 입력. 고해상도를 무작정 축소하면 성능 급감 |
| Small VLM | 10B 이하. SmallVLM(5GB), MoonDream(400MB). 양자화로 스마트폰 탑재 가능 |
| 한국어 토큰 문제 | 영어 중심 토크나이저에서 한국어는 토큰 효율 낮음. 한국어 서브워드 최적화 필요 |
| SAM | 세그멘테이션 파운데이션 모델. 10억 마스크 학습. 클릭/박스/텍스트 입력 |
| Set of Mark | 세그멘테이션 후 번호 붙여 VLM에 입력. VLM의 안경 역할. 성능 크게 향상 |
| Grounded SAM | Grounding DINO(텍스트 기반 탐지) + SAM. 인스턴스 탐지+세그멘테이션 동시 수행 |
| 이미지 생성 | Stable Diffusion(오픈소스), Flux2(오픈소스), DALL-E/Midjourney(클로즈드) |
| ControlNet | 생성 모델 파인튜닝으로 스케치/엣지/포즈 등 다양한 조건 입력 지원 |
| 월드 모델 | 비디오 생성 모델이 물리 세계를 시뮬레이션하는 시뮬레이터로 활용. 로봇 분야에 핵심 |
| Sapiens | 사람 중심 파운데이션 모델. 자세/세그멘테이션/깊이 추정. 객관적 측정 도구 |
| 파인튜닝 | 사전학습 모델을 작은 학습률로 소량 데이터 추가 학습. 좋은 출발점에서 보수적으로 시작 |
| 프롬프트 튜닝 | 학습 가능한 가상 토큰을 입력에 추가, 모델 고정. 효율적 개인화. 해석 불가능한 숫자열 |
| LoRA | 기존 레이어 옆에 작은 어댑터만 학습. 지식 손상 없고 성능·효율 모두 우수 |
| DreamBooth | 프롬프트 튜닝 + 파인튜닝 결합. 3~5장으로 개인화 이미지 생성 모델 구축 |
| 지식 증류 | 큰 모델의 출력을 정답으로 작은 모델 학습. 모델 구조 달라도 가능. 합성 데이터 활용 |
| 합성 데이터 | GPT로 질문/명령어 생성, 생성 모델로 이미지 쌍 합성, 시뮬레이션 기반 생성. 레이블 품질 검수 필수 |
| 파운데이션 모델 미래 | 멀티모달(눈·귀·입) → 도구 사용(검색·API) → 에이전트 → 멀티 에이전트. Physical AI로 확장 |
