# [데이터 기초] 실시간 Open API

---

## 1. 실시간 API란?

앞서 다룬 공공데이터 포털 API는 요청 시점에 **이미 적재되어 있는 정적인 데이터**를 조회하는 형태였다. 반면 **실시간 API**는 필요할 때마다 조회하는 게 아니라, **계속 업데이트되는 데이터**(예: 주식 가격)를 지속적으로 가져오는 데 사용한다.

---

## 2. 실시간 데이터 통신 방식 3가지

| 방식 | 동작 방식 | 특징 | 활용 예시 |
|---|---|---|---|
| **웹소켓(WebSocket)** | 클라이언트-서버 간 **양방향** 연결을 계속 유지 | 요청-응답 구조가 아니라 연결 자체를 유지하며 실시간으로 데이터 흐름 | 채팅 서비스 |
| **폴링(Polling)** | 클라이언트가 **주기적으로** 서버에 요청을 보내 상태를 확인 | 이벤트를 받는 구조가 아니라 우리가 반복적으로 호출해서 확인하는 구조 | 날씨 데이터 등 오픈 API |
| **웹훅(Webhook)** | 서버에서 **이벤트가 발생하면** 클라이언트에게 알려줌 (요청의 반대 방향) | Push 방식 — 클라이언트가 요청하지 않아도 서버가 먼저 알림 | 결제 완료 알림, 주문 상태 변경 알림 |

웹소켓과 웹훅은 실제로 소켓 통신처럼 양방향 채널을 열어야 하는 경우가 많아 구현 난이도가 높고, 무료로 쉽게 접할 수 있는 공개 API로 제공되는 경우는 많지 않다. 이 강의에서는 접근이 쉬운 **폴링 방식**을 중심으로 다룬다.

---

## 3. 폴링 방식 실습 — Open-Meteo 날씨 API

**Open-Meteo**는 무료로 제공되는 날씨 Open API다. 날씨처럼 계속 값이 바뀌는 데이터를 주기적으로 가져오는 예시로 활용한다.

```python
import requests
import time

url = "https://api.open-meteo.com/v1/forecast"
params = {
    "latitude": 36.3553,     # 위도
    "longitude": 127.2983,   # 경도
    "current": "temperature_2m",  # 현재 온도
}

def get_current_temperature():
    response = requests.get(url, params=params)
    data = response.json()
    return data["current"]["temperature_2m"]

# 폴링: 60초 간격으로 반복 조회
while True:
    temp = get_current_temperature()
    print(f"현재 온도: {temp}°C")
    time.sleep(60)
```

- 위도(latitude)·경도(longitude)로 위치를 지정하고, 원하는 항목(여기서는 현재 온도)을 파라미터로 요청
- 요청을 보내는 함수를 하나 작성해두고, 일정 시간 간격마다 반복 호출하는 것이 폴링 구조의 핵심
- 실습 중 실제로 온도가 29.6°C → 31°C대로 상승하는 것을 폴링을 통해 확인할 수 있었음

---

## 4. 폴링 주기 설정 시 고려사항

폴링 간격을 무조건 짧게 잡는다고 좋은 것은 아니다. **실제 데이터가 업데이트되는 주기**를 고려해서 폴링 간격을 정해야 한다.

> 예: Open-Meteo의 실측 데이터가 5~15분 간격으로만 갱신된다면, 1분 간격으로 조회하는 것은 불필요한 요청이다. 서비스에 필요한 수준(예: 1~10분 단위)으로 폴링 주기를 맞추는 것이 효율적이다.

- 서버에 불필요하게 잦은 요청을 보내면 리소스 낭비이자 서버 부담으로 이어질 수 있음
- 진짜 양방향 실시간 통신(채팅, 실시간 알림 등)이 필요하다면 웹소켓·웹훅 방식의 적용도 고려해야 함

## 💡 한 줄 요약
> 실시간 API는 계속 변하는 데이터를 다루기 위한 것으로, 웹소켓·폴링·웹훅 중 접근이 쉬운 폴링 방식을 활용해 실제 데이터 갱신 주기에 맞는 간격으로 주기적 요청을 보내 최신 상태를 확보하는 방법이다.
