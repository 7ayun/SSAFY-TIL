# [데이터 사이언스] 머신러닝 실험 환경

---

## 1. 머신러닝 실험이란?

머신러닝 실험은 모델의 성능을 개선하거나 다양한 설정(데이터, 알고리즘, 하이퍼파라미터)을 비교·분석하기 위해 **반복적으로 수행하는 과정 중심의 활동**이다.

> "어떤 데이터를 써서, 어떤 알고리즘에, 어떤 하이퍼파라미터를 적용했더니, 어떤 결과가 나왔는지"를 체계적으로 비교하는 작업

단순히 하나의 결과만 보는 것이 아니라, 그 결과를 만들어낸 조건들(데이터, 알고리즘, 하이퍼파라미터)을 요소요소 기록하고 비교하는 것이 핵심이다.

## 2. 머신러닝 실험 파이프라인

실험은 아래와 같은 흐름을 반복적으로 거치게 된다.

```
raw 데이터 → 전처리된 데이터 → 실험 설계 → 모델 학습
     ↑                                          |
     └──────────────── 전체 과정 반복 ───────────┘
```

- **raw 데이터 수집**: 다양한 경로로 원시 데이터를 확보
- **데이터 전처리**: 학습에 필요한 형태로 가공
- **실험 설계**: 데이터셋 분할(train/validation/test), 사용할 모델, 파라미터 반복 방식 등을 설계
- **모델 학습**: 설계한 대로 모델을 학습시키고, 이 과정을 주기적으로 반복

이 반복 과정 자체가 머신러닝 실험이며, 한두 번으로 끝나지 않기 때문에 체계적인 관리가 필요하다.

## 3. 실험이 중요한 이유 — 성능을 좌우하는 요소들

머신러닝에는 하나의 정답이 존재하지 않는다. 어떤 조건을 주느냐에 따라 성능이 달라지고, 학습 데이터 기준으로 좋았던 성능이 실제 서비스에서도 항상 좋게 나온다는 보장이 없다. 시간이 지나 데이터 분포가 달라지면 재학습이 필요해지는 것도 같은 맥락이다.

성능에 영향을 주는 대표적인 요소는 다음과 같다.

| 요소 | 설명 |
|---|---|
| 데이터셋 / 전처리 | 동일한 데이터라도 전처리 방식(이상치·결측치 처리, 피처 선택 등)만 바뀌어도 결과가 크게 달라질 수 있음 |
| 모델 구조 | 같은 데이터라도 단순 회귀 모델을 쓸지, 복잡한 딥러닝 모델을 쓸지에 따라 성능이 달라짐 |
| 하이퍼파라미터 | 학습률, 에폭, 정규화 강도 등 모델·태스크마다 다르게 작용 |
| 성능 지표 | 예: 클래스 불균형 상황에서는 accuracy만으로 좋은 모델을 판단하기 어려움 (다수 클래스만 예측해도 99% accuracy가 나올 수 있음) |

이처럼 한 번의 학습으로 끝나는 것이 아니라, 다양한 조건을 실험하고 비교·분석하는 과정이 반드시 필요하다.

## 4. 반복 실험에서 발생하는 문제점

체계적인 도구 없이 반복 실험을 진행하면 다음과 같은 문제가 발생하기 쉽다.

- **기록의 어려움**: 엑셀·메모장·노션 등에 결과만 간단히 남기면, 나중에 "이 실험이 어떤 설정이었지?"를 알기 어려움
- **중복 실험**: 이미 했던 실험을 실수로 다시 진행하며 시간·자원을 낭비
- **재현성 문제**: 환경, 전처리 방식, 시드, 하이퍼파라미터가 기록되지 않으면 좋은 성능이 나왔던 실험을 다시 재현할 수 없음 → 서비스 신뢰도 저하, QA/테스트 단계에서 재현이 안 되면 배포 자체가 어려워짐
- **버전 관리 문제**: `train.py`, `train2.py`, `train_final.py`처럼 파일명을 바꿔가며 관리하다 보면 어떤 코드가 어떤 결과를 냈는지 헷갈림. 코드뿐 아니라 데이터셋, 모델까지 함께 버전 관리가 필요
- **협업 문제**: 결과를 구두나 메신저 스크린샷으로만 공유하면 세부 조건이 남지 않아 동료가 이어서 작업하기 어려움
- **리소스 낭비**: 같은 실험을 중복 수행하면 특히 클라우드 GPU 등 비용이 드는 환경에서 불필요한 비용 발생
- **성과 비교의 어려움**: 여러 모델을 실험했는데 비교 테이블이 없으면 어떤 모델이 우수한지 한눈에 판단하기 어려움
- **튜닝 결과가 축적되지 않음**: 장기적으로 성능을 쌓아 올리기 위해서는 실험 이력이 누적 관리되어야 함

## 5. 실험 관리 도구가 필요한 이유

위와 같은 문제들을 해결하려면 실험마다 사용된 코드, 데이터, 하이퍼파라미터, 성능 지표 등을 **자동으로 기록**하고, 실험 결과를 쉽게 **비교할 수 있는 인터페이스**가 필요하다.

이때 핵심 요구사항은 단순 로깅을 넘어서는 두 가지다.

1. **재현 가능성**: 어떤 환경에서든 동일하게 재현되어 실행될 수 있어야 함
2. **서빙까지의 연결**: 기록 → 관리 → 서빙까지 전 과정을 지원해야 함

이 전반적인 흐름을 통합적으로 지원해주는 도구가 바로 **MLflow**이다. MLflow의 사용법 자체보다, 실험 관리가 왜 필요한지에 대한 전반적인 흐름을 이해하는 것이 더 중요하다.
