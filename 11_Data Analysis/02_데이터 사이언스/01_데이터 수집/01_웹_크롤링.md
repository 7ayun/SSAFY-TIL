# [데이터 기초] 웹 크롤링

---

## 1. 웹 크롤링이란?

**웹 크롤링(Web Crawling)** = Web(거미줄) + Crawling(기어다니다). 인터넷 상의 웹 페이지를 자동으로 탐색하면서 데이터를 수집하는 기술이다.

**특징 3가지**
- **자동화**: 사람이 하나하나 확인하지 않고 프로그램이 대신 처리
- **대량 데이터 수집**: 한 페이지가 아니라 여러 페이지를 타고 들어가며 수집
- **구조화된 데이터 추출**: 웹 페이지가 HTML이라는 구조화된 문서로 이루어져 있기 때문에 가능한 작업

### 크롤링 vs 스크래핑

용어를 좀 더 정확히 구분하면 다음과 같다.

| 구분 | 의미 | 예시 |
|---|---|---|
| **크롤링(Crawling)** | 웹 페이지를 자동으로 **탐색**하면서 데이터를 수집 (어디로 이동할지가 핵심) | 구글 검색봇이 사이트를 옮겨 다니며 페이지 연결 관계를 수집 |
| **스크래핑(Scraping)** | 특정 페이지 **안에서** 원하는 데이터를 뽑아오는 것 | 특정 사이트 하나에서 필요한 정보만 추출 |

실무에서는 둘을 크게 구분하지 않고 '크롤링'이라 부르는 경우가 많지만, 크롤링이 "돌아다니는 것"이라면 스크래핑은 "그 안에서 뽑아오는 것"이라는 차이가 있다.

## 2. 웹 데이터 수집 방법 3가지

| 방법 | 설명 | 사용 라이브러리 |
|---|---|---|
| 웹 페이지를 가져와서 필요한 정보만 추출 (스크래핑) | 정적 페이지의 HTML을 받아서 파싱 | BeautifulSoup |
| WebDriver로 웹 브라우저 자동화 | 로그인, 클릭, 드롭다운 선택 등 **동적 상호작용**이 필요한 경우 | Selenium |
| 제공된 Open API를 이용해 실시간으로 데이터 가져오기 | 기관/서비스가 정형화된 형태로 열어둔 데이터를 요청 | requests 등 |

**왜 3가지가 필요한가?** 정적 페이지는 URL만 접속해도 필요한 HTML을 그대로 받아올 수 있지만, 실제 서비스 대부분은 자바스크립트로 화면을 그리는 동적 페이지라서 HTML을 받아오는 것만으로는 한계가 있다. 이럴 때는 브라우저 자체를 직접 조작해 데이터를 가져와야 한다. 웹 드라이버는 크롤링뿐 아니라 게시판 자동 글쓰기, 이메일 자동 발송 같은 업무 자동화에도 활용할 수 있다.

**웹 크롤링이 필요한 상황 예시**: 편의점 사이트에서 상품명·가격 등을 정리해야 하는데, 상품 페이지가 수십 페이지에 달할 때 — 이를 수기로 정리하는 대신 크롤링으로 자동 수집한다.

## 3. 웹 페이지의 구조 — HTML, CSS, JavaScript

웹 페이지는 세 가지 기술의 조합으로 구성된다.

| 기술 | 역할 |
|---|---|
| **HTML** (HyperText Markup Language) | 제목·단락·목록 등 **구조적 의미**를 나타내는 필수 언어 (뼈대) |
| **CSS** (Cascading Style Sheets) | HTML 요소의 **외관을 디자인** (인테리어) |
| **JavaScript** | 동적 동작 처리 |

> 비유하자면 HTML은 건물의 철골 구조(뼈대), CSS는 완성된 인테리어(디자인)에 해당한다.

크롤링을 통해 얻고자 하는 데이터는 결국 HTML 어딘가에 들어 있기 때문에, 원하는 정보가 HTML의 어디에 위치하는지 파악하는 것이 중요하다. 데이터를 뽑아내 원하는 형태로 가공하는 작업을 **파싱(Parsing)**이라 한다.

### HTML 기본 구성 요소

```html
<p align="center">Hello, HTML!</p>
```

| 용어 | 의미 |
|---|---|
| Opening Tag / Closing Tag | `<p>` / `</p>` — 시작 태그와 종료 태그 |
| Content(내용) | 태그 사이에 들어가는 실제 내용 |
| Element(요소) | 태그를 포함한 전체 (여는 태그 + 내용 + 닫는 태그) |
| Attribute(속성) | 요소에 부가 정보를 담을 때 사용 (예: `align="center"` → 가운데 정렬). 여러 개 부여 가능하며, 없어도 무방 |

### HTML 전체 구조

```html
<html>
  <head>
    <title>Test홈페이지</title>
  </head>
  <body>
    환영합니다
  </body>
</html>
```

- `<html>`: 문서가 HTML임을 명시
- `<head>`: 문서 서문의 시작과 끝 (브라우저 탭에 뜨는 제목 등)
- `<body>`: 실제 화면에 보이는 본문의 시작과 끝
- 크롤링 대상 데이터 대부분은 `<body>` 하위에 중첩 구조로 존재

자주 쓰이는 속성으로는 `id`, `class`, 하이퍼링크 관련 속성, `src` 등이 있다.

## 4. CSS 셀렉터 문법

크롤링에서 CSS 자체는 디자인 목적이 아니라, **원하는 요소를 정확히 짚어내는 용도**로 셀렉터 문법만 빌려 쓴다.

```css
선택자 {
  속성: 속성값;
}
```

| 선택자 종류 | 표기 | 설명 | 예시 |
|---|---|---|---|
| **타입 선택자** | 태그명 | 해당 태그를 가진 **모든** 요소 선택 | `p` → 모든 `<p>` 태그 |
| **아이디 선택자** | `#id` | 문서 내 **유일한** 요소 선택 | `#item` |
| **클래스 선택자** | `.class` | 같은 class를 가진 **여러** 요소 선택 (중복 가능) | `.item` |
| **자식 선택자** | `상위 > 하위` | 상위 요소의 **직계 자식**만 선택 | `body > p` |
| **가상 클래스 선택자** | `:nth-child(n)` | 특정 순서(몇 번째)에 해당하는 요소만 선택 | `ul > li:nth-child(3)` |

- 아이디는 문서 내에서 유일하지만, 클래스는 여러 요소에 반복적으로 적용될 수 있다.
- 자식 선택자는 직접적인 자식 요소만 선택하며, 손자 요소 등 더 깊은 하위 요소는 포함하지 않는다.
- 가상 클래스 선택자는 아이디도 클래스도 없이 순서만으로 특정 요소를 지정하고 싶을 때(예: 표나 목록의 특정 번째 항목) 유용하다.

## 5. robots.txt

웹사이트 소유자가 검색 엔진 크롤러 등에게 **어떤 경로를 수집해도 되는지/안 되는지** 알려주는 표준 텍스트 파일. 사이트 최상위 URL(`/robots.txt`)에 위치한다.

```
User-agent: *
Disallow: /private/
Allow: /public/
```

| 항목 | 의미 |
|---|---|
| User-agent | 규칙이 적용되는 크롤러 이름 (예: 특정 봇 이름, 또는 `*`로 전체 지정) |
| Disallow | 수집을 허용하지 않는 경로 |
| Allow | 수집을 허용하는 경로 |

**주의할 점**: robots.txt는 **권고 규칙**일 뿐 법적 강제력이나 기술적 차단 효과는 없다. 대형 서비스의 크롤러는 대체로 이를 준수하지만, 개인이 만든 크롤러나 악의적인 크롤러는 무시하고 수집할 수도 있다. 실제로 접근을 막고 싶다면 캡차(CAPTCHA) 같은 기술적 차단을 별도로 구현해야 한다. 또한 과도한 요청은 서버에 부담을 줘 디도스(DDoS) 공격과 유사한 문제를 일으킬 수 있으므로, 무분별한 수집은 지양해야 한다.
