# [데이터 엔지니어링] 워크플로우 오케스트레이션

---

## 1. 지금까지 다룬 파이프라인 기술과 에어플로우의 위치

카프카(Kafka)는 데이터를 수집하고 빠르게 전달하는 역할, 스파크(Spark)는 그 데이터를 배치·스트리밍 방식으로 처리·분석하는 역할을 담당했다. 하지만 이런 파이프라인은 결국 여러 개의 **작업 단위**로 이루어져 있고, "이 작업이 끝나면 저 작업을 실행해라", "이 작업이 실패하면 이렇게 처리해라"와 같은 흐름을 매번 사람이 수동으로 처리할 수는 없다.

이렇게 여러 작업을 정해진 순서대로, 자동으로 실행되도록 관리해주는 도구가 **Apache Airflow**다. Airflow는 데이터 자체를 처리하는 엔진이 아니라, 데이터 처리 과정을 작업 단위로 쪼개서 이 작업들이 잘 흘러가도록(오케스트레이션) 관리해주는 도구라는 점을 우선 이해하고 가는 것이 중요하다.

## 2. 워크플로우 오케스트레이션이란?

데이터 파이프라인은 규모가 커질수록 처리해야 할 작업이 많아지고 복잡해진다. 이 작업들을 매번 수동으로 순서에 맞게 실행시킬 수 없기 때문에, **여러 작업을 정해진 순서·조건에 따라 자동으로 실행되도록 관리하는 기술**을 워크플로우 오케스트레이션이라고 한다.

예를 들어 데이터를 수집 → 전처리 → 저장 → 분석하는 흐름이 있을 때, 이 순서를 정의해두고 하루 단위·일주일 단위처럼 특정 주기로 자동 실행되게 만드는 것이 워크플로우 오케스트레이션의 역할이다. 데이터 파이프라인뿐 아니라 머신러닝 파이프라인, CI/CD의 배포 과정처럼 자동으로 처리되어야 하는 다양한 분야에서 활용된다.

### 워크플로우 오케스트레이션의 핵심 특징

| 특징 | 설명 |
|---|---|
| 작업 자동화 | 반복적인 수작업을 제거하고 자동으로 실행되게 함 |
| 의존성 관리 | 특정 작업이 완료된 이후에만 다음 작업이 실행되도록 함 |
| 실패 처리 및 모니터링 | 중간에 장애가 발생하면 재시도를 하고, 그래도 실패하면 알림을 보내는 등 트리거로 처리됨 |
| 스케줄링 | 특정 시간(예: 매일 새벽 1시)이나 특정 이벤트(예: 파일 업로드)를 기준으로 실행 시점을 지정 |

이런 시스템 중에서도 가장 표준처럼 쓰이는 오픈소스 도구가 **Apache Airflow**다. 루이지(Luigi), 대그스터(Dagster) 같은 대안 도구도 있지만, Airflow는 커뮤니티·생태계가 잘 갖춰져 있고 다양한 회사에서 널리 사용하고 있으며 확장성도 좋은 것으로 알려져 있다.

## 3. Apache Airflow란?

> **Python 기반의 데이터 파이프라인 자동화 및 스케줄링 도구**

- 작업을 언제, 어떤 순서로 실행할지를 **Python 코드**로 정의해두면, Airflow 시스템이 그 코드를 읽고 스케줄에 맞게 실행을 관리해준다.
- **배치 프로세스를 효율적으로 관리하는 워크플로우 오케스트레이션 도구**다. 예를 들어 "매일 새벽 1시에 실행되어 후속 작업들이 이어지게 만든다"는 흐름 자체가 하나의 배치 프로세스를 처리하는 단위가 된다.
- **다양한 시스템·데이터베이스와 통합 가능**하다. 데이터를 수집·저장하려면 여러 저장소·시스템과의 커넥션이 필요한데, Airflow는 이런 연결을 정의하고 통합 관리하기에 용이하다. (예: Spark와 연결해 처리 결과를 주고받는 경우 등) ETL, MLOps, 클라우드 환경과의 연동을 지원한다.

결국 Airflow가 하는 가장 큰 역할은 **데이터 파이프라인을 자동화**하는 것이며, 이를 **DAG**라는 단위로 작업을 정리해서 규칙에 따라 반복 실행되도록 만든다. DAG는 방향성이 있고 순환하지 않는 그래프이기 때문에 의존성과 순서가 명확하게 보장되고, 실패 시에는 예외 태스크를 만들거나 지정한 횟수만큼 재시도하도록 설정할 수 있다. 이 모든 과정은 Airflow가 제공하는 웹 UI를 통해 시각적으로 모니터링·관리할 수 있다.

## 4. Why Airflow? — 기존 방식(Cron Job, Bash Script)의 한계

Airflow 이전에도 작업을 자동으로 실행시키는 방법은 존재했다. 리눅스/유닉스 계열 운영체제 자체에서 제공하는 **크론잡(Cron Job)**이나 **Bash(Shell) 스크립트**를 짜서 정해진 시간에 명령어가 자동 실행되도록 만드는 방식이다. 하지만 이 방식에는 다음과 같은 한계가 있다.

| 한계 | 설명 |
|---|---|
| 작업 간 의존성 관리 어려움 | 정해진 시간에 실행시키는 것은 가능하지만, "A 작업이 끝나야 B 작업이 실행된다" 같은 조건이 많아지고 복잡해지면 크론만으로 관리하기 어려워짐 |
| 장애 발생 시 원인 추적·복구 어려움 | 어떤 에러가 어디서 발생해서 실패했는지를 한눈에 파악하기 어려움 |
| 로그 관리 및 모니터링 부족 | 지금 어떤 작업이 정상적으로 돌아가고 있는지, 어디서 실패했는지 확인하기 어려움 |

이런 한계를 보완하기 위해 도입된 것이 Airflow이며, 다음과 같은 장점을 가진다.

- **DAG 기반 의존성 관리** → Task 실행 순서를 명확하게 설정 가능
- **Web UI 제공** → 작업 실행 상태를 시각적으로 직관적으로 모니터링 가능, 실패한 작업만 골라서 재실행 가능
- **재시도 및 알림 기능** → 장애 발생 시 자동으로 재시도하거나 알림
- **확장성 및 유연성** → 로컬 실행뿐 아니라 클라우드 클러스터 형태로도 확장 가능(워커를 여러 개 두는 등). 하나의 Airflow로 수십~수백 개의 DAG·Task를 관리하는 것은 부담이 크기 때문에, 실무에서는 클러스터 형태로 구성해서 운영하는 경우가 훨씬 일반적이다.

## 5. Apache Airflow의 주요 활용 사례

| 활용 사례 | 설명 |
|---|---|
| **Business Operations** | 기업의 데이터 중심 애플리케이션·업무 자동화. 예: 매일 아침 정기 리포트를 자동 생성해 임원에게 전달, 고객 데이터 파이프라인을 CRM과 연동 |
| **ETL / ELT** | 데이터 파이프라인 구축 및 관리. 여러 소스를 통합해 분석 가능하게 만들고, Data Warehouse(BigQuery, Snowflake 등)와 연계해 최적화 |
| **Infrastructure Management** | 클라우드 리소스 자동 프로비저닝(AWS, GCP, Azure 등), CI/CD 파이프라인 자동 실행, Kubernetes 및 서버 배포 자동화 |
| **MLOps** | 데이터 수집 → 모델 학습 → 평가 → 배포 과정 자동화, 머신러닝 워크플로우 오케스트레이션, 모델 재학습·모니터링 자동화 |

### ETL vs ELT 다시 보기

- **ETL(Extract-Transform-Load)**: 수집 → 변환 → 저장 순서. 목적이 명확한 데이터를 변환한 뒤 저장하기 때문에 구조화가 된 형태로 적재되며, 보통 **데이터 웨어하우스**로 저장되는 경우가 많다.
- **ELT(Extract-Load-Transform)**: 수집 → 저장 → 변환 순서. 아직 활용 목적을 특정하지 않은 상태에서 원천(raw) 데이터를 먼저 저장해두고 이후 필요한 형태로 변환한다. 구조화가 덜 된 원본에 가깝기 때문에 보통 **데이터 레이크** 관점으로 보는 것이 이해하기 편하다.

> 반드시 ELT = 레이크, ETL = 웨어하우스로 고정되는 것은 아니지만, 개념을 쉽게 이해할 때는 이렇게 구분해서 보는 것이 도움이 된다.

### Infrastructure Management와 MLOps에서의 Airflow

- **인프라 관리**: 클라우드는 쓸수록 비용이 발생하기 때문에, 필요한 리소스를 자동으로 프로비저닝(미리 필요한 자원·설정을 준비)하고 운영을 자동화해 비용을 원활하게 관리하는 것이 중요하다. 개발자가 코드를 푸시하면 Airflow를 통해 자동으로 빌드·테스트·배포하는 CI/CD 흐름도 구성할 수 있고, Kubernetes(컨테이너 단위 배포·오토스케일링 도구)를 통한 서버 배포 자동화에도 활용할 수 있다.
- **MLOps**: 데이터 수집 → 모델 학습 → 평가 → 배포라는 흐름 자체는 MLflow 같은 도구가 도와주지만, 이 흐름이 **자동으로 반복 실행**되게 만드는 것은 별개의 영역이며 이 부분을 Airflow가 담당한다. 전처리·피처 엔지니어링·하이퍼파라미터 튜닝 같은 단계를 Task로 쪼개 순차 또는 병렬로 처리되게 구성할 수 있고, 특정 조건(예: 모델 정확도가 90% 이하로 떨어짐)이 발생하면 재학습 사이클이 자동으로 트리거되게 만드는 것도 가능하다.

## 💡 한 줄 요약
> 워크플로우 오케스트레이션은 여러 작업을 정해진 순서·조건에 따라 자동 실행·관리하는 기술이며, Apache Airflow는 Python 기반으로 이를 구현하는 대표적인 도구로 Business Operations, ETL/ELT, Infra Management, MLOps 등 다양한 영역에서 활용된다.
