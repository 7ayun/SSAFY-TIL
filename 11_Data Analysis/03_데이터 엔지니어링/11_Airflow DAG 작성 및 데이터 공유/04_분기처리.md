## 1. BranchOperator란?

**BranchOperator**는 조건에 따라 DAG 실행 흐름을 분기할 수 있도록 하는 Operator다. 특정 조건을 평가해서 다음에 어떤 Task를 실행할지 **동적으로 선택**하게 해준다.

- Airflow에서 DAG 실행 흐름을 조건에 따라 분기할 수 있도록 하는 Operator
- 특정 조건을 평가하여 어떤 Task를 실행할지 동적으로 결정
- **선택되지 않은 Task는 자동으로 Skipped 상태가 됨**
- DAG 실행을 최적화하고 불필요한 작업을 줄이는 데 유용
- `BranchPythonOperator`: Python 함수를 사용하여 실행할 Task를 결정

예를 들어 사용자 입력값이 어떻게 오는지, 혹은 연동된 API의 응답이 어떤지에 따라 그 다음 실행해야 하는 로직 자체가 달라질 수 있다. 이럴 때 다음에 타고 갈 Task를 조건에 따라 갈라주는 역할을 BranchOperator가 담당한다.

## 2. 조건 기반 실행 흐름 (`BranchPythonOperator`)

조건 판단 로직을 Python 함수로 작성해두고, 그 함수가 **리턴하는 task_id**로 다음 Task가 결정되는 구조다.

```python
from airflow import DAG
from airflow.operators.python import BranchPythonOperator
from airflow.operators.bash import BashOperator
import pendulum

# 분기 조건 함수
def choose_branch(**kwargs):
    value = "A"  # 실행 조건 변경 가능
    return "task_A" if value == "A" else "task_B"

with DAG(
    dag_id="simple_branch_operator_example",
    start_date=pendulum.datetime(2024, 3, 1, tz="Asia/Seoul"),
    catchup=False,
) as dag:
    # 조건 기반 분기 Task
    branch_task = BranchPythonOperator(
        task_id="branching",
        python_callable=choose_branch,
    )

    # 선택될 Task A
    task_A = BashOperator(task_id="task_A", bash_command="echo 'Task A 실행'")

    # 선택될 Task B
    task_B = BashOperator(task_id="task_B", bash_command="echo 'Task B 실행'")

    # 공통 종료 Task (Trigger Rule 적용)
    end_task = BashOperator(
        task_id="end_task",
        bash_command="echo '모든 분기 완료'",
        trigger_rule="none_failed_or_skipped",
    )

    # DAG 실행 흐름
    branch_task >> [task_A, task_B]  # 하나만 실행됨
    [task_A, task_B] >> end_task     # 종료 Task는 항상 실행됨
```

- `choose_branch()` 함수가 `"task_A"`를 리턴하면 `task_A`는 정상 실행되고, 선택되지 않은 `task_B`는 자동으로 **Skipped** 처리된다. (`value`를 `"B"`로 바꾸면 반대로 동작)
- 공통 종료 Task(`end_task`)는 `trigger_rule="none_failed_or_skipped"`로 설정되어 있어, 분기 중 하나가 스킵되더라도(실패만 없다면) 정상적으로 실행된다. 기본값(`all_success`)을 그대로 두면 스킵된 Task 때문에 종료 Task가 실행되지 않는 문제가 생기므로 주의해야 한다.

## 3. API 응답값 기반으로 분기 처리하는 방식

API에서 받아오는 값은 우리가 직접 조절할 수 있는 값이 아니다. 계속 바뀌며 들어오는 응답 값에 따라 다음 Task를 다르게 실행해야 하는 경우, 예를 들어 **외부 API로 현재 기온을 가져와서 15도 이상이면 `task_hot`, 미만이면 `task_cold`를 실행**하는 식으로 분기 조건을 구성할 수 있다.

```python
from airflow.operators.bash import BashOperator
from airflow.operators.python import BranchPythonOperator, PythonOperator
import pendulum
import requests

# API 응답값을 확인하며 실행할 Task 결정하는 함수
def check_weather():
    response = requests.get(
        "https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.9780&current_weather=true"
    )
    data = response.json()

    # 현재 기온 가져오기
    temperature = data["current_weather"]["temperature"]
    print("현재 기온:", temperature, "도")

    if temperature >= 15:
        return "task_hot"
    else:
        return "task_cold"

# API 응답값을 출력하는 함수
def print_weather():
    response = requests.get(
        "https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.9780&current_weather=true"
    )
    data = response.json()
    temperature = data["current_weather"]["temperature"]
    print("현재 날씨 데이터:", data)
    print("현재 기온:", temperature, "도")

with DAG(
    dag_id="branch_operator_weather_api_logging_example",
    start_date=pendulum.datetime(2024, 3, 1, tz="Asia/Seoul"),
    catchup=False,
) as dag:
    # API 상태 확인 후 실행할 Task 선택
    branch_task = BranchPythonOperator(
        task_id="branching_weather_api",
        python_callable=check_weather,
    )

    # 15도 이상이면 실행될 Task
    task_hot = BashOperator(task_id="task_hot", bash_command="echo '오늘 날씨: 덥습니다'")

    # 15도 미만이면 실행될 Task
    task_cold = BashOperator(task_id="task_cold", bash_command="echo '오늘 날씨: 춥습니다'")

    # API 결과값을 출력하는 Task
    log_weather = PythonOperator(task_id="log_weather", python_callable=print_weather)
```

실행 결과 예시(기온 1.1도인 경우): `task_cold`는 **정상 수행**되고, `task_hot`은 **Skipped** 처리됨. 로그(`log_weather` Task)에서도 `현재 기온: 1.1 도`가 그대로 찍히는 것을 확인할 수 있다. 반대로 기온이 35도처럼 높으면 `task_hot`이 실행되고 `task_cold`가 스킵된다.

> 여기서는 조건 로직을 `echo`로 단순화했지만, 실제로는 이 분기 결과에 따라 서로 다른 후속 처리 로직(알림, 다른 API 호출 등)을 연결할 수 있다.

## 4. TaskGroup — Task를 논리적으로 묶어서 관리하기

DAG가 단순할 때는 Task 몇 개만으로 그래프를 보는 데 문제가 없지만, 파이프라인이 커지고 수집/전처리 Task가 잘게 쪼개질수록 한 화면에 너무 많은 Task가 나타나 관리가 어려워진다. 이때 관련된 Task들을 그룹 단위로 묶어 표현하면 가독성과 유지보수성이 향상된다.

### TaskGroup이란?
- DAG 내에서 여러 Task를 그룹화하여 논리적으로 관리하는 기능
- DAG의 복잡성을 줄이고, 비슷한 작업을 하나의 그룹으로 묶어 가독성 및 유지보수성 향상
- UI에서 그룹별로 Task를 시각적으로 확인 가능 (그래프 상에서 접었다 펼쳤다 할 수 있음)

`start → group_1 → end`처럼 그래프에서는 하나의 Task처럼 보이지만, `group_1`을 펼치면 그 안에 `task_1`, `inner_group_1`, `task_3`, `task_4` 등 여러 Task가 들어있는 구조를 확인할 수 있다. TaskGroup은 이렇게 여러 개의 Task를 묶는 것뿐 아니라, **그룹 안에 또 다른 그룹(중첩 구조)**을 넣는 것도 가능하다. 예를 들어 "Extract 단계"라는 그룹 안에 여러 개의 세부 추출 Task를 묶어서 관리하는 식으로 활용할 수 있다.

### TaskGroup 활용법

```python
from airflow import DAG
from airflow.operators.empty import EmptyOperator
from airflow.operators.bash import BashOperator
from airflow.utils.task_group import TaskGroup
import pendulum

with DAG(
    dag_id="nested_taskgroup_example",
    start_date=pendulum.datetime(2024, 3, 1, tz="Asia/Seoul"),
    catchup=False,
) as dag:
    # 시작 Task
    start = EmptyOperator(task_id="start")

    # TaskGroup 정의 (group_1)
    with TaskGroup("group_1") as group_1:
        # 첫 번째 Task
        task_1 = BashOperator(task_id="task_1", bash_command="echo 'Task 1 실행'")

        # 내부 TaskGroup 정의 (inner_group_1)
        with TaskGroup("inner_group_1") as inner_group_1:
            inner_task = BashOperator(task_id="inner_task", bash_command="echo 'Inner Group 실행'")

        # 병렬 실행될 Task
        task_2 = BashOperator(task_id="task_2", bash_command="echo 'Task 2 실행'")
        task_3 = BashOperator(task_id="task_3", bash_command="echo 'Task 3 실행'")

        # 마지막 Task (task_2, task_3 완료 후 실행)
        task_4 = BashOperator(task_id="task_4", bash_command="echo 'Task 4 실행'")

        # DAG 내 실행 순서 설정
        task_1 >> inner_group_1 >> [task_2, task_3] >> task_4

    # 종료 Task
    end = EmptyOperator(task_id="end")

    # DAG 실행 흐름 설정
    start >> group_1 >> end
```

- `with TaskGroup("group_1") as group_1:` 구문으로 그룹을 선언하고, 그 안에서 Task들의 실행 순서(`task_1 >> inner_group_1 >> [task_2, task_3] >> task_4`)를 그룹 내부에서 별도로 설정한다.
- 그룹 안에 또 `with TaskGroup("inner_group_1")`처럼 그룹을 중첩해서 선언할 수 있다.
- DAG 전체 흐름에서는 `start >> group_1 >> end`처럼 그룹을 하나의 단위로 다루면 되고, 그룹 안쪽의 세부 순서는 그룹 내부 코드에서 관리한다.
- Graph View에서 그룹을 접으면 3개(`start`, `group_1`, `end`)의 노드로만 보이다가, 펼치면 내부의 세부 Task들이 모두 확장되어 보인다.

## 💡 한 줄 요약
> BranchPythonOperator는 조건(값, API 응답 등)에 따라 다음에 실행할 Task를 동적으로 선택하고 선택되지 않은 Task는 자동 Skip 처리하며, TaskGroup은 여러 Task(중첩 그룹 포함)를 하나의 단위로 묶어 DAG를 가독성 있게 관리할 수 있게 해준다.
