# [데이터 엔지니어링] 데이터 파이프라인

---

## 1. 정보(Information)와 데이터(Data)의 차이

과거에는 이미 정리되고 유의미하게 가공된 **정보**가 중요했다면, 지금은 가공되지 않은 원시 상태의 **데이터** 자체의 가치가 훨씬 커졌다.

| 구분 | 정보 (1970~2000년대) | 데이터 (2010년대 이후) |
|---|---|---|
| 상태 | 이미 정리·가공된 결과물 | 가공되지 않은 원시(raw) 자료 |
| 의미 | 그 자체로 의미가 있음 | 나중에 의미를 부여받음 |
| 활용 | 바로 의사결정에 사용 | 대규모로 수집 후 분석에 활용 |

예를 들어 "매출이 증가했다"는 **정보**는, 그 밑바탕이 되는 개별 주문·로그 같은 **데이터**들을 모아서 분석해야 얻을 수 있다. 즉 데이터는 정보를 만들어내는 원천이기 때문에, 일단 잘 모아두는 것 자체의 가치가 커진 것이다.

## 2. 데이터가 중요해진 이유 — 빅데이터

모바일, IoT 등 다양한 요소에서 사람이 의식하지 않아도 데이터가 끊임없이 생성되는 시대가 되었고, 이를 수집·가공·활용하는 기술도 함께 발전하면서 데이터의 중요성이 계속 커지는 선순환이 만들어졌다.

빅데이터를 정의할 때 가장 핵심이 되는 3가지 요소가 **3V**다.

- **양(Volume)**: 데이터의 양이 기하급수적으로 증가
- **다양성(Variety)**: 텍스트, 숫자, 이미지, 위치정보 등 형태가 다양함
- **증가 속도(Velocity)**: 생성되는 속도 자체가 매우 빠름

(최근에는 신뢰성·가치 등을 더한 5V, 7V로 확장해서 이야기하기도 하지만, 핵심은 위 3가지다.)

## 3. 데이터 엔지니어링의 역할

데이터는 크게 두 가지 목적으로 활용된다.

1. **의사결정**: 비즈니스 리더가 데이터 기반으로 중요한 판단을 내림
2. **서비스/제품 강화**: 사용자 행동 데이터를 분석해 기능 개선이나 업데이트에 반영

데이터 엔지니어링의 주요 활동은 다음과 같다.

- **주요 역할**: 데이터를 안정적으로 수집·가공해서 전달, 분석·모델링이 가능하도록 흐름을 자동화, 신뢰성 있고 재사용 가능한 파이프라인 구축
- **주로 하는 일**: 다양한 시스템에서 데이터 수집, 정제 및 변환(ETL 설계), 대용량 데이터를 저장소에 적재

> 좋은 모델은 좋은 파이프라인에서 나온다. 데이터 엔지니어는 모델(및 분석 결과)의 품질을 받쳐주는 기반을 설계하는 사람이다.

결국 모든 파이프라인 기술은 비즈니스 성과를 높이기 위한 수단이라는 점을 기억할 필요가 있다.

## 4. OLTP vs OLAP

파이프라인을 이해하기 전에 짚고 넘어가야 할 개념이 OLTP와 OLAP다.

| 구분 | OLTP (운영 데이터 처리) | OLAP (분석 데이터 처리) |
|---|---|---|
| 정식 명칭 | On-Line Transaction Processing | On-Line Analytical Processing |
| 목적 | 실시간 트랜잭션(주문, 결제, 예약) 처리 | 통계·리포트 등 분석 |
| 저장 구조 | 행(Row) 단위 | 컬럼(Column) 단위 (분석 성능에 유리) |
| 최적화 대상 | 빠른 입력·수정·삭제 | 집계·요약·예측 분석 |
| 예 | 서비스 DB (주문/결제 시스템) | 데이터 웨어하우스, 데이터 레이크 |

OLTP는 사용자의 행동이 발생하는 즉시 처리되어야 하는 실시간 트랜잭션을 다루기 때문에 행 단위 저장이 유리하고, OLAP는 여러 소스에서 모은 대량의 데이터를 빠르게 집계·분석해야 하므로 컬럼 단위 저장이 유리하다.

## 5. ETL vs ELT

데이터를 분석 가능한 상태로 만드는 핵심 과정이다. 파이프라인 전체가 하나의 방식으로 통일되는 것은 아니고, 구성 요소마다 ETL/ELT가 섞여서 사용된다.

### ETL (Extract → Transform → Load)
데이터를 **가공한 후 저장**하는 전통적인 방식.

1. **Extract**: 서비스 DB, 로그, 외부 API 등 다양한 소스에서 데이터를 가져온다.
2. **Transform**: 형식이 다르거나 불필요한 데이터를 정제하고 필요한 형태로 변환한다.
3. **Load**: 가공된 데이터를 웨어하우스 등에 저장한다.

### ELT (Extract → Load → Transform)
데이터를 **먼저 저장한 후 필요할 때 가공**하는 방식으로, 클라우드/데이터 레이크 환경에서 널리 쓰인다.

ELT를 쓰는 이유는 분석 목적이 언제든 바뀔 수 있기 때문이다. 원천 데이터를 먼저 확보해두면, 이후 목적에 맞게 유연하게 가공할 수 있다. 반대로 미리 가공해서 저장해버리면 나중에 추가 분석이 필요할 때 대응이 어려워진다.

## 6. 배치 처리 vs 스트리밍 처리

| 구분 | 배치(Batch) 처리 | 스트리밍(Streaming) 처리 |
|---|---|---|
| 방식 | 데이터를 모아서 한 번에 처리 | 들어오는 즉시 실시간 처리 |
| 적합한 경우 | 정확성과 대량 처리가 중요할 때 | 빠르게 변화하는 데이터에 즉각 대응해야 할 때 |
| 예시 | 하루 1회 매출 집계, 일정 시간 로그 분석 | 실시간 사용자 클릭 분석, 실시간 결제 처리 |
| 장점 | 안정적 처리 | 즉각적인 대응 가능 |
| 단점 | 데이터가 즉시 반영되지 않음(지연 발생) | 설계·구현 난이도가 높음 |

무엇이 더 좋고 나쁘다의 문제가 아니라, 데이터의 속도와 목표에 따라 적절한 방식을 선택하는 것이 중요하다.

## 7. 데이터 파이프라인의 전체 흐름

데이터 파이프라인이란 **데이터가 생성되어 활용되기까지 자동화된 흐름**이며, 아래 단계는 일반화한 것으로 순서가 고정된 것은 아니다.

```
소스(Source) → 수집(Ingestion) → 가공(Transformation) → 저장(Storage) → 분석/활용(Analytics)
```

- **소스**: 로그, DB, 외부 API 등 데이터가 발생하는 곳
- **수집**: 데이터를 빠짐없이, 안정적으로 가져오는 단계 (실시간 또는 배치)
- **가공**: 정제·변환을 거쳐 분석·저장에 적합한 형태로 만드는 단계
- **저장**: 데이터의 성격과 목적에 따라 웨어하우스(가공된 데이터) 또는 레이크(원본 데이터)에 저장
- **분석/활용**: 저장된 데이터를 실제로 분석하거나 서비스에 활용

중요한 점은 이 흐름이 한 번 실행되고 끝나는 것이 아니라, **지속적으로 반복·연결되는 사이클**이라는 것이다. 이 모든 과정이 유기적으로 연결되어야 데이터가 실제 가치로 이어진다.

## 8. 데이터 저장소의 종류

수집·가공한 데이터를 어디에 어떻게 저장하느냐에 따라 분석과 활용 범위가 완전히 달라진다.

| 구분 | 데이터 웨어하우스 (Data Warehouse) | 데이터 레이크 (Data Lake) |
|---|---|---|
| 목적 | 비즈니스 의사결정을 위한 정제된 저장소 | 다양한 원천 데이터를 원형 그대로 저장 |
| 데이터 형태 | 구조화된(Structured) 데이터 중심 | 정형+비정형 모두 유연하게 수용 |
| 적재 방식 | ETL (변환 후 적재) | ELT (적재 후 필요시 변환) |
| 스키마 적용 시점 | **Schema-on-Write** (적재 시점에 스키마 적용) | **Schema-on-Read** (조회 시점에 스키마 적용) |
| 비용/확장성 | 상대적으로 비쌈 (고가의 분석 엔진) | 상대적으로 저렴, 확장성 높음 (파일 기반 저장소) |
| 특징 | 스키마가 엄격하게 정의되어 변경이 까다로움 | 원본에 가까워 다양한 목적에 유연하게 대응 |

- **데이터 웨어하우스**: 분석에 적합하도록 정제·구조화한 데이터를 통합 저장하는 시스템. ETL 기반으로 적재하며, 리포트·BI 도구에 바로 활용 가능.
- **데이터 레이크**: 원본 데이터에 가까운 형태를 대규모로 저장하는 구조. 수집 후 필요할 때 재가공하여 분석·모델링·BI 등 다양한 분야에 대응 가능.
- **데이터 마트(Data Mart)**: 웨어하우스의 데이터 중 특정 부서(마케팅팀, 재무팀 등)가 반복적으로 쓰는 데이터만 추출한 더 작은 규모의 저장소. "웨어하우스=창고, 마트=마트"라는 비유로 이해하면 쉽다.
- **데이터 레이크하우스(Data Lakehouse)**: 레이크의 유연성 + 웨어하우스의 관리 기능을 결합한 최근 트렌드. 정형·비정형 데이터를 모두 저장하면서도, 스키마 적용은 레이크처럼 나중에 하되 트랜잭션을 지원해 데이터 일관성을 보장한다.

## 💡 한 줄 요약
> 데이터 파이프라인은 소스에서 발생한 데이터를 수집·가공·저장·분석까지 자동화된 흐름으로 연결하는 지속적인 사이클이며, OLTP/OLAP, ETL/ELT, 배치/스트리밍, 웨어하우스/레이크 같은 개념들은 이 흐름을 데이터의 성격과 목적에 맞게 설계하기 위한 도구다.
