# [데이터 엔지니어링] 리눅스 기본 명령어

## 1. WSL 리눅스 시작과 종료

윈도우 환경에서는 **WSL(Windows Subsystem for Linux)**을 통해 우분투를 사용한다.

```powershell
# PowerShell(관리자 권한)에서 설치된 WSL 배포판 목록 확인
wsl -l -v
```

- 설치된 배포판 목록에 `Ubuntu-22.04`가 보이면 정상 설치된 것
- 터미널에서 `Ubuntu`를 실행하면 리눅스 셸로 진입
- VS Code에서는 **WSL 확장(Extension)**을 설치하면 `Ctrl+Shift+P` → `WSL: New Window`로 WSL 환경에 바로 연결해서 작업할 수 있다

```bash
exit    # 현재 셸(또는 WSL) 세션 종료
```

`exit`으로 셸을 나가도 WSL 자체가 완전히 종료되는 것은 아니라는 점 참고.

## 2. root 사용자와 권한

**root 사용자**는 시스템의 모든 파일·설정·사용자 계정에 제약 없이 접근 가능한 **최고 권한 계정**이다. 윈도우의 관리자(Administrator) 계정에 대응되는 개념이다.

| 구분 | 일반 사용자 | root 사용자 |
|---|---|---|
| 시스템 파일 수정 | 불가 | 가능 |
| 새 프로그램 설치 | 제한적 | 가능 |
| 사용자 계정 관리 | 불가 | 가능 |
| 커널 모듈 수정 | 불가 | 가능 |

root 권한은 잘못 사용하면 실수로 중요 시스템 파일을 삭제하거나 OS 자체가 망가질 수 있고, 외부 공격자가 탈취할 경우 시스템 전체가 장악될 수 있어 **보안상 위험**하다. 그래서 실무에서는 root로 직접 작업하지 않고, 필요할 때만 아래처럼 권한을 잠깐 상승시켜 사용한다.

```bash
sudo -i          # root 사용자로 전환 (환경까지 유지)
# ... root 권한으로 작업 ...
exit              # 다시 기존 사용자 계정으로 복귀

sudo apt update   # 특정 명령 하나만 관리자 권한으로 실행 (Super User DO)
```

## 3. 디렉토리 및 파일 관리 명령어

### 디렉토리 탐색

```bash
pwd               # 현재 작업 디렉토리(Print Working Directory) 경로 확인
ls                 # 현재 디렉토리의 파일/폴더 목록 확인
ls -a              # 숨김 파일 포함해서 확인
ls -l              # 상세 정보(권한, 소유자, 크기 등) 포함해서 확인
cd 경로            # 디렉토리 이동
cd ..              # 상위 디렉토리로 이동
cd ~               # 홈 디렉토리로 이동
```

### 디렉토리 생성/삭제

```bash
mkdir 폴더명       # 새 폴더 생성 (make directory)
rmdir 폴더명       # 빈 폴더 삭제 (폴더 안이 비어 있어야 함)
rm -r 폴더명       # 폴더와 그 안의 내용을 재귀적으로 모두 삭제
```

### 파일 생성/편집/복사/삭제

```bash
touch 파일명                # 빈 파일 생성
echo "내용" >> 파일명       # 파일에 내용 추가 (이어쓰기)
echo "내용" > 파일명        # 파일 내용을 덮어쓰기
cat 파일명                  # 파일 전체 내용 출력
head -n 3 파일명            # 파일의 앞 3줄만 출력
tail -n 3 파일명            # 파일의 마지막 3줄만 출력

cp 원본 대상                # 파일 복사
cp -r 원본폴더 대상폴더     # 디렉토리 복사 (재귀적)
mv 원본 대상                # 파일/폴더 이동 또는 이름 변경

rm 파일명                   # 파일 삭제
rm -r 폴더명                # 디렉토리 삭제(재귀적)
rm -rf 폴더명               # 확인 없이 강제로 삭제 (주의해서 사용)
```

> `rm -rf`는 확인 절차 없이 즉시 삭제되므로 특히 조심해서 사용해야 한다.

## 4. 명령어 연결과 데이터 흐름

여러 명령어를 조합해서 쓸 때 자주 사용하는 기호들이다.

| 기호 | 이름 | 설명 | 예시 |
|---|---|---|---|
| `\|` | 파이프 | 앞 명령어의 결과를 뒤 명령어의 입력으로 전달 | `cat log.txt \| grep ERROR` |
| `>>` | 리다이렉션(추가) | 출력을 파일에 이어쓰기 | `echo "hello" >> file.txt` |
| `>` | 리다이렉션(덮어쓰기) | 출력을 파일에 새로 쓰기 | `echo "hello" > file.txt` |
| `&&` | 조건 실행(성공 시) | 앞 명령이 성공해야 다음 명령 실행 | `mkdir test && cd test` |
| `\|\|` | 조건 실행(실패 시) | 앞 명령이 실패하면 다음 명령 실행 | `cmd1 \|\| cmd2` |
| `;` | 순차 실행 | 성공 여부와 무관하게 순서대로 실행 | `cmd1 ; cmd2` |

## 5. 검색과 필터링

```bash
grep "ERROR" log.txt        # log.txt에서 "ERROR"가 포함된 줄만 검색
cat log.txt | grep "ERROR"  # 파이프와 함께 사용하는 경우도 많음

find . -name "*.txt"        # 현재 디렉토리 기준으로 .txt 파일 전체 검색 (* 는 전체를 의미)

history                      # 지금까지 입력한 명령어 기록 확인
```

## 6. 시스템 정보 및 프로세스 확인

```bash
ps aux                       # 현재 실행 중인 모든 프로세스 확인
ps aux | grep python         # 프로세스 중 이름에 python이 들어간 것만 필터링

kill 1234                    # PID(프로세스 ID) 1234 프로세스 종료
kill -9 1234                 # 정상 종료가 안 될 때 강제 종료

top                           # CPU, 메모리 등 자원 사용량을 실시간 모니터링 (q로 종료)
uptime                        # 시스템이 켜진 후 경과 시간(가동 시간) 확인
whoami                        # 현재 로그인한 사용자 확인
hostname                      # 호스트(네트워크상 이름) 확인
```

> 자기 자신의 셸 프로세스를 `kill` 하면 로그아웃되거나 세션이 끊길 수 있으니 주의해야 한다.

## 7. 파일 권한과 chmod / chown

리눅스는 파일·디렉토리마다 **3가지 주체**에 대해 **3가지 권한**을 따로 설정한다.

**주체 (Who)**

| 기호 | 의미 |
|---|---|
| `u` (User) | 파일의 소유자 |
| `g` (Group) | 파일이 속한 그룹 |
| `o` (Other) | 그 외 사용자 |

**권한 (What)**

| 기호 | 의미 | 숫자 값 |
|---|---|---|
| `r` (Read) | 읽기 가능 | 4 |
| `w` (Write) | 수정·삭제 가능 | 2 |
| `x` (eXecute) | 실행 가능(디렉토리는 접근 포함) | 1 |

`ls -l`로 파일을 확인하면 아래와 같은 형태로 권한이 표시된다.

```
-rwxr-xr-x   1 user user   220  7월 21 10:00  sample.sh
```

- 맨 앞 글자: `-`(파일) 또는 `d`(디렉토리)
- 이후 9글자를 3글자씩 끊어서 순서대로 **소유자(u) / 그룹(g) / 기타(o)** 권한을 의미

각 권한은 있으면 해당 숫자를, 없으면 0을 더해서 하나의 숫자로 표현한다. 예를 들어 `rwx` = 4+2+1 = **7**, `r-x` = 4+0+1 = **5**, `r--` = 4 = **4**.

```bash
chmod 755 sample.sh   # 소유자: rwx(7), 그룹: r-x(5), 기타: r-x(5)
chmod 644 file.txt    # 소유자: rw-(6), 그룹: r--(4), 기타: r--(4) → 소유자만 쓰기 가능, 나머지는 읽기만
chmod 700 syslog      # 소유자만 rwx(7), 그룹/기타는 권한 없음(0)

chmod +x sample.sh    # 모든 주체에 실행 권한 추가
chmod u+x sample.sh   # 소유자에게만 실행 권한 추가

chown user:group 파일명   # 파일 소유자/그룹 변경 (신중하게 사용)
```

`chmod 644`처럼 숫자로 지정하면 권한이 통째로 새로 설정되고, `chmod +x`처럼 기호로 지정하면 기존 권한에 해당 권한만 추가/제거된다는 차이가 있다.

## 8. vi 편집기 기본 사용법

`vi`(또는 `vim`)는 리눅스의 대표적인 텍스트 편집기다. VS Code에서 WSL 폴더를 직접 열어서 작업하면 vi를 몰라도 되지만, 터미널에서 빠르게 파일을 수정해야 할 때 알아두면 유용하다.

```bash
vi 파일명    # vi 편집기로 파일 열기(없으면 새로 생성)
```

| 모드/키 | 동작 |
|---|---|
| `i` | 현재 커서 위치부터 입력 모드 시작 |
| `a` | 현재 커서 다음 칸부터 입력 모드 시작 |
| `o` | 다음 행에 새 줄을 만들며 입력 모드 시작 |
| `Esc` | 입력 모드에서 빠져나와 명령 모드로 전환 |
| `:w` | 저장 |
| `:q` | 종료 (변경사항이 없을 때) |
| `:wq` | 저장 후 종료 |
| `:q!` | 저장하지 않고 강제 종료 |

## 9. 실습: 더미 로그 파일로 명령어 적용해보기

```bash
# 1) 작업 디렉토리 생성 및 이동
cd ~
mkdir practice
cd practice

# 2) 더미 로그 파일 생성
touch system.log
echo "INFO: 시스템 시작" >> system.log
echo "ERROR: 데이터베이스 연결 실패" >> system.log
echo "INFO: 유저 로그인" >> system.log
echo "WARNING: 디스크 공간 부족" >> system.log
echo "ERROR: 서비스 중단" >> system.log

# 3) 로그 확인 및 필터링
cat system.log            # 전체 보기
head -n 3 system.log      # 처음 3줄
tail -n 2 system.log      # 마지막 2줄
grep ERROR system.log     # 에러만 필터링

# 4) 백업 및 파일 복사/이름 변경
cp system.log backup.log
mv backup.log old.log
rm old.log

# 5) 디렉토리로 옮기고 삭제해보기
mkdir archive
mv system.log archive/
rmdir archive              # 안에 파일이 있어 삭제 실패
rm archive/system.log      # 안의 파일부터 먼저 삭제
rmdir archive               # 이제 빈 폴더이므로 삭제 가능

# 6) vi로 새 로그 파일 작성
vi syslog
# i 를 눌러 입력 모드 진입 후 내용 작성
# Esc → :wq 로 저장 후 종료

# 7) 파일 권한 확인 및 변경
ls -l syslog
chmod 700 syslog           # 소유자만 모든 권한을 갖도록 설정

# 8) 프로세스 확인
ps aux | grep bash
kill [확인한 PID]          # 필요시 프로세스 종료 (자기 셸은 주의)

# 9) 기타 유용한 명령어
history                     # 입력한 명령어 목록 확인
clear                       # 터미널 화면 정리
man ls                      # 명령어 매뉴얼(설명서) 확인
```
