### 0. 복습 — 자료구조 메서드

#### 문자열(str) 메서드

| 메서드 | 설명 | 주의 포인트 |
|---|---|---|
| `find(x)` | x 위치 인덱스 반환 | 없으면 `-1` 반환 |
| `index(x)` | x 위치 인덱스 반환 | 없으면 `ValueError` 발생 |
| `replace(a, b)` | a→b 교체 후 **새 객체** 반환 | 문자열 불변 → 원본 유지 |
| `split(sep)` | 문자열 → 리스트 분리 | 알고리즘 입력값 처리에 필수 |
| `join(list)` | 리스트 → 문자열 합치기 | `"구분자".join(리스트)` 형태 |
| `strip()` | 양쪽 공백 제거 | 테스트케이스 공백 이슈 방지 |

> 💬 강사님: *"테스트케이스 입력값 사이 공백이 두 개 들어가서 오류 발생한 실제 사례 있음. `strip()`은 알고리즘에서 습관적으로 활용 권장."*

#### 리스트(list) 메서드

| 메서드 | 설명 | 주의 포인트 |
|---|---|---|
| `append(x)` | 단일 항목 맨 뒤 추가 | `extend`와 혼동 주의 |
| `extend(iter)` | 이터러블 **펼쳐서** 추가 | 리스트 내 항목들을 분리해서 추가 |
| `insert(i, x)` | i 위치에 x 삽입 | |
| `pop(i)` | i번째 항목 제거·반환 | 기본값: 마지막 항목 |
| `sort()` | 원본 직접 정렬 | 반환값 `None` (리스트 메서드) |
| `sorted(list)` | 새 리스트 반환 | 내장함수 — 변수에 할당해서 사용 |
| `count(x)` | x 개수 반환 | |
| `reverse()` | 원본 뒤집기 | |
| `index(x)` | x의 인덱스 반환 | |

> ⚠️ **sort() vs sorted() — 시험 출제 포인트**
> * `sort()` → 리스트 메서드, 원본 직접 변경, 반환값 `None`
> * `sorted()` → 내장함수, 새 리스트 반환, 결과를 **변수에 할당** 후 사용

#### 얕은 복사 vs 깊은 복사

```python
import copy

original = [1, 2, ][1][2]

# 얕은 복사 — 1차원만 복사, 내부 가변 객체는 주소 공유
shallow = original.copy()       # 또는 original[:]
shallow = 999[3]
print(original)  # [1, 2, ] ← 내부 리스트 함께 변경됨![2]

# 깊은 복사 — 중첩 가변 객체까지 완전 독립 복사
deep = copy.deepcopy(original)
deep = 0[3]
print(original)  # 변화 없음
```

#### 해시 & 메서드 체이닝
* **해시**: 입력값을 고정 크기의 고유한 값으로 변환하는 과정
* `dict`, `set` — 해시값으로 저장 → **O(1) 탐색** 속도
* **메서드 체이닝**: 메서드가 **객체를 반환하는 경우에만** 연속 호출 가능

### 1. 절차지향 vs 객체지향

#### 절차지향 프로그래밍 (Procedural)
* 데이터(변수)와 함수를 **별개로** 관리
* 코드가 위→아래 순차 실행, 함수 호출 흐름 중심
* 대표 언어: **C**
* ✅ 장점: 직관적, 개발·실행 속도 빠름, 단순 구조
* ❌ 단점: 규모 증가 시 복잡성 급증 → **스파게티 코드** 발생

> 💬 강사님: *"변수·함수가 각자 따로 관리되니까 코드가 길어질수록 어디서 값이 바뀌는지 모르게 됨. 처음엔 1, 2, 3으로 예쁘게 짰는데 나중에 1.5 넣으라 하고 2.1 넣으라 하다 보면 코드가 스파게티처럼 꼬임. 더 이상 손대기 무서운 상태가 됨."*

#### 객체지향 프로그래밍 (OOP — Object Oriented Programming)
* 관련 데이터(속성)와 행동(메서드)을 하나의 **객체**로 묶어 관리
* 객체들의 상호작용으로 프로그램 구성
* 대표 언어: **Python, Java, C++**
* ✅ 장점: 유지보수 용이, 재사용성 높음, 협업 편리, 대규모 프로젝트 적합
* ❌ 단점: 초반 설계 복잡, 단순 스크립트에는 과도

> ⚠️ **절차지향 vs 객체지향 — 우열 없음, 상황에 따른 트레이드오프**
> * 알고리즘 문제 → **절차지향**으로 충분 (논리적 사고 구현이 목표)
> * 프로젝트 개발 → **객체지향** 적극 활용
> * 파이썬은 두 가지 모두 가능, 기본은 **객체지향**

> 💬 강사님: *"파이썬은 기본적으로 객체지향 언어. 우리가 써온 `str`, `list`, `int` 모두 클래스이고, 만든 변수들은 모두 해당 클래스의 인스턴스. 이미 OOP를 써왔던 것."*

### 2. 클래스 & 인스턴스 기초

#### 핵심 용어 정리

| 용어 | 의미 | 붕어빵 비유 |
|---|---|---|
| **클래스(Class)** | 객체를 만들기 위한 설계도 | 붕어빵 **틀** |
| **인스턴스(Instance)** | 클래스로부터 생성된 개별 객체 | 틀로 **찍어낸 붕어빵** |
| **객체(Object)** | 실체화된 개별 존재 (인스턴스와 혼용) | 붕어빵 자체 |
| **속성(Attribute)** | 객체가 가진 데이터 | 붕어빵의 팥, 크기 |
| **메서드(Method)** | 객체의 행동 (클래스 내부 함수) | 굽는 행위 |

> 💡 **객체 vs 인스턴스 정확한 표현**
> * `"아이유는 객체다"` → ✅ (뭉뚱그린 표현, 허용)
> * `"아이유는 인스턴스다"` → ⚠️ (어떤 클래스의 인스턴스인지 명시 필요)
> * `"아이유는 가수 클래스의 인스턴스다"` → ✅ (정확한 표현)

> 💡 내부 데이터가 같아도 **다른 인스턴스** — 클래스로 찍어낸 순간 독립 존재

#### 클래스 선언 규칙
* `class` 키워드 + **파스칼케이스(PascalCase)** 클래스명
* 파스칼케이스 사용 위치: 클래스 선언, 예외(Exception) — 단 두 곳
* 그 외 변수·함수명 전체: **스네이크케이스** (`my_variable`)

> 💬 강사님: *"안 지켜도 코드는 돌아가지만 아마추어 소리 들음. 파이썬 쓸 땐 파이썬 컨벤션, 자바 쓸 땐 자바 컨벤션. 언어는 수단이고, 적응력을 키우는 것이 핵심."*

---

### 3. 클래스 변수 vs 인스턴스 변수

| 구분 | 선언 위치 | 접근 방법 | 특징 |
|---|---|---|---|
| **클래스 변수** | 클래스 바로 아래 | `클래스명.변수명` | 모든 인스턴스 **공유** |
| **인스턴스 변수** | `__init__` 내부 `self.xxx` | `인스턴스명.변수명` | 인스턴스마다 **독립** |

* **이름 공간 탐색 순서**: 인스턴스 변수 우선 → 없으면 클래스 변수 탐색 (좁은 스코프 우선 원칙과 동일)
* 인스턴스로 클래스 변수 접근 가능하지만 **권장 안 함** (가독성 저하)

> 💬 강사님: *"클래스 변수는 전역변수 느낌, 인스턴스 변수는 로컬변수 느낌. 인스턴스에서 클래스 변수 접근하면 누가 봐도 헷갈림. `클래스명.변수`로 접근하는 게 가독성에 좋음."*

---

### 4. `__init__` 생성자 메서드

* 인스턴스 생성 시 **자동 호출**되는 특수 메서드
* 표기법: `__init__` (언더바 두 개 + init + 언더바 두 개)
* 역할: 인스턴스 변수 **초기화** 전담
* 생성자 메서드는 인스턴스 메서드의 일종 — 첫 번째 인자로 `self` 수신

> ⚠️ 생성자 메서드가 인스턴스 메서드인 근거 두 가지
> 1. 첫 번째 매개변수로 `self` 수신
> 2. 인스턴스 변수(`self.xxx`)를 초기화하는 역할

### 5. 메서드(Method) 3종류

#### 5-1. 인스턴스 메서드 (가장 많이 사용)
* 특정 인스턴스의 데이터 조작 및 행동 수행
* **첫 번째 매개변수 반드시 `self`** — 호출한 인스턴스 자신
* `self`의 역할: 이 메서드를 호출한 인스턴스가 누구인지 식별

> 💬 강사님: *"실제 파이썬 내부 동작은 `hello.upper()` → `str.upper(hello)` 형태. 클래스에서 호출하면서 첫 번째 인자로 인스턴스를 자동으로 넘김. 그래서 인스턴스 메서드 첫 번째 인자는 반드시 `self`."*

> ⚠️ `self`는 이름일 뿐 — `sel`, `s` 등 다른 이름으로도 동작. 단 **권장 = 필수**로 간주. 협업에서 `self`를 보면 모든 개발자가 즉시 인스턴스를 의미하는 것으로 인식

#### 5-2. 클래스 메서드
* 클래스 자체를 조작할 때 사용
* `@classmethod` 데코레이터 필요
* 첫 번째 매개변수 `cls` (클래스 자체 수신)
* 활용 예시: 인스턴스 생성 개수 추적 (생성 시마다 클래스 변수 증가)

#### 5-3. 스태틱 메서드
* 인스턴스·클래스 모두 참조하지 않는 독립 기능
* `@staticmethod` 데코레이터 필요
* `self`나 `cls` 매개변수 불필요

> 💬 강사님: *"세 가지 중 인스턴스 메서드가 압도적으로 많이 사용됨. 실제 동작하는 데이터는 인스턴스에 있기 때문."*

### 6. 매직 메서드 (Magic Method)
* `__이름__` 형태 특수 메서드 — 특정 내장 함수·연산자 호출 시 자동 실행
* 모두 인스턴스 메서드 (`self` 수신)

| 메서드 | 자동 호출 시점 |
|---|---|
| `__init__` | 인스턴스 생성 시 |
| `__str__` | `print(인스턴스)` 또는 `str()` 호출 시 |
| `__len__` | `len(인스턴스)` 호출 시 |

* **데코레이터**: 함수 위에 `@데코레이터명` 작성 → 원래 함수 실행 전 데코레이터 먼저 실행
* 데코레이터 = 다른 함수의 코드 유지한 채 수정·확장하기 위한 함수
* 직접 만들기는 어려운 수준 — *어떤 역할인지만 파악*

---

### 7. 상속 (Inheritance)

* 부모 클래스의 속성·메서드를 자식 클래스가 **물려받는** 것
* 목적: 중복 코드 제거, 재사용성 향상
* `super().__init__()` — 부모 클래스의 생성자 호출

#### 메서드 오버라이딩 (Overriding)
* 자식 클래스에서 부모와 **같은 이름의 메서드 재정의**
* 호출 시 자식 메서드 우선 실행 (좁은 스코프 우선 원칙 동일)
* 부모 메서드도 함께 실행 시 → `super().메서드명()` 활용

---

### 8. MRO (Method Resolution Order)

* 다중 상속 시 메서드를 어느 클래스에서 먼저 탐색할지 결정하는 **순서**
* **L 알고리즘(선형화)** 으로 결정
* 확인 방법: `클래스명.__mro__` 또는 `클래스명.mro()`

#### 다이아몬드 상속 구조 예시

```
    A
   / \
  B   C
   \ /
    D
```

* **D의 MRO**: D → B → C → A → object
* 탐색 규칙:
  1. 자기 자신 우선
  2. 상속 선언 순서 (왼쪽→오른쪽)
  3. 공통 조상은 마지막

> ⚠️ 다중 상속 시 `__mro__` 출력으로 탐색 순서 반드시 확인하는 습관 필요

---

### 9. 다형성 (Polymorphism)

* 동일한 메서드명이라도 클래스에 따라 **다른 동작** 수행
* 부모 메서드 오버라이딩 + `super()`로 부모 메서드 호출 병행 가능
* `super()` 체인은 MRO 순서에 따라 결정

### 11. 에러 종류 & 디버깅

#### 11-1. 버그(Bug) & 디버깅(Debugging)
* **버그**: 소프트웨어 오류·결함 — 예상 동작과 실제 동작의 불일치
* 어원: 실제 나방(Bug)이 회로에 합선을 일으킨 역사적 사건에서 유래
* **디버깅**: 버그 발견·수정 과정

> 💬 강사님: *"버그 났을 때 그냥 손 비비고 있지 말고, 버그 지점 위에 프린트문 찍어보기. 변수값이 내가 생각한 대로 출력되는지 확인하는 것이 기본 디버깅. 알고리즘 수업부터는 파이참 디버거 기능도 적극 활용."*

#### 11-2. 문법 에러 (SyntaxError) — 실행 전 발생

| 에러 메시지 | 의미 | 발생 예시 |
|---|---|---|
| `invalid syntax` | 올바르지 않은 문법 | `while` 조건·콜론 누락 |
| `cannot assign to literal` | 리터럴(값)에 할당 시도 | `1 = x` (할당·비교 혼동) |
| `EOL while scanning string literal` | 문자열 따옴표 미종료 | `"hello` (닫는 `"` 없음) |
| `unexpected EOF while parsing` | 괄호 미종료 | `print(` (닫는 `)` 없음) |

> 💬 강사님: *"EOL = End of Line, EOF = End of File. 읽으면 바로 알 수 있음. 영어가 불편해도 이 기술 영어 단어는 암기 필요."*

#### 11-3. 예외 에러 (Exception) — 실행 중 발생

| 에러 | 발생 상황 | 예시 |
|---|---|---|
| `ZeroDivisionError` | 0으로 나누기 | `10 / 0` |
| `NameError` | 미정의 변수 사용 | `print(x)` (x 미선언) |
| `TypeError` | 잘못된 타입 연산 | `"hello" + 1` |
| `ValueError` | 잘못된 값 전달 | `int("abc")` |
| `IndexError` | 인덱스 범위 초과 | `a[10]` (길이 3 리스트) |
| `KeyError` | 딕셔너리 키 없음 | `d["없는키"]` |

> 💬 강사님: *"에러 메시지 읽으면 코드 어디가 잘못됐는지 바로 파악 가능. 초보일수록 생각 없이 GPT에 넘기지 말고 한 번만 읽어볼 것."*

### 클래스 기본 구조 (변수 종류 + 생성자 + 매직 메서드)

```python
class Circle:
    # 클래스 변수 — 모든 인스턴스가 공유하는 공통 속성
    pi = 3.14

    # 생성자 메서드 — 인스턴스 생성 시 자동 호출, 인스턴스 변수 초기화 담당
    def __init__(self, radius):
        self.radius = radius    # 인스턴스 변수 — 각 인스턴스 독립 관리

    # 인스턴스 메서드 — self로 호출 주체 식별, 인스턴스마다 다른 결과
    def area(self):
        return Circle.pi * self.radius ** 2

    # 매직 메서드 — print(인스턴스) 호출 시 자동 실행
    def __str__(self):
        return f"원 (반지름: {self.radius})"

c1 = Circle(1)
c2 = Circle(2)

print(c1.radius)     # 1  — 인스턴스 변수 독립 관리
print(c2.radius)     # 2
print(Circle.pi)     # 3.14 — 클래스 변수 접근
print(c1)            # 원 (반지름: 1) — __str__ 자동 호출
print(c1.area())     # 3.14
```

### 메서드 3종류 비교

```python
class Person:
    population = 0  # 클래스 변수

    def __init__(self, name):
        self.name = name

    # 인스턴스 메서드 — 인스턴스 데이터 조작, self 필수
    def greeting(self):
        print(f"안녕하세요, {self.name}입니다.")

    # 클래스 메서드 — 클래스 자체 데이터 조작, cls 수신
    @classmethod
    def increase_population(cls):
        cls.population += 1     # cls = Person 클래스 자체

    # 스태틱 메서드 — 클래스·인스턴스 모두 참조 안 하는 독립 기능
    @staticmethod
    def is_adult(age):
        return age >= 18

p1 = Person("Alice")
p1.greeting()                  # 안녕하세요, Alice입니다.
Person.increase_population()
print(Person.population)       # 1
print(Person.is_adult(20))     # True
```

### 상속 & 오버라이딩

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def talk(self):
        print(f"안녕하세요, {self.name}입니다.")

# Student가 Person 상속
class Student(Person):
    def __init__(self, name, age, gpa):
        super().__init__(name, age)     # 부모 생성자 호출 — 부모 인스턴스 변수 초기화
        self.gpa = gpa                  # 자식 고유 속성 추가

    # 부모의 talk() 메서드 오버라이딩
    def talk(self):
        print(f"안녕하세요, {self.name} 학생입니다. GPA: {self.gpa}")

p1 = Person("Alice", 30)
s1 = Student("Bob", 20, 4.5)

p1.talk()   # 안녕하세요, Alice입니다.
s1.talk()   # 안녕하세요, Bob 학생입니다. GPA: 4.5 (오버라이딩 적용)
```

### MRO — 다이아몬드 상속

```python
class A:
    def show(self):
        print("A")

class B(A):
    def show(self):
        print("B")

class C(A):
    def show(self):
        print("C")

class D(B, C):      # B, C 순서로 다중 상속
    pass

d = D()
d.show()            # "B" — MRO: D → B → C → A → object

# MRO 순서 직접 확인
print(D.__mro__)
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
```

### 다형성 — super() 체인

```python
class ParentA:
    def show_value(self):
        print("ValueFromParentA")

class ParentB:
    def show_value(self):
        print("ValueFromParentB")

class Child(ParentA, ParentB):
    def show_value(self):
        print("ValueFromChild")
        super().show_value()    # MRO에 따라 ParentA.show_value() 호출

c = Child()
c.show_value()
# ValueFromChild
# ValueFromParentA     ← MRO 순서로 ParentA가 먼저 호출됨
```

## 🚀 복습 및 AI 인사이트

### 핵심 체크포인트

* **클래스 변수 vs 인스턴스 변수**: 이름 같을 때 인스턴스 변수 우선 참조 (스코프 원칙 동일)
* **`self` 역할**: 이 메서드를 호출한 인스턴스를 첫 번째 인자로 자동 수신
* **생성자 메서드 = 인스턴스 메서드**: `self` 수신 + 인스턴스 변수 초기화 담당이라는 두 근거로 확인
* **`sort()` vs `sorted()`**: 반환값 차이 — `sort()`는 `None`, `sorted()`는 새 리스트
* **MRO 확인 습관**: 다중 상속 시 `클래스명.__mro__` 출력으로 탐색 순서 파악
* **에러 메시지 직접 읽기**: GPT 전달 전 에러 메시지 먼저 직접 해독

### AI 활용 팁

* **에러 디버깅**: `"다음 파이썬 에러 메시지의 의미와 발생 원인, 수정 방법을 설명해줘: [에러 메시지 전체]"` → 에러 직접 읽고 모르는 경우에만 활용
* **MRO 시각화**: `"다음 다중 상속 구조의 MRO를 단계별 다이어그램으로 설명해줘: [클래스 구조 코드]"`
* **클래스 설계 검토**: `"다음 클래스 설계에서 클래스 변수와 인스턴스 변수를 올바르게 분리했는지 검토하고 개선점 제안해줘"`
