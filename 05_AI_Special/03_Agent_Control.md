## 1. 바이브 코딩의 개념과 올바른 접근법

### 1-1. 바이브 코딩이란

자연어를 활용하여 직관적이고 신속하게 프로그래밍을 수행하는 최신 개발 트렌드다. 코드를 한 줄씩 직접 작성하는 대신, AI에게 의도를 전달하고 결과물을 검증하는 방식으로 개발한다.

### 1-2. 위험한 습관 3가지

첫째, 코드 변경 사항을 확인하지 않고 무조건 `Keep`을 클릭하는 행위다. 둘째, 요청하지 않은 수정 사항이 포함되었을 때 의도적으로 묵인하는 것이다. 셋째, 실행과 테스트 과정을 생략한 채 결과물을 맹신하는 태도다.

모호한 지시로 인한 버그 발생 시 모든 책임은 검증을 소홀히 한 개발자 본인에게 있다.

> **강사님 강조**: AI가 만든 코드를 확인 없이 수락하는 것은 가장 위험한 습관이다. 변경 사항을 반드시 검토하고, 실행·테스트를 거쳐야 한다.

## 2. 에이전트 통제 — 전역 지침(Instructions) 설정

### 2-1. 설정 목적

AI의 임의 수정을 방지하고 사용자의 의도에 따라 적절한 역할로 분류(라우팅)하기 위함이다. Cursor, Windsurf 등 AI IDE의 기반이 되는 VS Code의 GitHub Copilot에서 설정할 수 있다.

### 2-2. 전역 지침 파일 구성

프로젝트 루트에 `.github/copilot-instructions.md`를 생성하고 라우팅 규칙을 작성한다.

```markdown
# AI 코딩 어시스턴트 전역 지침 — 라우팅 프롬프트

## 1. 의도 분류 규칙
- 기획/설계 요청: .github/rules/planner.md 참조
- 코드 생성/수정 요청: .github/rules/generator.md 참조
- 코드 검증/리뷰 요청: .github/rules/reviewer.md 참조

## 2. 예외 처리 원칙
- 요청이 모호할 경우 임의 생성을 중단하고 사용자에게 모드 재선택 요구
```

> **강사님 팁**: "어떤 모드(기획/생성/검증)로 도와드릴까요?"라는 역질문을 유도하면 AI에 대한 제어권을 유지할 수 있다.

---

## 3. 역할별 페르소나 파일 분리

### 3-1. 플래너 (planner.md)

목표 재정의와 단계별 계획 수립을 담당한다. 실제 코드 수정은 절대 금지이며, 구현 가능한 논리적 단계만 마크다운으로 출력한다.

### 3-2. 제너레이터 (generator.md)

플래너의 계획을 기반으로 코드를 구현한다. 최소한의 변경, 기존 스타일 유지, 하위 호환성 확보를 원칙으로 한다. 계획에 없는 기능 추가나 로직 변경은 금지다.

### 3-3. 리뷰어 (reviewer.md)

변경 사항의 영향 범위를 검토하고, 플래너의 계획과 대조하여 위험 요소를 리포트한다. 코드 직접 수정은 절대 금지이며, 피드백만 전달한다.

> **강사님 강조**: AI IDE의 화려한 기능보다 전역 지침 설정과 역할 분리가 근본적으로 더 중요하다. 이 구조가 잡혀야 AI를 안정적으로 통제할 수 있다.

## 4. Git을 활용한 상태 동기화

### 4-1. 맥락 누적 문제

하나의 채팅 세션에서 모든 작업을 진행하면 토큰이 낭비되고 환각 현상이 발생한다. 세션을 역할별로 분리하되, 분리된 세션 간 정보 단절 문제를 해결해야 한다.

### 4-2. Git Diff를 이용한 상태 동기화

```bash
# 1. 초기 상태 저장
git init
git add .
git commit -m "기본 환경 구축 완료"

# 2. 제너레이터 세션에서 코드 작성 후 커밋
git add .
git commit -m "기능 구현 완료"

# 3. 플래너 세션으로 이동하여 변경 사항 분석 요청
# 프롬프트: "git diff 결과를 분석하여 docs/plan.md에 변경 내역 반영해줘"
```

제너레이터 세션에서 수정한 내용을 Git으로 커밋한 뒤, 플래너 세션에서 `git diff`를 통해 변경 사항을 전달하면 세션 간 맥락을 효율적으로 공유할 수 있다.

> **강사님 팁**: 터미널에서 대기 상태가 발생하면 `q`를 입력하여 빠져나올 수 있다.
