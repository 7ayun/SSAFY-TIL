## 💡 주요 개념 정리
### 1. 바이브 코딩(Vibe Coding)의 명암과 올바른 접근법
* **개념 정의:** 자연어를 활용하여 직관적이고 신속하게 프로그래밍을 수행하는 최신 개발 트렌드
* **위험한 습관 3가지:**
    * 코드 변경 사항 미확인 상태에서의 무조건적인 `Keep` 클릭 행위
    * 요청하지 않은 수정 사항 포함 시 의도적 묵인 및 무시
    * 실행 및 테스트 과정을 생략한 채 결과물을 맹신하는 태도
* **책임 소재의 명확화:** 모호한 지시로 인한 버그 발생 시 모든 책임은 검증을 소홀히 한 개발자 본인에게 귀속

### 2. VS Code 및 Copilot 기반 에이전트 활용
* **도구의 본질:** Cursor, Windsurf 등의 기반이 되는 VS Code의 GitHub Copilot 숙련도 확보 강조
* **에이전트 역할 수행:** 단순 답변(Ask)을 넘어 프로젝트 분석 및 계획(Plan) 수립 능력 활용

## 💻 기능 구현 및 코드 실습
### 1. 에이전트 통제 - 전역 지침(Instructions) 설정
* **설정 목적:** AI의 임의 수정 방지 및 사용자 의도 분류(Routing) 강제
* **파일 위치:** `.github/copilot-instructions.md` 생성 및 라우팅 규칙 작성 수행

```markdown
# [라우팅 프롬프트] AI 코딩 어시스턴트 전역 지침
# 사용자의 의도를 분석하여 적절한 역할별 규칙 파일을 참조하도록 안내

## 1. 의도 분류 규칙
- 기획/설계 요청: `.github/rules/planner.md` 참조 필수
- 코드 생성/수정 요청: `.github/rules/generator.md` 참조 필수
- 코드 검증/리뷰 요청: `.github/rules/reviewer.md` 참조 필수

## 2. 예외 처리 원칙
- 요청이 모호할 경우 임의 생성을 중단하고 사용자에게 모드 재선택 요구 수행
```

### 2. 역할별 페르소나 파일 분리 구현
* **플래너 (planner.md):** 목표 재정의, 단계별 계획 수립, 실제 코드 수정 절대 금지 원칙 준수
* **제너레이터 (generator.md):** 계획 기반 구현, 최소한의 변경, 스타일 유지, 하위 호환성 확보 주력
* **검증자 (reviewer.md):** 영향 범위 검토, 계획 대조, 위험 요소 리포트, 코드 직접 수정 절대 금지

### 3. Git을 활용한 상태 동기화 실습
* **맥락 누적 문제 해결:** 단일 세션의 토큰 낭비 및 환각 현상 방지를 위한 채팅 세션 분리 기법 활용
* **상태 동기화 프로세스:**
```bash
# [상태 동기화] Git Diff 활용 예시
# 생성자 세션에서 수정된 내용을 기획자 세션에 효율적으로 전달하는 과정

# 1. 초기 상태 저장
git init
git add .
git commit -m "기본 환경 구축 완료"

# 2. 제너레이터 세션 작업 후 기획자 세션 이동
# 3. 변경 사항 분석 요청 프롬프트 입력
# "git diff 결과를 분석하여 docs/plan.md에 변경 내역 반영 수행"
```

* **헷갈렸던 점 2:** 세션 분리 시 정보 단절 문제를 해결하는 Git 기반 맥락 공유의 효율성 확인
