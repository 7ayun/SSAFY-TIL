## 1. 대규모 언어 모델(LLM)의 작동 원리

### 1-1. 통계적 언어 모델

LLM은 인간처럼 추론하는 것이 아니라, 데이터 기반의 강력한 **통계적 확률 계산 장치**다. 핵심 메커니즘은 **다음 토큰 예측(Next Token Prediction)** 으로, 현재 맥락(Context)을 분석하여 다음에 올 단어의 확률을 수학적으로 산출한다.

프로그래밍 언어는 반복적이고 예측 가능한 패턴이 많기 때문에, LLM이 코드를 잘 생성하는 것은 통계적 학습의 결과다.

```python
# Next Token Prediction 개념 예시
context = "for"
# 학습 데이터를 바탕으로 다음 토큰 확률 계산
next_token_prediction = ["i", "in", "range(10):"]

generated_code = f"{context} {next_token_prediction[0]} {next_token_prediction[1]} {next_token_prediction[2]}"
print(generated_code)  # for i in range(10):
```

### 1-2. GPT의 구성 요소

| 약자 | 의미 | 설명 |
|------|------|------|
| G (Generative) | 생성형 | 학습 데이터 외의 새로운 문장·코드 생성 가능 |
| P (Pre-trained) | 사전 학습 | 방대한 데이터로 미리 학습이 완료된 상태 |
| T (Transformer) | 트랜스포머 | 구글이 발표한 모델 아키텍처 기반 |

> **강사님 강조**: LLM이 지능적으로 보이는 결과물을 내더라도, 실제로는 통계적 장치라는 점을 혼동하면 안 된다. 결과물을 검증 없이 수용하는 것은 위험하다.

## 2. 프롬프트 엔지니어링과 창발적 능력

### 2-1. 창발적 능력 (Emergent Abilities)

모델의 규모와 학습 데이터가 증가하면 명시적으로 학습하지 않은 요약, 번역, 추론 같은 능력이 스스로 나타나는 현상이다. 이 능력을 극대화하는 것이 프롬프트 엔지니어링의 목표다.

### 2-2. 주요 최적화 기법

**인컨텍스트 러닝(In-Context Learning)** 은 모델을 재학습하지 않고, 프롬프트에 예시를 제공하여 규칙을 학습시키는 방법이다. 예시 개수에 따라 Zero-shot(0개), One-shot(1개), Few-shot(여러 개)으로 구분한다.

**CoT(Chain of Thought)** 는 "단계별로 생각해봐"라는 지시를 통해 모델의 토큰 예측 정밀도를 향상시키는 기법이다. 복잡한 문제일수록 효과가 크다.

**RAG(검색 증강 생성)** 는 외부 데이터베이스의 검색 결과를 프롬프트에 결합하는 기술이다. 모델이 학습하지 않은 최신 정보나 사내 문서를 활용할 수 있게 한다.

**ReAct(Reasoning + Acting)** 는 추론과 행동을 결합한 기법으로, 모델이 외부 도구 사용 계획을 수립하고 직접 실행할 수 있도록 한다.

## 3. 에이전틱 AI (Agentic AI)

### 3-1. 에이전트의 정의

에이전트란 목표 달성을 위해 **도구를 자율적으로 선택하고 행동하는 AI 시스템**이다. 핵심 요소는 자율성(Autonomy)과 도구 사용 숙련도(Proficiency)의 결합이다.

### 3-2. 작동 사이클

에이전트는 환경 인지(Perception) → 계획(Planning) → 도구 사용(Action)의 사이클을 반복 수행한다.

### 3-3. 에이전트 분류

**반독립적 에이전트**는 정해진 워크플로우 안에서만 작동한다. 버그 탐지기처럼 특정 범위의 작업만 수행한다.

**완전 자율 에이전트**는 파일 시스템, IDE, 터미널에 직접 접근하여 코드를 수정한다. Cursor 같은 AI 코딩 도구가 대표적이다.

> **강사님 주의**: 에이전트의 자율성이 높아지려면 도구 사용 숙련도(Proficiency)가 전제되어야 한다. 숙련도 없는 자율성은 오작동을 초래한다.

## 4. AI 시대의 소프트웨어 개발 주기(SDLC) 변화

### 4-1. 중요도가 급증하는 단계

**요구사항 분석**은 기계에게 명확한 지시를 내리기 위한 정교한 문서화 역량이 필수가 된다. **설계 및 아키텍처**는 구현이 자동화됨에 따라 시스템 전체를 조망하는 아키텍트 역할이 핵심이 된다.

### 4-2. 가치가 변화하는 단계

**구현**은 직접 코딩 행위의 가치가 하락하고 코드 최소화를 지향하게 된다. **검증**은 인간의 판단이 필요한 '오라클 문제' 해결을 위해 검증 루프 설계가 중요해지며 병목 구간이 된다. **유지보수**는 코드 생성 비용이 하락하면서 유지보수보다 재작성이 효율적인 경우가 늘어난다.

## 5. 개발자의 미래와 핵심 역량

### 5-1. 사고 범위 문제 (Frame Problem)

AI는 상식이 결여되어 있으므로, 비즈니스 도메인과 상식을 명확히 정의하여 AI를 제어하는 능력이 개발자의 핵심 역량이 된다.

### 5-2. 자동화의 역설

AI 의존도가 심화되면 장애 발생 시 대응 능력과 시스템 통제 능력을 상실할 위험이 있다. 코드의 원리를 이해하고 직접 구현한 경험이 있어야 AI의 통계적 결과물을 검증하고 통제할 수 있다.

> **강사님 강조**: AI가 코드를 대신 짜주는 시대라고 해서 공부를 안 해도 되는 것이 아니다. 통계적 결과물을 검증하고 통제하려면 코드 원리의 이해와 직접 구현 경험이 필수다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| LLM | 추론이 아닌 통계적 확률 계산 장치, 다음 토큰 예측(Next Token Prediction)이 핵심 메커니즘 |
| 코딩 능력 | 프로그래밍 언어의 반복적·예측 가능한 패턴에 대한 통계적 학습 결과 |
| 프롬프트 엔지니어링 | CoT(단계별 사고), RAG(외부 검색 결합), ReAct(추론+행동)으로 창발적 능력 극대화 |
| 에이전틱 AI | 도구를 자율적으로 선택·실행하는 AI, 자율성 + 숙련도가 핵심 |
| SDLC 변화 | 요구사항 분석·설계의 중요도 급증, 구현 가치 하락, 검증이 병목 |
| 자동화의 역설 | AI 의존도 심화 시 장애 대응·통제 능력 상실 위험, 원리 이해와 직접 경험 필수 |
