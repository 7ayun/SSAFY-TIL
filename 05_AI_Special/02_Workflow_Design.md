## 1. AI 코딩 어시스턴트 활용 배경

### 1-1. 생산성 혁명과 채용 트렌드

AI 코딩 어시스턴트는 단순 반복 작업을 비약적으로 줄여 개발 생산성을 높인다. 채용 시장에서도 기술 스택 이해를 넘어 AI 에이전트 활용 및 통제 능력이 중요해지고 있다.

### 1-2. 책임의 주체

AI가 생성한 결과물에 대한 최종 판단과 책임은 개발자 본인에게 있다. AI는 도구일 뿐이고, 검증 없이 결과물을 수용한 책임은 사용자에게 귀속된다.

---

## 2. 기존 LLM 사용의 한계

### 2-1. 단일 세션의 문제

하나의 채팅창에서 기획, 구현, 수정, 검증을 모두 진행하면 맥락이 뒤섞여 혼선이 생기고, AI의 망각 현상과 할루시네이션이 심화된다.

### 2-2. AI 에이전트 구조

이 한계를 극복하기 위해 등장한 것이 AI 에이전트다. 목표 달성을 위해 생각(Reasoning) → 행동(Acting) → 관찰(Observation)을 반복하는 ReAct 기법 기반 시스템이다.

## 3. 프롬프트 엔지니어링 심화

### 3-1. 핵심 기법

**페르소나(Persona) 부여**는 "10년 차 백엔드 아키텍트"처럼 특정 직무와 연차를 설정하여 답변 품질을 높이는 기법이다.

**맥락(Context) 제공**은 프로젝트 배경, 목표, 제약 사항을 구체적으로 명시하는 것이다. 모호한 지시는 모호한 결과를 낳는다.

**출력 형식 지정**은 마크다운 테이블, JSON 등 결과물의 구조를 강제하여 활용도를 높이는 것이다.

### 3-2. 고급 기법

**Few-shot Prompting**은 원하는 답변 양식의 예시를 2~3개 제공하여 AI가 패턴을 학습하도록 유도하는 기법이다.

**Chain of Thought(CoT)** 는 "단계별로 생각해봐"라는 지시로 논리적 추론을 극대화한다.

> **강사님 팁**: "프롬프트를 위한 프롬프팅"을 활용하면 좋다. AI에게 "이 프로젝트에 최적화된 플래너 프롬프트를 만들어줘"라고 지시하면 프로젝트 상황에 맞는 프롬프트를 자동 생성할 수 있다.

## 4. 핵심 전략 — 역할 분리 (계-생-검 프로세스)

### 4-1. 세 가지 역할

| 역할 | 담당 | 주요 임무 | 금지 사항 |
|------|------|----------|----------|
| 플래너 (계획) | 기획 | 요구사항 분석, 기능 명세, 개발 단계별 계획 수립 | 코드 직접 작성 금지, 추측성 기능 추가 금지 |
| 제너레이터 (생성) | 구현 | 플래너의 명세서 기반 소스 코드 구현 | 계획 임의 수정 금지, 명세 준수 |
| 리뷰어 (검증) | 검증 | 코드 검증, 요구사항 충족 확인, 버그 분석 | 코드 직접 수정 금지, 피드백만 전달 |

### 4-2. 피드백 루프

리뷰어의 피드백은 제너레이터에게 직접 전달하기보다 **플래너를 통해 계획을 수정**한 뒤 제너레이터에게 전달하는 것이 효율적이다. 플래너가 중심에서 흐름을 제어해야 일관성이 유지된다.

```
사용자 요구사항 → 플래너(계획 수립)
                    ↓
              제너레이터(코드 구현)
                    ↓
              리뷰어(검증·피드백)
                    ↓
              플래너(계획 수정) → 제너레이터 → ...반복
```

### 4-3. 시스템 프롬프트 예시

```markdown
## 플래너 페르소나
- 요구사항 분석 기반 상세 개발 명세서를 작성하는 전략가
- 코드 작성 절대 금지, 구현 가능한 논리적 단계만 마크다운으로 출력

## 제너레이터 페르소나
- 전달받은 명세서를 바탕으로 코드를 작성하는 시니어 개발자
- 명세 외 기능 추가 및 로직 임의 변경 금지

## 리뷰어 페르소나
- 코드 안정성 및 요구사항 일치 여부를 판별하는 QA 전문가
- 직접 수정 금지, 발견된 문제점과 개선 방향만 피드백
```
