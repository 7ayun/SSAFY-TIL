## 🎯 학습 목표
* AI가 다른 AI(에이전트)를 지휘하고 통제하는 오케스트레이션 개념의 완벽한 이해
* 로우 코드(Low-code) 도구인 랭플로우(Langflow)를 활용한 시각적 에이전트 설계 및 검증 방법 습득
* 단일 세션 대화의 한계를 극복하기 위한 상위 제어 구조(Orchestrator) 설계 역량 확보
* 실제 서비스 구현 전 단계로서의 설계도(Blueprint) 작성 및 프로토타이핑 능력 강화

## 💡 주요 개념 정리
### 1. AI 오케스트레이션 및 오케스트레이터 정의
* **오케스트레이션 개념:** 다수의 인공지능 모델과 시스템을 조정하고 관리하며 데이터 흐름(파이프라인)을 제어하는 행위
* **오케스트레이터(지휘자):** 오케스트라의 지휘자처럼 사용자의 요청에 따라 적절한 에이전트를 호출하고 실행 순서를 결정하는 상위 에이전트
* **필요성:** 에이전트의 기능이 강력해질수록 발생하는 도구 호출 루프 및 실행 경로 복잡성 제어의 필수성
* **구조적 특성:** 지휘자가 다수의 에이전트와 양방향으로 데이터 및 상태를 공유하며 최종 결과물을 산출하는 형태

### 2. 랭플로우(Langflow)의 이해 및 구성
* **도구의 본질:** 랭체인(LangChain) 기반의 GUI 환경 오픈소스 설계 도구
* **주요 구성 요소:**
    * **플로우(Flow):** 하나의 작업을 수행하기 위해 여러 컴포넌트를 연결한 전체 흐름
    * **컴포넌트(Component):** 에이전트, 프롬프트, 모델, 입력/출력 등 기능 단위별 블록
* **장점:** 코드 작성 없이 시각적으로 에이전트 아키텍처를 설계하고 플레이그라운드에서 즉시 테스트 가능

### 3. 에이전트 통제 및 세분화 전략
* **역할 분리:** 단일 대화창의 맥락 혼선 방지를 위한 독립적 실행 단위(Planner, Generator, Reviewer)로의 분리
* **비선형 구조 설계:** 상위 오케스트레이터가 사용자 입력값의 성격에 따라 비선형적으로 에이전트를 선택하여 호출
* **메모리 관리:** 랭기지 모델의 단일 요청-응답 한계 극복을 위한 `Message History` 컴포넌트 부착 필수

## 💻 기능 구현 및 코드 실습
### 1. [기본 구조] 랭기지 모델 및 메모리 연결
```python
# [메모리 기반 대화 구조 설계]
# 사용자의 이전 대화 내역을 기억하기 위한 컴포넌트 배치

# 1. Chat Input: 사용자로부터 텍스트 입력 수신
# 2. Message History: 이전 대화 로그(유저/시스템 응답) 저장 및 관리
# 3. Language Model (GPT-4o mini): 입력값과 히스토리를 합산하여 다음 토큰 예측 수행
# 4. Chat Output: 생성된 답변을 사용자에게 반환
```

### 2. [도구 활용] 위키피디아 API 에이전트 설계
```python
# [API 리퀘스트 도구화]
# 에이전트가 특정 정보를 검색해야 할 때 외부 도구를 호출하는 로직

# 1. 프롬프트 지시: "사용자 질문에서 키워드를 추출하여 위키피디아 API 경로 생성 수행"
# 2. API Request 컴포넌트: 툴 모드(Tool Mode) 활성화 및 에이전트 연결
# 3. Smart Transform: 제이슨(JSON) 형태의 응답 데이터에서 핵심 요약문(Extract) 추출 수행
```

### 3. [상위 지휘] 오케스트레이터 라우팅 프롬프트
```markdown
# [오케스트레이터 시스템 프롬프트]
# 상황에 따라 적절한 하위 에이전트를 선택하여 지휘하는 명령

## 규칙 1. 역할 수행
- 당신은 사용자 입력에 직접 대답하지 않고 적절한 도구(에이전트)만 호출함
- 취미 관련 이야기는 '못난이 에이전트(부정 답변)' 호출 수행
- 지식 검색 질문은 '위키피디아 에이전트' 호출 수행

## 규칙 2. 결과 처리
- 하위 에이전트가 생성한 답변을 변형 없이 그대로 사용자에게 전달함
```

## 🚀 복습 및 AI 인사이트
* **헷갈렸던 점 1:** 에이전트 컴포넌트 자체에 자동 메모리 기능이 내장된 것이 아니므로 별도의 히스토리 컴포넌트 부착이 필요함
* **헷갈렸던 점 2:** 랭플로우는 실제 배포용 서버 환경이 아닌 설계 검증 및 팀원 간 협업용 설계도로 활용하는 것이 적절함
* **주의 사항:** 동일 IP에서 대량의 API 요청 발생 시(예: 사피 동시 실습) 봇 차단 및 포비든(403) 오류 발생 가능성 인지
* **AI 활용 팁:** 랭플로우의 `Export` 기능을 활용하여 제이슨(JSON) 형태의 설계도를 팀원과 공유함으로써 프로젝트 개발 병목 현상 해소
