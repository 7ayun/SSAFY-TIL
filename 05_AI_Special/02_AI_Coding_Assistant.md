# [AI_Special] AI 코딩 어시스턴트 실습(AI Coding Assistant)

> **핵심 키워드:** #AI_Coding_Assistant #Role_Partitioning #Prompt_Engineering #TypingMind #Orchestrator

---

## 🎯 학습 목표
* 단순 반복 작업 탈피 및 AI 에이전트 활용 능력 중심의 생산성 향상 도모
* AI 출력에 대한 맹목적 의존 지양 및 작업 범위와 책임 정의를 통한 통제권 확보
* AI를 단순 챗봇이 아닌 '부하 직원'으로 대우하는 AI 네이티브 개발자 역량 강화
* 기획, 구현, 검증 프로세스를 직접 설계하고 제어하는 오케스트레이터 역할 수행

## 💡 주요 개념 정리
### 1. AI 코딩 어시스턴트 활용 배경
* **생산성 혁명:** 단순 반복 작업의 비약적 감소 및 효율적 개발 환경 구축
* **채용 트렌드 변화:** 기술 스택 이해를 넘어 AI 에이전트 활용 및 통제 능력의 중요성 대두
* **책임의 주체:** AI 결과물에 대한 최종 판단 및 개발자 본인의 책임 귀속

### 2. 기존 LLM 사용의 한계 및 에이전트의 등장
* **단일 세션의 한계:** 한 채팅창 내 기획, 구현, 수정, 검증 병행 시 맥락 혼선 및 부작용(Side Effect) 발생
* **AI 에이전트 구조:** 목표 달성을 위해 '생각(Reasoning) → 행동(Acting) → 관찰(Observation)'을 반복하는 ReAct 기법 기반 시스템

### 3. 프롬프트 엔지니어링 (Prompt Engineering) 심화
* **페르소나(Persona) 부여:** 특정 연차나 직무(예: 10년 차 아키텍트) 설정으로 답변 품질 상향 평준화
* **맥락(Context) 제공:** 프로젝트 배경, 목표, 제약 사항의 구체적 명시
* **출력 형식 지정:** 결과물의 구조적 활용을 위한 마크다운 등 특정 포맷 강제
* **고급 기법:**
    * **Few-shot Prompting:** 원하는 답변 양식의 예시 제공을 통한 패턴 학습
    * **Chain of Thought (CoT):** 논리적 추론 극대화를 위한 단계별 사고 유도

### 4. 핵심 전략: 역할 분리 (계-생-검 프로세스)
| 구분 | 역할 (Role) | 주요 임무 및 책임 | 금지 및 주의 사항 |
| :--- | :--- | :--- | :--- |
| **플래너** | 계획 (Planner) | 요구사항 분석, 기능 명세, 개발 단계별 계획 수립 | 코드 직접 작성 및 추측성 기능 추가 금지 |
| **제너레이터** | 생성 (Generator) | 플래너의 명세서 기반 실제 소스 코드 구현 | 계획 임의 수정 금지 및 주어진 명세 준수 |
| **리뷰어** | 검증 (Reviewer) | 코드 검증, 요구사항 충족 확인, 버그 분석 | 코드 직접 수정 금지 및 피드백 기반 루프 형성 |

## 💻 기능 구현 및 코드 실습
```markdown
# [TypingMind] 프롬프트 라이브러리 구성을 위한 시스템 프롬프트 예시
# 역할별 전문성 확보 및 세션 분리를 위한 가이드라인

## 1. 플래너(Planner) 페르소나
- 요구사항 분석 기반 상세 개발 명세서 작성 전략가
- 코드 작성 절대 금지 및 구현 가능한 논리적 단계만 마크다운 출력

## 2. 제너레이터(Generator) 페르소나
- 전달받은 명세서 바탕의 완벽한 코드 작성 시니어 개발자
- 명세 외 기능 추가 및 로직 임의 변경 금지

## 3. 리뷰어(Reviewer) 페르소나
- 코드 안정성 및 요구사항 일치 여부 판별 QA 전문가
- 직접 수정 금지 및 발견된 문제점과 개선 방향 피드백 전달
```

## 🚀 복습 및 AI 인사이트
* **헷갈렸던 점 1:** 단일 채팅창 사용 시 AI 망각 현상 및 할루시네이션 심화 인지
* **헷갈렸던 점 2:** 리뷰어 피드백을 제너레이터에게 직접 전달하기보다 플래너를 통한 계획 수정 루프의 효율성 확인
* **AI 활용 팁:** '프롬프트를 위한 프롬프팅' 활용을 통한 프로젝트 상황별 최적화된 플래너 프롬프트 생성 지시
