# [DB] 팔로우 기능 구현

---

## 1. 프로필 페이지

팔로우 버튼을 배치할 바탕이 되는 프로필 페이지를 먼저 구현한다.

**URL 설계**

- 프로필 페이지는 유저 관련 기능이므로 `accounts` 앱의 `urls.py`에 추가한다.
- 유저를 특정하는 값으로 PK 대신 `username`을 사용한다.
  - 인스타그램처럼 `username`도 고유한 값이므로 URL에 자연스럽게 쓸 수 있다.

```python
# accounts/urls.py
app_name = 'accounts'
urlpatterns = [
    ...
    path('profile/<username>/', views.profile, name='profile'),
]
```

**View 함수**

- 유저 모델은 직접 `import`하지 않고 `get_user_model()`을 사용한다.
  - `settings.AUTH_USER_MODEL`은 `models.py` 전용, 나머지 파일에서는 `get_user_model()` 사용
- URL로 전달된 `username`으로 유저를 조회해 `person`에 담아 템플릿에 전달한다.

```python
# accounts/views.py
from django.contrib.auth import get_user_model

def profile(request, username):
    User = get_user_model()
    person = User.objects.get(username=username)
    context = {
        'person': person,
    }
    return render(request, 'accounts/profile.html', context)
```

**Template**

`person` 객체의 역참조를 통해 게시글·댓글·좋아요한 게시글을 출력한다.

```html
<!-- accounts/profile.html -->
<h1>{{ person.username }} 님의 프로필</h1>
<hr>

<h2>{{ person.username }}가 작성한 게시글</h2>
{% for article in person.article_set.all %}
  <div>{{ article.title }}</div>
{% endfor %}
<hr>

<h2>{{ person.username }}가 작성한 댓글</h2>
{% for comment in person.comment_set.all %}
  <div>{{ comment.content }}</div>
{% endfor %}
<hr>

<h2>{{ person.username }}가 좋아요한 게시글</h2>
{% for article in person.like_articles.all %}
  <div>{{ article.title }}</div>
{% endfor %}
```

> `like_articles`는 Article 모델에 설정한 `ManyToManyField`의 `related_name`이다.

**프로필 링크 추가**

- 내 프로필로 가는 링크: `request.user.username` 전달
- 게시글 작성자 프로필로 가는 링크: `article.user.username` 전달

```html
<!-- articles/index.html -->
{% if request.user.is_authenticated %}
  <a href="{% url 'accounts:profile' user.username %}">내 프로필</a>
{% endif %}

{% for article in articles %}
  <p>작성자: <a href="{% url 'accounts:profile' article.user.username %}">{{ article.user }}</a></p>
{% endfor %}
```

## 2. 팔로우 모델 관계 설정

팔로우는 **유저 ↔ 유저** 간 N:M 관계이므로, 자기 자신을 참조하는 **self 관계**가 필요하다.

**핵심 설정**

```python
# accounts/models.py
class User(AbstractUser):
    followings = models.ManyToManyField('self', symmetrical=False, related_name='followers')
```

| 속성 | 설명 |
|------|------|
| `'self'` | 자기 자신(User 모델)을 참조. 문자열로 작성해 지연 평가 |
| `symmetrical=False` | 단방향 팔로우 허용. 기본값 `True`이면 A→B 팔로우 시 B→A도 자동 생성됨 |
| `related_name='followers'` | 역참조 이름. 미설정 시 `user_set`으로 생성되어 모호해짐 |

- `followings`: 내가 팔로우하는 사람들 (참조)
- `followers`: 나를 팔로우하는 사람들 (역참조)

**마이그레이션 결과**

중개 테이블 `accounts_user_followings`가 생성되며, 컬럼 구성은 다음과 같다.

| 컬럼 | 의미 |
|------|------|
| `from_user_id` | 팔로우를 건 유저 (참조 방향의 출발) |
| `to_user_id` | 팔로우를 받은 유저 (참조 방향의 도착) |

- `(2, 1)` 데이터 → 2번 유저가 1번 유저를 팔로잉
- `(1, 2)` 데이터가 없다면 → 1번은 2번을 팔로잉하지 않음 (맞팔 아님)

## 3. 팔로우 기능 구현

**URL**

```python
# accounts/urls.py
path('<int:user_pk>/follow/', views.follow, name='follow'),
```

**View 함수**

- `me`: 현재 로그인 유저 (`request.user`)
- `you`: 팔로우 대상 유저 (URL의 `user_pk`로 조회)
- 자기 자신은 팔로우할 수 없도록 `if me != you` 조건을 먼저 검사한다.

```python
# accounts/views.py
@login_required
def follow(request, user_pk):
    User = get_user_model()
    you = User.objects.get(pk=user_pk)

    if you != request.user:
        if request.user in you.followers.all():
            you.followers.remove(request.user)   # 언팔로우
        else:
            you.followers.add(request.user)      # 팔로우

    return redirect('accounts:profile', you.username)
```

**Template**

```html
<!-- accounts/profile.html -->
<div>
  팔로잉: {{ person.followings.all|length }} / 팔로워: {{ person.followers.all|length }}
</div>

{% if request.user != person %}
  <div>
    <form action="{% url 'accounts:follow' person.pk %}" method="POST">
      {% csrf_token %}
      {% if request.user in person.followers.all %}
        <input type="submit" value="Unfollow">
      {% else %}
        <input type="submit" value="Follow">
      {% endif %}
    </form>
  </div>
{% endif %}
```

- `request.user != person` 조건으로 본인 프로필에서는 팔로우 버튼을 숨긴다.
- 이미 팔로우 중이면 Unfollow, 아니면 Follow 버튼을 출력한다.

## 💡 한 줄 요약
> 팔로우 기능은 `ManyToManyField('self', symmetrical=False)`로 유저 간 단방향 N:M 관계를 설계하고, `followers`/`followings`로 참조·역참조를 명확히 구분해 구현한다.

## ❓ 더 찾아볼 것

- ManyToManyField의 `symmetrical` 옵션이 실제 DB 레벨에서 어떻게 동작하는지
- `add()`, `remove()` vs `exists()` 성능 비교
