# [DB] 좋아요 기능 구현

---

## 1. 모델 관계 설계

좋아요 기능은 **게시글(Article)과 유저(User) 간의 M:N 관계**다.

- 게시글은 좋아요가 없을 수도 있고, 여러 유저에게 좋아요를 받을 수 있다
- 유저도 좋아요를 한 번도 안 누를 수 있고, 여러 게시글에 좋아요를 누를 수 있다

`ManyToManyField`는 `Article`과 `User` 어느 쪽에 두어도 상관없지만, 교재에서는 `Article` 모델에 작성했다.

```python
# articles/models.py

class Article(models.Model):
    user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    like_users = models.ManyToManyField(settings.AUTH_USER_MODEL, related_name='like_articles')
    title = models.CharField(max_length=10)
    content = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
```

> User 모델은 항상 직접 참조(`User`) 대신 `settings.AUTH_USER_MODEL`로 간접 참조한다.

## 2. 역참조 매니저 충돌 문제와 해결

`ManyToManyField`를 추가하고 `makemigrations`를 실행하면 아래와 같은 에러가 발생한다.

```
SystemCheckError: System check identified some issues:

ERRORS:
articles.Article.like_users: (fields.E304) Reverse accessor 'User.article_set'
for 'articles.Article.like_users' clashes with reverse accessor for
'articles.Article.user'.
HINT: Add or change a related_name argument to the definition for
'articles.Article.like_users' or 'articles.Article.user'.
```

**충돌 원인**

`User`와 `Article` 사이에는 이미 두 가지 관계가 존재한다.

| 관계 | 방향 | 역참조 기본 이름 |
|------|------|-----------------|
| ForeignKey (작성자) | Article → User (N:1) | `user.article_set` |
| ManyToManyField (좋아요) | Article ↔ User (M:N) | `user.article_set` ← **충돌!** |

두 역참조 이름이 모두 `article_set`으로 생성되어 충돌이 발생한다.

**해결: `related_name` 설정**

일반적으로 **M:N 쪽의 역참조 이름을 변경**한다. N:1에서의 `_set`은 소유(소속) 관계를 표현하는 직관적인 이름이라 그대로 두는 것이 관례다.

```python
like_users = models.ManyToManyField(
    settings.AUTH_USER_MODEL,
    related_name='like_articles'  # article_set → like_articles로 변경
)
```

> **M:N 쪽을 바꾸는 이유** — N:1 관계는 '소유'의 의미를 가지므로 기본값(`_set`)이 직관적이다. M:N 관계는 '행위'의 의미를 가지므로 그 행위를 표현하는 구체적인 이름(`like_articles`)을 부여한다.

## 3. User-Article 간 전체 Related Manager 정리

| 접근 코드 | 관계 유형 | 의미 |
|-----------|-----------|------|
| `article.user` | N:1 참조 | 게시글을 작성한 유저 |
| `user.article_set` | N:1 역참조 | 유저가 작성한 게시글 |
| `article.like_users` | M:N 참조 | 게시글에 좋아요를 누른 유저 |
| `user.like_articles` | M:N 역참조 | 유저가 좋아요 누른 게시글 |

## 5. 좋아요 기능 구현 — View

좋아요 기능은 토글 방식으로 동작한다. 이미 좋아요를 누른 상태면 취소, 누르지 않은 상태면 추가한다.

```python
# articles/views.py

@login_required
def likes(request, article_pk):
    article = Article.objects.get(pk=article_pk)

    if request.user in article.like_users.all():
        # 이미 좋아요를 누른 상태 → 취소 (관계 삭제)
        article.like_users.remove(request.user)
    else:
        # 좋아요를 누르지 않은 상태 → 추가 (관계 생성)
        article.like_users.add(request.user)

    return redirect('articles:index')
```

> **동등한 두 가지 표현** — 아래 두 코드는 완전히 동일하게 동작한다.
> ```python
> article.like_users.remove(request.user)
> request.user.like_articles.remove(article)
> ```
> M:N 관계는 소유가 없는 동등한 관계이므로 어느 쪽에서 조작해도 결과가 같다.

## 6. 좋아요 기능 구현 — Template

게시글 목록 페이지에서 현재 유저의 좋아요 여부에 따라 버튼 텍스트를 다르게 표시한다.

```html
<!-- articles/index.html -->

{% for article in articles %}
  ...
  <form action="{% url 'articles:likes' article.pk %}" method="POST">
    {% csrf_token %}
    {% if request.user in article.like_users.all %}
      <input type="submit" value="좋아요 취소">
    {% else %}
      <input type="submit" value="좋아요">
    {% endif %}
  </form>
{% endfor %}
```

- 좋아요 버튼은 **POST 요청** 방식 (DB 데이터를 조작하는 행위이므로)
- 반복문 안에서 `article.pk`를 URL에 전달해 게시글마다 다른 주소를 가짐

**좋아요 수 표시**

```html
{{ article.like_users.all|length }}
```

## 7. forms.py에서 like_users 필드 제외

`Article`에 `ManyToManyField`가 추가되었기 때문에, 게시글 작성 폼에서 해당 필드를 제외해야 한다.

```python
# articles/forms.py

class ArticleForm(forms.ModelForm):
    class Meta:
        model = Article
        exclude = ('user', 'like_users',)  # like_users 추가
```

좋아요 정보는 유저가 직접 입력하는 것이 아니라 시스템이 처리해야 하기 때문이다.

## 💡 한 줄 요약

> 게시글과 유저의 M:N 관계인 좋아요 기능은 `ManyToManyField`로 관계를 설정하고, 역참조 충돌 시 `related_name`으로 해결하며, view에서 `in` 연산자로 기존 관계 여부를 확인해 `add()`/`remove()`로 토글한다.
