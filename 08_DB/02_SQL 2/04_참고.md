## 1. SQLite 타입 선호도 (Type Affinity)

- SQLite는 데이터 타입이 **5가지**뿐 (INTEGER, TEXT, REAL, BLOB, NUMERIC)
- `VARCHAR(100)`, `INT` 등 다른 타입 키워드를 써도 내부적으로 5가지로 변환됨
- → SQLite가 자동으로 타입을 **추론**하는 것

### 장단점

| | 내용 |
|---|---|
| 장점 | 유연성 높음, 타입 실수해도 에러 적음, 다른 DBMS로 이식 시 호환성 높음 |
| 단점 | 세밀한 타입 제약 조건을 걸기 어려움 |

> MySQL은 데이터 타입이 30개 이상  
> Django가 SQLite 위에서 ORM으로 추가 유효성 검사를 하는 이유도 이 때문

## 2. NOT NULL 제약조건

- 모든 필드에 NOT NULL을 써야 하는 건 아니지만 대부분 사용
- NULL 대신 `0`이나 빈 문자열 `''`로 대체하는 것이 일반적
- NULL은 `=`으로 값 비교가 안 되고 `IS NULL`로만 비교 가능
  - NULL을 처음 고안한 사람도 이 설계를 실수로 인정한 적 있음

---

## 3. SQLite 날짜와 시간

- SQLite에는 날짜/시간 전용 데이터 타입이 **없음**
- 대신 함수를 사용해 `TEXT`, `REAL`, `INTEGER` 값으로 저장
- 참고: https://www.sqlite.org/datatype3.html
