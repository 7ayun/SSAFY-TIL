## 1. 댓글 CREATE

### forms.py - CommentForm 작성

```python
# articles/forms.py
from .models import Article, Comment

class CommentForm(forms.ModelForm):
    class Meta:
        model = Comment
        fields = ('content',)  # article(FK) 필드는 사용자 입력 대상이 아님
```

> FK 필드(`article`)는 사용자가 입력하는 것이 아닌 view에서 직접 처리
> → form에 article 필드가 노출되면 사용자가 임의로 게시글을 선택할 수 있는 문제 발생

### urls.py

```python
# articles/urls.py
urlpatterns = [
    ...
    path('<int:pk>/comments/', views.comments_create, name='comments_create'),
]
```

### views.py - comments_create

```python
# articles/views.py
from .models import Article, Comment
from .forms import ArticleForm, CommentForm

def detail(request, pk):
    article = Article.objects.get(pk=pk)
    comment_form = CommentForm()
    context = {
        'article': article,
        'comment_form': comment_form,
    }
    return render(request, 'articles/detail.html', context)

def comments_create(request, pk):
    article = Article.objects.get(pk=pk)  # URL로 전달받은 pk로 게시글 조회
    comment_form = CommentForm(request.POST)
    if comment_form.is_valid():
        comment = comment_form.save(commit=False)  # DB 저장 보류
        comment.article = article                  # FK 필드에 게시글 객체 할당
        comment.save()                             # 이제 저장
    return redirect('articles:detail', article.pk)
```

> **`save(commit=False)`**: 인스턴스는 반환하되 DB에 저장하지 않음  
> → article 할당 후 저장해야 하기 때문에 필요한 단계

### detail.html - 댓글 작성 폼

```html
<!-- articles/detail.html -->
<form action="{% url 'articles:comments_create' article.pk %}" method="POST">
  {% csrf_token %}
  {{ comment_form }}
  <input type="submit" value="댓글 작성">
</form>
```

## 2. 댓글 READ

### views.py - detail 함수 수정

```python
def detail(request, pk):
    article = Article.objects.get(pk=pk)
    comment_form = CommentForm()
    comments = article.comment_set.all()  # 역참조로 해당 게시글의 댓글만 조회
    context = {
        'article': article,
        'comment_form': comment_form,
        'comments': comments,
    }
    return render(request, 'articles/detail.html', context)
```

### detail.html - 댓글 목록 출력

```html
<h4>댓글 목록</h4>
<ul>
  {% for comment in comments %}
    <li>{{ comment.content }}</li>
  {% empty %}
    <p>아직 댓글이 없어요</p>
  {% endfor %}
</ul>
```

> **`{% empty %}`**: 댓글이 없을 때 대체 콘텐츠를 출력하는 Django 템플릿 문법  
> 사용자 경험(UX) 향상을 위해 활용

## 3. 댓글 DELETE

### urls.py

```python
# variable routing으로 게시글 pk와 댓글 pk 두 개 모두 전달
path('<int:article_pk>/comments/<int:comment_pk>/delete/', views.comments_delete, name='comments_delete'),
```

### views.py - comments_delete

```python
def comments_delete(request, article_pk, comment_pk):
    comment = Comment.objects.get(pk=comment_pk)
    comment.delete()
    return redirect('articles:detail', article_pk)
```

### detail.html - 삭제 버튼

```html
{% for comment in comments %}
  <li>
    {{ comment.content }}
    <form action="{% url 'articles:comments_delete' article.pk comment.pk %}" method="POST">
      {% csrf_token %}
      <input type="submit" value="DELETE">
    </form>
  </li>
{% endfor %}
```

## 💡 한 줄 요약
> 댓글 CREATE는 `save(commit=False)`로 인스턴스를 반환받아 FK를 할당 후 저장하고, READ는 역참조(`comment_set.all()`)로 조회하며, DELETE는 URL에 article_pk와 comment_pk를 모두 전달한다
