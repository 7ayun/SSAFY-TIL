# [DB] 관계 모델 참조

## 1. 참조 vs 역참조

| 구분 | 방향 | 설명 |
|---|---|---|
| **참조 (정참조)** | N → 1 | FK를 가진 쪽(댓글)에서 반대쪽(게시글)을 참조 |
| **역참조** | 1 → N | FK가 없는 쪽(게시글)에서 자신을 참조하는 쪽(댓글)을 참조 |

- 참조는 마치 "친구의 전화번호를 저장해두고 언제든 연락하는 것"과 같음
- 댓글은 FK 필드(`article`)를 통해 언제든 게시글에 접근 가능
- 게시글은 댓글의 존재를 직접 알 방법이 없음 → **역참조** 필요

---

## 2. 역참조

- 1쪽(게시글)에서 N쪽(댓글)을 조회하는 것
- 게시글 모델 코드에는 아무런 변경이 없지만, Django가 **related manager**를 자동 생성해줌

### related manager

```python
article.comment_set.all()  # 특정 게시글의 댓글 전체 조회
```

| 구성 요소 | 설명 |
|---|---|
| `article` | 모델 인스턴스 (게시글 객체) |
| `comment_set` | related manager (역참조 이름, Django가 자동 생성) |
| `.all()` | QuerySet API |

- `comment_set`이라는 이름 규칙: **`모델명(소문자)_set`**
- `objects` 매니저처럼 related manager를 통해 QuerySet API 사용 가능
- `related_name`을 별도로 설정하지 않으면 Django가 기본적으로 `모델명_set` 형식으로 생성

### 잘못된 방법 vs 역참조

```python
# ❌ 잘못된 방법: 모든 댓글 조회 (게시글 구분 없음)
Comment.objects.all()

# ❌ 비효율적인 방법: 기준점이 댓글로 바뀜
article = Article.objects.get(pk=1)
Comment.objects.filter(article=article)

# ✅ 역참조: 게시글 기준으로 직관적으로 댓글 조회
article.comment_set.all()
```

---

## 💡 한 줄 요약
> 역참조는 FK가 없는 1쪽(게시글)에서 N쪽(댓글)을 조회하는 것으로, Django가 자동 생성하는 `모델명_set` related manager를 사용한다

## ❓ 더 찾아볼 것
- `related_name` 옵션으로 역참조 이름 변경하는 방법
- `comment_set.filter()`, `comment_set.count()` 등 다양한 QuerySet API 활용
