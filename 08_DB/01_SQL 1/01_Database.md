# [DB] Database

---

## 1. Database란?

- **데이터베이스**: 체계적으로 정리된 데이터의 모음
- 책장처럼 데이터를 구조적으로 저장해야 빠르게 찾고 효율적으로 관리할 수 있음

## 2. Data란?

- **데이터**: 저장이나 처리를 위해 변환된 정보
- DIKW 피라미드로 데이터의 계층을 이해할 수 있음

| 계층 | 설명 | 예시 (체온) |
|---|---|---|
| Data | 원재료, 가공되지 않은 수치 | 37.5 |
| Information | 의미가 부여된 데이터 | 체온 37.5도 |
| Knowledge | 해석이 들어간 정보 | 미열이 있다 |
| Wisdom | 판단 | 아직 약을 먹지 않아도 된다 |

> 데이터베이스에 저장하는 건 맨 아래의 **Data** 계층 → 위로 올라갈수록 사람의 해석이 필요

## 3. 데이터 저장 방식의 발전

| 방식 | 특징 | 한계 |
|---|---|---|
| 파일(File) | 어디서나 쉽게 사용 | 구조적 관리 어려움 |
| 스프레드시트 | 행/열로 구조적 관리 가능 | 크기·보안·정확성 한계 |
| 데이터베이스 | 구조적 + 관계 기반 관리 | - |

**스프레드시트의 한계**
- **크기**: 약 100만 행까지만 저장 가능
- **보안**: 파일/링크 소유 여부의 단순한 접근 권한만 제공
- **정확성**: 데이터가 여러 시트에 분산된 경우 변경 시 누락/오류 발생 가능

## 4. 데이터베이스의 역할 - CRUD

- **C**reate / **R**ead / **U**pdate / **D**elete

## 5. Relational Database (관계형 데이터베이스)

- **정의**: 데이터 간에 **관계**가 있는 데이터 항목들의 모음
- 테이블은 물리적으로 나뉘어져 있지만 **공통된 키(Key)를 통해 논리적으로 연결**

### 관련 키워드 6가지

| 키워드 | 별칭 | 설명 |
|---|---|---|
| Table | Relation | 데이터를 기록하는 곳 |
| Field | Column, Attribute | 각 필드에는 고유한 데이터 타입/제약조건이 지정됨 |
| Record | Row, Tuple | 각 레코드에는 구체적인 데이터 값이 저장됨 |
| Database | Schema | 테이블들의 집합 |
| Primary Key (PK) | 기본 키 | 각 레코드의 고유한 값, 레코드의 식별자로 활용 |
| Foreign Key (FK) | 외래 키 | 다른 테이블의 PK를 참조하여 테이블 간 관계를 맺는 필드 |

> 강의에서는 Column 대신 **Field**라는 용어를 주로 사용

## 6. RDBMS

- **RDBMS** (Relational Database Management System): 관계형 데이터베이스를 관리해주는 소프트웨어 프로그램
- 실시간 모니터링, 백업, 복구 등을 지원

| RDBMS | 특징 |
|---|---|
| SQLite | 경량, 오픈소스, 모바일/소규모 프로젝트에 많이 사용. 스마트폰 앱에도 수십 개 탑재됨 |
| MySQL | 국내 점유율 가장 높음 |
| PostgreSQL | 최근 5년간 점유율 급성장 |
| Oracle | 대기업 대규모 DB에 사용, 유료 |

> 모두 SQL 표준을 지원하지만 RDBMS마다 독자적인 기능이 있어 서로 호환되지 않는 문법도 존재
