# [Django] 역참조 데이터 구성

---

## 1. 역참조 개요

게시글(Article)을 조회할 때 기본적으로 **댓글 데이터는 포함되지 않는다.** N:1 관계에서 외래키는 N쪽(Comment)에 있기 때문에, 1쪽(Article)은 N에 대한 물리적인 필드를 가지지 않기 때문이다.

단, Django는 자동으로 **역참조 매니저(`comment_set`)**를 생성한다. 이를 DRF에서 활용하면 게시글 조회 시 댓글 데이터를 함께 제공할 수 있다.

DRF에서 모델 관계상 역참조 매니저를 활용하는 것을 **Nested Relationship(중첩 관계)**이라고 표현한다.

오늘 구현할 두 가지 역참조 커스텀:

1. 단일 게시글 조회 시 → 해당 게시글에 작성된 **댓글 목록** 함께 응답
2. 단일 게시글 조회 시 → 해당 게시글에 작성된 **댓글 개수** 함께 응답

## 2. 단일 게시글 + 댓글 목록

### 접근 방식

`ArticleSerializer` 내부에서 댓글 목록 직렬화 도구를 중첩 정의하고, `comment_set`(역참조 매니저)을 재정의한다.

```python
# articles/serializers.py
class ArticleSerializer(serializers.ModelSerializer):

    # 게시글 + 댓글 목록 조회를 위한 댓글 직렬화 도구 (내부 중첩 정의)
    class CommentDetailSerializer(serializers.ModelSerializer):
        class Meta:
            model = Comment
            fields = ('id', 'content')  # 메인은 게시글이므로 댓글은 필요한 필드만

    # 기존 역참조 매니저 comment_set을 위 도구의 결과로 재정의
    comment_set = CommentDetailSerializer(read_only=True, many=True)  # 1:N → 다중이므로 many=True 필수

    class Meta:
        model = Article
        fields = '__all__'
```

**핵심 포인트:**
- 변수명은 반드시 역참조 매니저 이름인 **`comment_set`**과 일치해야 한다
- N쪽 데이터는 항상 쿼리셋이므로 **`many=True`** 필수
- 사용자 입력 데이터가 아니므로 **`read_only=True`** 필수 (없으면 POST/PUT 시 유효성 검사 에러)

### 응답 결과

```json
{
    "id": 3,
    "title": "게시글 제목",
    "content": "게시글 내용",
    "comment_set": [
        { "id": 16, "content": "댓글 내용 A" },
        { "id": 17, "content": "댓글 내용 B" }
    ]
}
```

### 역참조 매니저 이름 변경 (related_name)

`comment_set`이라는 이름이 마음에 들지 않으면 `ForeignKey`에 `related_name`을 지정해 변경할 수 있다. 단, 모델을 변경하는 것이므로 **마이그레이션이 필요**하고, Serializer의 변수명도 함께 수정해야 한다.

```python
# articles/models.py
class Comment(models.Model):
    article = models.ForeignKey(Article, on_delete=models.CASCADE, related_name='comments')
    ...
```

```python
# articles/serializers.py
comments = CommentDetailSerializer(read_only=True, many=True)  # 이름도 변경
```

## 3. 단일 게시글 + 댓글 개수

### 핵심 개념

댓글 개수는 모델 필드에 존재하지 않는 **완전히 새로운 필드**다. 역참조 매니저를 재정의하는 것과 달리, 직접 연산해서 응답에 추가해야 한다.

**두 가지 구현 방법:**

| 방법 | 위치 | 특징 |
|------|------|------|
| `annotate` 사용 | View | 쿼리 시점에 DB에서 집계, 권장 구조 |
| 역참조 직접 카운트 | Serializer 메서드 | `annotate` 없이도 가능, Serializer에 로직이 혼재 |

> **권장:** View에서 복잡한 쿼리를 처리하고, Serializer는 직렬화에만 집중하는 구조가 유지보수에 유리하다.

### Step 1 — View에서 annotate로 댓글 개수 함께 조회

`annotate`는 SQL의 `GROUP BY`에 해당하며, 조회 시 집계 결과를 새 필드로 붙여준다. 실제 테이블은 변경되지 않는다.

```python
# articles/views.py
from django.db.models import Count

@api_view(['GET', 'PUT', 'DELETE'])
def article_detail(request, article_pk):
    # annotate로 댓글 개수를 num_of_comments 필드로 함께 조회
    article = Article.objects.annotate(
        num_of_comments=Count('comment')
    ).get(pk=article_pk)
    ...
```

이제 `article.num_of_comments`로 댓글 개수에 접근할 수 있다.

### Step 2 — SerializerMethodField로 새 필드 추가

`num_of_comments`는 모델의 실제 필드가 아니므로 `fields = '__all__'`에 포함되지 않는다. 이를 응답에 포함하려면 **SerializerMethodField**를 사용한다.

```python
# articles/serializers.py
class ArticleSerializer(serializers.ModelSerializer):

    # 댓글 목록 (앞에서 정의한 것과 동일)
    class CommentDetailSerializer(serializers.ModelSerializer):
        class Meta:
            model = Comment
            fields = ('id', 'content')

    comment_set = CommentDetailSerializer(read_only=True, many=True)

    # 완전히 새로운 필드 선언
    num_of_comments = serializers.SerializerMethodField()

    class Meta:
        model = Article
        fields = '__all__'

    # 반드시 get_<필드명> 형태로 메서드를 정의해야 연결됨 (DRF 규칙)
    def get_num_of_comments(self, obj):
        # obj = 현재 직렬화 중인 Article 인스턴스
        return obj.num_of_comments  # annotate로 미리 계산된 값 사용
```

### 응답 결과

```json
{
    "id": 3,
    "title": "게시글 제목",
    "comment_set": [...],
    "num_of_comments": 2
}
```

## 4. SerializerMethodField 정리

새로운 필드 값을 추가로 계산하여 응답에 포함할 때 사용하는 DRF 전용 필드다.

**동작 규칙 (반드시 지켜야 하는 약속):**

```python
# 1. 필드 선언
필드명 = serializers.SerializerMethodField()

# 2. 메서드 정의 — 이름 규칙: get_<필드명>
def get_<필드명>(self, obj):
    # obj: 이 Serializer가 처리하는 모델의 인스턴스 (여기선 Article)
    return <반환할 값>
```

**annotate 없이 Serializer 내부에서 직접 계산하는 방법:**

```python
def get_num_of_comments(self, obj):
    # obj.comment_set.count() 로 역참조하여 직접 카운트
    num_of_comments = obj.comment_set.count()
    return num_of_comments
```

**특징:**
- 기본적으로 **읽기 전용** (별도 `read_only=True` 불필요)
- 생성/수정 요청 시 사용되지 않음
- 비율, 합계, 평균 등 복잡한 연산도 함수 내부에서 자유롭게 처리 가능

## 5. N에서 1 vs 1에서 N 비교

| 구분 | N → 1 (댓글이 게시글 정보 포함) | 1 → N (게시글이 댓글 정보 포함) |
|------|-------------------------------|-------------------------------|
| 외래키 존재 여부 | N에 외래키 있음 (상대적으로 쉬움) | 1에 외래키 없음 (역참조 필요) |
| 구현 방법 | 중첩 Serializer로 필드 재정의 | 역참조 매니저(`comment_set`) 재정의 |
| many 옵션 | 단일 인스턴스 → `many` 불필요 | 쿼리셋 → `many=True` 필수 |

---

## 💡 한 줄 요약

> 1에서 N을 참조할 때는 Django의 역참조 매니저(`comment_set`)를 Serializer에서 재정의하고, 완전히 새로운 집계 필드는 `annotate` + `SerializerMethodField`의 조합으로 응답에 추가한다.

## ❓ 더 찾아볼 것

- `annotate`와 `select_related` / `prefetch_related`의 쿼리 최적화 차이
- `SerializerMethodField`의 내부 `get_<필드명>` 자동 탐색 원리
- `related_name` 변경 후 마이그레이션이 필요한 이유
- View와 Serializer의 역할 분리 원칙 (비즈니스 로직 위치)
