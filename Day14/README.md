# 연결 리스트 · Deque · 피자 굽기(큐 시뮬레이션)

---

## 1. 오늘의 큰 흐름

1) **리스트(배열)의 한계**: 중간 삽입/삭제 시 데이터 이동 → 느림
2) **연결 리스트(Linked List)**: 논리적 순서와 물리적(메모리) 순서가 불일치
3) **단순 연결 리스트(Singly Linked List)**: `next`만으로 연결
4) **이중 연결 리스트(Doubly Linked List)**: `prev`, `next`로 양방향 연결 (+ `tail`로 끝 접근 최적화)
5) **Python `collections.deque`**: 양쪽 끝 삽입/삭제가 빠름 (`pop(0)` 대체)
6) **문제 적용**: 피자 굽기 = 큐 회전 + 상태 갱신(치즈 절반)

---

## 2. 리스트(배열) vs 연결 리스트

### 2.1 리스트(배열)의 특징

- 메모리에 **연속적으로** 저장되는 구조
- 장점: **인덱싱이 빠름** (`arr[i]`가 한 번에 접근)
- 단점: 중간 삽입/삭제 시 **뒤 원소들을 밀거나 당겨야 함** → 비용이 큼
  - `pop(0)`, `insert(중간, 값)` 같은 동작이 내부적으로 부담

### 2.2 연결 리스트의 핵심 개념

- **논리적 순서(보이는 순서)**와 **물리적 순서(실제 메모리 위치)**가 일치하지 않음
- 각 원소는 흩어져 있고, **다음 노드의 주소(참조)**를 통해 연결
- 장점: 중간 삽입/삭제가 **포인터(참조)만 바꾸면 됨**
- 단점: **인덱싱 불가**(한 번에 점프 불가) → 원하는 위치까지 순차 탐색

## 3. 단순 연결 리스트(Singly Linked List)

### 3.1 기본 구조

- **Head**: 시작 노드(첫 노드)를 가리키는 참조
- **Node(노드)**
  - `data`: 값
  - `next`: 다음 노드의 참조 (없으면 `None`)

> `next == None` 이면 **마지막 노드**

### 3.2 삽입(Insert) 3가지 케이스

#### (1) 첫 번째 위치(맨 앞) 삽입

- 새 노드 생성
- **새 노드의 next를 기존 head로 연결**
- **head를 새 노드로 갱신**

주의: 순서가 중요합니다.
- `new.next = head` 를 먼저 하고
- `head = new` 를 나중에 해야 기존 첫 노드를 잃지 않습니다.

#### (2) 마지막(맨 뒤) 삽입

- 새 노드 생성 (`new.next = None`)
- head부터 따라가며 **next가 None인 마지막 노드**를 찾음
- 마지막 노드의 `next = new`

#### (3) 중간 삽입

- 삽입 위치의 **바로 전 노드(current)**까지 이동
- 새 노드 생성
- `new.next = current.next`  (새 노드가 기존 다음 노드를 가리키게)
- `current.next = new`       (이전 노드가 새 노드를 가리키게)

요약 그림

- 원래: `current -> A`
- 삽입 후: `current -> new -> A`

### 3.3 삭제(Delete) 2가지 케이스

#### (1) 맨 앞 삭제

- 삭제 대상은 `head`
- `head = head.next`
- 삭제된 노드는 더 이상 접근 경로가 없어져 **고아 노드**가 됨

#### (2) 중간 삭제

- 삭제 대상의 **바로 전 노드(current)**를 찾음
- 삭제 대상: `delete = current.next`
- `current.next = delete.next`
- 필요하면 `delete.next = None`로 끊어 고아 노드화

> “데이터를 지운다”는 의미는 보통 **접근 경로를 끊는다**는 의미로 이해하면 흐름이 자연스럽습니다.

## 4. 이중 연결 리스트(Doubly Linked List)

### 4.1 구조

- Node가 두 방향 포인터를 가짐
  - `prev`: 이전 노드
  - `next`: 다음 노드

장점
- 양방향 순회 가능

추가 최적화
- `tail`(마지막 노드)을 관리하면 끝 삽입/끝 접근이 쉬워짐

### 4.2 중간 삽입(핵심 포인터 4곳)

`A <-> B` 사이에 `D` 삽입

- `D.prev = A`
- `D.next = B`
- `A.next = D`
- `B.prev = D`

### 4.3 삭제(핵심 포인터 2곳)

`A <-> B <-> C`에서 `B` 삭제

- `A.next = C`
- `C.prev = A`

## 5. deque (collections.deque)

### 5.1 왜 쓰나

- 리스트에서 `pop(0)`은 앞에서 빼고 뒤 원소를 당기는 작업이 발생할 수 있음
- 큐처럼 **앞에서 꺼내는 작업**이 반복되면 `deque`가 유리

### 5.2 자주 쓰는 메서드

- `append(x)` : 오른쪽에 추가
- `appendleft(x)` : 왼쪽에 추가
- `pop()` : 오른쪽에서 제거
- `popleft()` : 왼쪽에서 제거
- `rotate(k)` : 회전 (k>0 오른쪽, k<0 왼쪽)

### 5.3 시간 감각

- `popleft()`는 큐 구현에서 매우 자주 등장
- `deque[i]` 같은 인덱스 접근은 가능하더라도 내부적으로 비용이 커질 수 있으니 **큐처럼 쓰는 용도**로 사용

## 6. 문제 적용: 피자 굽기(큐 시뮬레이션)

### 6.1 문제 핵심 모델

- 화덕 크기: `N`
- 피자 개수: `M`
- 피자는 1번부터 순서대로 투입
- 화덕은 큐처럼 순환
- 꺼낼 때마다 치즈가 절반(`//2`)으로 줄어듦
- 치즈가 0이면 꺼내고, 남은 피자를 새로 투입
- 마지막에 남는 피자 번호 출력

### 6.2 자료구조 설계

- `oven`: 화덕(큐) → `deque`
  - 원소: `[피자번호(0-based), 치즈]`
- `waiting`: 아직 화덕에 못 들어간 피자들 → `deque`

### 6.3 구현 코드(주석 포함)

```python
from collections import deque

T = int(input())

for tc in range(1, T + 1):
    n, m = map(int, input().split())
    cheese = list(map(int, input().split()))

    oven = deque()
    waiting = deque()

    # 1) 화덕에 처음 N개 투입 (0-based 인덱스로 관리)
    for i in range(n):
        oven.append([i, cheese[i]])

    # 2) 남은 피자 대기열
    for i in range(n, m):
        waiting.append([i, cheese[i]])

    # 3) 화덕에 피자가 1개 남을 때까지 반복
    while len(oven) > 1:
        pizza = oven.popleft()
        pizza[1] //= 2  # 치즈 반으로

        if pizza[1] > 0:
            # 치즈가 남으면 다시 화덕으로
            oven.append(pizza)
        else:
            # 치즈가 0이면 제거되고, 대기 피자가 있으면 투입
            if waiting:
                oven.append(waiting.popleft())

    # 마지막 남은 피자 번호(문제는 1-based)
    answer = oven[0][0] + 1
    print(f"#{tc} {answer}")
```

### 6.4 실수 포인트

- 피자 번호를 **0-based로 넣었으면 출력 시 +1**
- 치즈는 `// 2` (정수 나눗셈)
- 치즈가 0이 될 때만 대기열에서 새 피자 투입
