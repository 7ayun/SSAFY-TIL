---

## 2. 강의 핵심 요약
1. 알고리즘은 **유한한 단계**로 문제를 해결하는 절차이며, “더 적은 연산”으로 같은 결과를 내는 것이 중요합니다.
2. 좋은 알고리즘은 **정확성(예외 포함)** + **효율(시간/공간)** + **유지보수성(단순성)** 기준으로 평가합니다.
3. 성능 비교는 주관이 아니라 **시간복잡도**로 정량화하며, 실전은 보통 **최악의 경우(Big-O)** 를 기준으로 봅니다.
4. 리스트는 다수의 데이터를 한 변수에 저장해 **순회(for)** 로 처리하는 기본 자료구조입니다.
5. SWEA는 스켈레톤 코드 + input.txt로 로컬 디버깅 → 사이트에 제출(제출 시 `import sys` 관련 주의) 흐름이 핵심입니다.

## 3. 개념 구조 정리
- 알고리즘/자료구조
  - 알고리즘 정의
    - 유한한 단계로 문제 해결
    - 다양한 해결 방법 중 “좋은 방법” 선택
  - 좋은 알고리즘 기준
    - 정확성(모든 케이스/예외)
    - 효율성
      - 시간복잡도
      - 공간복잡도
    - 단순성/가독성(유지보수)
    - 최적성
  - 성능 분석(정량화)
    - 시간복잡도
      - Big-O(최악)
      - Big-Ω(최선)
      - Big-Θ(평균/일반)
    - 빅오 표기법
      - 최고차항만 남김
      - 계수/상수 제거
  - 자료구조(알고리즘과 함께 학습)
    - 리스트(1차원)
    - (예고) 스택/큐/연결리스트/트리/그래프/DFS/BFS/DP...
- SWEA 문제풀이 루틴
  - 문제 읽기 → 입력 범위 확인 → 풀이 구상(노트) → 구현 → 디버깅 → 제출
  - 로컬: `input.txt` 사용
  - 제출: sys 관련 코드 정리(환경 차이)

## 4. 핵심 개념 상세 설명

### 4.1 알고리즘을 왜 배우나?
- **문제 해결 능력**: 문제를 읽고 → 해결 아이디어 만들고 → 코드로 구현
- **논리적 사고력**: 조건/반복/분기 구조로 사고 확장
- **취업(코딩테스트)**: 기업은 정답만이 아니라
  - 문제 접근 방식, 언어 이해도, 코딩 컨벤션, 예외 처리, 최적화, 주석/커뮤니케이션까지 종합 평가

### 4.2 시간복잡도 & Big-O
- 시간복잡도: 입력 크기 N이 커질 때 **연산 횟수가 어떻게 증가하는지**
- Big-O(빅오): **최악의 경우** 기준으로 성능을 표현
  - 이유: 실전은 “1%의 최악 케이스”가 전체 품질을 망가뜨릴 수 있으므로

#### 빅오로 바꾸는 규칙
- 다항식에서 **최고차항만 남기고**
- **계수/상수 제거**
- 예)
  - `3n + 2` → `O(n)`
  - `2n^2 + 10n + 100` → `O(n^2)`
  - `4` → `O(1)`

#### 대표 복잡도 감각
- `O(1)` : 입력 크기와 무관(예: 키로 즉시 조회)
- `O(log n)` : 반씩 줄여나감(업다운/이분 탐색 감각)
- `O(n)` : 한 번 훑기(선형 탐색)
- `O(n^2)` : 이중 for
- `O(n log n)` : 좋은 정렬들
- `O(2^n)`, `O(n!)` : 대부분 실전에서 사용 불가(입력 조금만 커져도 폭발)

### 4.3 시간 vs 공간 트레이드오프
- 빠르게 하려면 미리 저장(인덱싱 등) → 공간 증가
- 공간을 줄이면 계산을 더 해야 함 → 시간 증가
- “세상에 공짜는 없다” = 상황에 맞는 균형점 찾는 것이 실력

## 5. 실전 코드 패턴

### 5.1 표준 입력 기본
```python
T = int(input())
for tc in range(1, T + 1):
    n = int(input())
    arr = list(map(int, input().split()))
```

### 5.2 최대/최소 직접 구현(내장함수 없이)
```python
min_v = arr[0]
max_v = arr[0]

for x in arr:
    if x < min_v:
        min_v = x
    if x > max_v:
        max_v = x

ans = max_v - min_v
print(f"#{tc} {ans}")
```

### 5.3 숫자 카드(0~9) 빈도 카운트(리스트 카운팅)
```python
cards = list(map(int, input().strip()))  # 예: '49679' -> [4,9,6,7,9]
count = [0] * 10

for d in cards:
    count[d] += 1

best_num = 0
best_cnt = 0
for num in range(10):
    # 같은 장수면 큰 숫자 선택: '>=' 사용
    if count[num] >= best_cnt:
        best_cnt = count[num]
        best_num = num

print(f"#{tc} {best_num} {best_cnt}")
```

### 5.4 SWEA 로컬 디버깅(input.txt) 스켈레톤 패턴
```python
import sys
sys.stdin = open("input.txt", "r")

T = int(input())
for tc in range(1, T + 1):
    ...
```
- 로컬에서는 편함
- **제출 전에는** `sys.stdin = open(...)` 같은 파일 입력 코드는 제거/주석 처리

## 6. 실수 & 감점 포인트
1. **풀이 구상 없이 바로 코딩** → 디버깅 지옥(초보일수록 ‘노트 설계’ 먼저)
2. 입력 파싱 실수
   - `input().split()`은 공백 기준 분리(문자열 전체를 “숫자 덩어리”로 받을 때는 다르게)
   - `map`은 즉시 리스트가 아님 → 필요 시 `list()`로 감싸기
3. 테스트케이스 출력 형식
   - `#1 정답` 형식 누락하면 오답
4. 카운팅/최대값 갱신 조건
   - “같으면 큰 숫자” 조건이면 `>=`를 써야 함
5. 제출 환경 차이
   - 로컬 파일 입력 코드를 그대로 제출하면 실패 가능

## 7. 실전 대비 연습문제

### (1) Min-Max
- 입력: 정수 N개
- 출력: 최댓값-최솟값
- 조건: 내장 `min/max/sort` 금지 버전으로 구현

### (2) 숫자 카드(0~9)
- 입력: 길이 N의 숫자 문자열(예: 49679)
- 출력: 가장 많이 나온 숫자와 장수
- 동률이면 숫자가 큰 쪽

### (3) Gravity(핵심 아이디어만)
- 각 열 i의 낙차 = (오른쪽에 있는 열들 중 **현재 높이 이상인 개수**) 만큼 감소
- 기본 낙하 가능 칸 = (전체 길이 - 1 - i)
- 낙차 계산 감각을 `O(n^2)`로 먼저 구현해도 괜찮음(이후 최적화)

## 8. 시험 직전 5분 요약
- 알고리즘 = 유한한 단계로 문제 해결
- 좋은 알고리즘 = 정확성 + 시간/공간 효율 + 단순성

- 입력 파싱 템플릿: `arr = list(map(int, input().split()))`
- 출력 템플릿: `print(f"#{tc} {ans}")`
- 카운팅 동률 처리: `>=`
