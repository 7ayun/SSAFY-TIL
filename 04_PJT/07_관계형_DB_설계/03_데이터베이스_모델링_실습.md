## 1. 실습 개요: 레시피 관리 프로젝트

요리 레시피와 식재료를 관리하는 Django 앱을 만들면서, **1NF 위반 → 정규화 적용 → ManyToMany 관계** 로 발전시키는 과정이다.

## 2. 문제 상황: 1NF 위반 구조

처음 설계는 `MultipleChoiceField`를 사용해 재료 목록을 콤마 구분 문자열(리스트)로 저장하는 방식이었다.

```python
# foods/models.py
class Recipe(models.Model):
    name = models.CharField(max_length=200)
    description = models.TextField(blank=True)
    ingredients = models.CharField(max_length=600, blank=True)  # ← 문제!

    def __str__(self):
        return self.name
```

```python
# foods/forms.py
class RecipeForm(forms.ModelForm):
    ingredients = forms.MultipleChoiceField(
        choices=[
            ('TMT', '토마토'),
            ('OLV', '올리브'),
            ('PAS', '파스타'),
        ],
        widget=forms.CheckboxSelectMultiple,
    )
    class Meta:
        model = Recipe
        fields = '__all__'
```

**실행 결과 (DB 저장값)**
```
["TMT", "PAS"]   ← 하나의 컬럼에 리스트가 저장됨
```

**문제점 정리**

| 항목 | 문제 |
|------|------|
| 1NF 위반 | 하나의 컬럼에 여러 값이 저장됨 |
| 하드코딩 | 새 식재료 추가 시 코드 수정 → 커밋 → 배포까지 필요 |
| 삽입 이상 | 식재료만 등록하려면 레시피 이름도 억지로 입력해야 함 |
| 갱신 이상 | "파스타" → "스파게티" 변경 시 문자열 전체 탐색 필요 |

## 3. 해결: 정규화 및 모델 정의

### 관계 파악
- 하나의 레시피 → 여러 식재료 필요
- 하나의 식재료 → 여러 레시피에서 사용

→ **N:M 관계** → 중개 테이블이 필요하다.

### 테이블 분리

```python
# foods/models.py

# 식재료 모델 (분리)
class Ingredient(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name

# 레시피 모델 (ManyToManyField 적용)
class Recipe(models.Model):
    name = models.CharField(max_length=200)
    description = models.TextField()
    ingredients = models.ManyToManyField(
        Ingredient,
        related_name='recipes',  # 역참조 시 사용할 이름
    )

    def __str__(self):
        return self.name
```

### 마이그레이션 실행
```bash
python manage.py makemigrations
# - Create model Ingredient
# - Alter field description on recipe
# - Remove field ingredients from recipe (char -> m2m)
# - Add field ingredients to recipe

python manage.py migrate
```

Django가 `foods_recipe_ingredients`라는 **중개 테이블을 자동으로 생성**해준다.

## 5. Form 개선: 하드코딩 제거

### 기존 방식 (하드코딩)
```python
# 재료를 폼에 직접 하드코딩 → 재료 추가 시 코드 수정 필요
choices=[('TMT', '토마토'), ('OLV', '올리브'), ...]
```

### 개선 방식 (ModelMultipleChoiceField)
```python
# foods/forms.py
from .models import Recipe, Ingredient

class RecipeForm(forms.ModelForm):
    ingredients = forms.ModelMultipleChoiceField(
        queryset=Ingredient.objects.all(),  # DB에서 동적으로 가져옴
        widget=forms.CheckboxSelectMultiple,
        required=False
    )

    class Meta:
        model = Recipe
        fields = ['name', 'description', 'ingredients']
```

**핵심 차이**: `queryset=Ingredient.objects.all()`을 사용하면 DB에 식재료를 추가하기만 해도 폼에 자동으로 반영된다. **코드 수정 없이** 선택지를 관리할 수 있다.

### 필터링 응용 (Q 객체 활용)
```python
from django.db.models import Q

def get_filtered_ingredients():
    return Ingredient.objects.exclude(name__contains='매운').filter(
        Q(name__startswith='A') | Q(name__endswith='B')
    )

class RecipeForm(forms.ModelForm):
    ingredients = forms.ModelMultipleChoiceField(
        queryset=get_filtered_ingredients(),
        widget=forms.CheckboxSelectMultiple,
        required=False
    )
```

## 6. 레시피 저장 (Views)

Recipe 모델이 ManyToMany 관계의 **주체**이기 때문에, `form.save()`만으로 중개 테이블까지 자동으로 저장된다. 별도 전처리 불필요.

```python
# foods/views.py
recipe_form = RecipeForm(request.POST)
if recipe_form.is_valid():
    recipe_form.save()  # 중개 테이블까지 자동 저장
```

만약 **역방향** (Ingredient 쪽에서 Recipe를 연결하는 경우)이라면 수동으로 처리해야 한다:

```python
recipe = recipe_form.save()
ingredients = form.cleaned_data.get('ingredients')
for ingredient in ingredients:
    ingredient.recipes.add(recipe)  # related_name으로 역참조
```

```html

<ul>
  {% for ingredient in recipe.ingredients.all %}
    <li>{{ ingredient.name }}</li>
  {% endfor %}
</ul>
```

`recipe.ingredients.all()`로 해당 레시피의 모든 재료를 역참조해 가져올 수 있다.

## 💡 한 줄 요약
> 1NF 위반인 다중값 컬럼은 별도 테이블로 분리하고, N:M 관계는 `ManyToManyField`로 연결하면 Django가 중개 테이블을 자동으로 관리해준다.

## ❓ 더 찾아볼 것

- `prefetch_related` vs `select_related` — N:M 관계 조회 성능 최적화
