# [관통 PJT] 프로젝트 기획과 설계

---

## 1. 기획과 설계란?

**기획(Planning)** 은 프로젝트의 목표와 전략을 수립하는 과정이고, **설계(Design)** 는 기획된 목표를 구현하기 위한 구조와 방법을 정의하는 과정이다.

개발자에게 기획이 중요한 이유는 두 가지다. 첫째로 팀 프로젝트에서 기획자가 따로 없기 때문에 개발자가 직접 기획에 참여해야 한다. 둘째로 기획의 이해 없이 코드만 작성하면 단순히 코드를 치는 **코더**에 머물게 된다. 반면 기획을 이해하고 코드를 짜면 진정한 **개발자**가 된다.

> 기획과 설계 없이 바로 코드를 치면 빠르게 나가는 것처럼 보이지만, 결과적으로는 매우 느린 속도로 개발이 진행된다. 기획을 하지 않은 프로젝트는 99%의 확률로 실패/재작업/미완성이 된다.

요즘은 기획을 디테일하게 짜면 AI가 그대로 코드를 구현해주기 때문에, 시스템 전체를 설계하고 조망할 줄 아는 개발자가 되는 것이 더욱 중요하다.

## 2. 기획 단계: 아이디어 도출 및 요구사항 분석

기획의 흐름은 다음과 같다.

**문제 정의 → 아이디어 구상 및 콘셉트 정의 → 타당성 검토 → 요구사항 수집 및 분석 → 요구사항 명세서 작성 → 이해관계자 검증**

아래는 **AI 자소서 코칭 서비스**를 예시로 각 단계를 설명한다.

| 단계 | 내용 |
|---|---|
| 1. 문제 정의 | 취업 준비생들이 기업 인재상에 맞춰 자소서를 작성하는 데 어려움을 겪음. 기존 맞춤법 검사기나 단순 첨삭 도구는 문맥·기업 특성을 고려하지 못함 |
| 2. 아이디어 구상 | LLM으로 자소서 초안을 전문가 수준으로 다듬는 웹 서비스 개발. 비용 부담 없이 1:1 맞춤형 자소서 코칭 |
| 3. 타당성 검토 | 기술적: OpenAI API로 문맥 파악/문장 재구성 가능 / 데이터: 사용자가 직접 입력하므로 학습 불필요 / 경제적: 가입 시 무료 코인 지급, 이후 결제로 API 비용 충당 |
| 4. 요구사항 수집 | 필수: 로그인/회원가입, 자소서 입력폼, 희망 직무, AI 첨삭 요청 및 결과 확인, 최종본 저장 / 부가: 자소서 다운로드, AI 기반 예상 면접 질문 생성 |
| 5. 요구사항 명세서 | 기능적: 사용자가 500자 이상 입력 후 "코칭받기" 클릭 시 직무 키워드 기반 2가지 수정안 제시 / 비기능적: AI API 호출부터 첫 글자 출력까지 레이턴시 최대 5초 |
| 6. 이해관계자 검증 | 5초 이내 응답 요건 → 스트리밍 방식 적용 / AI 할루시네이션 대비 → 결과 화면 하단에 면책 조항 명시 |

## 3. 설계 단계: 화면 기획 및 UI/UX

화면 설계의 흐름은 다음과 같다.

**정보 구조도(IA) 작성 → 화면 설계 → 프로토타이핑 및 사용성 검증**

- **정보 구조도(IA)**: 웹 서비스의 전체 뼈대와 메뉴 구조를 설계. 로그인/회원가입 → 자소서 초안 작성 및 설정 → AI 첨삭 요청 및 처리 → 수정 및 최종본 저장 → 최종 산출물 및 부가 기능의 흐름으로 구성
- **화면 설계**: Figma 등의 툴로 실제 화면 레이아웃을 스케치
- **프로토타이핑**: 기능 없이 각 요소에 이벤트를 연결해서 사용성 검증

## 4. 설계 단계: 시스템 및 아키텍처

시스템 설계의 흐름: **기술 스택 선정 → 시스템 아키텍처 설계 → 인프라 및 배포 환경 설계**

### 기술 스택 선정

프로젝트 특성에 맞는 언어와 프레임워크를 선정한다. 아래는 각 스택별 선택 근거 정리다.

| 영역 | 선택 | 이유 |
|---|---|---|
| Frontend | **Vue** | 이미 학습 완료, 진입 장벽 낮음, 백엔드/AI 집중 가능 |
| Frontend | React (대안) | 생태계 방대하나 특유의 문법과 복잡한 상태 관리 학습 필요 |
| Backend | **Django** | 압도적인 생산성, 핵심 기능 구현에 집중 가능 |
| Backend | FastAPI (대안) | 비동기 처리 빠르지만 필수 기능 직접 세팅 필요 |
| DB | **SQLite** | 설정 없이 즉각 연결, ORM 덕분에 추후 PostgreSQL 마이그레이션 가능 |
| DB | PostgreSQL (대안) | 대규모 트래픽 적합하나 별도 서버 환경 구축 필요 |

### 시스템 아키텍처 설계

서비스 로드맵에 따라 초기 런칭과 고도화 두 가지 방향으로 설계한다.

- **(초기) OpenAI API 활용**: 백엔드 서버가 직접 AI 연산을 하지 않고 클라이언트-OpenAI API의 중계 역할만 수행
- **(고도화) AI 모델 파인튜닝**: 독자적인 AI 모델 설계로 외부 API 종속성 탈피, 백엔드 옆에 GPU 추론 서버 별도 추가

### 인프라 및 배포 환경 설계

- 클라우드: **AWS**
- Frontend: AWS S3 + CloudFront / Backend: AWS EC2 + RDS / AI: AWS GPU 탑재 EC2
- 배포 자동화: Docker + CI/CD(Github Actions)
- 웹 서버: Nginx + WSGI(Uvicorn or Gunicorn)
- 비동기 처리: Redis + Celery
- 클라우드 네트워크/보안/부하 분산: VPC + Security Groups + Route53

## 5. 설계 단계: DB 설계

**개념적/논리적 설계 → ERD 작성 → 데이터 설계**

### 개념적/논리적 설계

서비스에 등장하는 개체(Entity)와 관계(Relationship)를 정의한다.

- 개체: 유저, 자기소개서, AI 코칭 로그, AI 코칭 결과물, 사용자 피드백
- 관계: 사용자는 여러 자기소개서 작성 (1:N) / 자기소개서는 여러 번 AI 코칭 결과물 생성 (1:N) / AI 코칭 결과물에 대해 하나의 사용자 피드백 생성 (1:1)

### ERD 작성

정의한 개념과 관계를 바탕으로 속성과 식별자를 시각화한다. (`users`, `cover_letters`, `ai_coaching_results`, `ai_coaching_logs`, `user_feedbacks` 테이블 구성)

### 데이터 설계 (AI용)

- AI API 모니터링 데이터: 비용 제어 + 프롬프트와 결과를 저장해 추후 프롬프트 엔지니어링 개선 지표로 활용
- 파인튜닝을 위한 데이터셋: 데이터 파이프라인 설계를 통해 안정적인 데이터셋 확보

## 6. 설계 단계: RESTful API 명세서 작성

프론트엔드와 백엔드 개발자가 협업하기 위한 명세서를 작성한다. Swagger 등의 도구를 활용해 엔드포인트, Request Body, Response 코드 등을 문서화한다.

```
POST /api/v1/resumes/coach/
Request Body: {"resume_id": 102, "job_title": "프론트엔드 개발자", "content": "저는..."}
Response 200: {"log_id": 456, "ai_result": "...", "status": "success"}
```

## 7. 프로젝트 관리 및 협업 세팅

**일정 관리와 마일스톤 / 버전 관리 / 그라운드룰 및 코딩 컨벤션 설정**

### 일정 관리 (WBS & Gantt Chart)

- **WBS(Work Breakdown Structure)**: 프로젝트를 큰 목표부터 작은 작업 단위까지 계층적으로 나눠 정리한 구조. 담당자 배정과 일정 관리에 사용
- **Gantt Chart**: 프로젝트 일정을 타임라인으로 나열해 기간과 진행률을 표현. WBS 이후 작성하며 프로젝트 진행사항을 한눈에 파악

> 일정 산정 팁: 개발 초기에는 예상 시간의 약 **2.5배** 정도 소요된다. 일정을 너무 빡빡하게 잡으면 회사에서 일정에 쫓겨 야근하고, 결국 번아웃으로 이어질 수 있다.

### 버전 관리

- 프론트엔드와 백엔드는 실행 환경이 다르므로 **저장소 분리**
- **Git Flow** 전략 도입
- PR 및 코드 리뷰 진행

### 그라운드룰 및 코딩 컨벤션

오해나 스타일 차이로 인한 시간 낭비를 막기 위해 규칙을 미리 정한다.

- 커밋 메시지 규칙: `[FEAT]` 새로운 기능, `[FIX]` 버그 수정
- 코드 포맷팅 자동화: 들여쓰기 2칸 vs 4칸 등 통일
- 이슈 트래킹: GitHub 이슈탭으로 팀원 모두와 이슈 공유 및 해결
- **데일리 스크럼(Daily Scrum)**: 매일 정해진 시간에 짧게 "어제 한 일 / 오늘 할 일 / 현재 문제점"을 공유. 서로 진행상황을 파악하고 막히는 부분을 빠르게 해결할 수 있음

## 💡 한 줄 요약
> 기획과 설계는 단순히 문서를 작성하는 게 아니라 프로젝트 전체의 구조와 목표를 설정하는 과정이며, 이 과정 없이 코딩부터 시작하면 99%는 실패하거나 재작업하게 된다.
