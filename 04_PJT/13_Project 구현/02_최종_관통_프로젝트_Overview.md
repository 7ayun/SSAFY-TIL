# [관통 PJT] 최종 관통 프로젝트 Overview

---

## 1. 최종 프로젝트 개요 및 일정

1학기의 마지막 프로젝트로, 지금까지 배운 기술 스택을 총동원해 팀 단위로 서비스를 완성한다.

| 항목 | 내용 |
|------|------|
| 개발 기간 | 월~목 (4일) |
| 발표 자료 제출 | 금요일 오전 9시까지 |
| 발표 시간 | 팀당 10~15분 (개발 완성도에 따라 최대 20분) |
| 평가 방식 | 팀 간 상호 평가로 순위 산정 |

---

## 2. 개발 환경

필수로 사용해야 하는 기술 스택이 지정되어 있다.

| 옵션 | 구성 |
|------|------|
| A (권장) | Django Rest Framework (DRF) + Vue.js |
| B (허용) | Django Only + Vanilla JS |

> 필수 기능은 반드시 위 스택으로 구현해야 한다.  
> **선택 기능**에 한해 Flask, FastAPI 등 다른 스택의 추가 사용은 허용된다.

---

## 3. 필수 구현 기능 3가지

### ① 추천 기능

특정 페이지에서 **어떤 기준으로든** 추천이 동작해야 한다. 알고리즘은 자유롭게 선택 가능하다.

- 코사인 유사도 기반 도서 추천
- 사용자 독서 이력 기반 추천
- 날씨/계절/기분 기반 추천
- 기타 독창적인 추천 로직 모두 허용

### ② 외부 API 연동

최소 **1개의 외부 API**와 연동하는 기능을 구현해야 한다.

- 알라딘 / 네이버 도서 API (데이터 수집)
- 유튜브 API (관련 영상 표시)
- 네이버 지도 / 구글 맵스 API (서점 위치 표시)
- 결제 API, 날씨 API 등 자유 선택

### ③ 커뮤니티 기능

사용자 간 소통이 가능한 커뮤니티를 구성해야 한다.

| 조건 | 내용 |
|------|------|
| 최소 페이지 수 | **5개 이상**의 URL 페이지 |
| 형태 | 게시글, 댓글, 채팅 등 자유 |
| 데이터 활용 | 50개 이상의 실데이터를 커뮤니티에서 활용 |

---

## 4. 데이터 요구사항

### 핵심 규칙

- 최소 **50개** 이상의 데이터 필요
- **실존하는 출처**가 있는 데이터여야 함 (ChatGPT로 생성한 JSON 파일 사용 불가)
- 데이터는 **Django fixtures(loaddata) 형식**으로 제출

```bash
# fixtures로 데이터 내보내기
python manage.py dumpdata app.Model --indent 2 > data.json

# fixtures로 데이터 불러오기
python manage.py loaddata data.json
```

### 허용 / 불허 기준

| 허용 | 불허 |
|------|------|
| 실제 사이트 크롤링 데이터 | AI가 처음부터 생성한 허구 데이터 |
| 공개 API로 수집한 데이터 | 출처 없는 임의 더미 데이터 |
| 실데이터를 기반으로 AI로 **증강**한 데이터 | ChatGPT와 함께 만든 JSON 파일 |

## 5. RESTful 설계 및 API 키 관리

필수 기능 전반에 RESTful 원칙을 적용해야 한다.

| 메서드 | 용도 |
|--------|------|
| GET | 데이터 조회 |
| POST | 데이터 생성 |
| PUT / PATCH | 데이터 수정 |
| DELETE | 데이터 삭제 |

> API 키는 반드시 `.env` 파일에 숨기고 `.gitignore`에 등록한다.

```python
# .env
OPENAI_API_KEY=sk-...

# settings.py
import os
API_KEY = os.environ.get("OPENAI_API_KEY")
```

## 6. 선택 기능 및 추천 개발 도구

### 추가 도전 기능

- **실시간 기능**: WebSocket을 활용한 실시간 채팅, 알림 등
- **검색 기능**: 도서 검색, 필터링
- **배포**: Vercel/Netlify (간단), AWS 클라우드 (심화)

### 클라우드 서비스 도전 (심화)

```
AWS EC2 (서버) + RDS (DB) + S3 (파일 저장)
+ Lambda (서버리스) + CDN + VPC (네트워크)
```

> 클라우드 엔지니어링은 취업 희소성이 높은 분야다. 이번 기회에 경험해두는 것을 추천한다.

### CI/CD 자동화 도구

| 도구 | 특징 |
|------|------|
| GitHub Actions | GitHub와 연동이 쉽고 진입 장벽이 낮음 |
| Jenkins | 현업에서 가장 많이 사용, 다소 복잡 |

### 설계 및 협업 도구

- **Figma**: UI/UX 프로토타입 설계. 프론트엔드 개발자는 기획자와의 소통을 위해 익혀두는 것이 좋다
- **Jira**: 팀 협업 일정 및 이슈 관리 (실무 표준)

## 7. 효과적인 AI 활용

AI가 편리하지만, **AI 실력이 곧 내 실력은 아니다.**

- AI는 빠르게 구현해주지만, 디테일한 버그를 많이 만든다
- 계산기가 있어도 덧셈·뺄셈을 배우듯, AI가 코드를 짜줘도 코드를 이해해야 한다
- 에러를 AI에게 바로 던지기 전에 **내가 먼저 읽고 이해하는 습관**이 필요하다

> "기본 지식이 있는 사람이 AI를 쓰면 더 빠르게 고치는 것이고,  
> 고칠 줄 모르는 사람이 AI를 쓰면 버그가 쌓인다."

## 8. AI 시대 개발자 성장 체크리스트

1학기를 마무리하며 스스로 점검할 항목들.

```
□ AI에게 질문하는 방식이 더 구체적이고 전문적으로 바뀌었는가?
  (야 해줘 → 기술 스택·아이디어 포함 구체적 프롬프트)
□ 에러를 이해하고 AI에게 던지는가, 아니면 무지성 복붙인가?
□ 공식 문서를 읽어본 적이 있는가?
  (개발 영어는 용어가 한정적이라 생각보다 읽을 만하다)
□ 팀원의 코드를 읽고 이해하거나 피드백할 수 있는가?
  (코드 작성 시대 → 코드 리뷰 시대)
□ 나만의 개발 철학이 생겼는가?
  (예: "가독성이 효율보다 중요하다" / "코드 길이보다 명확성이 우선")
□ 나만의 학습 루틴이 있는가?
  (개발 공부는 끝이 보이지 않는 마라톤. 루틴화하지 않으면 지친다)
```

## 9. AI 시대 취업 핵심 키워드: 희소성

> "잘한다의 시대는 끝났다. AI가 모두를 잘하게 만들어주기 때문이다.  
> 이제는 모두가 어려워하는 것을 할 수 있는 **희소성**이 중요하다."

- 모든 사람이 AI로 프로젝트를 빠르게 만드는 시대 → 포트폴리오 개수로 차별화 불가
- AI, 데이터, 도메인 지식, CS 기초, 디자인 감각 등 **폭넓은 역량**을 갖춘 풀스택이 유리
- AI가 생산성을 높여줬기 때문에, 이제 "이것도 할 줄 알아야 하지 않아?"라는 요구가 높아지는 시대

### 2학기 데이터 엔지니어링

- 강사 추천: "내가 학생이라면 데이터 엔지니어링으로 취업할 것 같다"
- 다음 기수부터 SSAFY 데이터 트랙이 대폭 확대될 예정 (원래 1반 → 3~4반)
- 취업 후 데이터 기반 개발 업무는 좋든 싫든 맡게 되므로, 미리 배워두는 것이 유리하다
