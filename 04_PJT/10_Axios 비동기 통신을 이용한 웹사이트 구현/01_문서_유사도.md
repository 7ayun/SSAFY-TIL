## 1. 문서 유사도란?

여러 개의 문서(또는 문장)가 **"얼마나 비슷한 내용(의미)을 담고 있는지"를 수치로 표현**한 것이다.

짧은 문장이라면 사람이 직접 읽고 비교할 수 있지만, 문장의 길이가 아주 길어지거나 (ex. 50~60페이지 계약서) 비교해야 할 문서의 양이 많아지면 사람이 눈으로 판단하기 어렵다. 알고리즘에서 빅오 표기법으로 성능을 수치화하듯, **"얼마나 유사한지"를 정량화**해서 객관적인 지표로 나타내는 것이 핵심이다.

### 활용 분야

| 분야 | 설명 |
|------|------|
| **추천 시스템** | 넷플릭스·웹툰 등에서 사용자가 본 것과 유사한 콘텐츠 추천 |
| **검색 및 정보 탐색** | 입력 쿼리와 유사한 문서를 빠르게 찾아 검색 결과 품질 향상 (과거 단순 키워드 매칭 → AI 시대 벡터 기반 검색으로 발전) |
| **분류·군집 및 중복 검출** | 뉴스 기사·논문·코드 표절 여부 계산, 중복 묶음 처리 |
| **의사결정 지원** | 방대한 문서(보고서, 계약서 등) 중 유사 문서·핵심 정보 신속 파악 |

## 2. 문서 유사도 수치화 방법 3가지

### 자카드 유사도 (Jaccard Similarity)

문서를 **"단어의 집합"**으로 보고, 공통으로 들어있는 **단어의 비율**을 계산한다.

```
자카드 유사도 = 교집합 단어 수 / 합집합 단어 수
```

**예시:**
- 문서 A: `{사과, 바나나, 포도}`
- 문서 B: `{바나나, 딸기, 포도, 개}`

```
교집합: {바나나, 포도} → 2개
합집합: {사과, 바나나, 포도, 딸기, 개} → 5개
자카드 유사도(A, B) = 2/5 = 0.4
```

**활용 사례:** 쿠팡의 "구매자가 함께 본 상품", Netflix의 "이 영화를 시청한 사람들이 함께 시청한 영화", 해시태그 기반 쇼츠 추천처럼 **복잡한 연산 없이 빠르게 유사도를 판별**해도 되는 경우에 많이 쓰인다.

**한계:** 단어의 등장 빈도수를 무시한다.

- 문서 D: `{사과, 사과, 사과}` (사과 3번 반복)
- 자카드(A, D) = 1/3 = 0.33 → 자카드(A, C)와 같은 값이 나와 직관에 어긋남

즉, 단어가 한 번 나오든 열 번 나오든 동일하게 취급되기 때문에 **빈도/비율을 정확히 반영하지 못한다.**

---

### 코사인 유사도 (Cosine Similarity)

문서를 **벡터**로 표현한 뒤, 두 벡터가 이루는 **각도의 코사인 값**을 계산한다. 오늘 강의의 핵심이다.

- `-1` 이상 `1` 이하의 값을 가지며, **값이 1에 가까울수록 유사도가 높다**고 판단
- 핵심은 벡터의 **방향(direction)** — 크기와는 무관

---

### 유클리드 거리 (Euclidean Distance)

문서를 벡터로 표현한 뒤, 두 벡터 사이의 **직선 거리**를 계산한다.

- **거리가 0에 가까울수록** 유사도가 높다고 판단
- AI 수업에서 배운 **K-평균 군집화(K-Means)** 에서 이미 활용했다 — 중심점(centroid)으로부터 각 데이터까지의 거리를 유클리드 거리로 계산해서 가까운 것끼리 묶는 방식

## 3. 코사인 유사도 상세

### 왜 "코사인"을 쓰는가?

삼각함수에는 사인(sin), 코사인(cos), 탄젠트(tan)가 있다. 동일한 두 문서를 비교할 때 각도 θ = 0°가 된다.

| 삼각함수 | θ = 0° 값 | 적합성 |
|---------|-----------|--------|
| sin 0° | 0 | ❌ 동일 문서인데 유사도가 0 → 직관에 어긋남 |
| tan 0° | 0에 가까울수록 무한대 | ❌ 수치가 발산 |
| **cos 0°** | **1** | ✅ 동일 문서 = 유사도 1, 범위 -1~1로 안정적 |

코사인은 동일한 방향이면 1, 반대 방향이면 -1로 직관적으로 표현되기 때문에 유사도 지표로 가장 적합하다.

---

### 벡터(Vector) 개념

**벡터**는 "방향과 크기"를 나타내는 수학적 표현이다.

| 차원 | 표현 | 설명 |
|------|------|------|
| 1차원 | `[v]` | 실수선에서 한 점을 가리키는 화살표 |
| 2차원 | `[x, y]` | 2D 평면에서 "오른쪽 x, 위로 y"를 가리키는 화살표 |
| 3차원 | `[x, y, z]` | 3D 공간에서 x축, y축, z축 방향 |
| 고차원 | `[v₁, v₂, ..., vₙ]` | N개의 실수 성분 — 우리가 시각화할 수는 없지만, 그 공간이 존재한다고 이해 |

문서에 1,000개의 단어가 있다면, 1,000차원 벡터가 그 문서를 나타낼 수 있다. **하나의 단어 = 하나의 차원**이다.

> **말뭉치 크기와 벡터 정밀도의 관계**
>
> A 문서(1,000개 단어)의 "사과"와 B 문서(100개 단어)의 "사과"는 **수치적으로 다르게 표현**된다. 차원이 다르기 때문이다. 말뭉치가 클수록 각 단어의 수치가 더 세밀하고 차별화된다.
> - 100개짜리 말뭉치: 사과 = 0.1, 배 = 0.2 (차이 0.1)
> - 1,000개짜리 말뭉치: 사과 = 0.015..., 배 = 0.016... (훨씬 세밀한 차이)
>
> LLM(대규모 언어 모델)이 만든 임베딩이 훨씬 정교한 이유가 여기에 있다.

---

### 내적(Dot Product)

두 벡터가 얼마나 같은 방향으로 향해 있는지를 반영한 값으로, **각 성분을 곱한 뒤 모두 더한 하나의 값**이다.

같은 차원에 있는 값끼리 비교한다 (예: 두 팀이 싸울 때 공격수끼리, 수비수끼리 비교하듯).

```
벡터 A(3, 3, 3), B(4, -1, 0)의 내적:
A·B = (3×4) + (3×-1) + (3×0) = 12 + (-3) + 0 = 9
```

| 경우 | 의미 |
|------|------|
| 두 성분 모두 양수 (3 × 4 = 12) | **같은 방향**으로 기여 |
| 한 쪽이 음수 (3 × -1 = -3) | **반대 방향**으로 기여 |
| 하나가 0 (3 × 0 = 0) | **방향이 없음** → 무관 |

결국 내적값 9 = "A와 B가 얼마나 같은 방향인지"를 수치화한 것.

---

### 정규화 (Normalization)

코사인 유사도는 크기가 아닌 **방향만** 확인하는 지표다. 내적만으로는 벡터의 크기가 클수록 값이 커지는 문제가 있다.

> 예: A(300, 300, 300), B(4, -2, 0) — A의 크기가 너무 커서 내적값(600)이 A에 치우쳐 있다.

이를 보정하기 위해 **각 벡터의 크기(원점으로부터의 거리)로 나누는 정규화**를 진행한다.

벡터의 크기: `||V|| = √(v₁² + v₂² + ... + vₙ²)` (피타고라스 정리와 동일한 원리)

**계산 예시** — A(300, 300, 300), B(4, -2, 0):

```
A·B = (300×4) + (300×-2) + (300×0) = 600
||A|| = √(300² + 300² + 300²) = 300√3 ≈ 519.62
||B|| = √(4² + (-2)² + 0²) = 2√5 ≈ 4.4721

cos θ = 600 / (519.62 × 4.4721) ≈ 0.2582
```

정규화 후에는 크기와 무관하게 **방향의 유사도만** 정확히 추출된다.

---

### 코사인 유사도 공식

$$\cos\theta = \frac{A \cdot B}{\|A\|\|B\|}$$

- 두 벡터의 내적을 각 벡터의 크기의 곱으로 나눈 값
- "길이가 1인 벡터"끼리 내적하면 두 벡터가 이루는 각도 θ의 코사인과 동일 (벡터 기하학의 기본 정의)

---

### 코사인 유사도가 "방향"만 확인하는 이유 3가지

1. **검색/추천에서 중요한 건** "어떤 단어/특징이 얼마나 중요한가"이지, "몇 번 출현했는가"가 아님
   - 두 문서가 `[10, 5, 0]`과 `[2, 1, 0]`이면 등장 수는 다르지만 비율은 동일하게 2:1 → 사실상 같은 결의 문서
2. 문서가 불필요하게 길어지거나 한 쪽에만 출현 횟수가 많아도, **패턴(비율)만 확인해서 정확히 비교** 가능
3. `-1` 이상 `1` 이하 구간으로 정규화되어 **알고리즘 설계와 수치 해석이 단순해짐**

---

### Python 구현

```python
from numpy import dot          # 벡터 내적
from numpy.linalg import norm  # 벡터 크기

def cosine_similarity(A, B):
    return dot(A, B) / (norm(A) * norm(B))
```

numpy에 내적 함수(`dot`)와 크기 함수(`norm`)가 이미 구현되어 있어, 공식을 그대로 한 줄로 표현할 수 있다.
