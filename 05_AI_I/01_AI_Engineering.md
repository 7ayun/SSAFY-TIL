## 1. LLM의 작동 원리

### 1-1. AI의 분류와 현재 위치

AI(인공지능)는 논리, 학습, 계획, 자연어, 인지, 동작 등 다양한 문제를 풀기 위한 기술의 총칭이다. 접근 방식에는 기호 기반, 통계 기반, 소프트 컴퓨팅(인공신경망, 유전 알고리즘 등)이 있다.

현재 흔히 말하는 AI — GPT, Claude, Gemini 등 — 는 AI 전체가 아니라 딥러닝 기반 **대규모 언어 모델(LLM)** 이라는 특정 갈래다. LLM은 머신러닝 > 딥러닝 > 트랜스포머 아키텍처로 이어지는 계보에 속한다.

> **강사님 강조**: LLM이 곧 AI 전부는 아니다. 피지컬 AI 등 다른 분야는 별도의 기술이 필요하다.

### 1-2. 통계적 언어 모델

통계적 언어 모델은 **다음 단어(토큰)가 무엇인지 확률로 예측하는 수학적 장치**다. 문장 S가 등장할 확률 P(S)를 계산하는 것이 핵심이며, n-gram 모델은 앞의 n개 단어만 보고도 다음 단어를 근사할 수 있음을 보였다.

프로그래밍 언어도 자연어와 마찬가지로, 실제 작성되는 코드는 반복적이고 예측 가능한 통계적 특성을 가진다(Naturalness of Software, 2012). `for` 다음에 `i in range`가 자동으로 떠오르는 것처럼, LLM이 코드를 잘 생성하는 이유도 이 원리에 기반한다.

```python
# 파이썬 맥락에서 for 다음에 오는 자연스러운 패턴
for i in range(n):   # 압도적으로 높은 확률로 선택됨
    ...

# 자바 맥락이라면 다른 패턴이 자연스러움
for (int i = 0; i < n; i++) {
    ...
}
```

> **강사님 강조**: LLM은 코딩을 '이해해서' 짜는 게 아니다. 해당 맥락에서 자연스러운 토큰이 그것이기 때문에 생성하는 것이다.

### 1-3. 트랜스포머와 GPT

GPT는 **Generative Pre-trained Transformer**의 약자로, 2017년 Google이 발표한 트랜스포머 아키텍처를 기반으로 한다.

| 구성 요소 | 의미 | 설명 |
|-----------|------|------|
| G (Generative) | 생성형 | 학습 시 본 적 없는 새로운 결과물을 만들어냄 |
| P (Pre-trained) | 사전학습 | 대규모 데이터로 미리 학습 완료, 추가 학습 없이 사용 가능 |
| T (Transformer) | 트랜스포머 | 어텐션 메커니즘으로 중요 토큰을 학습해 다음 토큰 예측 |

학습 방식은 **자기회귀(auto-regressive)** 다. 실제 문장에서 단어를 지우고 맞출 때까지 반복 훈련하며, 이후 사람 말을 잘 듣도록 파인튜닝(RLHF 등)을 추가한다.

### 1-4. 창발적 능력

창발(Emergence)이란 **구성 요소에는 없는 특성이 전체에서 저절로 나타나는 현상**이다. 모델 크기와 학습 데이터를 키웠더니, 산술 연산·QA·자연어 이해 등 명시적으로 학습시키지 않은 능력이 갑자기 생겨났다(2022).

- **장점**: 무엇이든 시킬 수 있다
- **단점 1**: 왜 이 능력이 생겼는지 설명하기 어렵다 (블랙박스)
- **단점 2**: 통계적 장치이므로 출력이 항상 예측 가능하지 않다

> **강사님 강조**: LLM은 생각해서 대답하는 게 아니라, 통계적으로 가장 자연스러운 토큰을 순서대로 산출하는 기계다.

## 2. 프롬프트 엔지니어링

### 2-1. In-Context Learning

LLM의 대표적인 창발적 능력이 **컨텍스트 내 학습(In-Context Learning)** 이다. 별도 재학습 없이 대화 맥락 안에서 예시만 줘도 그 패턴을 따라 수행한다.

| 기법 | 설명 |
|------|------|
| Zero-shot | 예시 없이 지시만으로 수행 |
| One-shot | 예시 1개 제공 후 수행 |
| Few-shot | 예시 여러 개 제공 후 수행 |

### 2-2. Chain of Thought (CoT)

복잡한 문제를 **단계적으로 풀게 유도**하면 최종 답의 정확도가 높아진다. LLM이 한 번에 먼 토큰 점프를 하는 대신, 중간 단계를 촘촘하게 거치게 하는 원리다.

```
# 직접 답 요구 (오답 가능)
Q: 카페테리아에 사과 23개, 20개를 쓰고 6개를 더 사면 몇 개?
A: 27  <- 확률 기반으로 틀린 숫자 생성

# CoT 방식 (단계 유도)
Q: 위와 동일, 단계별로 풀어라
A: 23개에서 20개를 사용했으므로 23 - 20 = 3개 남음
   6개를 더 구매하므로 3 + 6 = 9개  <- 정답
```

> **강사님 팁**: 프롬프트 끝에 "차근차근 생각해 보자"만 붙여도 CoT 효과가 나타난다. 중간 단계를 거치는 것이 통계적으로 더 자연스러운 흐름이기 때문이다.

### 2-3. Self-Consistency

같은 문제를 **여러 번 질의한 뒤 다수결로 답을 선택**하면 정확도가 높아진다. temperature > 0으로 매번 약간의 노이즈를 허용하면 서로 다른 추론 경로가 생성되어 일종의 앙상블 효과를 낸다.

### 2-4. RAG (Retrieval-Augmented Generation)

LLM은 학습 데이터에 없는 정보는 모른다. **RAG는 외부 DB에서 관련 정보를 검색해 프롬프트에 추가**하여, 학습 시 보지 못한 도메인 지식도 활용할 수 있게 한다.

```
[사용자 질문]
    ↓
[벡터 DB 검색 → 관련 문서 추출]
    ↓
[최종 프롬프트 = 질문 + 검색된 문서]
    ↓
[LLM 응답 생성]
```

> **강사님 강조**: RAG는 LLM 자체의 기능이 아니라, LLM을 활용하는 시스템 레이어에서 추가하는 기법이다.

### 2-5. ReAct (Reasoning + Acting)

LLM이 **도구 사용 의지를 표현(말)** 하면, 외부 시스템이 실제로 도구를 실행하고 결과를 다시 컨텍스트에 주입하는 패턴이다.

```
LLM    : "계산기 도구를 사용하겠습니다. 입력: 23 - 20 + 6"
외부   : 계산기 실행 → 결과 9 → 컨텍스트에 추가
LLM    : (9가 컨텍스트에 있음) "정답은 9개입니다"
```

> **강사님 강조**: ReAct는 현재 에이전틱 AI의 핵심 기반이다. 도구 개념 없이 에이전트를 이야기할 수 없다.

## 3. 에이전트(Agentic AI)

### 3-1. 에이전트의 개념

에이전트는 사용자의 **지속적인 통제 없이 자율적으로 문제를 해결**하는 AI 시스템이다. 두 가지 요건이 모두 충족되어야 한다.

- **자율성**: 상황을 판단하여 스스로 결정을 내릴 수 있는가
- **숙련도(Proficiency)**: 문제 해결에 필요한 도구를 적절하게 사용할 수 있는가

단순 LLM과 에이전트의 차이:

| 구분 | 단순 LLM | 에이전트 |
|------|----------|----------|
| 계산 문제 | 확률 기반 토큰으로 오답 가능 | 계산기 도구 사용 → 정확한 답 |
| 메모리 | 현재 컨텍스트 내에서만 | 외부 DB에 요약 저장 및 검색 |
| 행동 범위 | 텍스트 생성만 | 도구 실행, 환경 변화 인지 후 재계획 |

### 3-2. MCP와 닫힌 검증 루프

MCP(Model Context Protocol)는 ReAct 같은 도구 사용 개념을 표준화한 프레임워크다. 에이전트가 제대로 동작하려면 **닫힌 검증 루프(closed verification loop)** 가 필수다.

```
작업 지시
    → 에이전트 실행
    → 자동 검증 (테스트 / 결과 확인)
    → 실패 시 자동 재시도
    → 성공 시 완료
```

> **강사님 주의**: 에이전트에 PC 전체 권한을 주는 것은 보안 관점에서 매우 위험하다. 블랙박스가 임의 명령을 실행할 수 있으므로 권한 범위를 신중하게 설정해야 한다.

## 4. AI와 SW 개발 주기

### 4-1. SDLC 패러다임 변화

AI는 코드 리뷰 수준을 넘어 요구사항 분석부터 유지보수까지 **SDLC 전 단계**에 영향을 미친다. 결함 위치 자동 식별(AutoFL), 자동 패치 생성, 코드 리뷰 자동화 등 에이전트 기반 도구가 실제로 연구·사용되고 있다.

AI 코드 생성은 기계어에서 고수준 언어로의 전환(컴파일러 등장)에 비유할 수 있다. 컴파일러가 처음 나왔을 때 자동 생성 코드를 믿지 못했던 것처럼, 현재 AI 생성 코드의 신뢰 수준도 논의 중이다.

> **강사님 강조**: 코드를 많이, 빠르게 생성한다고 생산성이 높은 것이 아니다. 적재적소에 최소한의 코드를 쓰는 것이 여전히 좋은 소프트웨어 공학이다.

### 4-2. SW 개발자의 미래

**프레임 문제(Frame Problem, 1969)**: AI는 현실의 수많은 가능성 중 무엇이 중요하고 중요하지 않은지 스스로 결정할 수 없다. 이 경계를 설정하는 것은 여전히 사람의 역할이다.

```python
# LLM이 달력 코드를 리뷰할 때 발생한 실제 오류
# "12월 31일까지만 처리 가능하여 유연성이 부족하다"
# → 1년이 12월까지라는 상식(프레임)이 없어 발생한 오판
```

> **강사님 팁**: AI가 발전할수록 도메인 지식을 가진 전문가의 가치는 오히려 높아진다. 어떤 방향으로 흘러가든 가장 안전한 베팅은 직접 개발할 수 있는 능력을 갖추는 것이다.

## 참고 — 자동화의 역설 (읽을거리)

자동화가 증가할수록 사람은 자동화에 익숙해져 수동 대처 능력이 퇴화한다(에어프랑스 447편 사고, 2009). AI 코딩 도구 의존도가 높아질수록, 기초 개발 역량을 유지하는 균형이 중요하다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| LLM 본질 | 다음 토큰을 확률로 예측하는 통계적 장치. 이해가 아닌 패턴 생성 |
| 트랜스포머 | 어텐션으로 중요 토큰을 학습. GPT = 생성형 사전학습 트랜스포머 |
| 창발적 능력 | 모델 규모 확대 시 미학습 능력 출현. 블랙박스의 장점이자 한계 |
| CoT | 단계적 풀이 유도로 정확도 향상. "차근차근 생각해 보자"만으로도 효과 |
| Self-Consistency | 동일 문제 반복 질의 후 다수결 선택. 일종의 가짜 앙상블 |
| RAG | 외부 DB 검색 결과를 컨텍스트에 추가해 미학습 지식 활용 |
| ReAct | 도구 사용 의지 표현 → 외부 실행 → 결과 주입. 에이전트의 핵심 |
| 에이전트 | 자율성 + 숙련도. 닫힌 검증 루프 필수 |
| SDLC 변화 | AI가 코드 리뷰를 넘어 개발 전 주기로 영향 확대 |
| 개발자 미래 | 프레임 설정·도메인 지식 보유 전문가의 가치 증가 |
