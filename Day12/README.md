# Day12 - API · JSON · MCP 실습 정리

---

## 0. 오늘 수업 한 줄 요약
- **API**: 서로 다른 서비스가 “정해진 규격(문서)”으로 **요청/응답**하며 통신하는 방식  
- **JSON**: 서로 다른 언어/서비스끼리 주고받기 위한 **텍스트 기반 key-value 표준 포맷**
- **MCP**: LLM이 다양한 서비스/도구를 “한 번의 표준 연결 방식”으로 쓰도록 돕는 **프로토콜(규약)**

---

## 1) API 핵심 개념

### 1-1. API 정의
- **Application Programming Interface**
- “서비스가 제공하는 기능/데이터를 외부에서 쓰도록 공개한 **규격(문서 + 엔드포인트 + 요청/응답 형식)**”

### 1-2. 누가 API를 만들까?
- API는 **데이터/기능을 제공하는 당사자(회사/서비스)가 만든다**
- 사용자는 **문서(명세서)를 읽고** 그 규격대로 요청한다

### 1-3. 왜 API 키를 쓰나?
- 공개 API는 악용 가능성이 있어 **식별/요청 제한(레이트 리밋)**을 둔다
- 예: “1분에 N번” 같은 제한 + 키 발급

### 1-4. 비유로 이해
- **메뉴판(API 문서)** 보고 **주문(요청)** → **요리(응답)**  
- 메뉴에 없는 걸 달라 하면(문서에 없는 요청) 응답 불가

---

## 2) OAuth (소셜 로그인) 흐름 요약

### 2-1. 핵심 포인트
- “구글로 계속하기”는 **우리 서비스가 사용자의 ID/PW를 직접 받지 않는다**
- 인증은 **구글 로그인 화면(구글이 제공)**에서 이루어진다

### 2-2. 매우 간단 흐름
1. 사용자: “구글로 로그인” 클릭  
2. 서비스: 구글 로그인 페이지로 이동(인증 위임)  
3. 사용자: 구글에서 로그인  
4. 구글: 인증 결과(토큰/인가 코드 등)를 서비스에 전달  
5. 서비스: 그 결과로 “우리 서비스 로그인 처리”

## 3) JSON 핵심 개념

### 3-1. JSON은 “딕셔너리처럼 보이지만” 본질은 텍스트
- JSON은 언어 중립적으로 주고받기 위해 **텍스트(string)** 형태로 전달된다
- 파이썬에서 바로 `data['key']`로 접근하려면 **dict로 변환**이 필요

### 3-2. loads / dumps vs load / dump
- `json.loads(문자열)` : JSON **문자열** → dict
- `json.dumps(dict)` : dict → JSON **문자열**

- `json.load(파일객체)` : JSON **파일** → dict
- `json.dump(dict, 파일객체)` : dict → JSON **파일 저장**

> 뒤의 `s`는 **string** 의미

### 3-3. 실수 & 함정
- JSON 텍스트를 그대로 읽어오면 `type()`이 `str`일 수 있다  
  → 이 상태에서 `data['version']` 같은 접근은 불가능
- 확장자가 `.json`이 아니어도 **내용이 JSON 형식이면 로드 가능**(단, 실무에선 json 확장자 권장)

## 4) MCP (Model Context Protocol) 개념 정리

### 4-1. 왜 MCP가 나오나?
- 서비스마다 API 규격이 달라서 매번 연동 코드를 새로 짜야 함  
  → **연동 비용(코스트)**가 계속 발생

### 4-2. MCP는 “도구”가 아니라 “약속(프로토콜/규약)”
- 여러 서비스가 **같은 규약**으로 도구/데이터를 제공하면,
- LLM(호스트)이 상황에 맞는 도구를 골라 호출하고,
- 우리는 “자연어로 요청”만 해도 연동이 가능해진다

### 4-3. 구성 요소(외울 필요 X, 흐름만)
- **MCP Server**: 회사/개발자가 제공하는 기능(도구) 서버(= API 역할)
- **MCP Host**: 사용자 입력을 해석해 어떤 도구를 쓸지 결정(LLM이 수행)
- **MCP Client**: 실제 호출/통신/권한/전송 담당(LLM/환경이 수행)

### 4-4. 표준화 비유
- 각자 다른 포트(라이트닝/HDMI/… ) → **C타입처럼 표준화**
- 표준화의 핵심은 **“많이 채택되는 것”**
- 보안 이슈가 상용화의 큰 변수

## 5) MCP 실습 요약 (VS Code + 서버 등록)

### 5-1. 실습 목표
- 로컬 폴더의 이미지들을:
  1) **이미지 분석 결과로 파일명 자동 변경**
  2) 사람/동물 등 **카테고리 폴더 생성 + 이동**
- (추가) SQLite MCP 서버로 DB 조회/업데이트까지 시연

### 5-2. 실습 준비 체크리스트
- VS Code 실행
- Node 설치(실습에서 `npx/mpx` 계열 실행 목적)
- 실습용 폴더 생성(가급적 영어 경로 권장)
- Git clone 후 `git bash here`에서 `code .`로 열기  
  - 이유: 가끔 VS Code가 환경변수/파이썬 인식을 못하는 케이스 방지

### 5-3. VS Code에서 MCP 설정 열기
- `Ctrl + Shift + P`
- **MCP: Open User Configuration** 실행
- 여기에 MCP 서버 설정(JSON)을 추가
  - File System 서버
  - Image Reader 서버
  - (옵션) SQLite 서버

### 5-4. 경로 설정에서 자주 터지는 포인트(중요)
- Windows 경로 백슬래시(`\`)는 설정(JSON)에서 이스케이프 필요  
  → `\` 를 `\\` 로 입력

### 5-5. 실행/권한 흐름
- 서버 설정 후 **Start** → **Running** 상태 확인
- 채팅(Agent 모드)에서 MCP 서버 체크
- 자연어로 요청하면 LLM이 자동으로 적절한 서버를 호출
- 파일 변경/이동은 **권한(allow)** 을 요구할 수 있음

## 7) 실전 관점 정리
- MCP의 본질: “LLM이 외부 도구를 표준 방식으로 호출하게 하는 생태계”
- 기대 효과: 연동 비용 감소, 자동화 범위 확대(파일/DB/노션/슬랙 등)
- 리스크: 권한/보안(로컬 파일 접근, 자동 실행, 데이터 유출 가능성)

---

## 8) 오늘의 요약
- API = 서비스가 정한 규격으로 요청/응답
- OAuth = 인증을 외부(구글 등)에 위임하고 결과만 받음
- JSON = 언어 중립 텍스트 포맷(파이썬에선 dict 변환 필요)
- loads/dumps = 문자열 ↔ dict, load/dump = 파일 ↔ dict
- MCP = LLM 도구 연동 “표준 규약”, 서버/호스트/클라이언트로 동작
