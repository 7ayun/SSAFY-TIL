## 1. 어제 배운 비동기 JS 핵심 복습

오늘 내용은 어제 배운 비동기 JS의 복습이자 Django와의 결합이다. 어제 내용이 어렵게 느껴진다면 앞부분 학습이 아직 부족한 것이므로 다시 복습하자.

### 자바스크립트 비동기 동작 원리

자바스크립트는 **싱글스레드**임에도 비동기 처리가 가능한 이유는 아래 구조 덕분이다.

| 구성 요소 | 역할 |
|---|---|
| **Call Stack** | 함수 호출이 쌓이고 코드가 동작하는 영역. 비동기 함수가 들어오면 Web API로 보냄 |
| **Web API** | 비동기 작업을 처리하는 영역 |
| **Task Queue** | 처리가 끝난 비동기 작업들이 대기하는 영역 |
| **Event Loop** | Call Stack이 비면 Task Queue의 작업을 콜스택으로 옮겨 실행 |

> 용어 자체를 완벽히 외우는 것보다, 이런 흐름으로 돌아간다는 흐름을 이해하는 것이 더 중요하다.

### 비동기 처리 방식의 발전

```
콜백 함수 → 콜백 지옥 문제 발생
    ↓
Promise 객체 → .then() / .catch() 체이닝으로 해결, 하지만 코드가 길어짐
    ↓
async / await → 더욱 간결하게 표현 가능
    ↓
Promise.all → 여러 비동기 작업이 모두 끝나야 다음 코드가 진행되어야 할 때 활용
```

- `await`: Promise 객체 앞에 붙이며, 해당 Promise가 반환될 때까지 그 자리에서 기다림
- `async`: `await`가 사용되는 함수의 선언부 앞에 반드시 붙여야 함

## 2. 오늘의 목표 — 브라우저와 서버의 실시간 대화

인스타그램에서 '팔로우' 버튼을 누를 때 페이지가 새로고침되지 않는 것처럼, **페이지 전체 새로고침 없이 필요한 데이터만 받아와 DOM을 업데이트**하는 것이 오늘의 핵심이다.

### 기존 방식 vs Ajax 방식

```
[기존 풀스택 방식]
클라이언트 → 요청 → Django → HTML 전체 렌더링 → 클라이언트 (페이지 새로고침)

[Ajax 방식]  
클라이언트 → Axios 요청 → Django → JsonResponse (데이터만) → JS가 DOM 일부만 업데이트
```

- Django가 HTML을 반환하는 풀스택 역할 → **API 서버**로 전환
- 프론트엔드(JS)가 화면을 직접 그리는 방식
- 다음 주 배울 Vue.js와 결합하면 완전한 프론트-백 분리가 이루어짐

## 💡 한 줄 요약
> Ajax는 Axios로 Django API 서버에 요청하고, JsonResponse로 받은 데이터로 JS가 필요한 DOM만 업데이트하여 페이지 새로고침 없이 동적인 웹을 만드는 기술이다.

## ❓ 더 찾아볼 것
- Call Stack / Web API / Task Queue / Event Loop 동작 시각화 자료

- Node.js가 비동기 I/O 처리에 강한 이유 (싱글스레드인데 왜 빠른가)
- WebSocket 통신 — 실시간 양방향 데이터 동기화가 필요할 때
