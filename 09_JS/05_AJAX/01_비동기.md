# [JS] 비동기

---

## 1. 동기(Synchronous)와 비동기(Asynchronous)의 차이

프로그램의 작업 처리 방식은 크게 두 가지로 나뉜다.

| 구분 | 동기 (Synchronous) | 비동기 (Asynchronous) |
|------|--------------------|-----------------------|
| 처리 방식 | 시작 순서대로 처리, 앞의 작업이 끝나야 다음 시작 | 병렬적 수행, 완료 순서대로 처리 |
| 장점 | 단순하고 예측 가능한 흐름, 버그 지점 찾기 쉬움 | 시간이 걸리는 작업을 백그라운드에 위임, UX 향상 |
| 단점 | 오래 걸리는 작업 실행 시 프로그램 전체가 멈춤 (블로킹), 자원 낭비 | 실행 순서 불명확, 코드 복잡성 증가, 콜백 지옥 위험 |

**동기 실생활 예시** — 카페에서 손님 1의 주문이 완료(커피 제공)돼야만 손님 2의 주문을 받는 방식. ONE-BY-ONE.

**비동기 실생활 예시** — 손님 1이 주문 후 진동벨을 받으면, 바리스타는 바로 손님 2의 주문을 받을 수 있다. 커피가 만들어지는 동안 다음 손님을 처리하는 병렬 방식.

> **티켓팅 예시**: 버튼을 딱 눌렀을 때 브라우저가 멈추고 반응이 없어지는 현상이 동기 처리의 단점(블로킹)이다. 처리가 완료될 때까지 아무것도 못한다.

```js
// 동기: syncTask()가 끝날 때까지 다음 줄로 넘어가지 않음
console.log('작업 1 시작')
const syncTask = function () {
  for (let i = 0; i < 1000000000; i++) {} // 10억 번 반복 동안 멈춤
  return '작업 완료'
}
const result = syncTask()
console.log(result)
console.log('작업 2 시작')
// 출력: 작업 1 시작 → (대기) → 작업 완료 → 작업 2 시작
```

```js
// 비동기: setTimeout은 예약만 하고 즉시 다음 코드로 넘어감
console.log('A')
setTimeout(() => console.log('B'), 1000)
console.log('C')
// 출력: A → C → (1초 후) B
```

개발에서 정답은 없다. **트레이드오프**다. 오래 걸리는 작업이 없는 서비스라면 굳이 복잡한 비동기 코드를 짤 필요가 없다. 상황에 맞게 선택하는 것이 중요하다.

## 2. JavaScript는 Single Thread 언어다

JS는 **한 번에 하나의 작업만 수행**할 수 있는 Single Thread 언어다. 즉 동시에 여러 작업을 처리할 수 없다.

### 프로세스 vs 스레드 (면접 단골 질문!)

| 개념 | 설명 |
|------|------|
| **프로세스** | 프로그램을 실행하면 독립된 메모리 영역을 할당받아 올라가는 실행 중인 프로그램 |
| **스레드** | 프로세스 내부에서 코드가 실행되는 최소 단위. 실제로 일을 하는 주체 |
| **Single Thread** | 일하는 애가 하나. JS가 이에 해당 |
| **Multi Thread** | 일하는 애가 여러 명. Python이 이에 해당 (단, GIL에 의해 실질적으로는 하나씩 동작) |

> **Python과 GIL**: Python은 멀티스레드지만 **GIL(Global Interpreter Lock)** 에 의해 한 번에 하나의 스레드만 동작한다. 초창기에 여러 스레드가 공유 메모리를 동시에 건드릴 때의 관리 복잡성을 해결하기 위해 도입됐다. 관련 면접 키워드: GIL, 가비지 컬렉션, 레퍼런스 카운팅.

그렇다면 Single Thread인 JS가 어떻게 비동기 처리를 할 수 있을까?

## 3. JavaScript Runtime — 비동기 처리를 도와주는 환경

JS 자체는 싱글스레드지만, JS가 동작하는 **Runtime 환경**이 비동기 처리를 대신 해준다.

| Runtime 환경 | 비동기를 도와주는 것 |
|-------------|---------------------|
| 브라우저 (프론트) | **Web API** |
| Node.js (백엔드) | **libuv** 라이브러리 |

> **Node.js**: 원래 웹브라우저에서만 동작하던 JS를 서버에서도 실행할 수 있게 해주는 환경. Node.js를 백엔드로 선택하는 이유가 바로 이 비동기 처리 능력이다. 실시간 채팅, 스트리밍 서비스에 특히 강력하다.

## 4. 브라우저 환경의 JS 비동기 처리 구조 — 4가지 핵심 요소

```
┌──────────────┐   ┌──────────────────────────────┐
│  Call Stack  │   │           Web API            │
│   (일 목록)  │   │  (비동기 작업을 처리하는 곳)  │
│              │   │  브라우저가 제공하는 환경     │
└──────────────┘   └──────────────────────────────┘
        ↑                        ↓
┌──────────────┐   ┌──────────────────────────────┐
│  Event Loop  │   │         Task Queue           │
│   (안내원)   │   │  (끝난 비동기 작업들이        │
│  Call Stack이│←──│   줄 서서 기다리는 곳)        │
│  빌 때 전달  │   │                              │
└──────────────┘   └──────────────────────────────┘
```

| 구성 요소 | 역할 |
|-----------|------|
| **Call Stack** | 코드가 실행되면 함수 호출이 순서대로 쌓이는 **일 목록**. 비동기를 만나면 Web API로 던진다 |
| **Web API** | 시간이 걸리거나 언제 실행될지 모르는 비동기 작업들을 처리하는 곳. 브라우저가 제공 |
| **Task Queue** | Web API에서 처리가 완료된 작업들이 순서대로 **줄을 서서 기다리는** 대기열 (선입선출) |
| **Event Loop** | Call Stack이 비어있는지 계속 쳐다보다가, 비는 순간 Task Queue에서 가장 오래된 작업을 꺼내 전달하는 **안내원** |

## 5. 런타임 동작 흐름 — 단계별 시각화

```js
console.log('Hi')

setTimeout(function myFunc() {
  console.log('Work')
}, 3000)

console.log('Bye')
```

| 단계 | 동작 |
|------|------|
| 1 | `console.log('Hi')` → Call Stack에 쌓임 → 즉시 실행 → 제거 → `"Hi"` 출력 |
| 2 | `setTimeout(myFunc, 3000)` → Call Stack에 쌓임 → **비동기 작업** 감지 → Web API로 던짐 |
| 3 | `console.log('Bye')` → Call Stack에 쌓임 → 즉시 실행 → `"Bye"` 출력 |
| 4 | 3초 후 Web API가 `myFunc`를 Task Queue로 이동 |
| 5 | Event Loop가 Call Stack이 비어있음 확인 → `myFunc`를 Call Stack으로 전달 |
| 6 | `console.log('Work')` 실행 → `"Work"` 출력 |

**최종 출력 순서: `Hi` → `Bye` → `Work`**

---

## 💡 한 줄 요약
> JS는 Single Thread지만, 브라우저의 Web API · Task Queue · Event Loop 덕분에 비동기 처리가 가능하다. 이 동작 원리를 이해하는 것이 비동기 코드 작성의 출발점이다.
