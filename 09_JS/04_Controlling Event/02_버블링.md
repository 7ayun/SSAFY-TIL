# [JS] Controlling Event - 버블링

---

## 1. 이벤트 버블링(Event Bubbling)

**한 요소에 이벤트가 발생하면, 해당 요소의 핸들러가 동작한 후 이어서 부모 요소의 핸들러가 동작하는 현상.**  
가장 최상단의 조상 요소(`document`)를 만날 때까지 이 과정이 반복되며, 요소 각각에 할당된 핸들러가 동작한다.

> 이벤트가 제일 깊은 곳에 있는 요소에서 시작해 부모 요소를 거슬러 올라가며 발생하는 것이 마치 물속 거품과 닮아서 '버블링'이라 한다.

### 버블링 동작 예시

아래와 같이 `form > div > p` 형태의 중첩 구조에 각각 이벤트 핸들러가 연결되어 있을 때:

```javascript
const formElement = document.querySelector('#form')
const divElement = document.querySelector('#div')
const pElement = document.querySelector('#p')

const clickHandler1 = function (event) { console.log('form이 클릭되었습니다.') }
const clickHandler2 = function (event) { console.log('div가 클릭되었습니다.') }
const clickHandler3 = function (event) { console.log('p가 클릭되었습니다.') }

formElement.addEventListener('click', clickHandler1)
divElement.addEventListener('click', clickHandler2)
pElement.addEventListener('click', clickHandler3)
```

`<p>` 요소만 클릭해도 → `p` → `div` → `form` 순서로 3개의 핸들러가 모두 순차적으로 동작한다.

## 2. event.target vs event.currentTarget

이벤트 객체에는 이벤트가 어디서 발생했는지 파악할 수 있는 두 가지 속성이 있다.

| 속성 | 설명 |
|------|------|
| `event.target` | 이벤트가 **처음 발생한 가장 안쪽 요소**. 버블링이 진행돼도 변하지 않음 |
| `event.currentTarget` | **이벤트 핸들러가 연결된 현재 요소**. 일반 함수 핸들러 내에서 `this`와 같음 |

### 비교 예시

`outerouterElement`에만 핸들러가 연결된 상태에서 내부 요소를 클릭했을 때:

```html
<div id="outerouter">
  outerouter
  <div id="outer">
    outer
    <div id="inner">inner</div>
  </div>
</div>

<script>
  const outerOuterElement = document.querySelector('#outerouter')

  const clickHandler = function (event) {
    console.log('currentTarget: ', event.currentTarget.id)
    console.log('target: ', event.target.id)
  }

  outerOuterElement.addEventListener('click', clickHandler)
</script>
```

- `inner` 클릭 시: `currentTarget = outerouter`, `target = inner`
- `outer` 클릭 시: `currentTarget = outerouter`, `target = outer`
- `outerouter` 클릭 시: `currentTarget = outerouter`, `target = outerouter`

> 변수명이나 속성명을 그대로 해석하면 이해가 쉽다.  
> - **Current Target**: 지금 현재 이벤트가 실행되고 있는 요소  
> - **Target**: 이벤트가 실제로 시작된 (가장 안쪽) 요소

## 3. 캡처링(Capturing)

이벤트가 **최상위 조상에서 타겟 요소까지 하위로 전파**되는 단계. 버블링과 반대 방향이다.

```
이벤트 전파 순서:
1. 캡처링 (Window → Document → ... → target)  ↓
2. 타깃 (target에서 이벤트 실행)
3. 버블링 (target → ... → Document → Window)  ↑
```

> 캡처링은 실제 개발에서 거의 사용하지 않는다. 이런 이론이 있다는 것만 알아두고, 버블링을 집중적으로 학습하는 것이 좋다.

---

## 4. 버블링의 필요성 — 이벤트 위임(Event Delegation)

### 문제 상황

버튼이 여러 개 있을 때, 각 버튼마다 이벤트 핸들러를 등록하면 코드가 불필요하게 길어진다.

```html
<div>
  <button></button>
  <button></button>
  <button></button>
  <button></button>
</div>
```

### 해결책: 공통 조상에 핸들러 하나만 등록

버블링을 활용하면, **공통 조상 요소(`div`)에 이벤트 핸들러를 하나만 등록**해도 자식 버튼들의 이벤트를 모두 처리할 수 있다.

```javascript
const divTag = document.querySelector('div')

divTag.addEventListener('click', function (event) {
  console.log(event.target) // 실제로 클릭된 버튼 요소
})
```

- **어떤 버튼을 눌렀는지**는 `event.target`으로 구분 가능
- 자식 요소가 아무리 많아도 핸들러는 하나만 관리하면 됨 → **코드 간결화, 유지보수 용이**

> 공통 조상의 핸들러 내부 로직이 너무 복잡해지면 가독성과 유지보수가 어려워진다. 적절한 레벨의 조상 요소에 등록하는 것이 중요하다.

---

## 💡 한 줄 요약
> 이벤트 버블링은 자식 요소의 이벤트가 부모 방향으로 전파되는 현상이며, 이를 활용한 이벤트 위임으로 공통 조상에 핸들러를 하나만 등록해 여러 자식 요소의 이벤트를 효율적으로 처리할 수 있다.

## ❓ 더 찾아볼 것

- 이벤트 위임(Event Delegation) 패턴 심화
- `addEventListener`의 세 번째 인자 `useCapture` 옵션 (캡처링 단계에서 처리)
