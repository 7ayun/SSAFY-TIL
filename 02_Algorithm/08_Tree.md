## 1. 트리의 개념

### 1-1. 트리란

트리(Tree)는 나무처럼 위에서 아래로 확장되는 **비선형 자료구조**다. 앞서 배운 스택, 큐, 연결 리스트는 데이터 간 순서가 있는 선형 구조였지만, 트리는 **순서가 없고** 원소들 간에 **1대 N의 계층 관계**를 갖는다.

하나의 데이터(부모)에 여러 데이터(자식)가 붙어 있는 구조이며, 역방향(N대 1)이나 서로 얽히는 관계(N대 M)는 허용하지 않는다. N대 M 관계는 내일 배울 **그래프**에 해당한다.

일상 예시로는 회사 조직도, 파일 시스템 디렉토리, HTML DOM 구조 등이 있다.

> **강사님 강조**: 트리 자료구조 자체가 알고리즘 시험에 직접 나오지는 않지만, 공식 문서나 개발자 대화에서 서브트리, 리프노드 같은 용어가 상식처럼 쓰인다. 용어를 암기하려 하지 말고, 나중에 나왔을 때 알아들을 수 있을 정도로 익숙해지면 된다.

### 1-2. 트리 vs 그래프

| 구분 | 트리 | 그래프 |
|------|------|--------|
| 관계 | 1대 N (일방향 계층) | N대 M (서로 얽힘) |
| 루트 | 반드시 1개 | 없거나 여러 개 가능 |
| 사이클 | 없음 | 있을 수 있음 |
| 데이터 용어 | 노드(Node) | 정점(Vertex) |
| 시험 빈도 | 상식 레벨 | 실제 문제 대부분 |

실제 알고리즘 문제는 대부분 그래프 형태로 출제되지만, 트리의 개념을 먼저 이해해야 그래프를 제대로 다룰 수 있다.

## 2. 트리 용어 정리

### 2-1. 핵심 용어

**노드(Node)** 는 트리에 저장되는 데이터 하나하나를 의미한다.

**간선(Edge)** 은 노드와 노드를 연결하는 선으로, 두 노드의 관계를 나타낸다.

**루트 노드(Root)** 는 트리에서 가장 위에 있는 최상위 노드다. 트리에서 루트는 반드시 한 개만 존재한다.

**리프 노드(Leaf)** 는 더 이상 자식이 없는, 가장 아래에 있는 노드다. 차수가 0인 노드이기도 하다. 재귀적 탐색에서 **종료 조건**으로 활용된다.

**서브트리(Subtree)** 는 트리에서 간선 하나를 끊었을 때 만들어지는 또 다른 트리다. 트리 안에 트리가 반복되는 재귀적 구조를 보여준다.

### 2-2. 관계 용어

**부모 노드**는 특정 노드의 바로 위 노드이고, **자식 노드**는 바로 아래 노드다. 같은 부모를 가진 자식들끼리는 **형제 노드**라 한다. **조상 노드**는 특정 노드에서 루트까지 경로에 있는 모든 노드이고, **자손 노드**는 특정 노드의 서브트리에 포함된 모든 하위 노드다.

### 2-3. 수치 용어

**차수(Degree)** 는 노드에 연결된 자식 노드의 수다. 트리의 차수는 트리 내 모든 노드 차수 중 최대값이다.

**레벨(Level)** 은 루트에서 특정 노드까지의 거리다. 루트 노드의 레벨은 0이다.

**높이(Height)** 는 루트에서 가장 먼 리프 노드까지의 간선 수다. 즉 가장 깊은 리프 노드의 레벨이 곧 트리의 높이다.

> **강사님 팁**: 레벨은 "루트에서 몇 칸 내려왔나", 높이는 "가장 깊은 리프가 몇 칸이나 내려가 있나"로 구분하면 헷갈리지 않는다.

## 3. 이진 트리 (Binary Tree)

### 3-1. 이진 트리란

모든 노드가 **최대 2개의 자식 노드**만 가질 수 있는 특별한 형태의 트리다. 왼쪽 자식과 오른쪽 자식으로 구분한다.

이진 트리를 사용하는 이유는 **탐색 효율성** 때문이다. 이진 트리 기반의 이진 탐색 트리(BST)를 구성하면, 매번 절반씩 범위를 줄여 O(log N)의 시간 복잡도로 원하는 데이터를 찾을 수 있다. 10억 개의 데이터도 약 30번의 비교로 탐색 가능하다.

### 3-2. 이진 트리의 특성

레벨 i에서 노드의 최대 개수는 `2^i`개다. 높이가 h인 이진 트리의 노드 최소 개수는 `h + 1`(한쪽으로만 뻗은 경우), 최대 개수는 `2^(h+1) - 1`(모든 레벨이 꽉 찬 경우)이다.

### 3-3. 이진 트리의 종류

**포화 이진 트리(Full Binary Tree)** 는 모든 레벨의 노드가 빈자리 없이 꽉 차 있는 트리다. 높이 h일 때 노드 수는 정확히 `2^(h+1) - 1`개다.

**완전 이진 트리(Complete Binary Tree)** 는 노드 번호 1번부터 N번까지 빈자리가 없는 트리다. 꽉 차지 않아도 되지만 번호 순서에 빈 노드가 없어야 한다. 힙(Heap), 우선순위 큐 등의 전제 조건이 된다.

**편향 이진 트리(Skewed Binary Tree)** 는 한쪽 방향으로만 자식이 치우친 트리다. 사실상 리스트와 동일하므로 탐색 시간이 O(N)이 되어 이진 트리의 장점(O(log N))을 잃는다.

> **강사님 강조**: 편향 이진 트리를 없애는 것이 최종 목표다. 그래야 O(log N) 탐색을 유지할 수 있다. 이를 위해 AVL 트리, 레드-블랙 트리 같은 자가 균형 자료구조가 존재한다. 편향이 생기면 노드를 회전시켜 레벨을 평탄화하는 원리다.

## 4. 이진 트리의 리스트 표현

### 4-1. 노드 번호를 인덱스로 활용

이진 트리는 루트부터 위에서 아래로, 왼쪽에서 오른쪽으로 번호를 매긴다. 이 번호를 리스트의 **인덱스**로 사용하면 트리를 1차원 리스트로 표현할 수 있다.

```python
# 루트 번호를 1로 시작하는 경우
# 인덱스 0은 비워두고, 1번부터 데이터 저장
tree = [None, 'A', 'B', 'C', 'D', 'E', 'F', 'G']
#        0     1    2    3    4    5    6    7
```

### 4-2. 부모·자식 접근 공식 (루트 = 1)

노드 번호가 i일 때:

| 관계 | 공식 | 예시 (i=3) |
|------|------|-----------|
| 부모 노드 | `i // 2` | 3 // 2 = 1 (루트) |
| 왼쪽 자식 | `2 * i` | 2 * 3 = 6 |
| 오른쪽 자식 | `2 * i + 1` | 2 * 3 + 1 = 7 |

루트 번호를 0으로 시작하면 공식이 달라진다. 부모는 `(i - 1) // 2`, 왼쪽 자식은 `2 * i + 1`, 오른쪽 자식은 `2 * i + 2`가 된다. 어떤 방식이든 핵심 규칙만 지키면 정답이 없다.

```python
# 루트 번호 1 기준 구현
class BinaryTree:
    def __init__(self, size):
        self.tree = [None] * (size + 1)  # 인덱스 0은 사용 안 함

    def set_node(self, index, value):
        if 1 <= index < len(self.tree):
            self.tree[index] = value

    def left_child(self, index):
        left = 2 * index
        if left < len(self.tree):
            return self.tree[left]
        return None

    def right_child(self, index):
        right = 2 * index + 1
        if right < len(self.tree):
            return self.tree[right]
        return None

    def parent(self, index):
        if index > 1:
            return self.tree[index // 2]
        return None
```

> **강사님 강조**: 루트 번호를 0으로 하든 1로 하든 상관없다. 자료구조에는 정답이 없고, 핵심 기능(부모·자식 접근)만 올바르게 구현되면 된다.

### 4-3. 리스트 표현의 한계와 연결 리스트

편향 이진 트리의 경우 데이터 4개를 저장하는데 16칸의 공간이 필요하는 등 메모리 낭비가 심하다. 이를 해결하려면 이중 연결 리스트처럼 왼쪽 자식(left)과 오른쪽 자식(right) 포인터를 가진 노드를 사용하면 된다.

## 5. 이진 트리 순회

### 5-1. 순회란

비선형 자료구조에서 모든 노드를 **중복 없이 체계적으로** 방문하는 것이다. 선형 자료구조는 순서대로 가면 되지만, 트리는 순서가 없으므로 별도의 방문 규칙이 필요하다.

순회 방법은 **루트 노드를 언제 방문하느냐**에 따라 세 가지로 나뉜다.

### 5-2. 전위 순회 (Preorder) — 부모 먼저

**방문 순서: 부모 → 왼쪽 자식 → 오른쪽 자식**

루트를 가장 먼저(Pre) 방문한다. 트리의 구조를 그대로 복사할 때 활용된다.

```python
def preorder(node, tree):
    if node not in tree:
        return
    print(node, end=' ')              # 부모 먼저 방문
    for child in tree[node]:
        preorder(child, tree)         # 왼쪽 → 오른쪽 순서로 재귀
```

### 5-3. 중위 순회 (Inorder) — 부모 중간

**방문 순서: 왼쪽 자식 → 부모 → 오른쪽 자식**

루트를 중간(In)에 방문한다. 이진 탐색 트리(BST)에서 중위 순회를 하면 데이터가 정렬된 순서로 출력된다.

```python
def inorder(node, tree):
    if node not in tree:
        return
    children = tree[node]
    if len(children) > 0:
        inorder(children[0], tree)    # 왼쪽 자식 먼저
    print(node, end=' ')              # 부모 중간에 방문
    if len(children) > 1:
        inorder(children[1], tree)    # 오른쪽 자식
```

### 5-4. 후위 순회 (Postorder) — 부모 마지막

**방문 순서: 왼쪽 자식 → 오른쪽 자식 → 부모**

루트를 가장 나중(Post)에 방문한다. 하위 노드의 결과를 모아서 상위 노드에서 처리할 때 활용된다(예: 디렉토리 용량 계산).

```python
def postorder(node, tree):
    if node not in tree:
        return
    for child in tree[node]:
        postorder(child, tree)        # 자식들 먼저 전부 방문
    print(node, end=' ')              # 부모 마지막에 방문
```

## 6. 트리에서의 DFS

### 6-1. DFS란

DFS(Depth First Search, 깊이 우선 탐색)는 루트에서 출발하여 한 방향으로 **끝까지 깊이** 들어간 뒤, 더 갈 곳이 없으면 마지막 갈림길로 되돌아와 다른 방향을 탐색하는 방식이다. 후입선출(LIFO) 구조인 스택(또는 재귀 호출 스택)을 사용하여 구현한다.

### 6-2. 트리 DFS 구현

```python
tree = {
    'A': ['B', 'C', 'D'],
    'B': ['E', 'F'],
    'D': ['G', 'H', 'I']
}

def dfs(node, tree):
    print(node, end=' ')         # 현재 노드 방문
    if node not in tree:         # 자식이 없으면 (리프 노드) 종료
        return
    for child in tree[node]:     # 자식들을 순서대로 재귀 호출
        dfs(child, tree)

dfs('A', tree)
# 출력: A B E F C D G H I
```

`node not in tree`는 해당 노드가 딕셔너리의 키로 존재하지 않는다는 뜻이고, 이는 자식이 없는 리프 노드를 의미한다.

### 6-3. DFS vs BFS 개요

| 구분 | DFS (깊이 우선) | BFS (너비 우선) |
|------|----------------|----------------|
| 탐색 방향 | 한 방향으로 끝까지 깊이 진입 | 같은 레벨의 노드를 먼저 탐색 |
| 자료구조 | 스택 (재귀) | 큐 |
| 활용 | 경로 탐색, 과정·조건 확인 | 최단 거리, 가장 가까운 노드 탐색 |

> **강사님 강조**: 오늘은 트리에서의 DFS 맛보기이고, 내일 배울 그래프에서의 DFS가 실전이다. 트리는 1대 N이라 일방향으로 내려가면 되지만, 그래프는 N대 M이라 사이클과 방문 체크를 추가로 고려해야 한다. 오늘 15% 이해하고, 내일 30%, 문제 풀면서 50%로 올리면 된다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 트리 | 비선형 자료구조, 1대 N 계층 관계, 순서 없음, 루트는 반드시 1개 |
| 트리 vs 그래프 | 트리: 1대 N / 그래프: N대 M, 실제 문제는 대부분 그래프 |
| 핵심 용어 | 노드(데이터), 간선(연결), 루트(최상위), 리프(최하위, 자식 없음) |
| 차수 / 레벨 / 높이 | 차수 = 자식 수, 레벨 = 루트에서 거리, 높이 = 가장 깊은 리프의 레벨 |
| 이진 트리 | 자식 최대 2개, O(log N) 탐색이 목표, 편향 시 O(N)으로 퇴화 |
| 포화 / 완전 / 편향 | 포화 = 전부 꽉 참, 완전 = 번호 순서에 빈자리 없음, 편향 = 한쪽으로 치우침 |
| 리스트 표현 | 노드 번호 = 인덱스, 부모 `i//2`, 왼쪽 `2i`, 오른쪽 `2i+1` (루트=1 기준) |
| 순회 | 전위(부모 먼저), 중위(부모 중간), 후위(부모 마지막) |
| 트리 DFS | 깊이 우선 탐색, 스택/재귀로 구현, 리프 노드가 종료 조건 |
