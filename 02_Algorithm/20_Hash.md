## 1. 해시 개요

### 1-1. 해시란?

기존 탐색 방식의 한계에서 출발한다. 선형 탐색은 O(N), 이진 탐색은 O(log N)이지만 데이터가 정렬되어 있어야 하고 정렬 자체가 O(N log N)이다. 해시는 **데이터를 고정된 크기의 값(해시값)으로 변환**하여 대규모 데이터셋에서 O(1)에 가까운 탐색을 가능하게 하는 자료구조다.

동작 흐름은 다음과 같다.

1. 입력값(키)을 해시 함수에 넣는다
2. 고정된 크기의 해시값이 나온다
3. 해시값을 인덱스(키)로 사용하여 해시 테이블에 데이터를 저장/검색한다

```python
# 딕셔너리의 키 접근이 O(1)인 이유가 바로 해시
data = {"apple": 2, "banana": 5}
print(data["apple"])  # 해시값으로 바로 접근 -> O(1)
```

### 1-2. 해시의 특징

해시는 속도와 메모리 사이의 **트레이드오프** 관계를 갖는다.

**장점:** 키값 직접 접근으로 탐색/삽입/삭제가 O(1), 데이터 무결성 검증 가능(작은 변화에도 해시값이 크게 달라짐), 암호화/비밀번호 저장 활용(원본 대신 해시값 저장), 중복 식별이 쉬움

**단점:** 메모리 사용량이 높음(각 키-값 쌍을 개별 저장), 해시 충돌 발생 가능, 입력 데이터 순서를 보존하지 않아 정렬이 필요한 경우 부적합

> **강사님 강조**: 개발은 트레이드오프다. 무조건적으로 좋은 건 없다. 해시도 속도는 빠르지만 메모리를 많이 차지한다.

### 1-3. 해시의 활용 사례

해시는 실무에서 매우 폭넓게 사용된다: DB 인덱싱, 캐싱, 암호화/비밀번호 저장(원본 대신 해시값 저장하여 보안 강화), 데이터 무결성 검증(문서 전체를 해시값으로 변환해 위변조 판별), 로드 밸런싱 등.

> **강사님 팁**: 비밀번호는 서버에 평문으로 저장되는 게 아니라 해시값으로 저장된다. 해시는 단방향 변환이라 해시값에서 원본을 유추할 수 없다. 이건 장고 파트에서 다시 배운다.

### 1-4. 해시 테이블

해시 테이블은 해시 함수가 만들어낸 해시값을 **인덱스(키)로 활용**하여 데이터를 저장하고 검색하는 자료구조다. 대부분의 경우 키값으로 접근하기 때문에 O(1)에 데이터를 검색, 삽입, 삭제할 수 있다.

해시 테이블의 성능은 **해시 함수의 품질**과 **충돌 해결 방법**에 크게 좌우된다.

## 2. 해시 함수

### 2-1. 좋은 해시 함수의 조건

좋은 해시 함수는 다음 6가지 특성을 갖는다.

```
1. 결정론적 — 동일한 입력은 항상 동일한 해시값을 생성
2. 균등한 분포 — 해시값이 테이블 전체에 고르게 퍼짐
3. 충돌 최소화 — 서로 다른 입력이 같은 해시값을 가질 확률이 낮음
4. 눈사태 효과 — 입력값이 1만 바뀌어도 해시값이 완전히 달라짐
5. 빠른 연산 — 해시값 변환 속도가 빨라야 함
6. 역상 저항성 — 해시값으로부터 입력값을 예측하기 어려워야 함
```

### 2-2. 나머지 연산 해시 함수 (Division Hash Function)

가장 기본적인 해시 함수로, 키를 해시 테이블의 크기(M)로 나눈 **나머지**를 해시값으로 사용한다.

```
h(k) = k % M
```

사물함 30개가 있을 때, 14번 학생은 `14 % 30 = 14`번 사물함, 37번 학생은 `37 % 30 = 7`번 사물함을 사용한다. 만약 7번 학생이 오면 `7 % 30 = 7`로 충돌이 발생한다.

```python
def division_hash(key, table_size):
    return key % table_size

# 사물함 30개 예시
print(division_hash(14, 30))  # 14
print(division_hash(37, 30))  # 7
print(division_hash(7, 30))   # 7 -> 충돌!
```

**장점:** 정수 키에 효과적, 구현이 간단, 테이블 크기를 적절히 선택하면 좋은 성능

**단점:** 테이블 크기 선택에 민감, 특정 패턴의 키에 성능 저하, 문자열 등 복잡한 값에는 추가 처리 필요

> **강사님 팁**: 나머지 해시 함수는 버블 정렬 같은 존재다. 실질적으로 쓰진 않지만 해시 함수의 기초를 이해하기 위해 배우는 것이다.

**테이블 크기 선택 팁:** 소수(prime)를 사용하면 공약수가 없어 충돌 확률이 줄어든다. 2의 거듭제곱을 사용하면 `%` 대신 `&` 비트 연산으로 속도를 절약할 수 있다.

**개선 방식:** 보조 해시를 추가로 적용하거나, MAD(Multiply-Add-Divide) 방식으로 곱셈/덧셈/나눗셈을 조합해 값을 더 다채롭게 만들 수 있다.

### 2-3. 곱셈 해시 함수 (Multiplication Hash Function)

키에 특정 상수 A를 곱한 뒤, 그 결과의 소수 부분을 활용하여 해시값을 만든다.

```
h(k) = floor(M * (k * A % 1))
- A: 0 < A < 1 인 상수 (일반적으로 황금비 0.618 사용)
- M: 테이블 크기
- k * A % 1: k * A의 소수 부분만 추출
```

모든 비트가 서로 영향을 주기 때문에 나머지 연산보다 **균일한 분포**를 제공한다.

```python
def multiplication_hash(key, table_size, A=0.6180339887):
    return int(table_size * ((key * A) % 1))

print(multiplication_hash(14, 30))  # 나머지 연산보다 균일하게 분포
print(multiplication_hash(37, 30))
```

**장점:** 키 분포에 덜 민감, 균일한 분포 제공

**단점:** 부동소수점 연산으로 정밀도 문제 발생 가능, A값 선택이 중요

> **강사님 강조**: A값으로 0.618(황금비)을 사용했을 때 해시값 분포가 가장 균일하다는 것은 실험으로 증명된 결과다.

### 2-4. 폴딩 해시 함수 (Folding Hash Function)

키를 여러 부분으로 **나누고(접고)** 그 부분들을 조합하여 해시값을 생성한다. 긴 키나 문자열에 효과적이다.

```
1. 키를 일정 크기의 부분으로 나눈다
2. 나눈 부분들을 모두 더한다
3. 테이블 크기로 나눈 나머지를 해시값으로 사용한다
```

예를 들어 전화번호 `01012345678`을 세 자리씩 나누면 `010 + 123 + 456 + 780 = 1369`이고, 테이블 크기로 나눈 나머지를 해시값으로 사용한다.

```python
def folding_hash(key_str, chunk_size, table_size):
    total = 0
    for i in range(0, len(key_str), chunk_size):
        chunk = key_str[i:i+chunk_size]
        total += int(chunk) if chunk.isdigit() else sum(ord(c) for c in chunk)
    return total % table_size

print(folding_hash("01012345678", 3, 100))
```

**장점:** 긴 키/문자열에 효과적, 키의 모든 부분을 사용하여 균일한 분포

**단점:** 짧은 키에는 오버헤드, 쪼개는 크기(chunk size)에 따라 성능 좌우

**개선 방식:** 가중치 부여(`010*1 + 123*2 + ...`), XOR/곱셈 조합, 순환 시프트 등

### 2-5. 다항식 해시 함수 (Polynomial Hash Function)

문자열을 **다항식으로 표현**하여 해시값을 계산한다. 라빈-카프 알고리즘에서 활용한 방식이다.

```
h(s) = (s[0]*p^(n-1) + s[1]*p^(n-2) + ... + s[n-1]*p^0) % M
- s[i]: 각 문자의 아스키 코드값
- p: 소수 (보통 31 사용)
- M: 큰 소수
```

문자열의 순서가 해시값에 영향을 미치기 때문에 `"ABC"`와 `"ACB"`는 서로 다른 해시값을 갖는다.

```python
def polynomial_hash(s, p=31, M=1_000_000_007):
    h = 0
    for i, ch in enumerate(s):
        h = (h + ord(ch) * pow(p, len(s) - 1 - i, M)) % M
    return h

print(polynomial_hash("ABC"))  # 고유한 해시값
print(polynomial_hash("ACB"))  # 다른 해시값
```

**장점:** 문자열 비교에 효과적, 라빈-카프에서 롤링 해시로 활용 가능

**단점:** 긴 문자열에 대해 오버플로우 위험, p값과 M값 선택에 따라 성능 차이

### 2-6. SHA-256 (Secure Hash Algorithm 256-bit)

현대에서 가장 널리 사용되는 **암호학적 해시 함수**다. 임의 길이의 입력을 **항상 256비트(64자리 16진수)** 의 고정된 해시값으로 변환한다.

```python
import hashlib

password = "QWE123"
hashed = hashlib.sha256(password.encode()).hexdigest()
print(hashed)  # 항상 64자리 16진수 문자열
# 한 글자만 바꿔도 완전히 다른 해시값 (눈사태 효과)
hashed2 = hashlib.sha256("QWE124".encode()).hexdigest()
print(hashed2)
```

**특징:** 입력과 무관하게 항상 256비트 출력, 원본 복원 사실상 불가능, 눈사태 효과, 역상 저항성

> **강사님 강조**: 비트코인도 SHA-256을 적극 활용한다. 이전 블록의 값에 랜덤 값을 넣어 SHA-256을 돌리고, 결과의 앞부분에 연속 0이 특정 개수 이상 나오면 채굴 보상을 받는 구조다. 이 조건의 난이도를 조절해서 약 10분에 1개가 채굴되도록 통제한다.

## 3. 해시 충돌

### 3-1. 충돌이란?

두 개 이상의 서로 다른 키가 **동일한 해시값**을 생성하는 상황을 해시 충돌이라 한다.

### 3-2. 생일 문제 (Birthday Problem)

충돌 확률은 직관보다 훨씬 높다. 23명만 있어도 생일이 겹칠 확률이 **약 50%**, 57명이면 **약 99%** 에 달한다. 이를 생일 문제(Birthday Problem)라 하며, 해시 테이블에서도 데이터가 조금만 쌓여도 충돌 가능성이 높다는 것을 의미한다.

### 3-3. 충돌의 원인

- **비둘기집 원리**: N-1개의 공간에 N개의 데이터를 넣으면 반드시 충돌 발생
- **해시 함수 품질**: 균등 분포를 못하는 함수는 공간이 넉넉해도 충돌 유발
- **무한한 입력 vs 유한한 테이블**: 입력은 무한히 다양하지만 테이블 크기는 제한적

### 3-4. 충돌의 영향

- **성능 저하**: 충돌 처리로 인해 탐색 시간이 O(1)에서 O(N)까지 증가 가능
- **보안 위험**: 다른 비밀번호로 동일 해시값이 나오면 로그인 가능성 발생
- **데이터 무결성 훼손**: 변조된 문서가 동일 해시값을 가지면 위변조 탐지 불가

> **강사님 주의**: 해시 충돌을 악용한 공격(Hash Collision DoS Attack)도 있다. 의도적으로 같은 해시값을 만드는 입력만 보내서 탐색 시간을 O(N)으로 만들어 서버 속도를 급격히 떨어뜨린다.

## 4. 해시 충돌 해결 — 체이닝 (Chaining)

### 4-1. 체이닝의 원리

해시 테이블의 각 버킷에 **연결 리스트**를 두어, 충돌이 발생한 항목들을 같은 버킷에 연결하는 방식이다. 가장 일반적인 충돌 해결 방법이다.

예를 들어 테이블 크기 5, 나머지 연산일 때 키 2(사과), 7(바나나), 12(배)를 넣으면 2와 12 모두 해시값 2를 가지므로 인덱스 2 버킷에 `[사과] -> [배]`로 연결된다.

```python
class HashTable:
    def __init__(self, size):
        self.size = size
        self.table = [[] for _ in range(size)]

    def _hash(self, key):
        return key % self.size

    def insert(self, key, value):
        idx = self._hash(key)
        for i, (k, v) in enumerate(self.table[idx]):
            if k == key:
                self.table[idx][i] = (key, value)
                return
        self.table[idx].append((key, value))

    def search(self, key):
        idx = self._hash(key)
        for k, v in self.table[idx]:
            if k == key:
                return v
        return None

ht = HashTable(5)
ht.insert(2, "사과")
ht.insert(7, "바나나")
ht.insert(12, "배")      # 12 % 5 = 2 -> 사과와 충돌, 체이닝으로 연결
print(ht.search(12))      # "배"
```

### 4-2. 체이닝의 장단점

**장점:** 구현이 간단 (연결 리스트만 알면 됨), 테이블 크기를 동적으로 조절하기 쉬움

**단점:** 추가 메모리 필요, 최악의 경우 탐색이 O(N)으로 증가하여 해시의 장점이 퇴색

> **강사님 팁**: 체이닝에서 연결 리스트 대신 AVL 트리를 사용하면 최악의 탐색 시간을 O(log N)으로 제한할 수 있다. 단, 삽입 시 AVL 회전 비용이 추가된다.

## 5. 해시 충돌 해결 — 오픈 어드레싱 (Open Addressing)

오픈 어드레싱은 별도의 자료구조 없이 **해시 테이블 배열에 직접 저장**하며, 충돌 시 다른 빈 슬롯을 찾아 저장하는 방식이다.

### 5-1. 선형 탐사 (Linear Probing)

충돌 시 **바로 다음 슬롯**을 순차적으로 검색하여 빈 곳에 저장한다.

```
h(k, i) = (h(k) + i) % M    (i = 0, 1, 2, 3, ...)
```

예시 (테이블 크기 7, 나머지 연산):

```
데이터: 사과(9), 바나나(12), 배(12), 딸기(14), 수박(14), 포도(17)
해시값: 9%7=2, 12%7=5, 12%7=5, 14%7=0, 14%7=0, 17%7=3

[0] 14:딸기          <- 해시값 0, 빈칸이므로 바로 저장
[1] 14:수박          <- 해시값 0, 충돌 -> 다음 칸(1)에 저장
[2] 9:사과           <- 해시값 2, 빈칸이므로 바로 저장
[3] 17:포도          <- 해시값 3, 빈칸이므로 바로 저장
[4] (비어있음)
[5] 12:바나나        <- 해시값 5, 빈칸이므로 바로 저장
[6] 12:배            <- 해시값 5, 충돌 -> 다음 칸(6)에 저장
```

```python
class LinearProbingHashTable:
    def __init__(self, size):
        self.size = size
        self.keys = [None] * size
        self.values = [None] * size

    def _hash(self, key):
        return key % self.size

    def insert(self, key, value):
        idx = self._hash(key)
        while self.keys[idx] is not None:
            if self.keys[idx] == key:
                self.values[idx] = value
                return
            idx = (idx + 1) % self.size  # 다음 슬롯으로 이동
        self.keys[idx] = key
        self.values[idx] = value

    def search(self, key):
        idx = self._hash(key)
        while self.keys[idx] is not None:
            if self.keys[idx] == key:
                return self.values[idx]
            idx = (idx + 1) % self.size
        return None
```

**장점:** 구현 간단, 메모리가 연속적이라 **캐시 성능이 좋음**, 추가 메모리 불필요

**단점:** **클러스터링 문제** — 연속된 슬롯에 데이터가 몰리는 현상 발생. 테이블이 거의 가득 차면 성능이 급격히 저하

> **강사님 강조**: 캐시 성능이 중요하다. 메모리가 연속으로 붙어있으면 배달할 때 옆집 옆집 바로 가는 것처럼 빠르고, 떨어져 있으면 이 층 저 층 왔다갔다 하는 것처럼 느리다.

### 5-2. 로드 팩터 (Load Factor)

테이블의 효율성을 관리하기 위한 지표로, 저장된 항목 수를 테이블 크기로 나눈 값이다.

```
로드 팩터 = 저장된 항목 수 / 테이블 크기
```

일반적으로 로드 팩터가 **0.6~0.7**을 초과하면 성능이 급격히 저하되므로, 이 시점에 테이블 크기를 늘려(리사이징) 로드 팩터를 낮추는 전략을 사용한다.

### 5-3. 제곱 탐사 (Quadratic Probing)

충돌 시 **제곱수만큼 떨어진 위치**를 탐색하여 클러스터링 문제를 완화한다.

```
h(k, i) = (h(k) + i^2) % M    (i = 0, 1, 2, 3, ...)
- 충돌 1회: +1칸
- 충돌 2회: +4칸
- 충돌 3회: +9칸
```

```python
def quadratic_insert(keys, values, size, key, value):
    idx = key % size
    i = 0
    while keys[(idx + i * i) % size] is not None:
        if keys[(idx + i * i) % size] == key:
            values[(idx + i * i) % size] = value
            return
        i += 1
    pos = (idx + i * i) % size
    keys[pos] = key
    values[pos] = value
```

**장점:** 선형 탐사보다 클러스터링 문제가 덜함, 데이터가 더 넓게 퍼짐

**단점:** **2차 클러스터링 문제** — 제곱수 패턴이 반복되어 실제 사용 가능한 공간이 테이블의 절반 정도. 테이블이 절반 이상 차면 성능 급격히 저하. 모든 버킷을 탐색하지 못할 수도 있음

> **강사님 주의**: 테이블 크기가 M이면 제곱 탐사로 실제 접근 가능한 공간은 약 M/2뿐이다. 예를 들어 크기 10일 때 제곱수를 10으로 나눈 나머지는 0, 1, 4, 9, 6, 5 이렇게 일부만 반복된다.

### 5-4. 이중 해싱 (Double Hashing)

**두 개의 해시 함수**를 사용하여 충돌을 해결한다. 첫 번째 함수는 초기 위치를, 두 번째 함수는 충돌 시 이동 간격을 결정한다.

```
h(k, i) = (h1(k) + i * h2(k)) % M
- h1(k): 초기 버킷 위치
- h2(k): 충돌 시 이동 간격
```

각 키마다 h2(k)가 다른 값을 만들어내므로 탐사 순서가 키에 따라 달라져 클러스터링 문제가 크게 감소한다.

```python
class DoubleHashingTable:
    def __init__(self, size):
        self.size = size
        self.keys = [None] * size
        self.values = [None] * size

    def _h1(self, key):
        return key % self.size

    def _h2(self, key):
        return 1 + (key % (self.size - 1))  # 0이 되면 안 됨

    def insert(self, key, value):
        idx = self._h1(key)
        step = self._h2(key)
        while self.keys[idx] is not None:
            if self.keys[idx] == key:
                self.values[idx] = value
                return
            idx = (idx + step) % self.size  # step만큼 이동
        self.keys[idx] = key
        self.values[idx] = value
```

**장점:** 클러스터링 문제 크게 감소, 선형/제곱 탐사보다 균일한 분포

**단점:** 해시 함수 2개로 추가 연산 필요, 구현이 복잡, 두 함수의 조합 최적화가 어려움 (고려할 파라미터가 h1 x h2로 늘어남)

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 해시 | 입력값을 고정 크기의 해시값으로 변환하여 O(1) 탐색을 가능하게 하는 자료구조. 속도 vs 메모리 트레이드오프 |
| 해시 함수 | 나머지(기초), 곱셈(황금비), 폴딩(분할 후 합산), 다항식(문자열), SHA-256(암호학적) |
| 해시 테이블 | 해시값을 인덱스로 사용하여 키-값 쌍을 저장. 성능은 해시 함수 품질과 충돌 해결에 좌우 |
| 해시 충돌 | 서로 다른 키가 같은 해시값을 갖는 현상. 비둘기집 원리에 의해 불가피 |
| 체이닝 | 같은 버킷에 연결 리스트 연결. 간단하지만 최악 O(N). AVL 적용 시 O(log N) |
| 선형 탐사 | 다음 빈 슬롯에 저장. 캐시 성능 좋지만 클러스터링 문제 |
| 제곱 탐사 | 제곱수만큼 이동. 클러스터링 완화되나 사용 가능 공간이 절반 |
| 이중 해싱 | 두 번째 해시 함수로 간격 결정. 가장 균일하지만 구현 복잡 |
| 로드 팩터 | 저장 항목 수 / 테이블 크기. 0.6~0.7 초과 시 리사이징 권장 |
