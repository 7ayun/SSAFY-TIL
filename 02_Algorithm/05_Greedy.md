## 💡 주요 개념 정리

### 1. 탐욕 알고리즘 (Greedy) 개요
* **핵심 정의:** 복잡한 증명이나 전체 경로에 대한 고려 없이, 매 선택의 순간마다 직관적으로 최적이라고 생각되는 해답을 좇아 최종 결과를 도출하는 근시안적 문제 해결 기법
* **실생활 비유:** 마트 계산대에서 가장 짧은 줄 서기, 가방에 부피가 작고 비싼 물건부터 담기 (이마트 맛동산 무한 담기 등)
* **장단점 (Trade-off):**
    * **장점:** 복잡한 문제를 단순화하여 연산 속도(`O(N)` 또는 `O(N log N)`)가 매우 빠름
    * **단점:** 현재의 최선이 전체의 최적해를 항상 보장하지 않으므로, 정답 도출을 위해서는 엄밀한 수학적 증명(귀류법, 귀납법 등)이 필수적임

### 2. 탐욕 알고리즘 성립 조건과 예시
* **동전 교환 문제 (거스름돈):**
    * **탐욕 조건:** 각 동전의 단위가 하위 동전들의 '배수' 관계일 때만 큰 동전부터 거슬러 주는 탐욕적 접근이 성립함 (예: 500원은 100원의 배수)
    * **실패 케이스:** [500, 400, 100]원이 있을 때 800원을 거슬러 준다면, 그리디는 500(1)+100(3)=4개를 반환하지만 실제 최적해는 400(2)=2개임
* **배낭 짐싸기 문제 (Knapsack):**
    * **0-1 Knapsack (불가):** 물건을 쪼갤 수 없는 경우, 그리디(가장 비싼 것부터 or 무게당 가치가 높은 것부터)로 접근하면 최적해 도출에 실패하므로 완전탐색(`O(2^N)`)이나 DP(동적 계획법)를 사용해야 함
    * **Fractional Knapsack (가능):** 물건을 쪼개서 담을 수 있는 경우, 무게당 가치(Kg당 가격)가 높은 순서대로 정렬하여 가방을 채우면 탐욕 알고리즘이 성립함
* **선택 활동 문제 (회의실 배정 / 화물 도크):**
    * **그리디 접근법:** 가능한 많은 회의(작업)를 배정하기 위해서는 '종료 시간(End Time)'이 가장 빠른 순서대로 정렬한 뒤, 이전 작업의 종료 시간보다 늦게 시작하는 작업을 순차적으로 선택해야 함

### 3. 알고리즘 문제 해결 전략 및 CS 상식
* **풀이 접근 순서:**
    1. **완전탐색(Brute Force) 최우선:** 입력 조건이 작을 경우(`N < 20`) 무조건 완탐으로 접근하여 정답 보장
    2. **탐욕 알고리즘 전환:** 완탐 시 시간 초과(Time Out)가 우려되거나 N값이 매우 클 경우, 최후의 보루로 직관적인 탐욕 알고리즘 또는 DP/분할정복을 시도
* **P vs NP 문제 (7대 밀레니엄 난제):**
    * **P (Polynomial Time):** 주어진 다항 시간(`O(N)`, `O(N log N)`, `O(N^2)`) 내에 해결 가능한 문제
    * **NP (Non-deterministic Polynomial Time):** 다항 시간 내에 해를 구하기는 매우 어렵지만(예: 부분집합 `2^N`, 유전자 배열), 해가 주어졌을 때 그것이 정답인지 '검증'하는 것은 쉬운 문제

## 💻 기능 구현 및 코드 실습

### [문제] 스위치 조작 (순차적 반전)
> **활용 알고리즘:** `Greedy_Simulation`, `Array_Traversal`
> **난이도:** ★★☆☆☆

### 🔍 문제 설명
* N개의 스위치가 있으며, i번째 스위치를 누르면 i번부터 N번까지의 모든 스위치 상태가 반전됨
* 현재 상태에서 목표 상태로 만들기 위한 최소 조작 횟수 구하기
* **탐욕 로직:** 앞에서부터 순차적으로 비교하며, 다를 경우 스위치를 누름. 앞의 스위치를 맞추면 뒤에만 영향을 주므로 앞은 더 이상 건드릴 필요가 없음

### 💻 구현 코드 (Python)
```python
def switch_toggle(n, current, target):
    result = 0
    # 1. 앞에서부터 순차적으로 스위치 상태 비교
    for i in range(n):
        if current[i] == target[i]:
            continue # 같으면 패스
            
        # 2. 다르면 스위치를 누름 (결과 +1)
        result += 1
        
        # 3. 누른 위치(i)부터 끝(n)까지 모든 스위치 상태 반전
        for j in range(i, n):
            # 1에서 빼면 0은 1로, 1은 0으로 반전됨
            current[j] = 1 - current[j] 
            
    return result
```

### [문제] 배수 스위치 (모두 끄기)
> **활용 알고리즘:** `Greedy`, `Modulo_Operation`
> **난이도:** ★★★☆☆

### 🔍 문제 설명
* N개의 전구가 있으며, i번 스위치를 누르면 i의 '배수' 번호를 가진 모든 전구가 반전됨
* 켜져 있는 모든 전구(1)를 끄기(0) 위한 최소 조작 횟수를 구하되, 불가능한 경우 -1을 출력
* **탐욕 로직:** 1번부터 확인하며 켜져 있으면 무조건 누름. 배수만 영향을 받으므로 지나친 앞번호는 다시 바꿀 기회가 없음

### 💻 구현 코드 (Python)
```python
def turn_off_switches(n, switches):
    # Y/N 입력을 1과 0으로 치환했다고 가정 (켜짐: 1, 꺼짐: 0)
    result = 0
    
    # 1. 1번 스위치부터 N번 스위치까지 탐색 (배수 계산을 위해 1부터 시작)
    for i in range(1, n + 1):
        if switches[i - 1] == 0: # 이미 꺼져있으면 패스 (인덱스는 i-1)
            continue
            
        result += 1 # 켜져 있으면 누름
        
        # 2. 현재 누른 스위치(i)의 배수 번호에 해당하는 전구 반전
        for j in range(i, n + 1):
            if j % i == 0: # j가 i의 배수인지 확인
                switches[j - 1] = 1 - switches[j - 1]
                
    # 3. 모든 조작 후 켜져 있는 전구가 하나라도 남았는지 검증
    # 세트(set)를 활용하여 원소의 종류를 파악 (속도 최적화)
    if 1 in set(switches):
        return -1
        
    return result
```

### [문제] 화물 도크 (회의실 배정)
> **활용 알고리즘:** `Greedy`, `Lambda_Sort`
> **난이도:** ★★★☆☆

### 🔍 문제 설명
* 작업의 시작 시간과 종료 시간이 주어질 때, 겹치지 않으면서 가장 많은 작업을 수행할 수 있는 개수 구하기

### 💻 구현 코드 (Python)
```python
def max_cargo_dock(n, jobs):
    # 1. 종료 시간(index 1)을 기준으로 오름차순 정렬 (Lambda 활용)
    jobs.sort(key=lambda x: x[1])
    
    # 2. 가장 빨리 끝나는 첫 번째 작업 무조건 선택
    result = 1
    end_time = jobs[0][1]
    
    # 3. 남은 작업들을 순회하며 배정 가능 여부 판단
    for i in range(1, n):
        start_time = jobs[i][0]
        # 이전 작업의 종료 시간 이후에 시작한다면 선택
        if start_time >= end_time:
            result += 1
            end_time = jobs[i][1] # 종료 시간 갱신
            
    return result
```

## 🚀 복습 및 AI 인사이트
* **헷갈렸던 점:**
    * 탐욕 알고리즘은 정렬(Sort)이 핵심 전제조건이 되는 경우가 많음. 화물 도크 문제에서 `lambda`를 활용하여 2차원 배열의 특정 인덱스(종료 시간) 기준으로 정렬하는 문법 숙지
    * 배수 스위치 문제에서 스위치 번호(1~N)와 배열 인덱스(0~N-1) 간의 오프셋(`-1`) 차이를 꼼꼼히 제어해야 `IndexError`를 방지할 수 있음
* **AI 활용 팁:**
    * 탐욕 알고리즘으로 풀이 후 내부 테스트 케이스에서 지속적인 실패가 발생할 경우, AI에게 반례(Counter Example) 생성을 요청하여 로직의 수학적 증명 오류 확인
    * `in` 연산자 사용 시 리스트(`O(N)`)보다 세트(`set, O(1)`)를 사용하는 것이 압도적으로 빠르다는 점을 AI와 함께 복잡도 계산을 통해 시뮬레이션
