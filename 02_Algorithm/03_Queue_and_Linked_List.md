## 💡 주요 개념 정리

### 1. 큐(Queue)의 기본 원리 및 특성
* **핵심 정의:** 뒤에서 삽입하고 앞에서 삭제하는 선입선출(FIFO, First-In-First-Out) 기반의 선형 자료구조
* **실생활 비유:** 은행 번호표 대기열, 버스 정류장 줄 서기, 프린터 인쇄 대기열, 편의점 진열대(유통기한 선입선출 관리)
* **컴퓨터 응용:** 영상 재생 시 일시적으로 데이터를 보관하는 버퍼링(Buffering), 키보드 입력 버퍼 처리 등
* **저수준 관리 지표:**
    * **Front 포인터:** 데이터를 꺼내는(삭제) 위치. 마지막으로 삭제된 원소를 가리키며 초기값은 `-1`임
    * **Rear(꼬리) 포인터:** 데이터를 넣는(삽입) 위치. 마지막으로 삽입된 원소를 가리키며 초기값은 `-1`임
    * **데이터 개수 산출:** `Rear - Front` 연산을 통해 현재 큐에 남은 데이터 개수를 도출함
    * **상태 판별:** `Front == Rear`일 경우 뺄 데이터가 없는 비어있음(Empty) 상태를 의미함

### 2. 선형 큐의 한계와 원형 큐(Circular Queue)의 도입
* **선형 큐의 문제점:** `Rear` 포인터가 계속 뒤로만 이동하여 배열의 끝(`capacity - 1`)에 도달하면, 앞부분(`Front` 이전)에 빈 공간이 있어도 데이터를 더 이상 삽입할 수 없음
* **원형 큐의 논리적 해결책:** 인덱스를 큐의 전체 크기(N)로 나눈 나머지(`% N`) 연산자를 활용하여, 끝에 도달 시 다시 인덱스 0으로 순환하도록 구현함
* **원형 큐의 상태 판별 딜레마와 극복:**
    * `Front == Rear` 조건이 데이터가 '비어있을 때'와 '한 바퀴를 돌아 가득 찼을 때' 두 가지 상황에서 모두 성립하여 구분이 불가함
    * **해결 전략:** 배열의 한 칸을 의도적으로 비워두고(사용하지 않음), `(Rear + 1) % N == Front`일 경우 가득 찬(Full) 것으로 규정하여 비어있는 상태와 명확히 구분함

### 3. 데큐(Deque, Double-Ended Queue)
* **등장 배경:** 일반 파이썬 리스트에서 `pop(0)`을 수행하면 맨 앞 데이터가 빠진 후 남은 모든 원소를 한 칸씩 앞으로 당겨야 하므로 `O(N)`의 시간 복잡도가 발생하여 비효율적임
* **해결책:** 이중 연결 리스트(Doubly Linked List) 기반으로 내부가 구현된 `collections.deque`를 활용하면 양끝단 삽입/삭제를 `O(1)`의 속도로 처리할 수 있음
* **주요 기능:** `append`, `appendleft`, `pop`, `popleft`, `rotate(양수/음수)` 등

### 4. 연결 리스트(Linked List)의 구조와 동작
* **핵심 정의:** 자료의 논리적인 순서와 메모리상의 물리적인 주소가 일치하지 않으며, 각 데이터가 자신이 다음에 이동할 데이터의 주소(Link)를 독립적으로 기억하는 자료구조
* **장단점(Trade-off):**
    * **장점:** 데이터 삽입/삭제 시 전체 원소를 당기거나 미는 작업이 불필요하여 속도가 빠르며, 연속된 거대 메모리 블록이 필요 없어 메모리 관리가 유연함
    * **단점:** 인덱스(`[i]`)를 통한 `O(1)` 임의 접근(Random Access)이 불가능하며, 특정 요소를 찾으려면 처음부터 링크를 타고 순차 탐색(`O(N)`)해야 함
* **기본 구성 요소:**
    * **Node (노드):** 실제 값을 저장하는 '데이터 필드'와 다음 노드의 주소를 담는 '링크(Next) 필드'로 구성된 개별 원소
    * **Head (헤드):** 흩어진 노드들 중 가장 첫 번째 노드의 주소를 가리키는 시작 지점 포인터
* **이중 연결 리스트(Doubly Linked List):** `next` 주소뿐만 아니라 `previous` 주소도 저장하여 양방향 탐색이 가능하며, 꼬리를 가리키는 `tail` 포인터를 두어 후방 삽입(`append`)을 최적화함
* **고아 노드(Orphan Node):** 삭제 연산 시 선행 노드의 참조가 끊어져 접근이 불가능해진 노드. 파이썬에서는 가비지 컬렉터가 알아서 처리하므로 굳이 값을 수동으로 제거할 필요가 없음

### [문제] 마이쮸 나눠주기 시뮬레이션
> **활용 알고리즘:** `Queue`, `Simulation`
> **난이도:** ★★☆☆☆

```python
def solve_mychew():
    total_candy = 20
    queue = [] # [학생 번호, 받을 캔디 수]를 담는 큐
    next_person = 1
    last_person = None
    
    # 1. 초기화: 1번 학생이 1개를 받겠다고 큐에 진입
    queue.append([next_person, 1])
    
    while total_candy > 0:
        # 2. 선입선출: 제일 앞 학생 팝(pop)하여 사탕 지급
        person, count = queue.pop(0)
        total_candy -= count
        
        # 3. 종료 조건 검사: 사탕이 0개 이하가 되면 해당 학생이 마지막
        if total_candy <= 0:
            last_person = person
            break
            
        # 4. 재등록: 받은 학생은 요구 개수를 1개 늘려서 맨 뒤에 다시 줄 서기
        queue.append([person, count + 1])
        
        # 5. 신규 등록: 누군가 받을 때마다 새로운 학생이 1개를 요구하며 줄 서기
        next_person += 1
        queue.append([next_person, 1])
        
    return last_person
```

### [문제] 화덕에 피자 굽기
> **활용 알고리즘:** `collections.deque`, `Simulation`
> **난이도:** ★★★☆☆

```python
from collections import deque

def solve_pizza(N, M, cheese_list):
    # 피자의 초기 위치(인덱스)와 치즈 양을 묶어 2차원 형태로 저장
    pizzas = [[i, cheese] for i, cheese in enumerate(cheese_list)]
    
    # 1. 화덕(크기 N)과 대기열 덱 생성
    fire_queue = deque(pizzas[:N])
    waiting_queue = deque(pizzas[N:])
    
    # 2. 화덕에 피자가 단 1개 남을 때까지 무한 회전
    while len(fire_queue) > 1:
        # 3. 1번 위치의 피자를 꺼내서 치즈를 반으로 줄임
        idx, cheese = fire_queue.popleft()
        cheese //= 2
        
        # 4. 분기 처리: 치즈가 남았으면 화덕 맨 뒤로, 다 녹았으면 대기열 피자 투입
        if cheese > 0:
            fire_queue.append([idx, cheese])
        else:
            if waiting_queue: # 대기열에 남은 피자가 있다면
                fire_queue.append(waiting_queue.popleft())
                
    # 5. 마지막 남은 피자의 원래 번호(인덱스 + 1) 반환
    return fire_queue[0][0] + 1
```

## 🚀 복습 및 AI 인사이트
* **헷갈렸던 점:**
    * 큐의 데이터 개수를 구할 때 단순히 인덱스에 `+1`을 하는 것이 아니라, `Rear - Front` 공식을 써야 현재 남아있는 요소의 개수가 정확히 산출됨
    * 연결 리스트 중간에 노드를 삽입할 때, `새 노드의 다음 주소 할당`이 `이전 노드의 다음 주소 변경`보다 반드시 선행되어야 함. 순서가 바뀌면 원래 뒷부분의 주소를 영영 잃어버리게 됨
    * `pop(0)`과 `deque.popleft()`의 결과는 같지만 내부적으로 전자는 `O(N)`, 후자는 `O(1)`의 속도 차이를 가짐을 명확히 인지
* **AI 활용 팁:**
    * 원형 큐의 포인터 순환 구조(나머지 연산)가 머릿속에 잘 그려지지 않을 때, AI에게 배열 크기가 4일 때의 `Front/Rear` 변화 시뮬레이션 테이블 작성을 요청하여 시각적 이해도 향상
