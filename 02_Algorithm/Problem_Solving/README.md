## 🎯 문제풀이 학습 목표
* 알고리즘 이론(탐색, 정렬, 자료구조 등)을 실제 코드로 구현하고 실전 문제 해결 능력 배양
* 다중 조건문으로 인한 코드의 복잡도를 낮추고 디버깅을 용이하게 하는 '얼리 리턴(Early Return)' 설계 패턴 체화
* 2차원 배열 생성 시 발생하는 얕은 복사(Shallow Copy) 참조 문제를 방지하고, 독립적인 메모리 할당 방식 숙달
* `for`문과 `while`문의 사용 목적을 명확히 구분하고, 무한 루프 방지를 위한 종료 조건 설정 로직 확립

## 💡 문제풀이 공통 핵심 노하우

### 1. 2차원 배열 초기화 및 참조(Reference) 주의
* **오류 케이스 (얕은 복사):** `[[0] * N] * N` 형태로 초기화할 경우, 내부 리스트들이 동일한 메모리 주소를 공유함. 이로 인해 단 하나의 요소만 변경해도 모든 행의 동일 인덱스 값이 동시다발적으로 변경되는 치명적 논리 오류 발생
* **해결책 (깊은 복사 유도):** 반드시 리스트 컴프리헨션을 사용하여 `[[0] * N for _ in range(N)]` 형태로 선언해야 각 행이 독립적인 메모리 주소를 갖는 2차원 배열로 안전하게 생성됨

### 2. 반복문 제어 기법 (For vs While)
* **for문:** 탐색해야 할 횟수나 인덱스의 범위가 명확하게 정해져 있을 때 사용 (예: $N \times N$ 행렬의 전체 순회, 리스트 요소 순차 접근)
* **while문:** 끝나는 시점(조건)만 명확하고, 정확히 몇 번을 반복해야 할지 미지수일 때 사용 (예: 사다리 타기에서 바닥에 도달할 때까지 하강). 단, 무한 루프 방지를 위해 루프 내부에서 명확한 상태 변화와 종료 조건(`break`, `return`) 설정 필수

### 3. 얼리 리턴 (Early Return) 패턴 설계
* **정의:** 다중 `if-and` 조건문으로 인해 코드의 들여쓰기(Depth)가 깊어지는 것을 방지하는 프로그래밍 패턴
* **적용 방법:** 부정 조건(격자 범위 이탈, 진행 불가한 장애물 조우, 이미 방문한 노드 등)을 조건문 상단에 배치하여 `continue`나 `return`으로 실행 흐름을 일찍 차단함
* **장점:** 1. 예외 처리가 상단에 몰려 있어 조건 누락을 방지함
    2. 하단의 핵심 비즈니스 로직이 불필요한 들여쓰기 없이 깔끔하게 배치되어 가독성이 극대화됨
    3. 특정 조건에서 에러가 발생할 경우, 어느 분기에서 차단되었는지 프린트문(`print`)을 찍어 디버깅하기가 매우 용이함
