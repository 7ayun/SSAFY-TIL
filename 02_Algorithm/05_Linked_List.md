## 1. 연결 리스트 — 개념과 존재 이유

### 1-1. 배열(리스트)의 한계

배열은 메모리에 연속적으로 저장되므로 인덱스 접근이 O(1)이다. 시작 주소에 간격 × 인덱스를 더하면 한 번에 원하는 위치로 이동할 수 있기 때문이다. 그러나 중간에 삽입하거나 삭제하면 뒤의 모든 원소를 한 칸씩 이동해야 하므로 O(n)이 된다. 배열 크기를 확장할 때도 연속된 빈 공간을 찾아 통째로 이사해야 하는 부담이 있다.

> **강사님 강조**: Python의 리스트는 용량이 부족하면 기존의 약 40%를 확장하는데, 확장된 공간이 다른 데이터와 충돌하면 빈 주소를 찾아 통째로 이사한다. 그래서 메모리 관리가 유연하지 않다.

### 1-2. 연결 리스트의 아이디어

연결 리스트는 자료의 **논리적 순서와 물리적 순서가 일치하지 않는** 자료구조다. 각 원소(노드)가 메모리 어디에 있든 상관없이, "다음에 갈 주소"를 저장하고 있어서 그 주소를 타고 순서대로 탐색할 수 있다.

중간에 삽입하거나 삭제할 때는 해당 노드의 링크(주소)만 변경하면 되므로 나머지 원소를 이동할 필요가 없다.

### 1-3. 트레이드오프

| 항목 | 배열(리스트) | 연결 리스트 |
|------|-------------|------------|
| 인덱스 접근 | O(1) | O(n) — 순차 탐색 필요 |
| 중간 삽입·삭제 | O(n) — 원소 이동 필요 | O(1) — 링크만 변경 |
| 메모리 배치 | 연속적 | 비연속적 (유연) |
| 역방향 탐색 | 가능 | 단순 연결 리스트는 불가 |

> **강사님 강조**: 만능인 자료구조는 없다. 모든 것은 트레이드오프 관계에 있으므로 상황에 맞춰 선택해야 한다. 연결 리스트의 핵심은 "메모리가 독립적으로 흩어져 있고, 인덱싱은 안 되지만, 삽입·삭제가 용이하다" — 이것만 기억하면 된다.

## 2. 단순 연결 리스트 (Singly Linked List)

### 2-1. 기본 구조 — 노드와 헤드

연결 리스트의 기본 구성 요소는 **노드(Node)** 와 **헤드(Head)** 다.

노드는 두 가지 필드로 구성된다. **데이터 필드**(실제 값 저장)와 **링크 필드**(다음 노드의 주소 저장)다. 마지막 노드의 링크 필드는 None(null)으로, 다음 노드가 없음을 나타낸다.

헤드는 연결 리스트의 시작 지점, 즉 첫 번째 노드의 주소를 가리킨다. 흩어져 있는 노드들 중에서 어디서부터 시작할지를 알려주는 역할이다. 헤드는 데이터를 저장하지 않고 주소만 갖고 있다.

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None       # 다음 노드의 주소 (없으면 None)

class SinglyLinkedList:
    def __init__(self):
        self.head = None       # 시작점 (비어 있으면 None)
```

### 2-2. 삽입 — 세 가지 경우

**첫 번째 노드로 삽입:** 새 노드를 만들고, 새 노드의 next를 기존 head가 가리키던 노드로 설정한 뒤, head를 새 노드로 변경한다.

**마지막 노드로 삽입:** head에서 출발하여 next가 None인 노드(마지막)까지 순차 탐색한 뒤, 그 노드의 next를 새 노드로 연결한다.

**중간에 삽입 (A와 B 사이에 C를 넣는 경우):** 삽입 위치의 이전 노드(선행 노드, A)까지 순차 탐색한 뒤, 새 노드(C)의 next를 A의 next(즉 B)로 설정하고, A의 next를 새 노드(C)로 변경한다.

핵심 논리를 정리하면, 새 노드가 기존의 "다음"을 가리키게 하고 → 이전 노드가 새 노드를 가리키게 한다. 순서가 중요한데, 이전 노드의 next를 먼저 바꾸면 기존 다음 노드에 접근할 수 없게 된다.

### 2-3. 삭제와 고아 노드

삭제할 노드의 링크 필드(다음 주소)를 선행 노드의 링크 필드에 복사하면 선행 노드가 삭제 대상을 건너뛰고 그 다음 노드를 직접 가리키게 된다. 삭제된 노드의 next도 None으로 설정해 준다.

이렇게 연결이 끊긴 노드를 **고아 노드(orphan node)** 라고 한다. 데이터는 메모리에 남아 있지만 어디서도 접근할 수 없는 상태다. 파일을 지웠을 때 복구 센터에서 복구할 수 있는 이유도 실제 데이터를 지운 것이 아니라 접근 경로를 끊었기 때문이다.

> **강사님 강조**: 고아 노드를 굳이 별도로 삭제할 필요는 없다. 접근할 수 있는 방법이 없으니 없는 것이나 마찬가지다. 다만 꼼꼼하게 하려면 next를 None으로 설정해서 혹시 모를 접근을 차단하는 것이 좋다.

### 2-4. 탐색(Search)

head에서 출발하여 current를 next로 이동하면서 원하는 데이터를 찾을 때까지 순차 탐색한다. 찾으면 해당 인덱스(위치)를 반환한다. 인덱스 접근이 안 되므로 반드시 처음부터 하나씩 넘어가야 한다.

### 2-5. 단순 연결 리스트의 한계

next만 있어서 한 방향으로만 탐색할 수 있다. 마지막 노드에 접근하려면 head에서부터 전체를 순회해야 하고, 역방향 탐색이 불가능하다.

> **강사님 강조**: 연결 리스트의 삽입·삭제를 코드로 직접 구현할 줄 몰라도 된다. 시험에도 안 나온다. 중요한 것은 "B를 지우면 A가 C를 가리키게 한다", "중간에 넣으면 이전 노드가 나를 가리키고 내가 다음을 가리킨다" — 이 로직을 이해하고 있으면 충분하다.

## 3. 이중 연결 리스트 (Doubly Linked List)

### 3-1. 구조

이중 연결 리스트는 각 노드에 **next(다음 노드 주소)** 와 **prev(이전 노드 주소)** 를 모두 저장한다. 양방향으로 왔다 갔다 탐색할 수 있다.

```python
class DNode:
    def __init__(self, data):
        self.data = data
        self.prev = None       # 이전 노드 주소
        self.next = None       # 다음 노드 주소
```

첫 번째 노드의 prev는 None이고, 마지막 노드의 next는 None이다. 변수명이 next만 있던 것에서 prev가 추가된 것일 뿐, 노드의 기본 원리는 동일하다.

### 3-2. 삽입 — 네 개의 링크 변경

A와 B 사이에 D를 넣는 경우, 변경해야 할 링크가 네 개다.

```
변경 전:  A ⇄ B
변경 후:  A ⇄ D ⇄ B

① D.next = B       (D가 B를 가리킴)
② D.prev = A       (D가 A를 가리킴)
③ A.next = D       (A가 D를 가리킴)
④ B.prev = D       (B가 D를 가리킴)
```

코드로 표현하면 current가 A를 가리킬 때, B는 `current.next`이고, 새 노드 D의 링크를 설정한 뒤 A와 B의 링크를 D로 변경한다. 포인터가 많아서 복잡해 보이지만, 직접 A, D, B를 그려서 화살표를 그리면 어렵지 않다.

### 3-3. 삭제

A-B-C에서 B를 삭제하는 경우, A의 next를 C로, C의 prev를 A로 변경하면 B는 고아 노드가 된다. 단순 연결 리스트의 삭제와 원리는 같지만, prev 링크도 함께 처리해야 한다.

### 3-4. deque와의 연결

Python의 `collections.deque`는 이중 연결 리스트로 구현되어 있다. 그래서 앞에서 빼는 `popleft()`가 O(1)이고, 뒤에서 빼는 `pop()`도 O(1)이다. 단, 인덱스 접근(`deque[3]`)은 내부적으로 head에서부터 next를 타고 순차 탐색하므로 O(n)이다. 이것이 바로 연결 리스트의 "인덱싱 불가" 특성이 그대로 드러나는 부분이다.

> **강사님 강조**: `deque[3]`처럼 인덱스 접근이 파이썬에서 문법상 가능하긴 하지만, 실제로는 내부에서 next를 타고 순차 탐색하는 O(n) 작업이 일어나고 있는 거다. 된다고 다 되는 게 아니다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 연결 리스트 존재 이유 | 배열의 중간 삽입·삭제 O(n) 문제를 링크 변경만으로 해결 |
| 트레이드오프 | 배열: 인덱싱 O(1) / 삽입삭제 O(n), 연결 리스트: 인덱싱 O(n) / 삽입삭제 O(1) |
| 노드 | 데이터 필드 + 링크 필드, 마지막 노드의 링크는 None |
| 헤드 | 연결 리스트의 시작점(첫 번째 노드 주소)을 가리키는 포인터, 데이터 없음 |
| 삽입 핵심 | 새 노드가 기존 "다음"을 가리키고 → 이전 노드가 새 노드를 가리킴 (순서 중요) |
| 삭제 핵심 | 삭제할 노드의 next를 선행 노드의 next에 복사 → 고아 노드 발생 |
| 단순 연결 리스트 | next만 저장, 한 방향 탐색, 역방향 불가, 마지막 접근 시 전체 순회 필요 |
| 이중 연결 리스트 | next + prev 저장, 양방향 탐색, 삽입·삭제 시 링크 네 개 변경 |
| deque 연결 | 이중 연결 리스트 기반 → `popleft()` O(1), 인덱스 접근은 O(n) |
