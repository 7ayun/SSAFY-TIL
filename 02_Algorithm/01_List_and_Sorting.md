## 1. 알고리즘 개요

알고리즘이란 **유한한 단계**를 통해 문제를 해결하기 위한 절차나 방법이다. 컴퓨터 분야에서는 주어진 입력을 원하는 출력으로 변환하는 일련의 명령을 뜻한다.

좋은 알고리즘의 조건은 정확성(모든 경우의 수·예외 처리), 작업량(적은 연산), 메모리(적은 공간), 단순성(유지보수 용이), 최적성(개선 여지 없음) 등이다.

### 1-1. 알고리즘 표현 방법

알고리즘을 표현하는 세 가지 방식이 있다.

```
① 의사코드(Pseudo-code) — 프로그래밍 언어와 자연어의 중간 형태
② 순서도(Flowchart)    — 도형·화살표로 논리 흐름을 시각화
③ 프로그래밍 코드       — 실제 언어로 작성
```

> **강사님 강조**: 처음에는 의사코드(한글 코딩)로 로직을 먼저 정리한 뒤 프로그래밍 언어로 옮기는 습관을 들이자.

## 2. 시간 복잡도와 빅오(Big-O) 표기법

### 2-1. 시간 복잡도란

실행되는 **명령문의 개수**를 기반으로 알고리즘의 속도를 정량적으로 표현한 것이다.

```python
# 알고리즘 1: 1부터 n까지 순수 반복 — 2n + 1 번 연산
def sum_loop(n):
    total = 0             # 1번
    for i in range(1, n + 1):  # n번 반복
        total += i        # n번 누적
    return total

# 알고리즘 2: 가우스 합 공식 — 3번 연산
def sum_gauss(n):
    return n * (n + 1) // 2
```

n이 커질수록 알고리즘 1은 연산 횟수가 비례 증가하지만, 알고리즘 2는 항상 3번이다.

### 2-2. 빅오(Big-O) 표기법

**최악의 경우** 성능을 기준으로, 계수와 낮은 차수 항을 제거한 **최고차항**만 남긴다.

| 표기 | 이름 | 예시 |
|------|------|------|
| O(1) | 상수 시간 | 인덱스 접근, 가우스 합 |
| O(log n) | 로그 시간 | 이진 탐색 (업다운 게임) |
| O(n) | 선형 시간 | 단순 순회 |
| O(n log n) | 선형 로그 시간 | `sort()` (팀소트) |
| O(n²) | 이차 시간 | 이중 for문 (버블·선택·삽입 정렬) |
| O(2ⁿ) | 지수 시간 | 부분집합 |
| O(n!) | 팩토리얼 시간 | 순열 |

> **강사님 강조**: 빅오가 중요한 이유: "아무리 데이터가 꼬여도 이 시간 안에 끝남을 **보장**한다." 99%의 확률로 1초에 끝나더라도 1%의 확률로 100초가 걸리면, 그 알고리즘의 빅오는 100초 기준이 된다.

### 2-3. 공간 복잡도

알고리즘 실행에 필요한 **메모리 양**이다. 시간과 공간은 대체로 트레이드오프(trade-off) 관계에 있다. 시간도 줄이고 공간도 줄이는 알고리즘을 찾으면 대단한 것이지만, 보통은 한쪽을 얻으면 한쪽을 잃는다.

> **강사님 조언**: "세상에 공짜는 없다." 개발에서 가장 중요한 개념 중 하나가 트레이드오프다.

## 3. 1차원 리스트 활용

### 3-1. 선언과 접근

```python
# 선언 방법
arr1 = list()           # 빈 리스트 (클래스 인스턴스화)
arr2 = []               # 빈 리스트 (리터럴)
arr3 = [1, 2, 3, 4, 5]  # 선언과 동시에 할당
arr4 = [0] * 10         # 0이 10개인 리스트

# 접근
arr3[0]   # 1
arr3[-1]  # 5
```

### 3-2. 표준 입출력 — 알고리즘 문제의 기본

SWEA 등 알고리즘 문제에서 입력은 **문자열**로 들어온다. 이를 정수 리스트로 변환하는 패턴이 핵심이다.

```python
# 공백 구분 정수 한 줄 입력
arr = list(map(int, input().split()))

# 단계별 이해
raw = input()                # "477162 658880 ..."  ← 문자열 전체
tokens = raw.split()         # ['477162', '658880', ...]  ← 공백 분리
arr = list(map(int, tokens)) # [477162, 658880, ...]  ← 정수 변환
```

> **강사님 강조**: `input()` → `split()` → `map(int, ...)` → `list()` 이 흐름을 외우지 말고 **왜 되는지** 이해하라. 문자열을 공백으로 분리하고, 각 요소에 `int` 함수를 적용하고, 리스트로 감싸는 것이다.

### 3-3. SWEA 출력 형식

```python
T = int(input())
for tc in range(1, T + 1):
    # 풀이
    print(f"#{tc} {answer}")
```

## 4. 정렬 개요

정렬(Sorting)이란 데이터를 특정 기준(키값)에 따라 오름차순 또는 내림차순으로 재배열하는 것이다.

**정렬을 배우는 이유** — 정렬이 되어 있어야 이진 탐색(O(log n))을 적용할 수 있다. 데이터베이스 인덱싱, 검색 최적화 등 거의 모든 시스템의 기반이 정렬이다.

SSAFY에서 배우는 정렬: 버블·선택·삽입·카운팅 (기초) + 병합·퀵 (후반기).

### 4-1. 정렬 특성 용어

| 용어 | 의미 |
|------|------|
| **안정성 (Stability)** | 동일 키값을 가진 요소들의 **상대적 순서가 정렬 후에도 유지**되는가 |
| **적응성 (Adaptivity)** | 이미 정렬된 데이터에 대해 **실행 시간이 단축**되는가 |
| **제자리 정렬 (In-place)** | 외부 메모리를 사용하지 않고 **주어진 리스트 내에서** 정렬이 완료되는가 |

예시: 빨간 2와 파란 2가 있을 때, 정렬 후에도 빨간 2가 파란 2보다 앞에 있으면 안정한 정렬이다.

## 5. 버블 정렬 (Bubble Sort)

### 5-1. 동작 원리

**인접한 두 요소를 비교**하여, 왼쪽이 더 크면 교환한다. 한 패스가 끝나면 가장 큰 값이 맨 뒤에 고정된다. 이 과정을 반복하면 뒤에서부터 정렬이 완성된다.

```
[55, 7, 78, 12, 42]
 패스 1: 55↔7 교환 → [7, 55, 78, 12, 42]
         55 < 78 유지 → 78↔12 교환 → 78↔42 교환
         결과: [7, 55, 12, 42, | 78 고정]
 패스 2: 고정된 78 제외하고 나머지에서 반복 ...
```

### 5-2. 구현

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):                    # 패스 반복
        for j in range(n - i - 1):        # 비교 범위 (뒤에서 줄어듦)
            if arr[j] > arr[j + 1]:       # 왼쪽이 더 크면
                arr[j], arr[j + 1] = arr[j + 1], arr[j]  # 교환
```

**`n - i - 1`인 이유:**
- `-i` : 패스가 지날수록 뒤에 고정된 요소를 제외
- `-1` : `j+1`과 비교하므로 마지막 요소는 오른쪽이 없어 제외 (인덱스 에러 방지)

### 5-3. 특성

| 항목 | 값 |
|------|-----|
| 시간 복잡도 (최악) | O(n²) |
| 시간 복잡도 (최선) | Ω(n) — 이미 정렬된 경우 한 바퀴만 돌고 종료 |
| 안정성 | **있음** — 인접 요소끼리만 교환하므로 상대 순서 유지 |
| 적응성 | **있음** — 정렬된 데이터에서 조기 종료 가능 |
| 제자리 정렬 | **O** |

> **강사님 강조**: 버블 정렬은 실제로 안 쓴다. 이론 교육용이다. 하지만 "버블 정렬도 모른다"고 하면 공부를 안 한 사람 취급받을 수 있으므로, 상식으로 반드시 알아야 한다.

## 6. 선택 정렬 (Selection Sort)

### 6-1. 동작 원리

전체에서 **최솟값을 찾아** 맨 앞 위치와 교환한다. 나머지 영역에서 또 최솟값을 찾아 그 다음 위치에 놓는다. "인형 뽑기"처럼 아무 데서나 뽑아오는 개념이다.

```
[64, 25, 10, 22, 11]
 패스 1: 전체 최솟값 10 → 64와 교환 → [10, 25, 64, 22, 11]
 패스 2: [25, 64, 22, 11] 중 최솟값 11 → 25와 교환 → [10, 11, 64, 22, 25]
 ...
```

### 6-2. 구현

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n - 1):               # 마지막 1개는 자동 정렬
        min_idx = i                       # 현재 위치를 최솟값으로 가정
        for j in range(i + 1, n):         # i 이후 탐색
            if arr[j] < arr[min_idx]:     # 더 작은 값 발견 시
                min_idx = j               # 최솟값 인덱스 갱신
        arr[i], arr[min_idx] = arr[min_idx], arr[i]  # 교환
```

**최솟값의 인덱스를 찾는 이유** — 교환하려면 서로의 **위치(인덱스)**를 알아야 한다. 값 자체는 배열에 이미 들어있다.

### 6-3. 특성

| 항목 | 값 |
|------|-----|
| 시간 복잡도 | O(n²) — 항상 |
| 안정성 | **없음** — 떨어진 위치의 요소를 교환하므로 상대 순서 깨짐 |
| 적응성 | **없음** — 정렬 여부와 무관하게 매번 최솟값 탐색 |
| 제자리 정렬 | **O** |

## 7. 삽입 정렬 (Insertion Sort)

### 7-1. 동작 원리

첫 번째 요소는 이미 정렬되었다고 간주한다. 두 번째 요소부터 하나씩 꺼내어, **정렬된 부분을 뒤에서부터 비교**하며 자신의 위치를 찾아간다. 카드패를 정리하는 것과 같은 원리다.

```
[10, 30, 69, 16, 8, 31, 22]
 이미 정렬: [10]
 16 삽입: 69 > 16 교환, 30 > 16 교환, 10 < 16 STOP → [10, 16, 30, 69, ...]
 8 삽입:  69 > 8 교환, 30 > 8 교환, 16 > 8 교환, 10 > 8 교환 → [8, 10, 16, 30, 69, ...]
```

### 7-2. 구현

```python
def insertion_sort(arr):
    n = len(arr)
    for i in range(1, n):                     # 두 번째 요소부터 (미정렬 영역)
        for j in range(i, 0, -1):             # 현재 위치에서 뒤로 이동
            if arr[j - 1] > arr[j]:           # 왼쪽이 더 크면
                arr[j - 1], arr[j] = arr[j], arr[j - 1]  # 교환
            else:
                break                         # 내 위치 찾음 → 중단
```

**`range(i, 0, -1)` 이유:**
- `i`부터 시작: 미정렬 원소의 현재 위치
- `0`까지 (1까지 실행): 맨 앞 원소의 왼쪽은 없으므로 비교 불가
- `-1`: 뒤에서 앞으로 이동

### 7-3. 특성

| 항목 | 값 |
|------|-----|
| 시간 복잡도 (최악) | O(n²) — 역순 정렬된 경우 |
| 시간 복잡도 (최선) | Ω(n) — 이미 정렬된 경우 break로 즉시 종료 |
| 안정성 | **있음** — 인접 요소끼리 교환 |
| 적응성 | **있음** — 거의 정렬된 데이터에서 매우 빠름 |
| 제자리 정렬 | **O** |

> **강사님 강조**: 삽입 정렬은 실제로 쓰인다. 파이썬의 `sort()`(팀소트)도 내부적으로 작은 데이터셋에 삽입 정렬 로직을 사용한다. 실세계 데이터는 대부분 어느 정도 정렬되어 있기 때문에, 삽입 정렬의 실제 성능은 O(n) ~ O(n log n) 수준으로 돌아가는 경우가 많다.

## 8. 카운팅 정렬 (Counting Sort)

### 8-1. 동작 원리

비교 기반 정렬이 아닌, **각 값의 등장 횟수를 세는** 방식이다.

① 카운트 배열 생성: 최댓값 + 1 크기의 리스트를 만들어 각 값의 개수를 센다.
② 누적합 계산: 카운트 배열의 앞에서부터 누적합을 구한다 (각 값이 들어갈 **영역**을 결정).
③ 뒤에서부터 배치: 원본 배열을 **뒤에서부터** 순회하며 누적합을 기준으로 결과 배열에 배치한다.

### 8-2. 기본 구현 (단순 버전)

```python
def counting_sort_simple(arr):
    max_val = max(arr)
    count = [0] * (max_val + 1)    # 카운트 배열

    for val in arr:                # ① 개수 세기
        count[val] += 1

    result = []
    for i in range(len(count)):    # ② 개수만큼 값 나열
        result.extend([i] * count[i])
    return result
```

이 방식은 간단하지만 **안정성이 없다** — 같은 숫자의 원래 순서(부가 정보)가 보존되지 않는다.

### 8-3. 안정성 확보 구현 (누적합 버전)

```python
def counting_sort_stable(arr):
    max_val = max(arr)
    count = [0] * (max_val + 1)
    result = [0] * len(arr)

    # ① 개수 세기
    for val in arr:
        count[val] += 1

    # ② 누적합 → 각 값이 들어갈 마지막 위치
    for i in range(1, len(count)):
        count[i] += count[i - 1]

    # ③ 뒤에서부터 배치 → 안정성 확보
    for i in range(len(arr) - 1, -1, -1):
        val = arr[i]
        count[val] -= 1
        result[count[val]] = val

    return result
```

**뒤에서부터 배치하는 이유** — 같은 값을 가진 요소 중 원본에서 뒤에 있던 것이 결과에서도 뒤에 오도록 하여 상대적 순서(안정성)를 유지한다.

> **강사님 팁**: 빵집 줄 서기 비유: "세영1"이 9시, "세영2"가 11시에 왔는데, 정렬 후 "세영2"가 앞으로 오면 억울하다. 안정성이 필요한 이유다.

### 8-4. 특성

| 항목 | 값 |
|------|-----|
| 시간 복잡도 | O(n + k) — n: 데이터 수, k: 최댓값 |
| 안정성 | **있음** (누적합 버전) |
| 제자리 정렬 | **X** — 카운트 배열 + 결과 배열 필요 |
| 제한 | 정수 또는 정수로 표현 가능한 데이터만 가능 |
| 주의 | 최댓값이 매우 크면 메모리 낭비 심함 |

> **강사님 강조**: 딕셔너리로 카운팅하면 안 되느냐? 딕셔너리는 **키 순서를 보장하지 않으므로** for문으로 꺼낼 때 순서가 뒤섞일 수 있다. 정렬 목적이라면 리스트 인덱스를 활용해야 한다.

## 9. 정렬 비교 종합

| 정렬 | 시간 복잡도 (최악) | 시간 복잡도 (최선) | 안정성 | 적응성 | 제자리 |
|------|:---:|:---:|:---:|:---:|:---:|
| 버블 | O(n²) | Ω(n) | O | O | O |
| 선택 | O(n²) | O(n²) | X | X | O |
| 삽입 | O(n²) | Ω(n) | O | O | O |
| 카운팅 | O(n+k) | O(n+k) | O | - | X |

> **강사님 조언**: "이건 암기의 영역이 아니다. 동작 원리를 이해하면 안정성·적응성 같은 특성이 자연스럽게 보인다." 인접 요소끼리 교환하면 안정적이고, 이미 정렬된 걸 감지할 수 있으면 적응적이다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 알고리즘 | 유한 단계로 문제를 해결하는 절차, 의사코드로 먼저 설계하는 습관이 중요 |
| 시간 복잡도 | 알고리즘 성능을 정량적으로 비교하는 척도 |
| 빅오 표기법 | 최악의 경우 기준, 최고차항만 남긴다 (O(1) < O(log n) < O(n) < O(n²)) |
| 트레이드오프 | 시간과 공간은 대체로 반비례, 적절한 균형점을 찾는 것이 실력 |
| 표준 입출력 | `list(map(int, input().split()))` — 문자열 → 분리 → 정수 변환 → 리스트 |
| 버블 정렬 | 인접 비교·교환, 매 패스마다 최댓값이 뒤로 고정, 이론 교육용 |
| 선택 정렬 | 전체에서 최솟값 찾아 앞에 배치, 안정성·적응성 없음 |
| 삽입 정렬 | 정렬 영역에서 뒤로 비교하며 위치 탐색, 거의 정렬된 데이터에서 매우 효율적 |
| 카운팅 정렬 | 개수 세기 → 누적합 → 뒤에서 배치, O(n+k)이지만 메모리 제약 있음 |
