## 1. 탐욕 알고리즘이란

### 1-1. 정의 — 방법론이지 알고리즘이 아니다

탐욕(Greedy) 알고리즘은 델타 탐색이나 다익스트라 같은 **구체적인 알고리즘이 아니다.** 문제를 마주했을 때 "각 선택 시점에서 그 순간 최선이라고 생각되는 것을 선택해 나가면 전체 최적이 될 것이다"라는 접근 방식, 즉 **문제 해결 기법** 중 하나다.

핵심은 단순하다. 큰 문제를 작은 부분으로 나누고, 각 부분에서 그때그때 최선을 고른다. 앞에서 한 선택은 되돌아보지 않고, 남은 부분에서 또 최선을 고르는 것을 반복한다. 이렇게 모은 부분 최선들이 전체 최선이 되기를 기대하는 방식이다.

> **강사님 강조**: 탐욕 알고리즘은 정해진 규칙이나 방법 자체가 없다. 머릿속에 떠오르는 생각을 검증 없이 구현하면 그게 바로 그리디적 접근이다. 이걸 잘하는 방법은 정말로 문제를 많이 풀어보는 것뿐이다.

### 1-2. 장점과 한계

| 항목 | 내용 |
|------|------|
| 장점 | 복잡한 문제를 단순하게 바꿔 줌, 시간 복잡도가 보통 O(n) 수준으로 빠름 |
| 한계 | **최적해를 항상 보장하지 않음**, 수학적 증명(검증)이 필요하지만 그 검증이 매우 어려움 |

### 1-3. 탐욕 적용의 두 가지 조건 (이론)

이론적으로 탐욕 알고리즘을 적용하려면 두 조건을 만족해야 한다.

**탐욕적 선택 속성**: 지금 고른 최선이 이후 선택에 영향을 주지 않고, 계속 반복하면 전체 최선으로 연결되는 "안전한 선택"이어야 한다.

**최적 부분 구조**: 큰 문제가 동일한 형태의 작은 문제들로 쪼개져야 한다. 단계마다 같은 규칙을 적용해서 해결할 수 있어야 한다는 의미다.

실전에서는 이 두 조건을 매번 수학적으로 증명하기 어렵기 때문에, 결국 대표 유형을 많이 풀어서 패턴을 익히는 것이 최선이다.

## 2. 네 가지 문제 해결 기법과 선택 전략

### 2-1. 기법 개요

| 기법 | 핵심 | 시간 복잡도 | 특징 |
|------|------|------------|------|
| 완전 탐색 (Brute Force) | 모든 경우를 시도 | 느림 (2ⁿ, n! 등) | **무조건 정답을 구할 수 있음**, 대신 느림 |
| 탐욕 (Greedy) | 순간순간 최선 선택 | 빠름 (보통 O(n)) | 최적해 보장 안 됨, 검증 필요 |
| 분할 정복 (Divide & Conquer) | 문제를 쪼개서 해결 후 합침 | 다양 | 재귀 기반, 병합 정렬 등 |
| 동적 계획법 (DP) | 부분 문제의 결과를 저장하며 풀기 | 다양 | 중복 부분 문제 최적화 |

### 2-2. 실전 선택 순서

문제를 마주했을 때 접근 순서는 다음과 같다.

**① 완전 탐색부터 시도한다.** 무조건 답을 구할 수 있으므로 먼저 시도한다. 입력 조건의 n이 20 이하 수준이면 완전 탐색으로 충분하다.

**② 시간 복잡도가 감당 안 되면 탐욕을 고려한다.** n이 크고, 경우의 수가 폭발적이면 완전 탐색을 포기하고 "순간순간 최선을 골라보자"는 탐욕적 접근을 시도한다.

**③ 탐욕도 안 되면 분할 정복 또는 DP를 고민한다.** 탐욕으로 최적해가 보장되지 않을 때, 나머지 기법을 적용한다. 일반적으로 분할 정복이나 DP 쪽이 더 많이 쓰인다.

> **강사님 강조**: 알고리즘을 배우면 배울수록 오히려 실력이 퇴보하는 느낌이 든다. 완전 탐색만 알 때는 그것만 하면 됐는데, 기법이 늘어날수록 "이 문제는 네 가지 중 뭘로 풀지?"부터 고민해야 하기 때문이다. 그래서 기본적으로는 완전 탐색으로 먼저 풀어보고, 시간이 안 되면 다른 기법으로 넘어가는 습관을 들여야 한다.

### 2-3. IM vs A형에서의 탐욕

IM 시험은 제출 후 즉시 결과 확인 + 무한 재시도가 가능하다. 탐욕이 틀리면 바로 알 수 있으므로 "한번 해봐, 안 되면 말고" 전략이 통한다.

반면 A형은 최종 제출본만 채점되고 결과를 바로 확인할 수 없다. 탐욕으로 접근해서 샘플 테스트 케이스는 통과했지만 내부 테스트 케이스에서 틀리면 끝이다. 그래서 A형에서 탐욕은 **최후의 수단**이며, 차라리 완전 탐색이 더 안전하다.

> **강사님 강조**: A형에서 탐욕이 나오면 차라리 완전 탐색을 하고 말지, 탐욕으로 접근하기 어렵다. 검증이 안 되기 때문이다. 탐욕 알고리즘은 IM에서 나오면 쉽지만, A형에서 나오면 사실상 최후의 보루다.

## 3. 대표 유형 ① — 동전 교환

### 3-1. 아이디어

거스름돈을 최소 개수의 동전으로 거슬러주는 문제다. 직관적으로 **가장 큰 단위의 동전부터** 최대한 거슬러주면 될 것 같다.

800원을 거슬러줄 때, 동전이 500원·100원·50원·10원이면 500원 1개 + 100원 3개 = 4개가 최소다. 이것은 가장 큰 동전부터 사용하는 탐욕적 접근이 정답을 준다.

### 3-2. 함정 — 배수 관계가 아닌 경우

동전이 500원·400원·100원·50원·10원이면? 800원을 큰 것부터 거슬러주면 500원 1개 + 100원 3개 = 4개가 되지만, 실제 최소는 400원 2개 = 2개다.

탐욕이 성립하는 조건은 **각 동전의 가치가 그보다 작은 동전의 배수**인 경우다. 500원 = 100원 × 5 = 50원 × 10 = 10원 × 50처럼 상위 동전이 하위 동전의 조합으로 표현될 수 있어야 한다. 400원은 500원으로 조합할 수 없으므로 배수 관계가 깨지고, 탐욕이 실패한다.

### 3-3. 구현

```python
def coin_change(coins, amount):
    coins.sort(reverse=True)         # 큰 동전부터 정렬
    result = {}

    for coin in coins:
        if amount >= coin:
            count = amount // coin    # 해당 동전으로 최대한 거슬러줌
            amount -= coin * count    # 남은 금액 갱신
            result[coin] = count

    return result

print(coin_change([500, 100, 50, 10], 800))
# {500: 1, 100: 3}
```

> **강사님 강조**: 동전 교환에서 배수 관계 조건을 문제 풀다가 직접 떠올릴 수 있겠냐고? 솔직히 어렵다. 그래서 이런 유형을 기억해 두고, 비슷한 결의 문제를 만나면 "배수인 경우에만 탐욕을 적용할 수 있겠네"라고 판단하는 것이다.

## 4. 대표 유형 ② — 냅색 (배낭 문제, Knapsack)

### 4-1. 문제 정의

가방에 담을 수 있는 무게가 정해져 있고, 각 물건에는 무게와 가치가 있다. 가방에 물건을 담아서 가치의 합이 최대가 되도록 하는 문제다.

### 4-2. 0-1 Knapsack — 탐욕으로 안 된다

물건을 통째로 넣거나 안 넣거나, 둘 중 하나만 가능한 경우다. 가방 30kg, 물건 세 개가 있을 때 세 가지 탐욕 전략을 시도해도 모두 실패한다.

**가장 비싼 것부터**: 25kg/10만원을 넣으면 10만원이지만, 10kg/9만원 + 10kg/5만원을 넣으면 14만원이 더 크다.

**가장 가벼운 것부터**: 10kg 두 개를 넣으면 14만원이지만, 25kg/15만원 하나가 더 큰 경우도 있다.

**kg당 가치가 높은 것부터**: 역시 반례가 존재한다.

결국 0-1 Knapsack은 완전 탐색(2ⁿ)이나 **DP**로 풀어야 한다.

### 4-3. Fractional Knapsack — 탐욕으로 된다

물건을 잘라서 일부만 담을 수 있다면 이야기가 달라진다. kg당 가치가 높은 순서대로 넣되, 가방 용량이 부족하면 남은 용량만큼 잘라서 넣으면 된다.

가방 30kg 예시: 5kg/50만원(kg당 10만원) → 20kg/140만원(kg당 7만원) → 10kg 중 남은 5kg만 잘라서 30만원. 합계 220만원이 최적이다.

### 4-4. Fractional Knapsack 구현

강사님이 손으로 풀어준 과정을 그대로 코드로 옮기면 된다. "kg당 가치로 정렬 → 큰 것부터 넣기 → 남은 용량만큼 잘라 넣기"가 전부다.

```python
def fractional_knapsack(capacity, items):
    # items: [(무게, 가치), ...]
    # kg당 가치 기준 내림차순 정렬
    items.sort(key=lambda x: x[1] / x[0], reverse=True)

    total_value = 0

    for weight, value in items:
        if capacity >= weight:
            # 통째로 넣을 수 있으면 전부 넣기
            capacity -= weight
            total_value += value
        else:
            # 남은 용량만큼만 잘라서 넣기
            total_value += value * (capacity / weight)
            break                    # 가방 꽉 참

    return total_value

items = [(5, 50), (20, 140), (10, 60)]   # (무게, 가치)
print(fractional_knapsack(30, items))     # 220.0
```

동작 흐름을 따라가면: ① kg당 가치 정렬 → 5kg/50만(10만), 20kg/140만(7만), 10kg/60만(6만) ② 5kg 통째로 넣음 → 남은 용량 25kg, 누적 50만 ③ 20kg 통째로 넣음 → 남은 용량 5kg, 누적 190만 ④ 10kg 중 5kg만 잘라서 넣음 → 60만 × (5/10) = 30만 → 총 220만.

0-1 Knapsack과의 차이는 `else` 분기 하나뿐이다. 통째로 못 넣으면 비율만큼 잘라 넣는 것이 Fractional의 핵심이고, 이것이 가능하기 때문에 탐욕이 성립한다.

> **강사님 강조**: 0-1 Knapsack에서는 완전 탐색도, 탐욕도 안 되고 DP로 풀어야 한다. 물건을 잘라서 담을 수 있다는 Fractional 조건이 붙어야만 탐욕으로 풀 수 있다.

## 5. 대표 유형 ③ — 활동 선택 (Activity Selection)

### 5-1. 문제

회의실 하나에 여러 회의가 신청되어 있고, 각 회의에는 시작 시간과 종료 시간이 있다. 겹치지 않게 배치해서 **최대한 많은 회의**를 열어야 한다.

### 5-2. 탐욕 전략 — 종료 시간이 빠른 순

떠오르는 아이디어는 여러 가지다: 먼저 시작하는 순, 짧은 시간순, 먼저 끝나는 순 등. 이 중 **종료 시간이 빠른 순서대로** 선택하는 것이 정답을 준다.

이유는 직관적이다. 가장 빨리 끝나는 활동을 선택하면 남은 시간이 최대한 많이 확보된다. 남은 시간에서 다시 가장 빨리 끝나는 활동을 고르면 또 남은 시간이 확보되고, 이를 반복하면 가장 많은 활동을 배치할 수 있다.

### 5-3. 알고리즘 흐름

① 종료 시간 기준으로 활동들을 오름차순 정렬한다. ② 첫 번째 활동(가장 빨리 끝나는)을 선택하고 종료 시간을 기록한다. ③ 나머지 활동들을 순회하면서, 시작 시간이 현재 종료 시간 이상인 활동을 선택하고 종료 시간을 갱신한다.

### 5-4. 구현

```python
activities = [
    (1, 4), (1, 6), (10, 3), (5, 7), (3, 8),
    (5, 9), (6, 10), (8, 11), (8, 12), (2, 13)
]
# (시작 시간, 종료 시간)

activities.sort(key=lambda x: x[1])    # 종료 시간 기준 정렬

selected = [activities[0]]              # 첫 번째(가장 빨리 끝나는) 선택
end_time = activities[0][1]

for i in range(1, len(activities)):
    if activities[i][0] >= end_time:    # 시작 시간 ≥ 현재 종료 시간
        selected.append(activities[i])
        end_time = activities[i][1]     # 종료 시간 갱신

print(len(selected))    # 최대 활동 수
print(selected)         # 선택된 활동 목록
```

이 코드 패턴은 §7 화물 도크 문제와 완전히 동일하다. 화물 도크는 입력만 다를 뿐 "종료 시간 정렬 → 겹치지 않으면 선택 → 종료 시간 갱신"이라는 골격이 그대로 쓰인다.

> **강사님 강조**: 이 활동 선택 문제는 탐욕의 가장 대표적인 유형이다. 이런 유형을 외우고 많이 풀어 보는 게 탐욕 알고리즘의 고수가 되는 방법이다.

## 6. 문제 풀이 ① — 스위치 조작

### 6-1. 문제

N개의 전등이 있고, i번 스위치를 누르면 **i번부터 N번까지 전부 반전**된다. 현재 상태에서 목표 상태로 만들기 위한 최소 조작 횟수를 구한다.

### 6-2. 탐욕 아이디어

앞에서부터 하나씩 비교해서 다르면 누르고, 같으면 넘긴다. 누르면 해당 위치부터 끝까지 반전되지만, **앞쪽은 영향을 받지 않는다.** 따라서 앞에서부터 맞춰 놓으면 뒤에서 어떤 조작을 해도 앞은 안전하다. 이것이 탐욕적 선택 속성을 만족하는 이유다.

### 6-3. 구현

```python
n = int(input())
prev_switch = list(map(int, input().split()))
next_switch = list(map(int, input().split()))
result = 0

for i in range(n):
    if prev_switch[i] == next_switch[i]:
        continue
    # 다르면 → 눌러야 한다
    result += 1
    for j in range(i, n):                         # i번부터 끝까지 반전
        prev_switch[j] = 1 - prev_switch[j]       # 0↔1 반전 트릭

print(result)
```

반전 코드 `1 - x`는 외워 두면 편하다. x가 1이면 0, 0이면 1이 된다. `if/else`로 분기하는 것과 동일한 결과를 한 줄로 처리할 수 있다.

> **강사님 강조**: 이 스위치 조작 문제를 12기 때 강의했는데, 바로 그 기수 역량평가에서 배수 스위치 문제가 나왔다. 다들 야무지게 써먹었다.

## 7. 문제 풀이 ② — 화물 도크 (활동 선택 응용)

### 7-1. 문제

화물 도크 하나에 여러 화물차가 사용 신청을 했고, 각 신청에는 시작 시간과 종료 시간이 있다. 최대한 많은 화물차가 이용할 수 있도록 배정한다.

말만 화물 도크지, 활동 선택 문제와 완전히 동일한 구조다. 종료 시간이 빠른 순서대로 배치하면 된다.

### 7-2. 구현

```python
n = int(input())
jobs = [list(map(int, input().split())) for _ in range(n)]

jobs.sort(key=lambda x: x[1])       # 종료 시간 기준 정렬

result = 1                           # 첫 번째 작업 선택
end_time = jobs[0][1]                # 첫 작업의 종료 시간

for i in range(1, n):
    if jobs[i][0] < end_time:        # 시작 시간이 현재 종료보다 빠르면 → 겹침
        continue
    result += 1                      # 겹치지 않으면 선택
    end_time = jobs[i][1]            # 종료 시간 갱신

print(result)
```

`sort(key=lambda x: x[1])`는 2차원 리스트를 특정 인덱스 기준으로 정렬하는 코드다. 탐욕 문제에서는 정렬이 거의 필수적으로 등장하므로 이 패턴을 꼭 익혀 둬야 한다.

> **강사님 팁**: 제 코딩 스타일은 depth를 안 들어가려고 조건을 `continue`로 미리 잘라내는 것이다. 강요하지는 않지만, 이렇게 하면 코드가 간결해진다.

## 8. 문제 풀이 ③ — 배수 스위치

### 8-1. 문제

N개의 전구가 있고, i번 스위치를 누르면 **i의 배수 번호**에 해당하는 전구가 모두 반전된다. 모든 전구를 끄기 위한 최소 조작 횟수를 구한다. 모든 전구를 끌 수 없으면 -1을 출력한다.

### 8-2. 탐욕 아이디어

스위치 조작과 동일한 논리다. i번 스위치를 누르면 i의 배수(i, 2i, 3i, ...)만 반전되므로 **뒤쪽만 영향**을 받고 앞쪽은 안전하다. 앞에서부터 하나씩 보면서, 켜져 있으면 그때 누르는 것이 최선이다. 이 기회를 놓치면 뒤에서 앞쪽 상태를 바꿀 방법이 없다.

### 8-3. 구현

```python
n = int(input())
array = input()
switch = [1 if ch == 'Y' else 0 for ch in array]   # Y→1, N→0 변환

result = 0

for i in range(1, n + 1):                  # 1번 스위치부터 (배수 계산 위해)
    if switch[i - 1] == 0:                 # 이미 꺼져 있으면 넘김
        continue
    result += 1                            # 켜져 있으면 누름
    for j in range(i, n + 1):              # i부터 끝까지 순회
        if j % i == 0:                     # i의 배수인 전구만
            switch[j - 1] = 1 - switch[j - 1]   # 반전

# 모든 전구가 꺼졌는지 검증
if len(set(switch)) == 2:                  # 0과 1이 공존하면 실패
    result = -1

print(result)
```

`set(switch)`으로 검증하는 아이디어: 전부 0이면 집합의 원소가 `{0}` 하나뿐이다. 0과 1이 공존하면 원소가 두 개(`{0, 1}`)이므로 `len == 2`이면 실패다.

> **강사님 강조**: `if x in list`는 O(n)이지만 `if x in set`은 O(1)이다. 포함 여부를 확인해야 하는 문제에서 set을 적극 활용하면 시간을 크게 아낄 수 있다. 단, set은 순서 보장이 안 되고 중복 저장도 안 되므로, 이 조건이 허용되는 상황에서만 사용해야 한다.

## 9. 참고 — P vs NP (읽을거리)

Knapsack 이야기 중 강사님이 짧게 소개한 내용이다. 시험에는 나오지 않지만 알고리즘의 본질을 이해하는 데 도움이 된다.

**P(Polynomial)** 는 다항 시간 안에 풀 수 있는 문제 집합이다. O(n), O(n log n), O(n²), O(n³) 정도까지를 말한다.

**NP(Non-deterministic Polynomial)** 는 다항 시간 안에 풀기는 어렵지만, 답이 주어지면 **검증은** 다항 시간 안에 할 수 있는 문제다. 0-1 Knapsack, 수도쿠, 유전자 배열 조합 등이 대표적이다. 시간 복잡도가 2ⁿ, n! 수준이라 직접 풀기는 사실상 불가능하지만, "이 답이 맞는지"는 빠르게 확인할 수 있다.

"P = NP인가?"는 7대 밀레니엄 난제 중 하나로, 만약 P = NP가 증명되면 대부분의 암호화 시스템이 무력화되고, 현재 풀 수 없다고 여겨지는 문제들이 전부 풀릴 수 있게 된다. 현재는 대부분의 학계에서 P ≠ NP로 추정하지만, 어느 쪽도 증명되지 않았다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 탐욕 알고리즘 | 구체적 알고리즘이 아닌 문제 해결 **기법**, 순간순간 최선을 선택하여 전체 최적을 기대 |
| 장점과 한계 | 단순하고 빠르지만(O(n)), 최적해를 항상 보장하지 않으므로 검증이 필요 |
| 적용 조건 (이론) | 탐욕적 선택 속성 + 최적 부분 구조를 만족해야 함 |
| 실전 접근 순서 | 완전 탐색 → 탐욕 → 분할 정복/DP 순으로 시도, 완전 탐색이 기본 |
| 동전 교환 | 큰 동전부터 거슬러줌, 단 **동전이 배수 관계**일 때만 최적 보장 |
| 0-1 Knapsack | 넣거나 안 넣거나 → 탐욕 불가, DP로 풀어야 함 |
| Fractional Knapsack | 잘라서 담을 수 있음 → kg당 가치 높은 순으로 탐욕 적용 가능 |
| 활동 선택 | **종료 시간이 빠른 순**으로 정렬 후, 겹치지 않는 활동을 순차 선택 |
| 스위치 조작 | 앞에서부터 다르면 누름, 뒤쪽만 영향 → 앞이 안전하므로 탐욕 성립 |
| 배수 스위치 | 동일 논리 + 배수(`j % i == 0`) 조건으로 반전, 불가능하면 -1 |
| set 활용 팁 | `in set`은 O(1), `in list`는 O(n) — 포함 여부 확인 시 set 적극 활용 |
| 탐욕 마스터 비결 | 유형을 외우고, 문제를 많이 풀어서 패턴을 체득하는 것이 유일한 방법 |
