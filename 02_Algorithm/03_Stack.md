## 1. 자료구조 개요

자료구조란 데이터를 **효율적으로 저장하고 관리하기 위한 방법**이다. 어떤 문제를 풀 때 어떤 자료구조가 적합한지는 문제의 성격에 따라 달라진다. 알고리즘과 자료구조는 항상 세트로 다루며, 스택·큐·연결 리스트·트리·그래프 등 다양한 자료구조를 배우게 된다.

자료구조는 크게 두 가지로 분류된다.

| 분류 | 설명 | 예시 |
|------|------|------|
| **선형 구조** | 데이터가 일렬로 나열, 1:1 관계 | 리스트, 스택, 큐, 연결 리스트 |
| **비선형 구조** | 데이터가 계층·네트워크 형태, 1:N 또는 N:N 관계 | 트리, 그래프 |

## 2. 스택의 구조와 작동 원리

### 2-1. 스택이란

스택(Stack)은 물건을 쌓아 올리듯 자료를 쌓아 올린 형태의 자료구조다. **후입선출(LIFO, Last In First Out)** — 가장 나중에 넣은 데이터를 가장 먼저 꺼낸다.

일상에서의 예시로는 접시 쌓기, 무한리필 초밥, 호떡 쌓기 등이 있고, 개발에서는 **브라우저 뒤로가기**, **함수 호출 관리** 등에 활용된다.

> **강사님 강조**: 스택에서 기억할 핵심은 두 가지뿐이다. **후입선출(LIFO)**과 **top 포인터**. 이 두 가지 동작 원리만 구현되면 스택을 올바르게 구현한 것이다. 자료구조 구현에 정답은 없다 — 코드가 책이나 GPT와 달라도, 핵심 원리만 지켜지면 맞는 것이다.

### 2-2. 스택의 주요 연산

| 연산 | 설명 |
|------|------|
| `push` | 스택의 맨 뒤(top)에 데이터 삽입 |
| `pop` | 스택의 맨 뒤(top)에서 데이터를 꺼내고 반환 |
| `peek` | 맨 뒤(top) 데이터를 제거하지 않고 반환만 |
| `isEmpty` | 스택이 비어 있는지 확인 (True/False) |
| `isFull` | 스택이 가득 찼는지 확인 (고정 크기일 때) |

파이썬의 리스트를 사용하면 `append()`와 `pop()`으로 간단히 구현할 수 있지만, 내부 동작 원리를 이해하기 위해 **top 포인터 기반 저수준 구현**을 학습한다.

### 2-3. top 포인터

`top`은 스택에서 **마지막에 저장된 원소의 인덱스**를 항상 가리키는 포인터다. 스택이 비어 있을 때 `top = -1`로 초기화한다.

top을 사용하는 이유는 단순하다. 스택은 항상 맨 마지막에 삽입하고 맨 마지막에서 꺼내므로, 마지막 위치를 바로 알 수 있으면 매번 리스트를 순회할 필요가 없기 때문이다.

**push 과정:** top을 1 증가 → 그 위치에 데이터 저장

**pop 과정:** top 위치의 데이터를 꺼내서 저장 → 해당 위치를 None으로 초기화 → top을 1 감소 → 꺼낸 데이터 반환

## 3. 저수준 스택 구현

### 3-1. 클래스로 구현

```python
class Stack:
    def __init__(self, capacity):
        self.capacity = capacity        # 스택 최대 용량
        self.data = [None] * capacity   # 고정 크기 배열
        self.top = -1                   # 비어 있으면 -1

    def is_empty(self):
        return self.top == -1

    def is_full(self):
        return self.top == self.capacity - 1

    def push(self, item):
        if self.is_full():
            raise IndexError("Stack is full")
        self.top += 1
        self.data[self.top] = item

    def pop(self):
        if self.is_empty():
            raise IndexError("Stack is empty")
        item = self.data[self.top]
        self.data[self.top] = None
        self.top -= 1
        return item

    def peek(self):
        if self.is_empty():
            raise IndexError("Stack is empty")
        return self.data[self.top]
```

### 3-2. 동작 확인

```python
stack = Stack(3)
stack.push(1)
stack.push(2)
stack.push(3)

print(stack.pop())  # 3 (가장 나중에 넣은 것이 먼저)
print(stack.pop())  # 2
print(stack.pop())  # 1
```

> **강사님 강조**: `is_empty`, `is_full`처럼 **여부를 확인**하는 함수는 이름 앞에 `is`를 붙이는 것이 관례다. 결과가 True/False로 반환됨을 바로 알 수 있어 가독성이 올라간다.

## 4. 스택 응용 — 괄호 검사

### 4-1. 개념

괄호 검사는 스택의 가장 대표적이고 기본적인 응용이다. 주어진 문자열에서 소괄호 `()`, 중괄호 `{}`, 대괄호 `[]`의 짝이 올바른지 검사한다.

올바른 괄호의 세 가지 조건은 다음과 같다.

1. 왼쪽 괄호의 개수와 오른쪽 괄호의 개수가 같아야 한다.
2. 같은 종류의 괄호에서 왼쪽 괄호는 오른쪽 괄호보다 먼저 나와야 한다.
3. 괄호 사이에는 포함 관계만 존재한다 (짝이 교차하면 안 된다).

### 4-2. 알고리즘

문자열을 왼쪽부터 한 글자씩 순회하며 여는 괄호를 만나면 스택에 push하고, 닫는 괄호를 만나면 스택에서 pop하여 짝이 맞는지 확인한다.

핵심 논리는 이렇다. 닫는 괄호를 만났을 때 가장 최근에 들어간 여는 괄호와 짝이 맞아야 한다. "가장 최근에 들어간 것을 먼저 확인한다"는 것이 바로 LIFO, 즉 스택이 필요한 이유다.

```python
def check_brackets(text):
    stack = []
    pairs = {')': '(', '}': '{', ']': '['}

    for char in text:
        if char in '({[':
            stack.append(char)
        elif char in ')}]':
            if not stack:
                return False            # 스택이 비어 있는데 닫는 괄호 등장
            if stack.pop() != pairs[char]:
                return False            # 짝이 안 맞음
    return len(stack) == 0              # 남은 여는 괄호가 없어야 True
```

에러가 발생하는 경우를 정리하면 다음과 같다.

| 상황 | 의미 |
|------|------|
| 닫는 괄호인데 스택이 비어 있음 | 여는 괄호보다 닫는 괄호가 많음 |
| pop한 여는 괄호와 짝이 안 맞음 | 괄호 종류가 교차됨 |
| 순회 끝났는데 스택에 괄호가 남음 | 여는 괄호가 더 많음 |

## 5. 함수 호출과 복귀 — 스택 프레임

### 5-1. 호출 스택의 원리

프로그램에서 함수 호출과 복귀 순서를 관리할 때 스택을 활용한다. main에서 F1을 호출하면 F1이 스택에 쌓이고, F1 내부에서 F2를 호출하면 F2가 위에 쌓인다. F2가 끝나면 pop되어 F1으로 복귀하고, F1이 끝나면 pop되어 main으로 복귀한다.

함수 호출이 발생하면 **스택 프레임**에 지역변수, 매개변수, 복귀 주소 등이 저장된다. 함수가 끝나면 해당 프레임이 pop되면서 저장된 복귀 주소로 돌아간다.

### 5-2. 스택 오버플로우

재귀 함수에서 종료 조건을 잘못 구현하면 함수가 무한히 호출되면서 스택 프레임이 계속 쌓인다. 스택의 크기를 초과하는 순간 **Stack Overflow** 에러가 발생한다.

> **강사님 강조**: 재귀 함수를 작성할 때 반드시 **종료 조건**을 명시해야 한다. 종료 조건이 없으면 무한 재귀 → 스택 오버플로우가 발생한다. Stack Overflow라는 사이트 이름도 여기서 유래한 것이다.

## 6. 중위 표기법과 후위 표기법

### 6-1. 표기법의 종류

| 표기법 | 연산자 위치 | 예시 | 특징 |
|--------|------------|------|------|
| 중위(Infix) | 피연산자 **사이** | `A + B` | 사람에게 익숙 |
| 후위(Postfix) | 피연산자 **뒤** | `A B +` | 컴퓨터에 유리 |

후위 표기법은 **연산자 우선순위가 이미 반영**된 형태이므로, 컴퓨터가 계산할 때 우선순위를 별도로 고려할 필요 없이 앞에서부터 순서대로 처리하면 된다.

> **강사님 강조**: 코딩 테스트에서 계산기 구현 문제가 자주 나온다. 대부분 후위 표기법이 이미 주어진 채로 출제되므로, 후위 표기법 계산 로직만 구현하면 된다. 중위→후위 변환은 까다로우므로 보통 문제에서 변환까지 요구하지 않는다.

### 6-2. 중위 → 후위 변환 (스택 활용)

연산자 우선순위를 정의한다.

| 우선순위 | 연산자 |
|----------|--------|
| 2 (높음) | `*`, `/` |
| 1 (중간) | `+`, `-` |
| 0 (낮음) | `(` (스택 내부에서) |

**변환 알고리즘:**

1. 토큰을 왼쪽부터 하나씩 읽는다.
2. **피연산자**(숫자/문자)를 만나면 → 그대로 출력한다.
3. **여는 괄호** `(`를 만나면 → 스택에 push한다.
4. **닫는 괄호** `)`를 만나면 → 스택에서 여는 괄호가 나올 때까지 모두 pop하여 출력한다 (여는 괄호 자체는 버린다).
5. **연산자**를 만나면 → 스택 top에 있는 연산자의 우선순위가 현재 연산자보다 **크거나 같으면** pop하여 출력하는 것을 반복한 뒤, 현재 연산자를 push한다.
6. 모든 토큰을 읽은 후 → 스택에 남은 연산자를 모두 pop하여 출력한다.

핵심 논리를 비유하면 이렇다. 스택 안에서 우선순위가 높은 연산자가 위에 쌓여야 한다. "먼저 빠져나가는 것 = 먼저 계산되는 것"이므로, 우선순위가 높은 연산자가 먼저 나가도록 스택 위에 있어야 한다. 새로운 연산자가 들어올 때 자기보다 높거나 같은 선배가 스택에 있으면 그 선배를 먼저 내보낸다.

```python
def infix_to_postfix(expression):
    priority = {'*': 2, '/': 2, '+': 1, '-': 1, '(': 0}
    stack = []
    result = []

    for token in expression:
        if token.isdigit() or token.isalpha():      # 피연산자
            result.append(token)
        elif token == '(':                            # 여는 괄호
            stack.append(token)
        elif token == ')':                            # 닫는 괄호
            while stack and stack[-1] != '(':
                result.append(stack.pop())
            stack.pop()                               # '(' 제거
        else:                                         # 연산자
            while stack and priority.get(stack[-1], 0) >= priority[token]:
                result.append(stack.pop())
            stack.append(token)

    while stack:                                      # 남은 연산자 출력
        result.append(stack.pop())

    return result
```

### 6-3. 후위 표기법 계산 (스택 활용)

후위 표기식을 앞에서부터 읽으며 피연산자를 만나면 스택에 push하고, 연산자를 만나면 스택에서 두 개를 pop하여 계산한 뒤 결과를 다시 push한다. 모든 토큰을 처리한 후 스택에 남은 값이 최종 결과다.

```python
def eval_postfix(expression):
    stack = []
    tokens = expression.split()

    for token in tokens:
        if token.lstrip('-').isdigit():               # 피연산자 (음수 포함)
            stack.append(int(token))
        else:                                         # 연산자
            b = stack.pop()                           # 나중에 넣은 것이 두 번째 피연산자
            a = stack.pop()
            if token == '+':   stack.append(a + b)
            elif token == '-': stack.append(a - b)
            elif token == '*': stack.append(a * b)
            elif token == '/': stack.append(int(a / b))

    return stack.pop()
```

**계산 예시:** `6 5 2 8 - * 2 / +`

| 단계 | 토큰 | 동작 | 스택 |
|------|------|------|------|
| 1 | 6 | push | [6] |
| 2 | 5 | push | [6, 5] |
| 3 | 2 | push | [6, 5, 2] |
| 4 | 8 | push | [6, 5, 2, 8] |
| 5 | - | pop 2, 8 → 2-8=-6 | [6, 5, -6] |
| 6 | * | pop 5, -6 → 5×(-6)=-30 | [6, -30] |
| 7 | 2 | push | [6, -30, 2] |
| 8 | / | pop -30, 2 → -30/2=-15 | [6, -15] |
| 9 | + | pop 6, -15 → 6+(-15)=-9 | [-9] |

결과: **-9**

## 7. 재귀 함수

### 7-1. 재귀의 원리

재귀 함수란 **자기 자신을 호출하는 함수**다. 범위를 점점 줄여가면서 호출하다가 **종료 조건(base case)** 에 도달하면 값을 반환하고, 그 값을 기반으로 거슬러 올라가며 최종 결과를 구한다.

재귀 함수 작성의 핵심은 두 가지다.

1. **종료 조건:** 더 이상 재귀하지 않고 값을 반환하는 조건
2. **재귀 호출:** 범위를 줄여서 자기 자신을 호출

> **강사님 강조**: 재귀가 어려운 것은 당연하다. "통곡의 벽"이라 불릴 만큼 어렵지만, DFS와 DP에서 계속 쓰이므로 포기하지 말고 한 번에 다 이해하려 하지 않아도 된다. 반복적으로 접하면서 점점 익숙해지면 된다.

### 7-2. 팩토리얼

수학적 정의를 그대로 코드로 옮기면 된다. `n! = n × (n-1)!`이고, `0! = 1! = 1`이 종료 조건이다.

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)
```

호출 흐름: `factorial(4)` → `4 × factorial(3)` → `4 × 3 × factorial(2)` → `4 × 3 × 2 × factorial(1)` → `4 × 3 × 2 × 1 = 24`

### 7-3. 피보나치 수열

`F(n) = F(n-1) + F(n-2)`이고, `F(0) = 0`, `F(1) = 1`이 종료 조건이다.

```python
def fibonacci(n):
    if n == 0:
        return 0
    if n == 1:
        return 1
    return fibonacci(n - 1) + fibonacci(n - 2)
```

호출 흐름: `fibonacci(5)` → `fibonacci(4) + fibonacci(3)` → 각각 다시 분기하면서 종료 조건에 도달할 때까지 재귀한다. 최종 결과는 5.

### 7-4. 거듭제곱

**기본 방식 — O(n):**

`x^n = x × x^(n-1)`이고, `x^0 = 1`이 종료 조건이다.

```python
def power(x, n):
    if n == 0:
        return 1
    return x * power(x, n - 1)
```

**분할정복 방식 — O(log n):**

`2^10 = 2^5 × 2^5`처럼 지수를 절반씩 줄여 나가면 호출 횟수가 대폭 줄어든다.

```python
def power_fast(x, n):
    if n == 0:
        return 1
    half = power_fast(x, n // 2)
    if n % 2 == 0:                # 짝수: x^n = (x^(n/2))^2
        return half * half
    else:                         # 홀수: x^n = x × (x^(n//2))^2
        return x * half * half
```

`2^1000`을 기본 방식으로 구하면 1,000번 재귀하지만, 분할정복 방식은 약 10번(log₂1000 ≈ 10)이면 충분하다.

> **강사님 강조**: 거듭제곱 분할정복은 여러분이 코드로 구현할 필요까지는 없지만, "지수를 절반씩 줄이면 O(log n)이 된다"는 아이디어를 이해하는 것이 중요하다. 이런 사고의 확장이 논리적 사고력을 키우는 훈련이다.

## 8. 행렬 전치와 회전

스택 강의 시간에 함께 다룬 행렬 연산 팁이다. A형 시험에서 회전이 필요한 문제가 종종 출제되므로 공식처럼 기억해 두면 유용하다.

### 8-1. 전치 (Transpose)

전치란 **행과 열을 바꾸는 것**이다.

```python
matrix = [[1, 2, 3],
          [4, 5, 6],
          [7, 8, 9]]

transposed = list(map(list, zip(*matrix)))
# [[1, 4, 7], [2, 5, 8], [3, 6, 9]]
```

원리: `*matrix`로 언패킹하면 각 행이 풀리고, `zip()`이 같은 열끼리 세로로 묶어 준다.

### 8-2. 90도 시계방향 회전

행을 뒤집은 뒤 전치하면 90도 시계방향 회전이 된다.

```python
rotated_90 = list(map(list, zip(*matrix[::-1])))
# [[7, 4, 1], [8, 5, 2], [9, 6, 3]]
```

### 8-3. 90도 반시계방향 회전

전치한 뒤 행을 뒤집으면 90도 반시계방향 회전이 된다.

```python
rotated_270 = list(map(list, zip(*matrix)))[::-1]
# 또는: [row[::-1] for row in list(map(list, zip(*matrix)))]
```

> **강사님 팁**: 회전을 인덱스로 직접 구현하면 30분은 걸린다. 이 공식을 외워 두면 한 줄이면 끝난다. 90도 회전 함수를 하나 만들어 놓고 필요한 만큼 호출하는 방식이 가장 효율적이다. 외우기 어려우면 유도 과정을 기억하자 — **뒤집고 전치 = 시계방향**.

## 9. 함수 호출 시 가변·불변 인자 주의

### 9-1. 리스트 인자의 함정

리스트는 가변(mutable)이므로 함수에 리스트를 넘기면 **주소를 공유**한다. 함수 내부에서 리스트를 변경하면 원본도 변경된다.

```python
def modify(x_list):
    x_list.append(4)

data = [1, 2, 3]
modify(data)
print(data)  # [1, 2, 3, 4] ← 원본이 변경됨
```

원본에 영향을 주고 싶지 않으면 **복사**해서 넘겨야 한다.

```python
modify(data.copy())         # 얕은 복사
modify(data[:])             # 슬라이싱 복사
modify(list(data))          # list() 복사

import copy
modify(copy.deepcopy(data)) # 깊은 복사 (중첩 리스트일 때)
```

> **강사님 강조**: 알고리즘 문제를 풀 때 "논리는 완벽한데 왜 안 되지?"라면 **75%는 이 문제**(리스트 주소 공유)가 원인이다. 나머지는 오타, 범위 설정 실수 등이다. `pass by value`와 `pass by reference` 개념은 면접에서도 자주 물어본다.

## 정리

| 구분 | 핵심 포인트 |
|------|-------------|
| 스택 | 후입선출(LIFO), top 포인터로 마지막 원소 관리, push/pop이 핵심 연산 |
| 저수준 구현 | 고정 크기 배열 + top 포인터, is_full/is_empty 검사 필수 |
| 괄호 검사 | 여는 괄호 → push, 닫는 괄호 → pop 후 짝 비교, 마지막에 스택이 비어야 정상 |
| 함수 호출 스택 | 호출 시 스택 프레임에 push, 종료 시 pop하여 복귀 주소로 이동 |
| 스택 오버플로우 | 재귀 종료 조건 미구현 → 무한 호출 → 스택 프레임 초과 |
| 중위 → 후위 변환 | 연산자 우선순위에 따라 스택에 넣고 빼면서 후위 표기식 생성 |
| 후위 표기법 계산 | 피연산자 push, 연산자 만나면 두 개 pop하여 계산 후 결과 push |
| 재귀 함수 | 종료 조건 + 범위 축소 재귀 호출, 팩토리얼·피보나치·거듭제곱이 대표 예제 |
| 분할정복 거듭제곱 | 지수를 절반씩 줄여 O(log n) 달성 |
| 전치·회전 | 전치: `zip(*matrix)`, 시계 90도: `zip(*matrix[::-1])` |
